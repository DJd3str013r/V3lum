# Backlog - batch p1-G10-1 (P219 sanctions_lists, P232 br_validators, P233 boleto_pix)

Items of the final conditions that this batch could not deliver in its own files, or delivered as an
interim inside them. Each has the reason and what unblocks it. Everything else in the three proposals
is implemented and tested (`tests/modules/test_sanctions_lists.py`, `test_br_validators.py`,
`test_boleto_pix.py`; live check `tests/live/test_p1_g10_1.py`).

## P219 sanctions_lists

| item | reason | unblock condition |
|---|---|---|
| `v3lum data update sanctions` (cond 3) as a group name | `v3lum data update` takes dataset names only; there are no dataset groups. The six datasets are registered `essential=True`, so `v3lum data update --essential` refreshes them, and the module's UNAVAILABLE message lists the explicit names. | Core adds dataset groups (`register_dataset(..., group='sanctions')` and `v3lum data update <group>`); then the module only needs the group name. |
| Shared safe XML helper in the core (cond 5) | The core has no safe XML helper. The parser lives in `v3lum/modules/company_org/sanctions_data.py::safe_xml_parse` (DOCTYPE/ENTITY/ELEMENT/ATTLIST/NOTATION refused, encoding allow-list, size, depth and element caps). Batch p1-G12-1 built a second one in `file_analysis/file_type_sniff.py`. | Core lands `v3lum/core/safexml.py` with these semantics. Both modules then import it, and the two copies are removed. |
| Shared matcher at `core/namematch.py` (cond 6) | Modules may not create core files. The matcher is `v3lum/modules/company_org/namematch.py` (pure Python, with an optional rapidfuzz accelerator giving identical scores; both paths tested; benchmark < 300 ms per name on 50k aliases). | Core moves it to `v3lum/core/namematch.py` unchanged (same names). P240, P244, P254 and P221 then import it from the core. |
| Previous list version kept by the dataset manager (cond 12) | The dataset manager replaces a copy in place. **Interim, delivered:** the module keeps a compact snapshot of the last screened version in `ctx.state`: base32 digests of exact identifiers (wallets, CNPJs) and of non-individual primary names, plus name and programmes of identifier owners. Delisted wallets, CNPJs and organisation names read 'formerly listed (<date>)'. Not covered: aliases, person names (never stored, by design), and versions installed between two screenings. | The dataset manager keeps the previous copy (`keep_previous=True`) and exposes it as `ctx.data.previous(name)`. The module then diffs full versions. |
| List publication date in the MANIFEST (cond 3) | The MANIFEST records `fetched_at` and `sha256`. The source date (UN `dateGenerated`, EU `fileGenerationDate`) is read from the file at load time. SDN.CSV carries no date, so the OFAC date shown is the download date. | Dataset `validate` returns metadata (e.g. `{'source_date': ...}`) that the manager stores, or the manager records `Last-Modified`. |
| EU FSF public token as a configuration value (cond 1) | Dataset URLs are fixed at registration and cannot be built from settings. The token is the module constant `EU_FSF_PUBLIC_TOKEN` (the Commission's published value). | Core supports setting placeholders in dataset URLs. |
| UN/EU attribution line and list dates in reports (cond 12) | The module emits `data_attribution` and `dataset_age` attributes. Printing them in the report's coverage section is renderer work (WP19/WP20). | Report renderers print `data_attribution` and the per-list dates in the coverage section. |
| Due-diligence case model (cond 10) | Interim: a person name is screened only as an analyst-typed, confirmed seed with a recorded `--purpose`, or as a QSA partner one hop from an analyst-typed CNPJ when setting `sanctions_lists_due_diligence_partners` is on (purpose also required). Everything else is SKIPPED 'privacy'. | When cases carry an explicit 'due diligence' type, the gate checks it in addition to the purpose. |
| P295 alias index API (cond 11) | Aliases are read from the `v3lum/data/aliases/*.json` fragments (kind `threat_actor`), the frozen `v3lum.aliases/1` schema. | WP17 lands the aliases index; the module switches to its API. |
| Redaction of the OFAC S3 pre-signed URL | The SLS exports answer 302 to an S3 URL carrying `X-Amz-Credential`, `X-Amz-Security-Token` and `X-Amz-Signature`. `redact.KEY_PARAMS` does not list them. | Core adds the `X-Amz-*` (and Azure SAS `sig`, already covered) parameters to `KEY_PARAMS`. |

## P232 br_validators

| item | reason | unblock condition |
|---|---|---|
| Validators as an extension of `core/validators.py` (cond 1) | Modules may not edit core files. The CPF/CNPJ (alphanumeric), plate, CEP, PIX-key and BR-rule-set helpers live in `v3lum/modules/brazil_public_data/br_parsers.py` (stdlib only; they use `core.validators` and `core.entities.mask_cpf`). | Core moves the identifier helpers into `core/validators.py` under the same names. |
| BR rule set inside the P172 extraction engine (cond 8) | `core/ioc.py` (WP17) does not exist yet. The rule set is `br_parsers.BR_RULES` plus `extract_br_entities` (priority BR Code > boleto > CNJ > CNPJ > PIX key > CPF > phone, checksum gating, provenance and type confidence). `br_validators` calls it directly. | WP17 registers `BR_RULES` in `core/ioc.py`. `br_validators` then calls the engine. |
| CPF masked in every renderer (cond 5, AR24) | Module facts are masked in every renderer (tested). The core renderers still print the raw seed key of a typed CPF: the terminal input line, Markdown seeds, the STIX report description, and the JSON case dict. `test_raw_cpf_never_appears_in_any_renderer` is xfail. | Core renderers and the case export use `entities.display_value()` for seeds. |
| `--show-personal` single-view unmask recorded in the case audit (cond 5) | This is a CLI/report and audit feature (WP13/WP15), not a module one. | Lands with the WP13/WP15 work. |
| PIS/NIS, titulo de eleitor, RENAVAM, CNS, CNH validators (cond 6) | Cond 6 says they ship only with official test vectors, and research found none (C0578 unverified). Masking ships now (`br_parsers.mask_national_id`). They are not entity types, never auto-detected and never pivoted. | Official vectors are collected (TSE for the titulo, Caixa for PIS/NIS, DATASUS for CNS, DENATRAN for RENAVAM/CNH). Then the validators and their tests are added. |
| P327 lint rejects modules that take these identifiers as lookup keys (cond 6) | Lint rules are core code (`core/lint.py`). Lint-table fragments only add hosts. | Core adds a lint rule refusing `accepts`/request parameters named for PIS/NIS, titulo, RENAVAM, CNS or CNH. |

## P233 boleto_pix

| item | reason | unblock condition |
|---|---|---|
| OCR (P363) and QR-decode (P261) input origin (cond 7) | Those modules do not exist yet. The origin is inferred from the last provenance step: a module or relation name containing `ocr` or `qr`. In that case a failed check digit or CRC reads 'could not verify (OCR)'. | When P363/P261 land, they use a relation the heuristic recognises (e.g. `ocr_text`, `qr_decode`), or the core adds an explicit origin flag to `RunInfo`. |
| Payee CNPJ roots from the P236 chain (cond 6) | A CNPJ key pivots to the P236 chain (expand=True), and the brand comparison uses the claimed brands' CNPJ roots: org profile, bank tables, and P360 conglomerate roots. Resolving the payee's own company name through P236 within the same run would be a network call, which this disclosure 'none' module must not make. | A correlation rule over the P236 result (payee company vs claimed brand) can add it after the scan, in a later wave. |

## Not adopted (council)

* P219: OpenSanctions (CC BY-NC) is excluded from this module; it belongs to P222.
