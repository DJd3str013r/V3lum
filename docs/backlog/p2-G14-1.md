Delivered:

* six packs in `v3lum/data/pivot_links/`: `domain_dns`, `ip_network`, `url_web`, `threat_intel_ioc`,
  `malware_hash` and `vulnerability`;
* the gated-link renderer `v3lum/modules/utility/pivot_gated_links.py`;
* four offline modules: `pivots_domain_dns`, `pivots_ip_network`, `pivots_url_web` and `pivots_threat_intel`.
  P180 and P194 are pack-only;
* 28 provider fragments and the extension `netcraft__p2-G14-1.json`;
* offline tests, verification records, golden URLs, acceptance routes and a live check.

Links that the frozen core (`v3lum.core.links`, schema `v3lum.pivot_pack/1`) cannot render correctly sit in each
pack under the pack-level extension key `x_module_links`. The pack's module renders them; they are linted like pack
links and fail closed. They need one of these:

* a TLP ceiling;
* analyst-typed values only;
* a value rule;
* a vetted encoder.

Five cond-8 entries are already core links of other batches with the same template. They are referenced in
`x_served_by`, not duplicated: an identical template would be dropped by the core loader, or would displace the
other pack's link, which modules use as `manual_link`.

## Items not delivered as written

Each item gives the reason first, then the unblock condition.

### P057 cond 9: core pack links still render for CGNAT addresses and in `v3lum links`

**Item.** The core pack links of `ip_network` (bgp.he.net, IPinfo, Scamalytics, CIDR Report, Myip.ms).

**Reason.** `links.render` has no value filter.

* The engine attaches pack links only to non-noise entities, and noise covers private, loopback, link-local, ULA,
  reserved and documentation addresses. CGNAT (100.64/10) is not noise.
* `v3lum links <value>` renders any typed value.
* Module links apply the full filter (`pivot_gated_links.public_value_problem`, one unit test per range).
* Every core link of the pack carries `x_public_only: true`.

**Unblock.** Core `links.render` / `pivot_links_for` honour `x_public_only`.

### P057 cond 1/10, P170 cond 1/10, P083 cond 11: per-link `max_tlp`

**Item.** The per-link `max_tlp` field.

**Reason.** It is not in the frozen schema. Criminal IP, FOFA, ScamAdviser, securityheaders.com and URLVoid are
module links with `x_max_tlp: green`.

* They are hidden from reports at TLP:AMBER and above (code-enforced from the run's TLP).
* `v3lum links` does not list them at any TLP, so cond 10's "listed only by `v3lum links` with the warning" is not
  met.

**Unblock.** Core links carry `max_tlp`, and `v3lum links` lists such links with the warning (or lists
`x_module_links`).

### P057 cond 11: `{b64q}` placeholder

**Item.** The vetted `{b64q}` placeholder.

**Reason.** It is implemented module-side: `pivot_gated_links.b64q` is `links.b64` over the entry's fixed
`ip="{q}"` / `icon_hash="{q}"` expression, and it refuses quotes, backslashes and control characters. FOFA links
therefore render in scans only, not in `v3lum links`.

**Unblock.** A core `{b64q}` placeholder with an entry-declared vetted expression.

### P057 cond 11: FOFA `cert="{q}"`

**Item.** The FOFA certificate search.

**Reason.** On 2026-11-26 FOFA answered in the page `[824001] Keyword: cert requires Registered User and above`.
This is a login wall, so the entry is excluded and the P311 lint drops `login_required` links.

**Unblock.** None (FOFA policy). Re-check if FOFA opens the keyword.

### P057 cond 5: FOFA tier

**Item.** FOFA's tier.

**Reason.**

* The `fofa` fragment belongs to another batch and records tier `unknown`, while cond 5 proposes community.
* FOFA links carry the 'unknown operator' badge.
* Its values (IPs, favicon hashes) are IOC types, so nothing else changes.

**Unblock.** The registry reviewer confirms the tier in `fofa.json` (owning batch).

### P083 cond 11, P170 cond 9: scan-trigger module links are clickable at TLP:CLEAR/GREEN

**Item.** "Defanged, non-clickable" for ScamAdviser, securityheaders.com and URLVoid.

**Reason.**

* Module links reach `case.links` as plain `{label, url}`, so the renderers cannot see `touches_target`.
* At CLEAR/GREEN, for analyst-typed non-hostile values, these links are clickable. The label carries
  'WARNING: opening makes <host> contact the target live'.
* At AMBER and above they are not emitted at all.

**Unblock.** `ModuleResult.link(..., host=, category=, touches_target=, verified=, badge=)`, or the engine carries
the rendered-link metadata of module links into `case.links`.

### P083 cond 11, P170 cond 9: "hidden for hostile entities unless expanded"

**Item.** Hiding scan-trigger links for hostile entities.

**Reason.**

* The module runs `policy.hostile_reasons` at run time: case-DB sightings with a hostile verdict, hostile-shaped
  names and org-brand lookalikes. Hostility found later in the same scan by other modules is not seen.
* There is no "expand" for module links.

**Unblock.** Same as the previous item: the renderers would then hide touches_target items for hostile entities and
honour `--full`.

**Item.** The `v3lum doctor --links` command.

### Core `{asn_num}` placeholder is not encoded

**Item.** The core `{asn_num}` encoder.

**Reason.**

* It returns `value[2:]` raw. A non-normalised `Entity(ASN, value)` can therefore inject query parameters (found by
  this batch's hostile-value CI test).
* This batch's ASN templates use `{q}` on the normalised `AS<digits>` value.

**Unblock.** Core encodes `{asn_num}`.
