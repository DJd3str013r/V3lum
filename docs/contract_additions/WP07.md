# Contract additions - WP07 (wave 2)

Policy as code (P327): the single policy gate the frozen guide announced as "the policy gate and
the licence, TLP, tier, privacy, own-asset, scope and egress gates (wave 2)", the licence profile and
legal allow-list (A1/P377), the hostile-host contact guard (A13/P376) and the measured-health
demotion state (A3). Nothing of the frozen guide is renamed or changes meaning: `run_on`,
`default_enabled`, `manual_link`, `requires_egress`, `requires_keys`, `daily_quota`, the reserved
tags (`watch_only`, `cached_only`), `ctx.allowed_sources` and every reason code keep their
documented meaning; this file adds names and states the enforcement the guide marked "from wave 2".
`v3lum.core.policy.decide` and `v3lum.core.licence.source_allowed` move here from the guide's
"Arriving later" table.

Who needs it: **module authors** of every batch (what the gate does with their metadata - section
"What module authors can rely on"), **WP08** (engine selection, two-phase guard, coverage rows,
`licence_used`, health records), **WP11** (redirect hops re-run `contact_guard`), **WP12** (spec
auto-disable through `HealthState`), **WP13** (every CLI path builds its context with
`make_context`; `valid_authorization_ref`, `resolve_profile`, `describe_policy`), **WP16** (the
sightings lookup protocol, `HealthState.record_votes`), **WP17** (`recipient_token`), **WP20**
(`Decision.licence_basis` -> licence banner), **WP25** (doctor: notices, expiring entries,
`record_check`, `effective_default_set`), **WP29** (`rules_markdown()` -> docs/RULES.md).

## What module authors can rely on

The gate reads only the metadata the frozen guide already documents. From wave 2:

* **Default set (POL-01, A3).** With the preset `quick` (default) only `default_enabled = True`
  modules run unless selected with `-M`; `--preset deep` / `--all-modules` add the opt-in ones.
  `default_enabled` only lowers the set: every other gate still applies to `-M` and deep runs. A
  module tagged `watch_only` runs only inside `v3lum watch` (SKIPPED `not_applicable` elsewhere,
  even with `-M`). Demoted modules (measured health, below) leave the default set; `-M` still runs
  them.
* **Licence (POL-04, A1).** Each declared source is evaluated under the licence profile (corporate
  by default): `open` runs; `key-terms` runs when the source's `free_plan_business_use` is true or a
  key of the module that belongs to the source's provider has the plan `business` - a required key,
  or an optional key that is configured (an optional key that is not set means keyless requests,
  which only `free_plan_business_use` allows; another provider's business key never counts); `noncommercial` /
  `license` run only with an active licence_allow entry (or, under research, inside the research
  basis scope); `unknown` never. Aggregators receive the passing sources in `ctx.allowed_sources`
  and must query only those (the engine reports the others as coverage rows `licence`); a module
  with no passing source is SKIPPED `licence` with its `manual_link` emitted. A dataset source is a
  source like any other: an offline module whose dataset is `noncommercial` is skipped as well.
* **TLP (POL-05, A2)** follows `Module.max_tlp`: disclosure `none`/`internal` up to RED;
  `third_party` trusted AMBER+STRICT, community AMBER, unknown tier or `reuses_queries` GREEN;
  `publishes_queries` never (SKIPPED `policy`, rule 7); `target` AMBER, and RED only on verified own
  assets that are not third-party hosted, through a usable `proxy_light`/`proxy_active` (a Tor port
  is never an ACTIVE route; an unparseable proxy URL does not count) or a recorded
  `--egress-override`. A `target` module that also queries a provider API is bound by that
  provider's ceiling too. The provider flags and tiers are read from the live registry as well as
  from the derived class attributes (the stricter wins). The entity TLP is `RunInfo.tlp`, else the
  seed TLP, else `options.tlp`, and never below AMBER in a LIGHT/ACTIVE case.
* **Tier (POL-06, A8).** Unknown-tier providers need `--allow-unknown` (CLEAR/GREEN) and receive
  IOC_TYPES values only - never PERSONAL_TYPES, CNPJ, keywords or company names (also when a
  `target` module queries them).
* **Secrets (POL-07, A7/A8).** SECRET_TYPES values (jwt, telegram_bot_token, secret,
  payment_card) never reach a module whose disclosure is not `none`, at any TLP and even with `-M`:
  SKIPPED `policy` ('secret value ...: never sent to a provider, an internal platform or the
  target'). Offline modules may still parse them.
* **Privacy (POL-07).** `run_on='seeds'`: only confirmed analyst-typed seeds (not pivots, not
  text-extracted values, not `options.unconfirmed_seeds`). Any PERSONAL_TYPES entity needs a
  recorded `--purpose`, whatever the disclosure. A value-receiving provider without
  `personal_data_review` gets PERSONAL_TYPES only when the module is selected explicitly (`-M`);
  `core_doh` (DoH-only modules) is exempt because resolvers only ever receive DNS names.
  `run_on='own_assets'`: verified (txt_verified/attested) org-domain addresses, or analyst-typed
  seeds with `--breach-scope all` and a purpose; otherwise SKIPPED `privacy` ('breach check
  skipped: not an org domain'). A URL that carries a recipient token (detected, or tagged
  `recipient_token` in the case graph) is never handed to a `fetches_target` provider (unless the
  module is tagged `cached_only` or the URL was confirmed with `--confirm-url`): SKIPPED `policy`,
  rule GUARD-02. A `target` module that also queries a provider API needs that provider's
  personal-data review like a `third_party` module. Doctor health checks (path `doctor`) on the
  module's `BENIGN_VALUES` value are exempt from the personal-data rules (reserved example values).
* **Own assets (POL-08, A11).** `run_on='own_assets_only'` needs a txt_verified or attested org
  entry; without a profile the reason is 'no org profile (v3lum org)'.
* **Opsec and engagement (POL-09/POL-10, A7).** No escalation above the scan mode. ACTIVE needs a
  valid `--authorized REF` (`^[A-Za-z0-9][A-Za-z0-9._:/#-]{2,63}$`, not a placeholder such as
  confirmed/yes/ok/none/n/a/test - the policy list is a superset of `v3lum.core.scope.PLACEHOLDER_REFS`)
  and `options.scope` bound to the same reference, inside its window, without problems from
  `Scope.validate(ref, now, org_terms=<org name and brands>)` (an ROE identity naming the
  organisation is refused), containing the target (`matches_url`/`matches_host`/`matches_ip`; a
  CIDR entity must lie inside one target network and overlap no exclusion). LIGHT runs only on
  analyst-typed seeds; with setting `light_for_own_assets` it may run without `--mode light` on
  verified own seeds. Pivots never inherit scope.
* **Registration (POL-02).** Only classes registered through `@register` and present in the
  registry run; a network module (disclosure other than `none`) placed in the registry by hand has
  no derived provider flags and is refused (SKIPPED `policy`); a module file with a load error, or a
  spec with an error under `spec:<name>`, is refused too.
* **Egress, keys, packages, datasets, quota, circuit (POL-11..POL-16).** `requires_egress` vs setting
  `egress_country` (manual link emitted); missing `requires_keys` -> NEEDS_KEY (manual link); an
  internal platform without its URL setting, or a provider whose `http_profile` asks for an
  identifying contact without `contact_email`/`contact_url`, -> SKIPPED `config`; a missing
  optional package -> UNAVAILABLE `package`; a large registered dataset never downloaded ->
  UNAVAILABLE `dataset` during scans (any missing dataset when offline); an exhausted provider quota
  block (seed priority honoured) or the legacy `daily_quota` -> QUOTA (manual link); a declared
  host (or the target host of a `target` module) short-circuited in this run -> BLOCKED `circuit`
  (manual link).
* **Contact guard (GUARD-01/02, A13).** After an entity's passive results, LIGHT/ACTIVE contact is
  BLOCKED `hostile_host` ('needs non-corporate egress') when the entity, its host, its registrable
  domain or a graph redirect target / CNAME / non-noise resolved address is tagged (node or finding
  tags, `HOSTILE_TAGS`) or flagged (boolean attributes `malicious`/`suspicious`) hostile, carries a
  reputation listing (finding tags `LISTING_TAGS`; attributes `blocklist_hits`, `blocklists`,
  `blocklist_families`; a CR27 correlation - a finding or hit that is only an ad/tracking listing,
  tag `ads_tracking` / hit category `ads_tracking`, does not count), has a hostile case-DB sighting
  verdict, serves a URL of the case tagged hostile on exactly that host (edges `hosts_url` /
  `url_host`; noise hosts and URLs tagged `hosted_on_legit_platform`/`abused_legit_service` are
  not tainted), or is hostile-shaped (org-brand lookalike after accent/homoglyph folding, tag
  `typosquat`/`brand_abuse`, `domain_age_days` <= 30 or a domain whose `created` date is at most 30
  days old or tag `newly_registered`, a lure word from `v3lum/data/brand_lures*.json`, extracted
  from text/file/e-mail input; own confirmed assets and supplier domains are exempt from the shape
  checks). It yields only to a usable `proxy_light` (LIGHT) / `proxy_active` (ACTIVE; never a Tor
  port) or a recorded `--egress-override`; a configured profile that cannot be used is named in the
  refusal. Recipient-token URLs (GUARD-02) need `--confirm-url` for the exact URL; an egress profile
  or override never lifts that, and a confirmed URL still passes GUARD-01.
  Modules record `domain_age_days` (or the registration date `created`) and the reputation tags or
  boolean attributes of the vocabulary so the guard can see them; the guard never needs anything
  else from a module.

Every refusal quotes its rule id (`... [POL-04]`) and uses only the canonical A3 reason codes.

## Details

### `decide()` and `Decision`

`decide(module_cls, entity, pctx, *, run)` never raises outside strict contract mode: an unexpected
error fails closed (SKIPPED `policy`, POL-02). `run` is the RunInfo of the candidate run (the
engine's; `is_seed`, `provenance`, `tlp`, `priority`, `case_id` are read). An allowed Decision has
status OK and no code; its `reason` is 'allowed' (or lists the licence-blocked feeds of an
aggregator). `allowed_sources` is None for modules without registry sources (no restriction), the
passing subset otherwise - also on refusals after POL-04, so coverage can list blocked feeds;
`blocked_sources` maps each licence-blocked source to its reason ('skipped: noncommercial terms
(licence profile corporate)'). `licence_basis` maps the usable sources to `'open'`,
`'business_plan:<key>'`, `'allow:<legal_ref>'` or `'research:<legal_ref>'` (WP08 copies it into
`case['licence_used']`). `emit_manual_link` is set for POL-04, POL-11, POL-12 (needs_key), POL-15,
POL-16 and GUARD-01. Tests: `tests/test_policy.py` (a table of more than 120 rows, one test per
rule named in `RULES`).

### `PolicyContext` and `make_context()`

`make_context` reads the runtime's config, clock, org profile, registry (the live process-wide one
unless the runtime injected one), quota book, health state (`Runtime.health` when present, else
`shared_health()`), the HTTP client's circuit (a live view: hosts tripped during the run are seen at
once), `runtime.meta['sightings_lookup']` and the licence allow-list (setting
`licence_allow_path`). `explicit` is united with `options.include`. A research profile without an
active research basis falls back to corporate (fail closed) with a note in `pctx.notes`; the CLI
refuses it first with `licence.RESEARCH_REFUSAL`. Each call builds a fresh context: the engine
builds one per investigation and passes the case graph for the guard.

### Sightings protocol (for WP16)

`pctx.sightings` is called as `lookup(entity)`, with the keywords `case_id=` and `case_tlp=` added
when the callable declares them (`Store.sightings_for(entity, *, case_id, case_tlp)` fits). The
guard reads `summary.visible` (or `summary['visible']`): a row whose `verdict` is one of malicious,
phishing, c2, suspicious, compromised, positive or true_positive makes the host hostile; an optional
`tags` attribute is read the same way. Restricted (higher-TLP) sightings carry no verdict and never
block by themselves. A failing lookup is ignored (the case DB being down is not a signal).

### Licence allow-list file (`v3lum.licence_allow/1`)

```json
{"schema": "v3lum.licence_allow/1",
 "entries": [{"source_id": "sans_isc.api", "basis": "terms_clause", "scope": "own-network defence only, no resale",
              "legal_ref": "LEGAL-2026-014", "approver": "legal (DPO office)", "decided_at": "2026-11-26",
              "review_by": "2027-05-26", "evidence_url": "https://isc.sans.edu/api/", "quote": "..."}],
 "research_basis": {"legal_ref": "LEGAL-2026-020", "approver": "legal", "date": "2026-11-26", "scope": ["shodan.internetdb", "abusech"]}}
```

`LicenceState.load()` without arguments reads setting `licence_allow_path` from `Config.load()`.
An entry is active only while `decided_at <= today <= review_by` and `review_by` is at most 12
months after `decided_at` (an entry beyond the cap is kept for doctor but never active). Dates are
`YYYY-MM-DD` or a full ISO date-time; anything else ('2026-11-01garbage') drops the entry.
Malformed entries are dropped and listed in `errors`; a file writable by other users (or
group-writable inside the V3LUM home) is ignored with a warning; a readable-by-others copy in the
home only warns ("looser than 0600"). The research basis follows the same 12-month review (default
`date + 12 months`; an unreadable `review_by` makes it inactive) and covers only the source ids
(`pid.sid`), provider ids (`pid.*`, or a bare `pid` that is a registered provider) or `*` named in
its scope. A scope holding any other word is prose and covers nothing: `all` is not a wildcard, and
'everything except shodan' never covers shodan. Tests: `tests/test_licence.py`.

### Health state (`~/.v3lum/health.json`, `v3lum.health/1`, 0600)

`record_run(module, duration, status, *, reason_code='')` keeps a rolling window of the last 50
durations of runs that reached the source and the BLOCKED streak (ok/empty resets it, other
statuses leave it; a BLOCKED run with reason code `circuit` or `hostile_host` - or a ModuleResult
passed as `status` that carries one - never reached the source: it counts as a run but neither
extends the streak nor adds a duration). **WP08**: pass `reason_code=res.reason_code` from
`Engine._record_health`, otherwise one challenge that trips the circuit can demote a module within
a single scan through its in-flight runs.
`record_votes(module, wrong, total)` stores the current feedback totals (not increments);
`record_check(module, result)` stores doctor results (ok resets the failure streak, dead/blocked/
error extend it, quota/needs_key are neutral; the last 30 are kept with their time). A module is
demoted while p50 > 10 s over >= 20 runs, > 30% wrong after >= 10 votes, >= 3 consecutive failed
checks or >= 5 consecutive BLOCKED runs. `consecutive_failed_days()` / `auto_disabled(days=7)` serve
the P331 spec auto-disable. `HealthState.load()` tolerates a missing or corrupt file; with
`autosave` (default) every record is a read-modify-write under the exclusive cross-process lock
`health.json.lock` (0600, POSIX flock, waits at most `LOCK_WAIT` s): it first adopts what another
writer saved, then writes atomically 0600; failures go to `errors`. `refresh()` re-reads the file
when another writer changed it (never dropping unsaved changes); an explicit `save()` of an
instance without autosave keeps the newer file's records of every module it did not change.
`stamp` is `(inode, mtime_ns, size)` (every save is a new inode). `policy.shared_health()` keeps one
instance per file for the process and refreshes it in place, so engine worker threads never write
a stale copy over newer records. Only module names, durations, statuses and counts are stored.
Tests: `tests/test_health.py`, `tests/test_policy.py::test_shared_health_keeps_every_concurrent_record`.

### Recipient tokens

`recipient_token(url, org=None)` is True when the path, query, fragment or userinfo holds an e-mail
address (plain, URL-encoded once or twice, base64 or base64url; punycode TLDs included) -
org-profile addresses and any other one, which identifies a recipient as well - or when a path
segment or query value holds an opaque token of >= 16 characters (UUID, hex digest, long number,
letters mixed with digits, random-looking mixed case), or an org-profile domain in base64. Article
slugs, versioned words ('windows11', 'ios17') and ordinary query words are not tokens. WP17 can flag
`recipient_token` on extracted URLs with it: a URL node tagged `recipient_token` in the case graph
is guarded exactly like a detected one (GUARD-02). Tests: `tests/test_policy_guard.py`.

### Lure-word lists

`v3lum/data/brand_lures*.json` (none ships with the core): a JSON list of words or an object whose
list values hold them (`schema`, `source`, `licence`, `notes`, `description`, `reviewer` and `date`
keys are ignored). Words are accent-folded; words of 5+ letters match inside a host label, shorter
ones only as a whole hyphen-separated token.
