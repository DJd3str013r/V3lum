# Contract additions - WP08 (wave 2)

Engine v2: selection through the policy gate, run deadlines and the kill switch, pivot-expansion
rules, noise semantics, two-phase passive-before-contact scheduling, coverage matrix, TLP
inheritance, ownership tags, the core suppression stage and the evidence store. This is the
enforcement the frozen guide marked "from wave 2" for the engine; no name of the guide is renamed or
changes its documented meaning. `v3lum.core.evidence.EvidenceStore` moves here from the guide's
"Arriving later" table.

Who needs it: **module authors** of every batch (section "What module authors can rely on"),
**WP13** (`Engine.select`/`decide_single`/`plan` on every CLI path, `ScanOptions.confirmed_urls` /
`subject_roles`, `CaseResult.cache_keys` -> `Store.record_cache_keys`, the case dict v2), **WP14 /
WP20** (coverage v2, `execution`, `answered`, `skips`, `partial`, `pending_personal`, manual links,
TLP), **WP15** (`EvidenceStore`, case hooks, request records), **WP16** (`Finding` ownership, the
suppression stage never crossing overrides), **WP18** (`only_pairs` for `cases resume`,
`case.deferred`), **WP19** (`Node.path_confidence`, `context_only`), **WP22-WP24 / WP30** (graph
noise, ownership and tags in rule fixtures, `weak_edge`), **WP25** (`on_before_finish` hook,
`Runtime.health`), **WP27** (the two-phase order is never reordered by lanes).

## What module authors can rely on

* **Selection**: a module runs only when `policy.decide` allows it for that entity (licence, TLP,
  tier, privacy/run_on, own assets, opsec, rules of engagement, egress country, keys, packages,
  datasets, quota, circuit). The interim wave-1 rule "source modules only with -M" is gone:
  `default_enabled=True` modules that pass every gate run in a plain scan (`--preset quick`);
  `default_enabled=False` modules are listed under `case.skips['not_default']` (`--preset deep`,
  `--all-modules` or `-M` runs them, through the same gates).
* **`ctx.allowed_sources`** is the Decision's `allowed_sources` (None in the Decision = every declared
  source). Aggregators query only those; the engine adds a coverage row with reason_code `licence`
  for every declared source outside it (`case.coverage[module]['sources']`, merged with
  `res.source_status` rows by the coverage rank).
* **Deadlines (AR05)**: `ctx.deadline`/`ctx.remaining()` start when the run starts (not when it was
  queued). A run that returns more than `timeout` + 1 s after its start ends ERROR `timeout` and its
  findings, pivots, attributes, links, raw payload and evidence are dropped (its disclosure ledger
  `res.hosts` stays). When the scan deadline, Ctrl+C or the end of the scope window stops a scan,
  requests raise `Cancelled` (let it propagate: partial results), and results that arrive after the
  stop are dropped.
* **Expansion (AR07)**: pivots below setting `min_expand_confidence` (0.5, on the path product of
  edge confidences), POSSIBLE pivots over `same_person`/`uses_username`/`uses_email`/`has_account`/
  `commit_email`, `similar_to`, noise, warninglisted values and SECRET_TYPES never auto-expand. From
  `text_blob`/`file`/`email_headers` parents only IOC_TYPES auto-expand (INPUT_LIST_CAP 200 per type);
  PERSONAL_TYPES found there become `expand=False` and are listed in `case.pending_personal` unless
  `options.expand_personal` and `options.purpose`.
* **Two-phase (P376)**: LIGHT/ACTIVE runs of an entity start only after every passive run of that
  entity was merged, and only when `policy.contact_guard` allows them (case-DB sightings and internal
  platforms run first among the passive ones, A12). Redirect hops of target contact re-run the guard.
* **TLP**: `ctx.tlp` is the entity TLP: the seed's (`options.seed_tlp`, else `options.tlp`), inherited
  by pivots and extracted entities (highest parent wins), raised by `res.set_marking(...)` for the
  entity and its pivots; LIGHT/ACTIVE cases are at least AMBER.
* **Manual links (P311 cond 9)**: `Module.manual_link` is emitted on `case.links[entity]` as
  `{label, url, host, note: 'automation skipped: <reason_code>', manual: True, touches_target,
  privacy, badge, module}` when the gate refuses with `emit_manual_link` (licence, needs_key,
  egress_country, quota, circuit, hostile_host) and when a run ends BLOCKED, QUOTA or NEEDS_KEY
  (a configured key the provider refuses). Privacy links render only for analyst-typed seeds of a
  case with `show_personal` and a purpose.
* **Coverage and the answered line (P328)**: `res.source_statuses` count per feed in
  `case.answered[seed]` (`applicable`, `answered`, `could_not_verify`, `sources`); modules tagged
  `reputation` count in `reputation_applicable`/`reputation_answered`. Quota outcomes
  (QUOTA, or partial with stop_reason `quota`) are deferred (`case.deferred`, `QuotaBook.defer`).
* **Exception mapping additions**: `v3lum.core.datasets.DatasetError` with a canonical
  `reason_code` maps to `status_for(reason_code)` (a challenge page -> BLOCKED `challenge`, a quota ->
  QUOTA `quota`; an unknown code -> ERROR `error`), never to a module bug with a traceback;
  `v3lum.core.tools.ToolUnavailable` (WP11) maps to UNAVAILABLE `package`.
* **Suppression**: findings tagged malicious/suspicious/phishing/c2/spam/scanner on a warninglisted
  entity become POSSIBLE (`'POSSIBLE - on warninglist <name>'`); on a sinkhole POSSIBLE +
  `context_only`; breach/infostealer/credential_exposure findings on generic/role/test addresses
  POSSIBLE + `context_only`. Modules never call these rules; analyst overrides always win.
* **Ownership**: with an org profile, asset entities (domain, url, email, ip, cidr, asn, cnpj,
  favicon hash, card BIN) get `own_asset`/`third_party` (node tag, criticality) and findings copy
  their node's ownership.
* **Persistence**: SECRET_TYPES values (raw JWTs...) are written only redacted (`entities.redacted_value`)
  in the case dict, `Graph.to_dict()` and evidence (the entity key and any raw secret value of the
  run's entity or pivots wherever it appears in the payload); evidence file names carry the keyed
  HMAC of the installation, never the value, and are never written through a planted symbolic link.
* **Kill switch of a run**: `ctx.cancel_event` is the runtime's cancel flag when the run was built
  and `ctx.cancelled()` reads it - a run abandoned by a stopped scan stays cancelled even after a
  later scan of the same runtime installs a fresh flag (its requests were already refused).
* **Correlations after suppression**: the legacy rules of `v3lum/correlations/generic.py` use only
  `evidence_finding` findings: `context_only` findings (sinkholes, generic/role/test addresses,
  third-party breach context) and findings downgraded by a `SUP-*` rule never support
  `multi_source_malicious`, `high_signal_tags` or `breach_and_infostealer` (P171 cond 5,
  A4 BR6); `malicious` attributes on a sinkholed or warninglisted entity are no consensus either.
  `breach_and_infostealer` (now `(graph, results, rctx)`) never fires for generic/role/test
  addresses, is HIGH only for a verified own asset (txt_verified/attested org-profile domain) and
  MEDIUM + `context_only` otherwise (A4 BR9-BR10). Pack rules (WP22-WP24) replacing them follow
  the same rule.

## Details

### Case dict 'v3lum.case/2'

`CaseResult.to_dict()` keeps every v1 key and adds `tlp`, `partial` ({`deadline`|`cancelled`|`window`:
True}), `execution` (rows `{module, entity, seed, status, reason_code, outcome, partial, stop_reason,
requests, cache_hits, duration}`), `answered` (`{seed_key: {applicable, answered, could_not_verify,
sources, reputation_applicable, reputation_answered}}`), `skips` (`{reason_code: sorted module
names}`), `pending_personal` (`[{entity, parent, relation}]`), `deferred` (`[{module, entity,
reason}]`), `licence_used` (`{source_id: {class, basis}}`), `licence_profile`, `meta`
(`runtime.meta` at the end, with `quota_lines`), `org_profile_sha256`; `summary.partial`;
`coverage[module]` = `{title, category, status, reason_code, reason, runs, counts {status: n},
entities {entity_key: {status, reason_code, reason, partial, stop_reason, seed}}, sources {source_id:
{status, reason_code, reason}}}` plus the v1 per-status counters; `links[entity]` items are dicts
(`label`, `url`, and the manual-link keys above). Stored v1 cases still render (renderers use
`.get()`). Tests: `tests/test_engine.py::test_case_dict_v2_shape`, `tests/test_engine_coverage.py`.

### Review fixes (WP08 review, wave 2)

* `case.links[entity]` items are dicts with `label`, `url`, `host`, `category`, `verified`,
  `touches_target`, `privacy`, `antibot`, `badge` and `ref` (the rendered pivot link: renderers
  apply P311 cond 5-8 and A2 from them); manual-link fallbacks add `note`, `manual` and `module`.
  privacy=true pack links are included only for analyst-typed seeds (not in
  `options.unconfirmed_seeds`) of a case with `options.show_personal` and `options.purpose`
  (P311 cond 6), the same rule as the manual-link fallback; module links (`res.links`) stay
  `{label, url}`.
* `case.meta` holds only JSON data of `runtime.meta` (strings redacted): live objects such as the
  `sightings_lookup` callable stay in the runtime, so `case.to_dict()` always serialises.
* `case.tlp` is set before `on_case_start` hooks run (the highest seed TLP, at least AMBER for a
  LIGHT/ACTIVE mode) and recomputed with the platform markings at the end.
* Every investigation starts a new quota run (`QuotaBook.reset_run()`): backoffs "for the rest of
  this run", token buckets, this run's provider signals and per-run deferral counts never leak into
  the next scan of the same runtime or its `meta['quota_lines']`.
* `Engine.select` / `plan` outside a scan decide with a fresh policy context per call (no context
  cached for the engine's lifetime: a key configured in the meantime counts).
* A run in flight when the scan stops is recorded SKIPPED with the stop's code and the reason
  '... while it ran: results dropped (could not verify)'; a pair that never started keeps
  '... before it ran: not run'. Overdue runs (ERROR `timeout`) report the time waited in
  `duration`.
* A finding about an entity that is neither the run's entity nor one of its pivots creates that
  node one level below the run's entity, with the inherited TLP and its ownership tag (not depth 0,
  not unannotated).
* `Graph.add_attributes` / `Graph.add_finding` never move an existing node: before, recording a
  fact or a finding reset the node's depth to 0 (pivots two hops away were reported at depth 0).

### Case hooks

`runtime.case_hooks` objects may define `on_case_start(case)` (before any module runs; an exception
aborts the scan - fail closed, e.g. an audit record that cannot be written), `on_before_finish(case)`
(after the BFS, before the suppression stage, correlations and scoring) and `on_case_end(case)`
(after everything; exceptions of the last two become case notes). Test:
`tests/test_engine.py::test_case_hooks_order`, `tests/test_engine_suppression.py`.

### Evidence store

`EvidenceStore(case_dir, *, now=None).save(res, *, requests=())` writes `{module, entity,
collected_at, redacted_fields, data[, requests]}` (redacted through the central redactor) to
`<case_dir>/evidence/<module>__<type>__<hmac12>__<sha10>.json`, 0600 in 0700 directories, and returns
`(path, sha256)`; `requests` are RequestInfo records (or dicts) summarised with their redacted URL,
status, cache flag, egress profile and classification. The engine passes the run's
`ctx.http.request_log`. Test: `tests/test_engine.py::test_evidence_store_names_modes_and_requests`.

### Graph fixtures

Edges of `v3lum.graph_fixture/1` documents may carry `"expand": false` (default true); graphs rebuilt
from stored cases or fixtures keep their recorded `noise`, `noise_kind`, `tags` and
`path_confidence` (no re-evaluation).
