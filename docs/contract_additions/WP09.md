## Details

### `scrub_text(text, *, hits=None) -> str`

For text and file inputs (a pasted text_blob, a text file) before anything is stored, extracted or
shown (P145 cond 5). In order: `drop_combos` (email:password, user:pass@host, URL userinfo,
URL-encoded `alice%40corp.example%3Ahunter2`), two-field dump lines `email<TAB or ,>secret` (the second
field is kept when it is an e-mail, URL, domain, IP or a count of 1-3 digits), password-hash formats
(bcrypt, argon2, scrypt/yescrypt, sha-crypt, md5-crypt, phpass, PBKDF2, MySQL; never file hashes),
masked hints ('p***2', '58.10.**.***'; markdown '**bold**' is kept) and every `SECRET_PATTERNS` hit:
'drop' hits (labelled passwords: `DB_PASSWORD=...`, `password: ...`) are removed, never hashed (a
SHA-256 of a password is a crackable hash); 'mask' hits become the SECRET entity value
`'<kind>:<first4>…<last4>:<sha16>'` (`entities.parse_fingerprint` reads it back). Indicators (URLs,
domains, IPs, file hashes, the e-mail of a combo) are kept. `hits` (optional list) receives one
`{'kind', 'action', 'value'}` dict per removal ('value' = the fingerprint of a masked secret, '' for
drops) so the caller can report 'sensitive data in pasted text' once (P323 cond 6). Covered by
`tests/test_sanitize.py::test_exposed_env_sample_is_masked_and_passwords_dropped` and the combo tests.

```python
from v3lum.core.sanitize import scrub_text
hits: list[dict[str, str]] = []
clean = scrub_text(pasted, hits=hits)      # extract IOCs from `clean`, never from `pasted`
```

Not wired yet: the seed text of a text_blob/file input is still stored as typed. WP17 (extraction)
and WP13 (CLI/app input paths) call `scrub_text` before extraction and before the seed is stored.

### `SECRET_PATTERNS`, `find_secrets`

Distinctive formats (`distinctive=True`: AWS access key ids and labelled secret keys, GitHub/GitLab,
Slack tokens and webhooks, Discord webhooks and bot tokens, Stripe secret keys, Google API keys and
OAuth secrets, OpenAI/Anthropic/Hugging Face keys, SendGrid, Mailgun, npm, PyPI, Shopify,
DigitalOcean, Telegram bot tokens, JWTs, private-key blocks, bearer tokens) and one `assignment`
pattern whose label decides: password labels drop the value, secret labels (secret, token, api key,
access/private/app/account/signing/encryption key, credential, authorization, webhook, session id,
cookie, salt) mask it (8+ characters, not numeric, not a placeholder or a form word). Every regex is
bounded and linear (pathological-input tests in `tests/test_sanitize.py`). `find_secrets(...,
distinctive_only=True)` is what pivot values and link URLs get: key-like URL parameters of an
indicator stay part of it (AR01; the redaction pass masks configured keys).

### What the sanitizer stage does to a result (module authors)

Every behaviour of section 12 of the guide stays; the stage now also (P145 complete):

* **every module, first**: what the module produced is made JSON-shaped so every later pass sees
  every string (review addition): sets/frozensets become sorted lists, bytes become text (UTF-8,
  invalid bytes replaced), non-string dict keys become strings, and any other object becomes its
  `str()` when that text carries something a pass removes (always for sensitive modules); a harmless
  object (a `datetime`, a `Decimal`) is kept as built. The stores serialise unknown objects with
  `default=str`, so without this a combo or a token inside a set, bytes or a custom object would
  reach the case JSON, evidence and reports untouched. `Finding.observed_first`/`observed_last` are
  scrubbed like the other finding fields.
* **every module**: URL-encoded combos are dropped; a string value that is entirely a secret becomes
  a mask dict `{type, preview, sha256}` (the shape of `mask_secret()`; the preview follows
  `v3lum.core.entities.secret_preview`: first 4/last 4 from 16 characters, 2/2 from 12, none below,
  so a secret never shows more characters as a value than as an inline fingerprint), a secret
  inside text becomes its fingerprint; HTTP Basic credentials ('Authorization: Basic <base64 of
  user:password>') are dropped like passwords; a
  value under a password key (`db_password`, `senha`) is dropped and one under a secret key
  (`api_token`, `client_secret`) masked, like the same assignment in text; a link or a reference URL
  carrying a distinctive secret (a Slack webhook, a token in the path) is dropped; a pivot value
  carrying one is rebuilt from the masked value or dropped (SECRET_TYPES entities are left to the
  entity layer); every string passes `redact.redact_text` (pivot values only lose registered keys);
  `password_form` values must satisfy `is_password_form` or the field is dropped.
* **sensitive modules** (category breach_leak or a sensitive provider): fields of the provider that
  carry the password FORM under another name (XposedOrNot `password_risk`, a `hash_type`) and hold a
  form word are renamed `password_form` with the normalised value (A4: the form survives only under
  that name; schemas keep `password_form` next to any kept field implicitly, so list the provider's
  own field in the keep paths); then the second net; MD5/SHA hex values next to a credential (any
  value anywhere under a record with an account or password key, nested dicts and lists included; a
  string with an e-mail or a credential word) and every password-hash format are dropped; free text
  (titles, descriptions, criteria, finding data,
  attributes, raw strings, pivot notes, link labels, errors, per-feed reasons) loses 'name: value'
  pairs of second-net names, every value the module read from a second-net field (replaced by
  `[redacted]`), masked tokens, IP addresses other than the investigated one, file paths and default
  Windows computer names; pivots carrying such a value and IP pivots other than the entity are
  dropped; links whose URL carries one are dropped. Modules of `HASH_EXEMPT_CATEGORIES` keep their
  hash fields and are exempt from the hex-hash detector (P145 cond 6).
* `res.redacted_fields` lists dropped/masked paths (`raw.stealers[].ip`, `raw.config.api_token`,
  `raw.breaches[].password_risk:password_form`) and the areas where text was cleaned
  (`<area>:combo`, `<area>:secret`, `<area>:second_net` with area raw, attributes, findings, pivots,
  links or error).

`sanitize_body` (HTTP cache hook) applies the same schema, form renaming, second net, sensitive
detectors, combos, secrets and redaction to JSON bodies of sensitive providers (JSON labelled
application/json, text/plain or untyped); anything else, a source without schema or any failure
gives None: the body is fetched no-store and the module gets it in memory only. The sanitized body
is ASCII-only JSON (non-ASCII as `\uXXXX`), so it decodes identically under whatever charset the
provider's content-type declares.

### The forbidden-capability lint

Rules (`LINT_RULES`): LINT-00 unparsable/invalid file, a data file (> 20 MB) or Python source
(> 5 MB) too large to lint, or a file the lint cannot read (never skipped silently, never a crash of
the gate); LINT-01 direct network
or process APIs in modules, and what the lint cannot see: `eval`/`exec`/`compile`, imports of a
computed name (`importlib.import_module(<not a constant>)`), deserialisers that execute code
(`UNSAFE_LOADERS`, `yaml.load` without a safe loader), `webbrowser`, WHOIS/NTP/DNS/SOAP/GraphQL/IPC
clients, `anyio.connect_tcp`-style connectors, `invoke`/`ptyprocess`; LINT-02 anti-bot/CAPTCHA
bypass and borrowed-session dependencies and solver services; LINT-03 enumeration/availability/
reset/verification/login endpoints, identity-host account lookups
(`passport.example/usernames/{account}`), `/join?email=`-style sign-ups, mailbox-verification
services, username-claim attempts (`/username-attempt-unauthed`), `GetCredentialType`, account
recovery paths and password-recovery hosts (`iforgot.`, `recovery.`), OTP/SMS/magic-link senders,
`isEmailRegistered`-style oracles, `/validations/email`; SMTP mailbox probing commands (`RCPT TO`,
`VRFY`, `EXPN`) in module strings; credentials or borrowed sessions in requests, keys, settings
(`ctx.setting('session_cookie')`, a `settings` entry named like a session cookie or id); LINT-04 CPF
lookups and people-search/leak/'painel' hosts; LINT-05 submission/publishing endpoints; LINT-06
POST/PUT/PATCH/DELETE in LIGHT/ACTIVE modules (the module's opsec may come from a constant or a base
class of the file; the request may go through an alias such as `h = ctx.http`) unless an approved
`v3lum/data/policy/method_allowlist/<module>.json` (WP11: approved_by and decision_ref set) lists the
module and the method - a module name that is not a plain file name never matches a fragment - and
any non-GET spec; LINT-07 credential/password fields produced by a source-reading module without a
P145 schema (dict keys in finding data included; only HTTP request payloads are exempt, they are
LINT-03's) and credential keep paths in a sanitizer schema, credential fields extracted by a spec;
LINT-08 hash/JWT cracking (libraries, `run_tool('hashcat'|'/usr/bin/john'|name='...')`, hash-reversal
sites); LINT-09 exploitation payloads (JWT 'alg: none' forgery included), brute force, DoS tools,
OAST hosts, `run_tool` of attack tools, PUT/PATCH/DELETE and `files=` uploads, SDK write/delete
calls; LINT-10 TLS verification disabled: `verify=False` and its aliases (`ssl=False`,
`verify_ssl=False`, `verify_certs=False`, `validate_certs=False`, `insecure=True`...), `CERT_NONE`,
`check_hostname=False`, `_create_unverified_context`, `disable_warnings`, TLS environment variables
set through `os.environ[...]`, `setdefault`, `update` or `putenv` (no pragma accepted).

The source pass is iterative (a deeply nested expression cannot exhaust the interpreter stack); a
source the AST pass cannot read gets LINT-00 plus the regex checks. A pragma covers the lines of the
node it is on; for an issue about a function or class name, only the `def`/`class` line.

`lint_module_source(path)` profiles: 'module' (modules, plugins: every rule), 'code' (correlation
packs: imports, process/socket calls, host tables, TLS), 'core' (other package files: subprocess
outside `core/tools.py`, forbidden/cracking/offensive imports, TLS). `lint_tree('v3lum')` picks the
profile from the path (`modules/`, `correlations/`, the rest) and lints every JSON/TOML data file
(pivot packs through `links.lint_pack`, specs, provider fragments through the provider loader, extras,
method allow-lists, lint-table fragments, WhatsMyName/Maigret/Sherlock site lists and any data file
with probe-URL keys: `uri_check`, `urlProbe`, `probe_url`, `check_url`... and `url` entries that come
with a method or a body). Any other root (`~/.v3lum/plugins`, `~/.v3lum/specs`) is linted as modules
and data files. The CI gate is `tests/test_lint.py::test_shipped_tree_is_clean`
(`blocking(lint_tree('v3lum')) == []`).

Pragma, on the offending line (or any line of a multi-line node): `# v3lum-lint: allow LINT-03 --
login-wall detection only, never requested`. The issue is still returned (`allowed=True`,
`justification`), never silent; a pragma without `-- <justification>` is ignored, and LINT-10 has none.

### Writing a module that passes the lint

* Network only through `ctx.http`, `ctx.dns`, `ctx.net` (external binaries: `ctx.net.run_tool`).
  `import socket` is accepted only when every use is an address helper (`inet_pton`, `inet_ntop`,
  `inet_aton`, `inet_ntoa`, byte-order helpers, `AF_INET*`, `has_ipv6`, the exception classes).
* URL literals in request calls, class attributes and constants are checked as probes; literals used
  only for detection (comparisons, `in`, `startswith`/`endswith`, regex compile/search, loops and
  comprehensions that only compare, class-level `error_markers`) are not. Dataset URLs passed to
  `register_dataset`/`register_list` and repository files on code hosts (github.com,
  raw.githubusercontent.com, gitlab.com... below `<owner>/<repo>`) get host-level checks only.
* LINT-07 looks at dict keys, subscript stores, `res.attr(...)` and `dict(...)` keywords whose value is
  runtime data (a constant label table is not); it applies to source-reading modules (disclosure
  third_party/internal or declared `sources`) without `sanitize.register_schema` in the file and
  without fragment schemas for every declared source. Offline and target modules are covered by the
  runtime sanitizer instead.
* Identifiers and whitespace-free literals naming brute force, spraying, default credentials,
  cracking or exploitation helpers are flagged; names of detectors (`detect_*`, `is_*`, `*flag*`,
  `*parse*`, `*score*`, `*match*`, `*count*`) are not. Prose ('no brute force') is not code.
* No `eval`/`exec`, no import of a name computed at runtime (a module-level string constant is
  fine: `importlib.import_module(HELPER)`), no pickle/marshal/joblib/yaml.load on provider data
  (`json`, `yaml.safe_load`).
* Settings are configuration, never a session: no setting named like a session cookie, session id
  or login token (`session_cookie`, `sessid`, `cookie`); `session_timeout` and similar are fine.
* Name the result keys of a module so they do not read as secret labels when their value is
  metadata (the sanitizer masks values under keys containing token/secret/api key/session id...;
  `token_kinds` and `secret_kind` with a value of 8+ characters would be masked - prefer `kinds`,
  `recipient_kinds`, `rule`).

### Host-table fragments (`v3lum.lint_tables/1`)

Batches extend the host tables without code changes (WP05 note: `CPF_LOOKUP_HOSTS` and
`PEOPLE_SEARCH_DENYLIST` grow by data only, keeping their names). One file per batch in
`v3lum/data/lint/<name>.json`, merged at import time (`reload_tables()` re-reads them):

```json
{
  "schema": "v3lum.lint_tables/1",
  "name": "<file stem>",
  "notes": "why these hosts are listed",
  "sources": ["C0216"],
  "cpf_lookup_hosts": [],
  "people_search_hosts": ["people-lookup.example"],
  "smtp_verification_hosts": [],
  "captcha_solver_hosts": [],
  "oast_hosts": [],
  "cracking_hosts": []
}
```

Every list is optional and holds lower-case host names (a subdomain of a listed host is listed too).
A fragment with an unknown field, a wrong name or an invalid host is ignored whole and reported by
`lint_table_errors()` and, as LINT-00, by the tree lint.
