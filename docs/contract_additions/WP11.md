# Contract additions - WP11 (wave 2)

Egress profiles, the SSRF/redirect guard, scope binding (A7) and the LIGHT/ACTIVE ceilings in the
HTTP client and the socket connector, plus the external-tool runner. Every name below is new;
nothing of the frozen guide (`docs/MODULE_GUIDE.md`, contract v2) was renamed or changed: the
wave-1 signatures `ctx.net.connect(host, port, *, timeout=None)` and `ctx.net.wrap_tls(sock,
server_hostname, *, timeout=None)` and every `ctx.http` call keep working, and the checks the guide
announced "from wave 2" (target modules: scope binding; egress) now run behind them.

**Who needs this:** authors of LIGHT modules (G03) and ACTIVE modules (G13: nuclei, port and TLS
probes, wordlists), the CLI (WP13: scope files), doctor (WP25: tool versions, egress public IP) and
the safety suite (WP28). PASSIVE module authors need nothing here: third-party traffic stays on the
default route and their code does not change.

## Details

### Target contact through `ctx.http` (LIGHT/ACTIVE modules)

Nothing changes in how a target module calls `ctx.http`; the core now applies, per request:

* **egress profile** - LIGHT requests leave through `proxy_light` and ACTIVE requests through
  `proxy_active` when configured (else the default route, where the policy's hostile-host guard
  refuses hostile contact). A configured profile whose proxy is down or unusable fails closed:
  `PolicyError` ('policy', e.g. `proxy_light unreachable: request refused`) -> SKIPPED 'policy';
  the request is never resent on the default route. Third-party API calls always use the default
  route.
* **methods** - LIGHT: GET/HEAD; ACTIVE: GET/HEAD/OPTIONS. Anything else needs an approved
  `v3lum/data/policy/method_allowlist/<module>.json` (see that directory's README; none ships);
  writes/deletes (PUT, PATCH, DELETE, ...) can never be allow-listed. A Tor route carries GET/HEAD only.
* **SSRF guard on every hop** (`ip_problem`, `host_problem`) - private, loopback, link-local, CGNAT
  100.64.0.0/10, ULA fc00::/7, multicast, reserved, documentation and cloud-metadata addresses
  (`METADATA_IPS`), single-label names, internal suffixes (`INTERNAL_SUFFIXES`) and ambiguous
  numeric hosts (`2130706433`, `0x7f.1`) are refused (PolicyError 'policy') unless the run's seed is
  internal (`RunInfo.internal_seed`; never for metadata endpoints unless the seed is that very
  address) or the scope lists them.
* **binding** - when the context bound `ctx.http` to the run (WP08 passes `run=` and `scope=`), each
  hop is resolved through the egress profile (DoH sent through that profile, never a local
  `getaddrinfo`), every address is checked, and on the direct route the connection is pinned to
  the checked address (Host header, SNI and certificate check keep the name;
  `Response.pinned_ip`). LIGHT: the first hop must be the analyst-typed seed or a subdomain of it
  (a pivot run is refused: PolicyError 'scope'). ACTIVE: a scope is required and every hop must
  match it (`Scope.matches_url` + `Scope.allows_contact(probe='http')`; out of scope ->
  PolicyError 'scope'). Redirect targets re-run the hostile-host guard (`contact_guard`, installed
  by the context: BLOCKED 'hostile_host').
* **identity** - the UA is setting `ua_light`; ACTIVE uses the scope's ROE user agent and header
  when it defines them. A `From` header and any header naming the contact mailbox/URL are dropped;
  the V3LUM or contact UA never reaches a target (a UA or ROE value naming V3LUM *anywhere*, e.g.
  `Mozilla/5.0 (compatible; V3LUM/1.0)`, counts as identifying).
* **no credentials toward targets** (A7: no login attempts, no borrowed sessions, no use of found
  credentials or keys) - a LIGHT/ACTIVE request carrying a credential header (`Authorization`,
  `Cookie`, `X-Api-Key`... - `v3lum.core.redact.is_credential_header`) or a configured secret in a
  header, the URL or the body is refused (PolicyError 'policy'). The scope's own ROE header (an
  engagement token agreed with the owner) is the only exemption.
* **scope window** - with a scope bound, contact happens only inside `window_start <= now <
  window_end` on the client clock: before it PolicyError 'scope', at or after its end `Cancelled`
  (the end of the window is a kill switch). The same applies to `ctx.net` and `ctx.net.run_tool`.
* **ACTIVE contexts without an entity** (`RunInfo()` without `entity`, no scope: self-tests, never
  a scan run) reach only internal hosts, and only with `RunInfo.internal_seed`; that is the only
  ACTIVE contact without a scope. A bound ACTIVE run (with its entity) always needs the scope. (A
  LIGHT context without an entity keeps the name/literal SSRF checks only: the engine always binds
  LIGHT runs to their seed; WP25's self-test harness should build offline contexts.)
* **internal names** (single label, `.corp`, `.internal`...) are resolved only by the
  organisation's own resolver (setting `doh_internal`), never by a public DoH resolver (that would
  leak the internal namespace) and never through a proxied egress profile.
* **kill switch** - besides refusing new requests, a body read blocked on a slow or silent server
  is shut down within ~100 ms of the cancel flag (urllib3 >= 2.3); the wait for the first response
  byte is still bounded by the request timeout and the run deadline.
* **ceilings** - LIGHT <= 1 req/s and <= 25 requests per target host per scan; ACTIVE <= 10 req/s
  (lower with the scope's `max_rps`), <= 2 concurrent connections per host (lower with
  `max_concurrency`) and 10000 requests/probes per case (scope `max_requests` up to 50000). A
  passed ceiling raises `RequestCapReached` (partial result, stop_reason 'request_cap').
* `.onion` hosts are reached only by LIGHT reads (GET/HEAD) through a SOCKS `proxy_light` (Tor;
  a SOCKS route used for `.onion` counts as Tor whatever its port), by name and never resolved.

Every request record (`ctx.http.request_log`, the event bus, the ledger) carries `egress_profile`
and, for bound target requests, `resolved_ip`.

### `ctx.net` (raw sockets) - same signatures, wave-2 checks

`ctx.net.connect(host, port, *, timeout=None)` resolves `host` through the egress profile, applies
the SSRF guard, ACTIVE scope (`Scope.allows_contact(probe='network')`: CDN/shared hosting and
org-profile `third_party_hosted` addresses need their IP/CIDR listed) or the LIGHT seed binding,
the ceilings (<= 10 probes/s and <= 2 concurrent per host, LIGHT 1/s and 25 per host, <= 1000 TCP
ports per host, <= 100 connection attempts/s in total unless the scope's `max_pps` raises it to at
most 1000, the per-case ACTIVE budget) and connects **to the checked address** on every route: SOCKS
proxies through PySocks (optional extra), HTTP proxies through a CONNECT tunnel (onion names are sent
to Tor as names). It returns a `ProbeSocket` (a plain `socket.socket`); close it (or use `with`) to
free the per-host slot. Once the kill switch fires (Ctrl+C, scope window end, scan deadline) new
connections are refused, a pending connect or proxy handshake is abandoned within ~100 ms (a SYN to
a filtered port never outlives the cancel flag) and every open socket of the run is shut down within
2 s. Every connection attempt is recorded (`RequestInfo` method 'CONNECT', url `tcp://host:port`,
IPv6 as `tcp://[v6]:port`). `ctx.net.wrap_tls` keeps the verifying context (never disabled). UDP is
not offered at all (no UDP sweeps). A proxy URL without a port uses the transport's default (http
80, https 443).

```python
words = ctx.net.cap_wordlist(load_my_wordlist())          # never more than 5000 entries
with ctx.net.connect(entity.value, 443, timeout=5) as sock:
    tls = ctx.net.wrap_tls(sock, entity.value)
    cert = tls.getpeercert(binary_form=True)
    tls.close()
```

### External tools: `ctx.net.run_tool` and `v3lum.core.tools`

```python
from v3lum.core.tools import ToolSpec, register_tool

register_tool(ToolSpec(
    name="nuclei", binary="nuclei", version_args=("-version",), version_regex=r"v?(\d+\.\d+\.\d+)",
    min_version="3.3.0", licence="MIT",
    forced_args=("-duc", "-ni", "-silent", "-jsonl", "-t", "<pinned template dir of the active lock>"),
    forbidden_args=("-up", "-update", "-ut", "-update-templates", "-interactsh-url", "-iserver", "-headless", "-code"),
    rate_flag="-rl", max_rate=10.0, proxy_flag="-proxy",
))

result = ctx.net.run_tool("nuclei", ["-u", url], targets=[url], timeout=120)
for line in result.stdout.splitlines(): ...
```

`ToolSpec(name, binary, version_args=('-version',), version_regex=r'(\d+(?:\.\d+)+)', min_version='',
licence='', forced_args=(), forbidden_args=(), rate_flag=None, max_rate=10.0, proxy_flag=None,
notes='')`; `register_tool` refuses a binary given as a path, an invalid name or flag, and a
different spec under an existing name. `run_tool(name, args, *, targets, timeout=None) ->
ToolResult` (disclosure 'target' modules only): the binary is found with `shutil.which` on PATH
(never imported, bundled, downloaded or updated; missing -> `ToolUnavailable`, status 'unavailable',
reason_code 'package'); `shell=False`; the environment keeps only PATH, locale and temp variables
(no proxy variables, no keys) and HOME is the run's temporary working directory (the analyst's own
`~/.curlrc`, `~/.config/<tool>`, `~/.pdcp` or `~/.netrc` are never read: they could move the
traffic off the egress profile or log in somewhere); `args` must be a list. The command line is
`binary + forced_args + [rate_flag, rate] + [proxy_flag, proxy] + args`: the core's arguments come
**first**, because parsers such as Go's `flag` package (nuclei, httpx...) stop at the first
positional argument and would silently ignore flags appended after it. `args` naming a
`forbidden_args` flag, a forced flag or the core-owned `rate_flag`/`proxy_flag` in any spelling
(`-up`, `--up`, `-up=x`, `--up=x`), or holding the `--`/`-` terminators, raise PolicyError 'policy'
before launch; every URL or IP literal in `args` must be one of the checked `targets` (or a checked
address), else PolicyError 'scope' (bare host names in `args` cannot be told apart from other values:
list every contacted host in `targets`). The rate becomes `min(max_rate, 10/s ACTIVE or 1/s LIGHT,
the scope's max_rps)`; on a LIGHT/ACTIVE proxy profile the proxy goes through `proxy_flag`, and a
tool without one is refused (fail closed); every target is checked before launch exactly like a
socket (`targets` is required; URL targets are judged as HTTP probes, hosts/IPs as network probes;
LIGHT accepts only the analyst-typed seed, never a pivot; the scope window applies); cancel, the run
deadline or `timeout` kill the whole process group within 2 s (`ToolResult.killed`); stdout is capped
at 10 MB and stderr at 1 MB (`truncated`); one `RequestInfo` per target (method 'EXEC', url
`exec://<tool>/<host>`, status = return code) reaches the ledger; `ToolResult.argv` (evidence) shows
the proxy without its credentials. A tool resolves names itself: the checked address cannot be
pinned for it. Doctor uses `tools()`, `version(name)` and `version_ok(name)`. The engine maps
`ToolUnavailable` to UNAVAILABLE 'package' (WP08): let it propagate like any other core exception.

### Scope files: `v3lum.core.scope.Scope`

`Scope.load(path)` (TOML via tomllib on Python 3.11+, or JSON; ScopeError only when unreadable or
unparsable), `Scope.from_dict(data)`, attributes `authorization_ref, owner, contacts, ticket,
window_start, window_end, targets, exclusions, shared_infra_hosts, limits, roe, sha256, path,
problems`; `validate(authorization_ref, now=None, *, org_terms=()) -> list[str]` (malformed fields,
limits above the ceilings, REF mismatch, outside the window, ROE naming the organisation);
`matches_host(host)`, `matches_ip(ip)`, `matches_url(url)` (exclusions win; `'*.'` wildcards match
strict subdomains; URL prefixes are judged on the path the transport sends and the server sees -
`v3lum.core.scope.path_variants(path)`: unreserved percent-escapes decoded, dot segments removed,
repeated slashes collapsed, encoded slashes taken as separators - a target prefix must hold for every
form and an exclusion for any form, case-insensitively, `/admin/` also covering `/admin`; a prefix
with an encoded slash or a backslash is a scope problem); `allows_contact(host, ips, *,
probe='http'|'network', url=None, org=None) -> (bool, reason)`; `window_expired(now=None)`, `in_window(now=None)`, `to_dict()` (audit view; the ROE
header value only as a SHA-256 prefix), `summary()`. The schema and an example are in the
`v3lum.core.scope` docstring (WP29 copies it to docs/ROE.md). A scope with problems allows no
contact at all.

### Egress profiles and the public IP

`EgressProfiles(settings, *, transports=None, default_transport=None, default_proxy=None,
ca_bundle=None, clock=None, resolver=None)`: `profile_for(opsec, *, tags=())`, `effective(name)`,
`profile(name)`, `session_for(opsec, *, tags=()) -> (name, requests.Session)` (non-default sessions:
`trust_env=False`, explicit proxies, no netrc, no cookies), `transport_for(name)`, `check(name)`,
`ensure_reachable(name)`, `describe()`, `errors`, `public_ip(name, *, client=None)`. Settings:
`proxy` (default route), `proxy_light`, `proxy_active` (http, https, socks5h, socks4a; `socks5://`
is upgraded to `socks5h://` on LIGHT/ACTIVE routes; credentials in the URL are registered with the
redactor). A SOCKS proxy on port 9050/9150 is Tor: allowed as `proxy_light`, refused as
`proxy_active`. `public_ip(profile='default', *, client=None, egress=None, settings=None,
timeout=10.0) -> str | None` asks https://api.ipify.org?format=json through the route, on request
only, never cached.

### Core streaming and content TTL (carry-forward items)

`HttpClient.request(..., stream_to=<seekable binary file>)` writes the body into the file
(`Response.streamed_bytes`; `content` keeps the first 64 KB for classification; never cached; retries
and redirect hops start the file over). `HttpClient.request(..., ttl_from=callable(resp) -> seconds |
None)` makes a cached answer older than its own lifetime a miss (0 = never stored), e.g.
`min(DNS TTL, resolver ttl)` for DoH answers. Only core scopes may pass `stream_to`.

### Testing LIGHT/ACTIVE modules

* A module run through `run_module`/`make_ctx` with an entity is **bound**: give every target host
  a DoH answer (`tests.fakes.add_dns(http, host, "A", [...])` **and** `"AAAA"`); the request is then
  pinned to that address (`http.calls[-1]["pin_ip"]`). Internal target names are answered by the
  internal resolver only: set `doh_internal` and pass `provider="https://<that url>"` to `add_dns`.
  An ACTIVE `make_ctx` **without** an entity or a scope reaches only internal hosts (self-tests).
* Use public documentation-free addresses (e.g. 93.184.216.34) for targets: TEST-NET ranges
  (192.0.2.0/24, 198.51.100.0/24, 203.0.113.0/24) are refused like any non-routable address.
  Loopback servers need `internal_seed=True` (LIGHT, or an ACTIVE self-test context without an
  entity) or a scope listing 127.0.0.1/32 (ACTIVE runs).
* Scopes in tests: give them a window around the clock in use (`tests.fakes.FakeClock` starts at
  2026-11-26 12:00 UTC); a test on the real clock needs a window that does not age out.
* ACTIVE tests pass `options=ScanOptions(mode=Opsec.ACTIVE, authorization_ref=..., scope=Scope.from_dict({...}))`.
* `tests/test_egress.py` has a minimal SOCKS5 server (`FakeSocks5`) for proxied routes; tests of
  `run_tool` put a fake binary on a temporary PATH (`tests/test_tools.py`).
* LIGHT/ACTIVE `HealthCheck(offline=True, selftest=...)` self-tests that contact a loopback listener
  need a context whose `RunInfo` carries `internal_seed=True`.

Covered by: `tests/test_http_ssrf.py`, `tests/test_egress.py`, `tests/test_scope.py`,
`tests/test_net_connector.py`, `tests/test_tools.py`, `tests/test_http.py` (streaming, ttl_from).
