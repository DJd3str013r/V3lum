# Contract additions - WP13 (wave 3)

CLI/app/shell wiring: the policy gate on every execution path, the rules-of-engagement flags, TLP,
purpose/ticket/legal basis, presets, privacy flags and the decentralised command registry. Every
name below is new; nothing of the frozen guide (`docs/MODULE_GUIDE.md`, contract v2) was renamed or
changed. The behaviours the guide marked "until the CLI is rewired in wave 3" now hold: `v3lum scan
--tlp` defaults to setting `tlp` (amber), `v3lum run` goes through the policy gate and never
escalates the mode, `--authorized REF` is mandatory and non-empty, and purpose/ticket are recorded
when a seed is personal.

**Who needs this:**

* **module authors**: nothing changes in module code. Two runtime facts become reliable:
  `ctx.runtime.meta['sightings_lookup']` is installed by every App scan (`Store.sightings_for`,
  WP16; the `case_sightings` module and the policy guard read it), and a seed typed as a single
  low-confidence token (username/person name) is listed in `ScanOptions.unconfirmed_seeds` until
  the analyst confirms it (run_on 'seeds' packs and LIGHT never run on it, A5);
* **command authors** (WP18 cases/data/links/doctor/keys/org/scope, WP21 export, WP22 rules,
  WP25 doctor v2, WP26 watch): the command registry;
* **WP14/WP20** (report header): `case['meta']['header_notes']`, `case['meta']['tlp_change']`,
  `case['meta']['execution_path']`;
* **WP15** (case audit): `App.prepare_runtime` installs `audit.AuditHook` for every case and
  `ScanOptions.tlp_change` carries the TLP lowering; App writes the `tlp_change` audit row when
  the hook did not;
* **WP30** (paste console, plugin hardening): `Shell.remember`, `App.scrub_input`,
  `cli.dispatch(..., path=...)`, `ScanOptions.subject_roles` from `--incident-victim`.

## Details

### Command registry

```python
from v3lum.commands import command

@command("export", "deterministic STIX/MISP exports", aliases=("exp",))
class Export:
    """Long help shown by `v3lum export -h`."""

    @staticmethod
    def add_arguments(parser):
        parser.add_argument("case_id")

    @staticmethod
    def run(args, app, console) -> int:
        ...
        return 0
```

`build_parser()` calls `load_commands()` and adds one sub-parser per command (aliases included);
`dispatch()` calls `CommandSpec.run(args, app, console)` and uses its return value as the exit
code. Raise `v3lum.app.UserError` for an analyst-facing refusal (exit 1, printed without a
traceback). An import error of a command module, or an `add_arguments` that raises, leaves that
command out and is listed by `load_errors()` (doctor); the CLI keeps working. Names: `^[a-z][a-z0-9-]{1,31}$`,
unique across commands and aliases, never one of `INLINE_COMMANDS` (`version, detect, run, scan,
modules, info, extract, feedback, cache, config, shell` and the shell built-ins `help, set, show,
clear, exit, quit, history, paste`). The shell lists every registered command in its command table
and completion. Tests: `tests/test_cli_policy.py::test_registry_commands_are_dispatched`,
`::test_broken_command_module_never_breaks_the_cli`, `tests/test_shell.py::test_registered_commands_in_table_and_completion`.

### Execution paths and the policy context

Every path builds its PolicyContext with `policy.make_context(..., path=<path>)`: `scan`, `batch`
(`scan -i FILE`), `extract` (`extract --scan`), `shell` (lines and `scan` typed in the console) and
`run` (`Engine.decide_single`). Scans use an `Engine` subclass whose investigations ask for the
App's path instead of the engine default 'scan'. Test:
`tests/test_cli_policy.py::test_every_path_builds_its_policy_context_with_make_context`.

### Rules of engagement checked by App (before any module runs, exit 1)

* `--mode active` needs `--authorized REF` (A7 syntax, no placeholder: `policy.authorization_problem`)
  and `--scope FILE` (`Scope.load` + `Scope.validate(REF, now, org_terms=...)`) on every path, TTY or
  not, `-y` included; the refusal lists exactly what is missing (`active mode refused (A7): missing
  --authorized REF ... and --scope FILE ...`) or the scope problems. An invalid `--authorized` is
  refused in every mode, an empty one too ('--authorized needs a non-empty authorization
  reference'); `--scope` outside ACTIVE is ignored with a notice.
* `--egress-override REASON` needs a non-empty reason; it reaches `ScanOptions.egress_override`
  (case audit `overrides`, WP15; report header, WP14) and prints one warning line (P376 cond 8).
* `--licence-profile research` (or the setting) without a recorded research basis: the exact
  `licence.RESEARCH_REFUSAL` text.
* A personal seed (PERSONAL_TYPES), `--breach-scope all` or `--expand-personal` need `--purpose`
  and `--ticket` (prompted in a TTY, refused otherwise: `refused: personal identifier (email ...)
  needs --purpose TEXT and --ticket TEXT (LGPD purpose limitation, AR16)`); `--incident-victim`
  needs `--purpose`. Settings `default_purpose`, `default_ticket`, `default_legal_basis` fill
  IOC-only scans. Legal basis codes: `LEGAL_BASES`.
* `v3lum run` uses `--mode` or setting `mode` (passive) and never escalates: the policy gate's
  POL-09 refusal ('needs --mode light: contacts the target') is the analyst's message.

Everything else (licence, TLP, tier, privacy, quota, guard...) is decided by `policy.decide`: `run`
exits 1 with the Decision's reason; scans record it in the case coverage.

### TLP (A2, AR17)

`--tlp` (scan, `scan -i`, run, extract --scan; shell `set tlp`) defaults to setting `tlp`
('amber'); `amber+strict` is accepted, and `--tlp`/`--mode` values are case-insensitive (`--tlp RED`). Every seed gets the request's TLP in `options.seed_tlp`.
LIGHT/ACTIVE requests below AMBER are raised to AMBER with a notice (`meta['header_notes']`). A TLP
below the configured default sets `options.tlp_change = {os_user, analyst, at, from, to}`, is copied
to `case['meta']['tlp_change']` and written once as audit row `tlp_change` (through
`audit.CaseAudit` when available, else `Store.append_audit`). Test:
`tests/test_cli_policy.py::test_tlp_lowering_is_recorded`. A passive `v3lum run` normally writes no
case; with a `--tlp` below the configured default it writes one so the lowering reaches a case audit
(`::test_passive_run_below_the_configured_tlp_is_recorded_in_a_case_audit`). The AR07 follow-up scan
takes the higher of the request TLP and the case TLP (picked identifiers inherit the case TLP).

### Inputs (P145 cond 5, AR18, A5, P172)

`App.scrub_input` runs `sanitize.scrub_text` on every input except local file paths and values that
are a secret entity themselves (JWT, tokens: detect-only, persisted redacted by the engine), keeping
an explicit `TYPE:` prefix: `user@example.com:secret` becomes the e-mail seed `user@example.com`,
URL userinfo is dropped, and the seed value, the detections, the case JSON and the reports hold only
the scrubbed text; one line 'sensitive data in pasted text: ...' is printed and added to the case
notes and header notes. `extract` scrubs the text before extracting; `extract --scan` investigates
ONE `text_blob` seed (the scrubbed text, or the selected IOCs with `-t`), so extracted IOCs keep their
text provenance (passive only, personal values listed for selection). Every detection below 0.75
prints 'read as <type> (<confidence>); force with TYPE:value'; single tokens read as username or
person name below 0.75 are confirmed in a TTY, else listed in `unconfirmed_seeds`. In a TTY, text
and file seeds show the extraction preview ('37 IOCs: 12 domains, 5 IPs, 4 low-confidence',
`App.ioc_preview`, using `ioc.extract` when WP17 provides it) and ask for a confirmation above 25
IOCs. After a TTY scan, `case['pending_personal']` is offered as a numbered pick that starts a
follow-up scan with the recorded purpose and ticket (AR07).

### Runtime facts set by App before an investigation

* `meta['sightings_lookup']`: `Store.sightings_for` (bound method; `policy` passes `case_id` and
  `case_tlp` when the signature has them). Live object: never copied into the case.
* `meta['header_notes']`: list of strings for the report header (TLP raised, sensitive data removed,
  ignored `--scope`).
* `meta['tlp_change']`: the TLP lowering record (see above).
* `meta['execution_path']`: 'scan' | 'batch' | 'extract' | 'shell' | 'run'.
* `runtime.case_hooks`: the `audit.AuditHook` of the case (WP15), installed with
  `hook.attach(runtime)` (case hooks and the `http_request` events, so ledger lines are written as
  requests happen). Without it LIGHT/ACTIVE runs are refused ('LIGHT/ACTIVE runs need the case
  audit trail and the request ledger (A7)...').

After the investigation App records report paths (`Store.record_report_paths`), saves the case and
records its cache keys (`Store.record_cache_keys(case.case_id, case.cache_keys)`, A10 purge).

### Shell (A2, A7, A10)

Prompt `v3lum[<mode>|<TLP>]> ` (plain outside a TTY). Session values (TLP, authorization, scope,
purpose, ticket; mode/depth/format/max-entities for scans; mode for run/extract) are inserted right
after the command name and only for options that command's parser takes (so `links` gets the session
TLP, `modules` gets nothing); whatever the analyst typed wins in any argparse form (`--tlp red`,
`--tlp=red`, `--tl red`, `-mlight`), so a typed TLP:RED is never replaced by the session's AMBER. A
line that is not a command is ONE input, passed after `--`. `set tlp <level>`; `set authorized <ref>` and
`set scope <file>` are bound together (a scope that binds another reference is refused either way)
and expire 8 h (`BINDING_TTL`) after the binding: a TTY re-prompts, otherwise both are cleared;
`set purpose` / `set ticket` fill this session's cases. History: `~/.v3lum/shell_history`, one JSON
line `{ts, line}` per entry, written 0600 with `paths.secure_write_text`, every line scrubbed like
pasted text, no line typed while the session TLP is RED (or with `--tlp red` in any argparse form), C0/C1 control
characters (terminal escapes from pasted text) never stored nor printed, entries older than
`retention_days` (and untimestamped legacy lines) dropped at start; `history` lists the last 20 and
`history clear` forgets them. Tests: `tests/test_shell.py`.

### Catalog views

`v3lum modules` shows per module: opsec, disclosure · provider tier · terms class (+ publishes /
reuses / fetches target / sensitive flags and the access label) and the effective-default-set
membership ('yes', else the first refusal's reason code; run_on when not 'any'); `modules --json`
adds `default_set {member, reason_code, reason}` to each `describe()`. `v3lum info <module>` adds
disclosure, tier, per-source terms, flags, access, run_on, the default-set membership with its
reason and the `policy.describe_policy` lines (active licence_allow entries included).
`App.doctor`, `App.keys_table` and `App.set_key` delegate to `v3lum.commands.doctor.doctor_table`
and `v3lum.commands.keys.keys_table` / `set_key` (WP18). Listings send nothing, so they also work
under `--tor` without PySocks (scans still refuse a SOCKS proxy without it). The extraction preview
line is `ioc.ExtractionResult.preview()` (WP17), the same groups as `v3lum extract`.

### Settings output (AR01)

`config show` and `config set` print setting values through `redact.redact_text`: a proxy URL with
credentials (`proxy`, `proxy_light`, `proxy_active` = `http://user:pass@host`) shows `user:***@host`,
and registered secrets / key-like URL parameters are masked; refusals naming a value too.
