# Contract additions - WP14 (wave 3)

Terminal UI safety and first-screen honesty (AR13, AR14, AR17 rendering, AR01 in the live feed;
P328 cond 7, P322 cond 7, P311 cond 5/8/10, P377 cond 8, P325 cond 5, P302 cond 6/9; A1, A2, A3,
A8). No name of the frozen guide is renamed and no documented behaviour changes: module authors keep
writing plain strings, and the renderers now guarantee that those strings are shown literally.

Who needs it: **module authors** (section "What module authors can rely on"), **WP13** (`App.show_single`
delegates to `render_single`; `--show-personal` / `--no-defang` reach the view through the case
options), **WP16** (`core.attention.attention_points` / `limitations` are printed in the attention
block), **WP18** (`cases show`, `links`: TLP labels, `safe_href`, masked/defanged displays),
**WP19** (risk v2 keys `contributors`, `label`, `inconclusive` are read by `bottom_line` /
`seed_level`; level 'no findings'), **WP20** (HTML/Markdown reuse `report.summary` and `ui.safe`),
**WP25+** (header lines through `case['meta']['header_notes']`).

## Details

### `ui.safe` (AR13)

Removal comes **before** escaping, so a control character can never hide a tag from the escaper
(`'[\x00bold]'` stays literal). Removed: `\x00-\x08`, `\x0b-\x1f` (ESC, CR, BEL, VT, FF...), `\x7f-\x9f`
(DEL, the 8-bit CSI/OSC), the bidi marks U+061C/U+200E/U+200F, U+202A-U+202E and U+2066-U+2069;
U+2028/U+2029 become spaces; newline and tab stay. A stored case is untrusted as a whole: risk levels,
severities and confidence labels read from it reach the screen only as one of the known words (or
with control characters removed), never as styles or markup. `safe_href` returns the URL unchanged or None:

```python
safe_href("https://www.shodan.io/host/8.8.8.8")  # -> the URL
safe_href("javascript:alert(1)")                  # -> None (also data:, file:, vbscript:, //host, userinfo)
entity_display("cpf", "52998224725")             # -> '***.982.247-**'
entity_display("url", "https://evil.example/x")   # -> 'hxxps://evil[.]example/x' (never a clickable URL)
defang_display("evil.example", "domain", ["c2"])  # -> 'evil[.]example'
```

JSON and STIX exports never call these helpers: they stay raw. Covered by `tests/test_render_safety.py`.

### `report.summary` (AR14; pure functions over v2 and stored v1 case dicts)

* Header: `TLP:<LABEL>` (case TLP; unreadable -> RED, nothing recorded -> the A2 default AMBER),
  `mode <m> · egress <e> · preset · depth [· egress override <o>] [· offline (no network)] [·
  unknown-tier providers allowed (--allow-unknown)] [· authorization <ref>]` (egress from
  `case['engagement']['egress']` - `case['meta']['engagement']` when the case dict has no top-level
  copy (WP15) - or `case['meta']['egress' | 'egress_profile']`; passive cases read 'default route',
  LIGHT/ACTIVE without a record 'not recorded'), the engagement banner and its refusals (targets shown
  as masked/defanged entity displays; `refusals_omitted` counted in '+N more targets'), `PARTIAL RESULT: <note>` lines, per seed `'<seed>: N of M applicable sources answered; K
  could not verify (<module[/source]>: <code>, ...) · reading: <reading>'`, `'value disclosed to N
  third-party providers: <names>'` (cached responses excluded, DoH resolvers included, internal
  providers and the investigated target itself excluded; 'value disclosure not recorded (stored v1
  case)' for v1), the licence banner (`LICENCE: research profile ...` or, in any profile, the
  noncommercial/license sources used with their basis from `case['licence_used']`), `purpose: · ticket:
  · legal basis:` and every `case['meta']['header_notes']` string.
* Readings: a seed is 'inconclusive' when `case['answered'][seed]['reputation_answered'] < 2` (or the
  seed is in `risk['inconclusive']`, or no answered record exists); otherwise its risk level with
  'no findings' replacing 'clean'. The case reads 'inconclusive' at the lowest level when any seed is
  inconclusive. An inconclusive seed with a scored finding keeps showing it ('highest scored level
  high'). No function returns the word 'clean'.
* Bottom line: `What it is: <type> <value> - <2-3 key facts>` (per-type attribute lists such as
  registrar/created/a_records for domains, asn/as_org/country for IPs; personal attributes are never
  key facts), `Why: <LEVEL> <score>/100 (triage aid, not a conclusion) - <contributors [LABEL]>`
  (`risk['contributors'][*]['words']` when present, else the strongest correlation and the top risky
  entities' findings; POSSIBLE identity links never), and `Next step: <recommendation of the highest
  correlation>` (fallbacks: coverage suggestions when inconclusive, 'no action suggested ...' for no
  findings, 'confirm the <sev> finding ...').
* Skip lines (order: licence, not_default, needs_key, own_asset, privacy, tlp, tier, quota, ...):
  `'N sources skipped: licence profile corporate - v3lum doctor --licences'` (modules skipped plus
  licence-blocked feeds of aggregators that ran), `'N opt-in sources not run (use --preset deep)'`,
  `'N sources need an API key: v3lum keys'`, `'N own-asset modules need a verified org profile: v3lum
  org'`, ... then `case['meta']['quota_lines']`.

Covered by `tests/test_summary.py`.

### Terminal rendering

`render_case` prints: header panel -> bottom line -> attention points and limitations
(`core.attention`, WP16; until it lands the limitations fall back to the could-not-verify coverage
groups) -> correlations -> findings (confidence label on every row, criterion for HIGH/CRITICAL;
POSSIBLE identity links counted, never listed) -> entity map, seed facts, timeline -> skip lines and
follow-ups (`--full`: coverage lost under the licence profile) -> coverage per status with reason codes
(could-not-verify feeds included; a module whose per-entity outcomes differ shows its coverage v2
counts, e.g. `rep_c [challenge] (blocked 1 · empty 2)`, P328 cond 3) -> manual pivots -> notes -> TLP
footer. The header lists at most `MAX_HEADER_SEEDS` inputs and answered lines unless `--full` (a
batch of inputs: the rest summed in one line). Manual pivots: at most 8 per
seed (manual fallbacks, then verified first), grouped by analyst question with badges; clickable only
at TLP:CLEAR/GREEN; at AMBER and above defanged plain text with `opening sends <value> to <host>`;
touches_target links always defanged with a warning and hidden for hostile entities unless `--full`;
at RED third-party links hidden (`v3lum links` shows them); personal-data links only with
`show_personal`; non-http(s) links dropped. A link whose host is the investigated entity's host
(`summary.entity_host`, subdomains included) or the host of any hostile entity of the case counts as
touches_target even when the pack or module did not declare it (module `res.link` items carry no
host): never clickable, defanged with the warning, hidden for hostile entities unless `--full`;
`render_single` applies the same rule to the `v3lum run` links. `opening sends <value> to <host>` names
the URL's host when the item declares none. Valid CPFs inside module-derived text (finding titles,
descriptions, criteria, attribute values, correlation texts, timeline events, coverage reasons,
engine notes, the echoed `v3lum detect` input, live-feed errors/log/HTTP lines) are masked unless
`--show-personal` (AR24). Covered by `tests/test_render_first_screen.py` and
`tests/test_render_safety.py`.

## What module authors can rely on

* Every string a module produces (finding title, description, criterion, attribute values, link
  labels, error text, log messages, source reasons) is displayed **literally**: rich markup is never
  interpreted and control characters are removed. Do not escape anything yourself.
* Entity values are displayed through `entities.display_value` (CPF masked unless the analyst asked
  for `--show-personal`; personal-form EU VAT numbers and valid CPFs inside text blobs masked; a CPF
  quoted in your titles, descriptions, criteria or attribute values is masked as well - still never
  write one there) and defanged when the entity or one of
  its findings carries `malicious`, `phishing`, `c2`, `suspicious` (or the other GUARD-01 hostile
  tags), and for every URL. Tag hostile findings accordingly.
* Modules tagged `reputation` count for the reading: below two answering reputation sources a seed
  reads 'inconclusive'. Never write 'clean' yourself; the terminal never prints it.
* A finding tagged `identity` with confidence POSSIBLE is an identity link: it is counted on the first
  screen but listed only in the entity map and the HTML report (P258 cond 12).
* The confidence label is shown for every finding, the criterion for HIGH/CRITICAL ones: write a
  criterion an analyst can read in one line.
* `res.link(...)` URLs are shown according to the case TLP (clickable only at CLEAR/GREEN); a link to
  the investigated host itself (or to a hostile entity's host) is never clickable.

## Hand-offs (files WP14 does not own)

* **WP20** (`report/html.py`, `report/markdown.py`): still print the v1 level 'clean'
  (`RISK_COLORS['clean']`, `.risk-clean`, `s.get('risk_level', 'clean')`) and have no `.st-quota`
  CSS rule; they should take the header, bottom line, readings, skip lines, disclosure and licence
  appendices from `report.summary` and every anchor through `ui.safe.safe_href`, so the three media
  say the same thing.
* **WP13** (`app.App.cases_table`) and **WP18** (`commands/cases.py` cases list): both still print the
  v1 level word 'clean' (`lvl = c.get("risk_level") or "clean"`, style `risk.{lvl}`) and the raw seed
  keys (`", ".join(c["seeds"])`, so a CPF seed shows unmasked). Change needed: `lvl =
  report.summary.level_label(c.get("risk_level"))` with style `ui.theme.risk_style(lvl)`, and the
  inputs column built from `ui.safe.entity_display(type, value)` per seed key (`type, _, value =
  key.partition(":")`). Pass `case_id`/`created`/`tlp` cells as `rich.text.Text`, not markup strings.
* **legal_dpo**: personal-form EU VAT numbers are masked in displays (`mask_personal_vat`, AR24 'other
  national ids'); the stored value and the JSON/STIX exports keep the value as the module recorded it.
