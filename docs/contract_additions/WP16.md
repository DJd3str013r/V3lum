# Contract additions - WP16 (wave 3)

Case DB v2: analyst verdicts and idempotent feedback with Beta reliability (P325), analyst overrides
(P322 cond 3), TLP-safe cross-case sightings (P375, A2, A4, A10, A12), attention points and
limitations (P325 cond 5). Nothing of the frozen guide changes: every v1 `Store` method keeps its
name and arguments (`add_feedback` and `flag_finding` now delegate to the idempotent v2 calls), and
this file only adds names.

Module authors need only the first table (the `sightings` attribute, the `case_sightings` module and
the `recurrent_infrastructure` rule). The other names serve the application, commands, renderers,
scoring and exporters (WP13, WP14, WP18, WP19, WP20, WP21, WP22, WP26).

## Module-facing names

| name | kind | since | summary |
|---|---|---|---|
| attribute `sightings` | core attribute (vocab) | wave 3 | `{count, last, verdict, restricted, verdicts}` recorded by `case_sightings` on an entity seen in earlier cases: `count` visible earlier cases (TLP <= the entity's), `last` YYYY-MM-DD of the newest, `verdict` the newest recorded entity verdict, `restricted` higher-TLP AMBER/AMBER+STRICT cases (counted only), `verdicts` visible cases per verdict. Never a case id. |
| module `case_sightings` | module (utility) | wave 3 | offline lookup in the case DB through `ctx.runtime.meta['sightings_lookup']`; one info finding (criterion 'case DB sighting', key 'sightings'). Scheduled first among passive runs (A12). |
| rule `recurrent_infrastructure` | correlation rule (code P375) | wave 3 | the same IOC (domain/onion, URL, IP, file hash, wallet) in >= 2 cases; never for PERSONAL_TYPES, noise or own assets. Severity medium when an earlier visible case recorded malicious/c2/phishing/compromised, info for benign, low otherwise. |
| `runtime.meta['sightings_lookup']` | runtime protocol | wave 3 | `callable(entity, *, case_id='', case_tlp='') -> SightingsSummary` = `Store.sightings_for`, installed by the App (WP13). The policy guard (GUARD-01) and `case_sightings` call it with `case_id=`/`case_tlp=` when the callable declares them. |
| `v3lum.core.store.NOISE_TAGS` | constant | wave 3 | entity tags that make an entity noise for sightings and recurrence: sinkhole, parked, benign_scanner, noise, known_good |

A module that wants to read earlier sightings of an entity reads the `sightings` attribute of the
graph node (correlation rules) - never the case DB itself. No module ever writes the case DB.

## Store API (`v3lum.core.store.Store`)

| method | semantics |
|---|---|
| `record_verdict(case_id, verdict, notes='', *, analyst) -> dict` | overall verdict `yes` / `partial` / `no` (`y`/`p`/`n`/`partially` accepted), one per case and analyst (replaced on re-vote). `yes` credits no finding. Notes are case data (configured key values masked, <= 2000 chars), purged with the case. ValueError for another verdict or an unknown case. |
| `vote(case_id, finding_id, *, analyst, vote, reason=None, source_id='', rule_id='', module='') -> dict` | explicit judgement `right` / `wrong` / `partly` (0.5) on a finding or correlation of a stored case; `reason` (wrong/partly only) one of `homonym`, `outdated`, `benign_infra`, `wrong_type`. UPSERT per (case, deterministic item id, analyst): the earlier vote's contribution is removed from the aggregates before the new one is added, in one transaction - re-running `cases feedback` never double-counts. `source_id`/`rule_id`/`module` default to the stored item's. The module's vote totals go to `HealthState.record_votes` (A3 demotion) for the home DB. |
| `votes_for(case_id) -> list[dict]`, `feedback_for(case_id) -> list[dict]` | the stored votes / verdicts of a case. |
| `source_reliability(now=None) -> {source_id: weight}` | Beta per registry source: prior mean = Admiralty grade of the source's provider (A 1.0, B 0.85, C 0.7, D 0.5, E 0.3, F 0.5; unregistered 0.5) with strength 4, plus age-weighted votes (`partly` 0.5 each side; votes older than 12 calendar months weigh 0.5). The weight stays the prior until >= 5 votes and never falls below 0.3. Sources without votes are absent (use the prior). Feeds P302 R_SRC (WP19). |
| `source_stats(now=None) -> list[dict]` | per source: `source_id, grade, prior, votes, alpha, beta, weight, active`. |
| `rule_precision(now=None) -> {rule_id: (precision, votes)}` | age-weighted 'right' share per correlation rule (feeds P301 demotion, WP22; consumers apply their own minimum). |
| `feedback_summary()` | v1 keys `verdicts`, `modules` kept; adds `sources` (source_stats rows) and `rules` (`{rule_id, precision, votes}`). |
| `reliability()` | v1 module view, derived from the votes (`module_stats`). |
| `set_override(finding_id, *, analyst, label=None, severity=None, verdict=None, note='', case_id='') -> dict` | analyst decision keyed by the deterministic finding id (P322 cond 3): label confirmed/probable/possible, severity info..critical, verdict one short word (right, wrong, malicious, benign, false_positive...), note. One row per (finding, analyst); fields given again replace, fields left out are kept. The finding must belong to a stored case. Returns the merged decision. |
| `overrides_for(finding_ids) -> {finding_id: {label, severity, verdict, analyst, note, at}}` | stored decisions (several analysts merged in time order; the keyword arguments of `Finding.apply_override`). |
| `index_case(case_dict, *, org=None) -> int` | (re)build the sightings rows of a stored case; `save_case` calls it (an index failure never fails the save). A case that is not stored gets no rows (0): rows without a case row would escape the retention purge. IOC_TYPES by entity key; PERSONAL_TYPES only as `hmacid.hmac_hex` (entity_key '') and only when setting `sightings_personal` is true and the case recorded a purpose; noise (recorded noise, NOISE_TAGS, noise lists, warninglists) and own org assets (recorded ownership or the org profile) never indexed; stores the case TLP (highest of case and entity TLP; unreadable -> red; at least AMBER for a LIGHT/ACTIVE case, A2), the LIGHT/ACTIVE engagement flag and the entity verdict. |
| `reindex_sightings() -> int` | rebuild every case's index (after enabling `sightings_personal`, a profile change, or for cases stored before the index). |
| `sightings_for(entity, *, case_id='', case_tlp='') -> SightingsSummary` | A2: only cases with TLP <= `case_tlp` are listed (`visible`); higher non-RED, non-engagement cases are counted in `restricted_count` (no ids, dates or verdicts); RED and LIGHT/ACTIVE engagement cases above `case_tlp` never surface. Empty/unreadable `case_tlp` is read as CLEAR. `case_id` itself is never listed. Personal types only while `sightings_personal` is on (HMAC equality). |

Purge (A10): `purge_case` removes the votes, verdicts and notes, the sightings rows of the case and
the overrides of finding ids no other stored case holds; `source_stats` / `rule_stats` /
`module_stats` survive. `source_stats` and `rule_stats` rows are monthly buckets keyed
`'<id>@<YYYY-MM>'` (value-free), so the 12-month age rule keeps applying after the votes are purged.

## `v3lum.core.attention` (pure, P325 cond 5; used by WP14/WP20)

* `limitations(case) -> list[str]`: one 'could not verify: X, Y (reason)' line per reason code
  (blocked: challenge / geo_block / login_wall / circuit / hostile_host, quota, rate_limited,
  needs_key, licence, tlp, policy, timeout, deadline, error, sanitizer, offline, dataset, package)
  from `case['coverage']` (per-entity rows, aggregator `sources`), the partial-run notes and the
  'no evidence of absence' reminder; `[]` when every source answered. An aggregator feed is not
  listed again under a reason its module is already listed with. Runs that answered only in part
  (status ok/empty, `partial`, stop reason quota / rate_limited / request_cap / deadline /
  cancelled) add one 'partially verified: X (reason)' line per stop reason.
* `attention_points(case, *, verdict=None) -> list[str]`: suggestions (keys to add, deferred lookups
  to resume, manual checks, licence/TLP/policy reviews, re-runs, inconclusive seeds, earlier cases to
  review, personal identifiers awaiting selection); with `verdict` the first line says the analyst's
  verdict prevails. Unavailable sources (`offline`) get 'consider re-running later (or without
  --offline)', not the `--debug` hint of failed ones; partial runs join the quota, rate-limit and
  'did not finish' suggestions.
* `could_not_verify(case) -> {reason_code: [names]}`, `partially_verified(case) -> {stop_reason:
  [names]}`, `LIMITATION_REASONS`, `PARTIAL_REASONS`, `BLOCKED_CODES`, `MAX_NAMES`, `SUGGESTION_NOTE`.

## `v3lum.ui.feedback` (P325 cond 1, 4; used by App.ask_feedback and `cases feedback`)

* `ask_feedback(console, store, case, *, analyst='', ask=None) -> FeedbackResult | None`: the verdict
  with one keypress (`y`/`p`/`n`/`s`, Enter = skip); `yes` stores only the verdict, then an optional
  'which were right?' step; `partial`/`no` list at most 10 items (findings and correlations, ordered
  by score contribution: the risk model's contributors first, then severity weight x confidence)
  and ask which were wrong, each with an optional one-key reason (`h`/`o`/`b`/`w`); `Np` marks an
  item partly right; unlisted items stay unrated (no row); optional notes. `ask(prompt) -> str`
  replaces the terminal (tests, other front ends); outside a TTY without `ask` nothing is asked
  (None); Ctrl+C / EOF stores nothing (None). A verdict the store refuses (unknown/purged case,
  locked DB) is reported and nothing is stored (None); a vote the store refuses is reported and
  skipped, the other votes are kept. Plain rich consoles are themed for the round.
* `FeedbackResult`, `review_items(case, limit=10)`, `parse_selection(text, count, *, vote)`,
  `default_analyst(store)` (setting `analyst`, else the OS user), `MAX_ITEMS`, `VERDICT_KEYS`,
  `REASON_KEYS`, `SEVERITY_WEIGHTS`.

## `v3lum.modules.utility.case_sightings`

`CaseSightings` plus `LOOKUP_KEY` ('sightings_lookup'), `NO_CASE_DB` ('case DB not available'),
`CRITERION` ('case DB sighting'), `FINDING_KEY` ('sightings'), `call_lookup(lookup, entity, *,
case_id, case_tlp)` and `summary_parts(summary)`. Status mapping: no lookup installed (or it
returns None) -> UNAVAILABLE 'offline'; the lookup raises -> ERROR (could not verify, never absent);
nothing visible or restricted -> EMPTY; otherwise OK with the attribute and the finding. `applies()`
is False for PERSONAL_TYPES unless setting `sightings_personal` is true and `options.purpose` is set,
for types outside IOC_TYPES | PERSONAL_TYPES, for noise/warninglisted entities and for own org assets.
The lookup runs with the entity TLP (`ctx.tlp`) and the case id.

## Integration notes (for the owners of the files named)

* **Overrides on re-runs (P322 cond 3)**: the engine applies stored analyst decisions only through a
  case hook: `rt.case_hooks.append(store.OverrideHook(app.store))` belongs next to the
  `meta['sightings_lookup']` line of `App.prepare_runtime` (WP13; `commands/cases._prepare_runtime`
  has the same interim branch). Until WP19's `Engine(..., overrides=store.overrides_for)` lands, a
  re-run without the hook shows the automatic labels again (display paths such as `cases show`
  re-apply them). Covered by `tests/test_overrides.py` with the hook installed.
* **Exports and shareable reports (A2, P375 cond 3)**: writers call
  `store.omit_cross_case(case)` at CLEAR/GREEN (`not store.cross_case_allowed(case['tlp'])`) and
  `store.omit_cross_case(case, keep_count=True)` for AMBER+ exports (WP20 reports, WP21 STIX/MISP).
* **Summary line (P375 cond 6)**: the `case_sightings` finding title is the one-line entity text;
  renderers (WP14 terminal, WP20 reports) show it first among internal sightings per entity and in
  the summary.
