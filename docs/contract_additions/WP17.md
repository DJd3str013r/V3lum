# Contract additions - WP17 (wave 3): IOC extraction engine, detection v2, pattern DB

Additions only (module contract v2 is frozen; nothing documented in `docs/MODULE_GUIDE.md` was
renamed). Proposals P172, P333, P323, P217; architecture actions AR24, AR18.

## `v3lum.core.ioc` - the extraction engine (P172)

```python
from v3lum.core.ioc import extract, ExtractionResult, ExtractedIOC, scrub
result = extract(text, *, limit=5000, source_type="text", org=None, own_domains=(), aliases=True, annotate=True)
```

* **Who needs it**: every module that mines indicators out of free text (post bodies, pastes,
  documents, e-mail bodies, API answers with prose). Use it instead of private regex sets; the old
  `v3lum.core.detect.extract_iocs(text, limit)` stays and is now a thin wrapper
  (`[e.entity for e in extract(text).entities]` minus file-name lookalikes).
* **Stage order**: scrub (`sanitize.scrub_text` + the pattern-DB secrets it does not know + card
  numbers -> `BIN6…last4`; PIX BR Codes left intact) -> decode layers (quoted-printable and HTML
  entities in place; base64 blocks and hex-encoded `http` runs as decoded segments; percent-encoded
  URLs nested in URLs; depth <= 3, decoded output <= 2x input and <= 20 MB; archives/binaries
  never decoded) -> refang -> span-masked extraction -> validation -> annotation.
* **`ExtractionResult`**: `entities` (reading order), `counts` (per type value, plus masked kinds
  `cpf`/`iban`), `limit_hit`, `notes` (the single 'sensitive data in pasted text: ...' line among
  them), `masked` (`{'cpf'|'iban': {'count', 'previews'}}`, previews masked), `sensitive` (scrub
  rows `{'kind', 'action'}`, no values), `decoded` (layer -> blocks), `source_type`, `limit`;
  `preview()` -> `'37 IOCs: 12 domains, 5 IPs, 4 low-confidence'`, `by_type()`, `to_dict()`.
* **`ExtractedIOC`**: `entity`, `span` (start, end) and `line` (1-based) of the first occurrence
  in the scrubbed text (`scrub(text)`; a value found inside a decoded block carries the block's
  span), `confidence`, `defanged`, `flags`, `occurrences`, `source` ('text' | 'url' | 'base64' |
  'hex' | 'url_encoding' | 'headers'), `note`, `noise`; properties `expand` (IOC_TYPES without a
  NO_EXPAND flag), `low_confidence` (< 0.75 or `low_confidence_tld`), `provenance`
  ('line 3, chars 120-135, defanged').
* **Flags** (`ioc.FLAGS`): `bogon`, `private`, `low_confidence_tld`, `warninglisted` (noise kinds
  or warninglists, `v3lum.core.noise`), `org_domain` (org profile or `own_domains`),
  `recipient_token` (`policy.recipient_token`: an e-mail in plain/URL-encoded/base64 form or an
  opaque token in the URL), `personal` (PERSONAL_TYPES), `secret` (SECRET_TYPES), plus `decoded`,
  `unverified_attack_id` (not in the bundled ATT&CK index, confidence 0.6) and `from_url` (a host
  derived from a URL). `ioc.NO_EXPAND_FLAGS` lists the flags that keep a value from auto-expanding.
* **Privacy**: CPFs never become entities (masked previews in `masked['cpf']`); IBANs likewise;
  cards become `payment_card` `BIN6…last4`; secrets become `secret` / `telegram_bot_token`
  fingerprints; e-mail addresses in To/Cc/Bcc/Delivered-To header lines and Message-ID local parts
  are never listed (P333 cond 8). Extraction is static and offline: nothing is resolved or fetched.
* **Brazilian scam text**: national phones without '+' (`(11) 98765-4321`, `11 98765-4321`,
  `0800 123 4567`) validated against `v3lum/data/anatel_ddd.json`; `wa.me/<digits>`,
  `api.whatsapp.com/send?phone=` -> phone; `t.me/<name>` -> telegram_handle; `t.me/+<code>`,
  `t.me/joinchat/<code>` -> telegram_invite; `discord.gg/`, `discord.com/invite/` ->
  discord_invite; profile URLs of the merged platform fragments -> social_account; PIX BR Codes
  (CRC16) -> pix_brcode; 14-digit / punctuated CNPJ with valid check digits -> cnpj.
* `scrub(text, *, hits=None) -> str`: the scrub stage alone (idempotent). Callers that store a
  pasted text should store `scrub(text)`: spans then refer to the stored text.
* `refang_text(text)`, `preview_line(items)`, `url_typed_entities(url)` (typed accounts a URL
  names, `[(Entity, note)]`), `LOW_CONFIDENCE` (0.75), `DEFAULT_LIMIT`, `MAX_DECODE_DEPTH`,
  `MAX_DECODED_CHARS`, `FILE_EXTENSION_TLDS`.

## Alias index (AR18) - `v3lum/data/aliases/*.json`, schema `v3lum.aliases/1`

`{kind: 'malware_family'|'threat_actor', source, licence, names: {alias: canonical}}`
(see `v3lum/data/aliases/README.md`). API in `v3lum.core.ioc`: `alias_lookup(name) ->
[(EntityType, canonical)]`, `alias_index()`, `alias_errors()`, `reload_aliases(extra_dirs=())`,
`ALIASES_SCHEMA`, `ALIASES_DIR`. **Who needs it**: the P295 batch ships the data; modules that type
names (actor handles, malware names in reports) should call `alias_lookup` instead of keeping a
private list.

## `v3lum.core.detect` - detection v2 (P333, P323 cond 1, P217 cond 5)

Unchanged names and signatures: `detect`, `best`, `primary`, `extract_iocs`, `Detection`. Today's
precedence is kept; additions:

* new types only from an explicit `TYPE:value` prefix, a URL pattern (`t.me/`, `discord.gg/`,
  `discord.com/invite/`, `bsky.app/profile/`, `steamcommunity.com/`, `wa.me/`, profile URLs of the
  merged platforms) or an unambiguous structure (a header block -> email_headers; `T1` + 70 hex ->
  tlsh; a leading `@user@instance` -> fediverse_handle; a PIX BR Code with a valid CRC16) - never
  from bare hex or digit length;
* a URL with a scheme stays a URL (0.98); the account it names is an alternative at 0.7. A
  scheme-less account link types the account (0.95) with the URL as a 0.7 alternative;
* a header-only block is email_headers (0.95, text_blob 0.7); headers + body stay text_blob (0.95,
  email_headers 0.7);
* checksummed crypto is typed only with a passing checksum (an EIP-55 mixed-case mismatch, a
  Monero or Base58Check failure is not typed); with an explicit prefix a failing checksum (or a JWT
  without the `eyJ...eyJ...` structure) gets confidence 0.4;
* known malware/actor names (alias index) are typed malware_family/threat_actor at 0.8 instead of
  username (an explicit `@handle` / `user:` prefix stays a username).

## `v3lum.core.patterns` - the validated pattern DB (P323)

`Pattern` (name, kind, regex, validator, confidence, enabled, consumer, vectors_ok, vectors_bad,
group, entity_type, mask, hints, source, description; `emitted`, `check()`), `PatternMatch`
(name, kind, start, end, value, masked, confidence, entity_type), `PATTERNS`, `KINDS`,
`match_patterns(text, *, kinds=None, names=None, include_disabled=False, include_unconsumed=False,
overlapping=False)`, `pattern(name)`, `emitted()`, `odd_headers(text)`, `card_brand`, `iban_valid`,
`mask_pan`, `mask_iban`, `mask_cpf_inplace`, `SRV_NAMES`, `STANDARD_HEADERS`, `IBAN_LENGTHS`,
`CARD_BRANDS`. Rules: no validator -> confidence <= 0.5; generic patterns disabled; only patterns
with a consumer or a masking need are emitted; secret and financial hits are local-only (the raw
`PatternMatch.value` must never be stored, logged, rendered or sent; use `masked`). **Who needs
it**: modules scanning fetched content for keys/tokens/analytics ids (always through `masked`).

## Module `ioc_extract` (reference module, metadata unchanged)

Now a thin wrapper over `ioc.extract`: pivot notes end with the provenance
('line 3, chars 120-135'), personal ones read
'personal identifier from text: analyst selection required (line ..., chars ...)'; IOC_TYPES the
engine flagged are pivoted with `expand=False` and 'listed, not auto-investigated: <flags>';
`withheld` is keyed by `cpf`, `iban`, `secret`, `payment_card`, `telegram_bot_token` (a JWT is now
a `secret` fingerprint); the first finding's description starts with the preview line; a finding
'IOC limit reached' appears when the limit was hit; `res.raw['iocs']` keeps per-IOC provenance.

## Review additions (WP17 reviewer)

* **`detect()` - sensitive single values** (P323 cond 5-7, AR24): a value that IS a secret (a
  pattern-DB secret or a `sanitize.find_secrets` distinctive format covering the whole value), a
  secret fingerprint (`'<kind>:<prev>…<prev>:<sha16>'`), a payment card (Luhn + brand IIN and a
  printed layout; a 14-digit CNPJ and a 15-digit non-Amex/Diners number keep today's reading) or a
  `BIN6…last4` value gets ONE detection: `secret` / `telegram_bot_token` (fingerprint, 0.95) or
  `payment_card` (`BIN6…last4`, 0.9). An IBAN returns `[]` (no entity type: masked everywhere,
  never investigated). JWTs keep their structure-gated `jwt` detection (tests/test_detect.py).
  Before this, `4111111111111111` was a keyword seed and `AKIA…`/`ghp_…` were username seeds
  holding the raw value.
* **`detect()` - stored text is scrubbed**: the `text_blob` value of a multi-line text, of a
  pasted e-mail (headers + body), of a header block's alternative and of a forced `text_blob:` is
  `ioc.scrub(text)` (combos/password hashes dropped, secrets fingerprinted, cards truncated); the
  `email_headers` value is parsed from the scrubbed text. URL seeds lose `user:password@`
  credentials (`sanitize.scrub_text`), as P145 cond 5 requires for seeds.
* **`ioc.extract` - encoded values inside URLs**: a path segment, query value or fragment that
  hides a secret, a card number, a CPF or an IBAN behind percent-encoding (up to 3 layers) or
  base64 is handled like its plain form: the hit becomes the same masked entity/count (reported in
  'sensitive data in pasted text'), the URL is cut before that component (the plain form's span is
  blanked the same way) and a URL nested in it is extracted from the scrubbed component. CPFs and
  IBANs that only appear after HTML-entity / quoted-printable decoding are counted masked too.
* **Phones**: international numbers are taken whole (`+12025550143`, `+44 20 7946 0958`; a window
  that ended 8 characters after '+d' cut or dropped them) by a flat, linear regex; the separator
  layout (single separators, balanced parentheses) is checked in code.
* **Decode cap**: a decoded block that would take the decoded total past `min(2 x input, 20 MB)` is
  skipped (the cap held only before each block); the 'decode budget reached' note is added once.
* **Guide section 24.4 note**: the reference module now pivots IOC_TYPES the engine flagged
  (bogon/private IPs, file-name lookalikes, warninglisted, org-profile, recipient-token, unverified
  ATT&CK ids) with `expand=False` (P172 cond 7 and 10), where the frozen guide text says 'IOC_TYPES
  pivot with expand=True'. Metadata is unchanged; the guide excerpt needs the architect-approved
  migration note (WP29), the code follows the council condition.
