# Contract additions - WP18 (wave 3)

Operator commands on the WP13 registry (`v3lum cases | data | links | doctor | keys | org | scope`)
and the organisation profile v2 (P378, A11). Nothing of the frozen guide (`docs/MODULE_GUIDE.md`,
contract v2) was renamed or changed: `ctx.org`, `OrgProfile.load` / `from_dict` / `owns` /
`is_verified_domain` / `brand_terms` / `supplier_domains`, `load_default`, the entry dataclasses and
the lenient loader keep their documented behaviour. The entry dataclasses `NetEntry`, `AppId` and
`SupplierEntry` gained an optional `note: str = ''` field (keyword with a default: existing
constructors keep working). Everything below is new.

**Who needs this:**

* **module authors whose modules discover ownership facts** (registro.br RDAP, NIC.br ASN list,
  RIPEstat, M365 tenant, CT SAN, BCB/gov.br lists, SPF, favicons): `v3lum org seed` turns your
  pivots into profile proposals only when the edge uses one of the relations in
  `v3lum.commands.org.SEED_RELATIONS` (or the analyst passes `--any-relation`), and reads M365
  tenant ids from the domain attribute `m365_tenant_id`. Use those names (core vocabulary or your
  `data/vocab/` fragment) for "same owner" edges; a resolved/CNAME target whose node carries a
  `noise.CDN_KINDS` noise kind marks the proposed domain `third_party_hosted`. Nothing else in
  module code changes; modules still read the profile only through `ctx.org`;
* **own-asset / per-person breach module authors** (run_on 'own_assets_only' / 'own_assets'):
  the verified states your modules require now have operator commands: `v3lum org verify <domain>`
  (DNS TXT `v3lum-verify=<orgprofile.txt_token(domain)>`) and `v3lum org verify <domain> --attest
  --by NAME`. Point your SKIPPED 'own_asset' hint at them;
* **quota-limited module authors**: `v3lum cases resume <id>` re-runs exactly the deferred and
  could-not-verify (module, entity) pairs with their recorded `RunInfo` (`is_seed`, `depth`,
  `provenance`, `tlp`); a run must therefore behave the same on a re-run of one pair (no hidden
  cross-entity state in `ctx.state` that a single pair cannot rebuild);
* **WP19/WP20** (re-render): `v3lum.commands.cases.apply_overrides` is the display-time merge of
  `Store.overrides_for` into a stored case dict (same shape as `Finding.apply_override`);
* **WP25** (doctor v2, keys wizard): extend `v3lum/commands/doctor.py` (`PROBES`, `probe_allowed`,
  `doctor_table`) and `v3lum/commands/keys.py` (`keys_table`, `set_key`, `record_plan`);
* **WP26** (watch): the org profile writers (`orgprofile.save`, `OrgProfile.add_*`) and the
  audit helper `v3lum.commands.org.audit_profile_change`.

## Details

### Strict validation (`orgprofile.validate`, `v3lum org check [FILE]`, P378 cond 1)

The lenient loader stays as documented for scans (problems in `OrgProfile.errors`, invalid entries
dropped or downgraded, fail closed). `validate` reports everything the loader drops, downgrades or
merely tolerates, each with its field path (`domains[2].verification`, `org.cnpj_roots[0]`) and the
file line: unknown keys; unknown verification states; `attested` without the analyst's name and a
past `YYYY-MM-DD` date (as `attested_by`/`attested_date` or `attested = {by, date}`), attestation
fields on another state; invalid or public-suffix domains; malformed ASNs; malformed, host-bit or
too-broad networks (IPv4 shorter than /8, IPv6 shorter than /19); CNPJ roots that are not 8
characters; duplicate domains, brands, roots, BINs, favicon hashes, ASNs, networks and app ids;
executives without `opt_in = true` or `informed_at`; wrong value types; parse errors (with the
parser's line); a file mode that lets other users read or write it. Executive names and card numbers
are never echoed. Tests: `tests/test_cmd_org.py::test_check_*`, `test_validate_api`.

### Saving (`orgprofile.save`)

Validated first (ValueError listing the problems: an invalid profile is never written), written with
`paths.secure_write_text` (0600, atomic). A file outside the V3LUM home (team-maintained) keeps its
group bits but never any for other users. `profile.path` and `profile.sha256` are updated (the
SHA-256 of the written text: the value cases record as the org profile hash). YAML is never written.
Tests: `test_save_writes_0600_and_round_trips`, `test_save_refuses_an_invalid_document`,
`test_save_keeps_group_bits_of_a_team_profile_outside_the_home`.

### DNS TXT proof of control (`txt_token`, `txt_record`, `verify_txt`; P378 cond 5)

The token is keyed with the installation secret (`hmacid`), so it cannot be computed elsewhere; IDN
domains are normalised to punycode first. `verify_txt(resolver, domain)` reads `TXT` through the core
resolver (`Resolver.query(name, 'TXT')`): True when one string equals the record (quotes and case
ignored), False when the name answered (NOERROR or NXDOMAIN) without it, None when it could not
verify (SERVFAIL, timeout, policy, offline) - never read as "absent" (team rule 5). `v3lum org verify`
changes nothing on False/None. Tests: `test_txt_token_is_keyed_and_idn_normalised`,
`test_verify_txt_true_false_none`, `test_verify_by_dns_txt_marks_txt_verified_and_audits`,
`test_verify_when_dns_cannot_answer_is_could_not_verify`.

### Profile changes are audited (P378 cond 11)

Every change made by `v3lum org verify|seed` is saved 0600 and written as one hash-chained row of
kind `'profile_change'` in the audit trail with case id `'org-profile'` (`audit.CaseAudit`, no case
directory) carrying the action, field, value, analyst, path and the profile SHA-256 before/after
(executives are never named). An invalid or read-only (team-maintained) profile is never rewritten.
The trail is not a case: `v3lum cases delete org-profile` is refused (the case purge would wipe it)
and `v3lum cases verify org-profile` checks its hash chain offline. Tests:
`tests/test_cmd_cases.py::test_the_org_profile_trail_is_not_a_case`.

### `org seed` (P378 cond 8)

A normal PASSIVE scan (`Engine.investigate`, every module through the policy gate; never LIGHT or
ACTIVE) seeded with the typed inputs, or by default with the profile's own domains that are not
merely `seeded` and not `third_party_hosted`, plus its own ASNs. Proposals are
entities of `SEED_KINDS` reached through `SEED_RELATIONS` edges (noise nodes and entries the profile
already holds are left out), plus `m365_tenant_id` attributes of reached domains. An entry the
profile already holds is not proposed again but still leads on (a known CNPJ root -> its NIC.br ASN
-> the announced prefixes); a supplier's domain is never proposed and never walked through. Each needs a
per-proposal confirmation in a terminal; a non-interactive session prints them and writes nothing;
accepted domains are added as `seeded` (nothing is auto-trusted). Tests:
`test_seed_in_a_non_tty_proposes_and_writes_nothing`, `test_seed_needs_a_confirmation_per_proposal`,
`test_seed_follows_entries_the_profile_already_holds`, `test_seed_proposals_never_walk_through_a_supplier_domain`.

### ACTIVE scope never defaults from the profile (P378 cond 9, A7/A11)

`v3lum scope draft --from-org [-o FILE]` writes a draft whose targets are only the verified
(`txt_verified`/`attested`) domains that are not `third_party_hosted`; every `third_party_hosted`
domain and network goes under `[exclusions]`; networks are comments; `authorization_ref = 'REQUIRED'`
and empty owner/contacts/ticket/window keep `Scope.validate` refusing it until the analyst binds it.
An ACTIVE run still needs an explicit `--scope FILE`. Tests:
`test_scope_draft_excludes_third_party_hosted_and_is_never_usable_unbound`,
`test_the_active_scope_never_defaults_from_the_profile`.

### `cases resume` (P334 cond 7)

`resume_plan(case, deferred_rows)` collects the deferred pairs (`QuotaBook.deferred(case_id,
case=stored)` and `case['deferred']`) and the could-not-verify pairs of `case['execution']`
(statuses in `CNV_STATUSES`, deadline skips, partial runs cut by deadline/quota/cancel/window), each
with `run_info_of(case, entity_key)` = `{is_seed, depth, provenance, tlp}` from the stored graph.
`is_seed` is True only for analyst-typed seeds that were not unconfirmed: a pivot is never promoted
to a typed seed. Pseudonymised deferrals that do not map back and secret values (stored redacted)
are left out with a note. The resumed run uses the stored options (TLP, purpose, mode, scope
reference), never escalates the mode, needs `--authorized REF --scope FILE` again for an ACTIVE case
(same reference and scope SHA-256, usable now, its ROE identity never naming the organisation), and
creates a new case with `meta['resumed_from']`. Tests: `tests/test_cmd_cases.py::test_resume_*`,
`test_resuming_an_active_case_needs_its_own_reference_and_scope`.

### Report re-render (`cases report`, P324 cond 6)

`cases report` and `cases resume` record every written report with its SHA-256 through
`record_reports` (`Store.record_report_hashes`; a re-render replaces the recorded hash), so
`cases verify` recomputes it and flags an edited report; `cases report` also writes a `'report'` row
(format, file name, SHA-256; never the directory) to the case audit trail. `cases purge
--older-than` takes 0-36500 days (NaN/inf/negative refused). Tests:
`test_report_rerender_records_hashes_audits_and_verify_checks_them`, `test_a_resumed_case_with_reports_verifies`,
`test_purge_rejects_impossible_ages`.

### Overrides (`cases override|confirm`, P322 cond 3)

`Store.set_override` (WP16) records one decision per (finding, analyst); each is also written to the
case audit trail (kind `'override'`). `apply_overrides` applies them at display time: the item gets
`override = {analyst, label, severity, verdict, note, at, auto: {label, severity, criterion}}` and its
`confidence_label`/`severity` take the override values; the stored case is not rewritten. Tests:
`test_override_and_confirm_are_recorded_audited_and_shown`.

### `v3lum links` (P311 cond 5, A2)

Links come from `core.links.pivot_links_for`, grouped by `links.LINK_CATEGORIES`, verified first.
At AMBER and above each URL is defanged, non-clickable text followed by
`links.disclosure_note(entity, link)` ('opening sends <value> to <host>'); at RED a banner states
that third-party links are listed only here. `--open N` at AMBER+ (or for a `touches_target` link)
needs an interactive confirmation naming the host and is refused in a non-TTY. Entities flagged by
`policy.hostile_reasons` (case-DB sightings with a hostile verdict included) show the contact warning
first and hide `touches_target` links unless `--all`. The investigated value is printed defanged when
it is a URL (P311 cond 8: never a clickable link, at every TLP) or a flagged host-bearing entity, in
the header and in every disclosure note; `--json` keeps the raw value. Tests: `tests/test_cmd_links.py`.

### `v3lum doctor` (P377 cond 2, A10)

The v1 table, moved. Each reachability probe names the registry source it exercises
(`Probe(url, source)`); `probe_allowed(probe, pctx)` asks `licence.evaluate_source` under the doctor
path's licence profile and state, so `internetdb.shodan.io` (source `shodan.internetdb`,
noncommercial) is never contacted under corporate unless a licence_allow entry or research basis
clears it; an unregistered host is never contacted. A probe answered with 401/403/407/429/430/451 (or
an `HttpError` such as `RateLimited`/`Blocked`) reads `[~] could not verify`, never reachable or
failed (team rule 5). Also: `paths.check_permissions()` warnings,
command-module import errors, licence allow-list warnings, exhausted provider quotas and the org
profile summary. Tests: `tests/test_cmd_doctor.py`.

### `v3lum keys` and `v3lum data`

`keys list` iterates `config.key_registry()` (legacy table + provider-fragment keys such as `misp`
and `opencti`, with their env aliases) plus module-declared and stored keys; values are masked.
`keys set <name> [value] --plan business|free` records `key_plans.<name>` (A1); without a value the
key is read hidden (a pipe works too, keeping it out of the shell history) and an empty input stores
nothing. `data update`
uses `DataStore.update` per dataset (`--essential` = the essential ones); active (pinned) datasets
come back `needs_accept` with their diff summary and are installed only by `--accept-new`
(interactive confirmation, the copy staged by an earlier call, or `--sha256 HEX`; `--sha256` needs
`--accept-new` and 64 hex digits; `--offline` refuses `data update`). `data list` shows
licence, terms class, age, stale flag and size, plus `DataStore.first_run_hint()`. Tests:
`tests/test_cmd_doctor.py::test_keys_*`, `tests/test_cmd_data.py`.
