## What module authors need to know

No new call. The risk model reads fields the frozen contract already has, so filling them well now
changes the score:

| field / name | effect on scoring (P302) and grouping (P335) |
|---|---|
| `res.finding(..., source='<provider>.<source>')` | selects R_src: the Admiralty grade of that provider (A 1.0, B 0.85, C 0.7, D 0.5, E 0.3, F 0.5), replaced by the analyst-feedback weight of the source once it has 5 votes (floor 0.3). Without `source=` (or with a value the registry does not know) the module's declared `Module.sources` count (several: the least reliable). Modules without registry sources (offline analysis) weigh 1.0. A short id of the module's own provider (`source='feed'`) is resolved too. The source's `upstream_family` / `embeds` decide what is a duplicate and what is independent corroboration; findings of modules without registry sources (family `module:<name>`) are derived facts and never count as an independent source for the '+1 confidence level'. |
| `res.finding(..., observed_last=<provider timestamp>)` | MISP decay `1 - (t / tau)` with `tau` per class (`scoring.TAU_DAYS`: ip 30 d, url 30 d, domain 90 d, typosquat 180 d, breach 1095 d, infostealer 365 d, hashes never). No timestamp: no decay, contributor label 'age unknown'. Pass the provider's last-seen date, never the scan time. |
| finding tags | the tag family (`scoring.TAG_FAMILIES`) groups findings that state the same kind of fact (e.g. malicious/malware/c2/botnet) for de-duplication per upstream family; the tags `infostealer`, `breach`/`credential_exposure` and `typosquat` choose the decay class before the entity type. `context_only` and `known_good` findings never score. |
| `data['breach_key']` (breach findings, tag `breach`) | the display grouping key of 'the same breach across sources' (else `data['name']` / `data['breach']` / `data['breach_name']`, normalised). A sensitive breach whose name is withheld groups only through `breach_key`. |
| `data['cve']` / `data['cve_id']` (or one CVE id in the title) | the display grouping key of 'the same CVE from several sources' about one subject. |
| severity | a LOW finding can never make an entity or a case more than 'low' (severity ceiling); weak signals escalate only through a correlation rule (`Correlation` severity). |

Correlation rules: a correlation takes the max over the findings it cites (never a second noisy-OR
term) and lifts the ceiling of the entities it names to its severity; a correlation tagged
`context_only` never scores. List the cited finding ids in `Correlation.evidence`: own assets and
known-good/verified entities are uplifted only by a correlation that cites one of their own findings.

## `v3lum.core.scoring` (P302)

```python
from v3lum.core.scoring import score, level, W_SEV, TAU_DAYS, DELTA, A_CRIT, LEVELS, decay
risk = score(graph, correlations, reliability=None, *, source_reliability=None, now=None, coverage=None, registry=None)
```

| name | kind | summary |
|---|---|---|
| `score(...)` | function | pure risk model (module docstring documents every rule). `reliability` v1 `{module: weight}` (`Store.reliability()`); `source_reliability` `{source_id: weight}` (`Store.source_reliability()`); `now` decay reference (UTC now when None); `coverage` `{'coverage': case.coverage, 'answered': case.answered}` (a case dict works too); `registry` a `ProviderRegistry` (default the loaded one). |
| result keys | dict | v1: `score` (0-100, 1 decimal), `level`, `entities` (`{key: {score, level, ceiling, contributors[, uplifted_by][, personal]}}`), `top` (`[{entity, score, level}]`, 10). v2: `contributors` (top-3 of the case: `finding_id`, `entity`, `path` (`[{from, relation, to}]` from a seed), `confidence_label`, `weight`, `words`, `severity`, `source`, `age`; a correlation entry has `correlation_id`/`rule` and an empty `finding_id`), `label` ('triage aid, not a conclusion'), `inconclusive` (seed keys with < 2 reputation-capable answers), `no_export` (PERSONAL_TYPES entity keys: never exported to STIX/MISP as a score about a person, never an automated action), `ceiling`, `excluded` (`{context_only, known_good, analyst_rejected, licence, noise: n}`), `model` ('v3lum.risk/2'). Review additions: `reading` (the level, or `'inconclusive'` at the lowest level when a seed is listed in `inconclusive`: P302 cond 6), `automation` (`{score, level, basis}`: the case score without PERSONAL_TYPES entities and without the correlations naming one - the only score an automated action such as `--fail-on` may use, P302 cond 10 / LGPD art. 20), and `top` entries of personal entities carry `personal: true`. Malformed reliability values (NaN, text, infinities) are ignored (the prior applies), never read as the 0.3 floor. |
| `level(score)` | function | critical >= 80, high >= 55, medium >= 30, low >= 8, else 'no findings' (the v1 'clean' is gone). |
| `decay(age, tau_days, *, base=1.0, delta=DELTA)` | function | MISP polynomial `base x (1 - (age/tau)^(1/delta))`; `age`/`tau` None -> `base`; age >= tau -> 0. |
| `decay_class(finding_or_dict, entity_type=None)` | function | the `TAU_DAYS` class of a finding (or None): exporters use it for STIX `valid_until` (WP21). |
| `age_days(observed, now=None)` | function | days since an ISO date/datetime (None when empty/unreadable). |
| `tag_family(finding_or_dict)` | function | the de-duplication family of a finding (`TAG_FAMILIES`, else `tag:<tag>`, else `title:<title>`). |
| `upstream_families(source_ids, registry=None)` | function | `Source.families` of registry sources (unknown -> `source:<id>`). |
| `W_SEV`, `C_CONF`, `TAU_DAYS`, `DELTA`, `A_CRIT`, `A_CRIT_DEFAULT`, `LEVELS`, `SEVERITY_CAP`, `TOP_PIVOTS` (5), `TOP_CONTRIBUTORS` (3), `SHARED_RELATIONS`, `SHARED_TRANSFER_CAP`, `PROTECTED_TAGS`, `PROTECTED_ATTRIBUTES`, `REJECT_VERDICTS` (equal to `store.REJECT_VERDICTS`, tested), `TAG_FAMILIES`, `LOCAL_RELIABILITY`, `LOCAL_FAMILY_PREFIX` ('module:'), `SCORE_LABEL`, `NO_FINDINGS`, `INCONCLUSIVE`, `AUTOMATION_BASIS`, `MODEL` | constants | documented in the module; `WEIGHTS` (v1 name) is kept as `W_SEV / 10`. |

## `v3lum.core.grouping` (P335, presentation only)

```python
from v3lum.core.grouping import normalize_url_key, group_findings, group_correlations, FindingGroup
```

| name | kind | summary |
|---|---|---|
| `normalize_url_key(url) -> str \| None` | function | refanged, http/https scheme dropped, host lower-cased without `www.`/`m.`, default ports and credentials dropped, no trailing slash, `utm_*`/fbclid/gclid/igshid/ref/si/hl/trk dropped, query sorted, fragment dropped; None for a URL without a path (never groups). |
| `group_findings(findings) -> list[FindingGroup]` | function | finding dicts (case JSON) or `Finding` objects; union-find over `breach|<entity>|<breach key>`, `url|<url key>|<tag family>`, `cve|<entity>|<CVE>|<tag family>`; a group of several members is named by the smallest key at least two members share (never by a key one member carries alone); a lone finding is `finding|<id>`. Every finding lands in exactly one group; the input is never modified; identity entities are never merged (keys contain the exact entity key); `Finding` objects of SECRET_TYPES entities are keyed by their redacted (persisted) entity key, like the case JSON. Ordered by severity, confidence, key. |
| `group_correlations(correlations) -> list[FindingGroup]` | function | by subject entity (first entity), key `entity|<entity key>`, `sources` = rule ids. |
| `FindingGroup` | frozen dataclass | `key`, `member_ids` (principal first), `severity` (max), `confidence_label` (max), `criterion` (of the principal: highest confidence, then severity, then id), `count`, `sources`, `upstream_families`, `kind` (breach/url/cve/finding/correlation), `entities`, `title`, `principal_id`; `label()` -> 'seen by 3 sources: a, b, c'; `to_dict()`. |
| `TRACKING_PARAMS`, `HOST_PREFIXES` | constants | the URL-key rules. |

## Engine and App (WP19 review additions)

| name | summary |
|---|---|
| `Engine(runtime, options, *, reliability=None, source_reliability=None, overrides=None)` | `overrides`: `callable(finding_ids) -> {finding_id: override dict}` (`Store.overrides_for`). |
| `Engine.apply_overrides(case) -> int` | first step of `_finish`: stored analyst decisions applied through `Finding.apply_override` before suppression, correlation rules and scoring (they survive re-runs, P322 cond 3); a failing lookup adds the case note 'analyst overrides not applied: ...'. |
| `Engine._finish` scoring call | `scoring.score(graph, correlations, reliability, source_reliability=..., now=runtime.now(), coverage={'coverage': case.coverage, 'answered': case.answered})`. |
| stored case | `summary.risk_level` defaults to 'no findings'; the 'no source answered' note ends with '- the risk level is not a verdict'. The evidence store reads its caps from the runtime config (`EvidenceStore(..., settings=rt.config, case_id=case_id)`). |
| `App.scan`, `App.run_single` | build the engine with `reliability=Store.reliability()`, `source_reliability=Store.source_reliability()` and `overrides=Store.overrides_for` (a case-DB failure leaves that input out). |
| `App.prepare_runtime` | also installs one `store.OverrideHook` (when the case DB offers `overrides_for`), so engines built without `overrides=` (e.g. `v3lum cases resume`, which builds `Engine(rt, options)` itself) still apply the analyst decisions before suppression, correlations and scoring; a decision applied twice (hook + `Engine(overrides=)`) is idempotent. |
| `level_at_least(level_or_case, threshold)` | reads 'no findings' / 'inconclusive' / v1 'clean' as the lowest level; given the case dict it uses `risk['automation']['level']` (falls back to `summary.risk_level` for a v1 case), so a person's score never drives `--fail-on` once `cli.py` passes the case dict (open issue for WP13). |
| `App.cases_table` | prints v1 'clean' as 'no findings' with the theme's `risk_style`. |
