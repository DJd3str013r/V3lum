# Contract additions - WP21 (wave 4)

STIX 2.1 determinism and markings, MISP event export and the gated push to the organisation's own
MISP/OpenCTI (P303; A1, A2, A7, A12; AR09, AR17, AR24). Nothing of the frozen guide changes:
`v3lum.report.stix.bundle(case)` keeps its positional signature (keyword-only flags are added) and
the guide's names (`entities.STIX_SCO`, `attack.stix_id`, `Confidence.stix`...) are only read.

**Module authors need nothing new.** What a module already writes decides what is exported:

* an entity becomes an exported observable when its type has a STIX object (`entities.STIX_SCO`,
  plus CVE, ATT&CK, actor, malware and company SDOs) and is not personal/secret;
* it becomes an **indicator** / MISP `to_ids` only through a CR27 `multi_source_malicious`
  consensus (>= 2 independent upstream families, so `Finding.source` matters) or an analyst
  decision: an override labelled `confirmed` on a finding/correlation tagged `malicious`,
  `phishing`, `malware`, `c2`, `botnet` or `compromised`, or an override verdict `malicious`, `c2`,
  `phishing` or `compromised` (`stix.HOSTILE_VERDICTS`) - never because a single module tagged it
  malicious, never with a rejecting verdict (`store.REJECT_VERDICTS`);
* a value on a warninglist or any other noise list (CDN, resolver, sinkhole, parked, private...:
  node `noise` / `noise_kind`) stays an observable unless `--include-weak`;
* `Finding.observed_last` becomes the indicator's `valid_from` (and drives `valid_until` through the
  P302 decay tau); `Finding.attack` / `Correlation.attack` become `indicates` relationships to the
  official ATT&CK attack-pattern ids;
* findings/correlations tagged `privacy` are left out of default exports, `context_only` items are
  observables only, findings tagged `internal_sighting` (other platforms' event ids) and findings of
  results marked above the case TLP (`res.set_marking`) are never exported - not even as a count;
* a free-form value (URL, user agent, company name) carrying a CPF is never exported, and in
  default exports one carrying an e-mail address, a phone number or a personal value of the case is
  withheld too (the IOC cannot be masked without changing it);
* the free-text fields of findings (title, description, criterion) are exported as STIX notes after
  scrubbing (personal values of the case, e-mail addresses, phone numbers removed; CPF masked):
  never put identifiers in a title that the entity itself does not carry.

## Details

**Indicator gating.** `prepare()` collects candidates per entity: CR27 correlations (rule in
`CONSENSUS_RULES`, family count read from the criterion/title `N independent ...`, >= the pack's
`CONSENSUS_FAMILIES`, no rejecting override verdict) and confirmed hostile items. The best candidate
(label, then confirmed over consensus) decides the confidence (90/70/40). It stays an observable
when its label is `possible` or the entity is warninglisted (`SUP-warninglist` suppression, node
`noise_kind`/tags/attribute) unless `include_weak`, and always when it is `context_only`.

**Personal data.** Default exports drop every PERSONAL_TYPES entity (and SECRET_TYPES, local
`file` paths), the edges and correlations that touch them, URLs / user agents / company names that
contain a personal value, an e-mail address, a phone number or a CPF (a CPF in every export), and
`privacy`-tagged items; free text is scrubbed. `include_personal`
exports e-mail addresses, user accounts and person identities (MISP: email, phone-number,
full-name, text); CPF never becomes an object or attribute and is masked in every text. The report
description and the MISP event info list only seeds of IOC types whose entity is exported (never
personal seeds, local files, text blobs, keywords or a withheld URL; they are counted as 'N
personal seed(s)' / 'N other seed(s) not listed'); a case whose seeds are personal exports no risk
score (`Risk score withheld`, MISP `threat_level_id` 4), any other case only the score without
personal-data entities (`export_risk`).

**Cross-case references (A2 BR10, P375 cond 3).** CLEAR/GREEN exports go through
`store.omit_cross_case(case)`; AMBER+ exports through `omit_cross_case(case, keep_count=True)`
reduced to the *visible* count: the restricted count (cases above this case's TLP) never travels,
a sightings finding or recurrence correlation resting only on restricted cases is dropped, and the
recurrence text is recounted from the visible counts.

**Ids.** SCOs: `sco_id`. Vulnerability: `uuid5(V3LUM_NS, 'vulnerability|<CVE>')`. Attack-pattern:
`attack.stix_id` (`uuid5(V3LUM_NS, 'attack-pattern|<id>')` for an id the index lacks).
Threat-actor/malware: `galaxy.lookup(...).stix_id`. Indicator: `uuid5(V3LUM_NS,
'indicator|<pattern>')` (one indicator per pattern everywhere; its `external_references` cite the
deciding finding/correlation id; a CIDR uses `ISSUBSET`). ATT&CK ids are canonicalised first: a
revoked technique counts as its replacement, an id that is not `T####[.###]` is dropped. Objects
whose id is shared across cases (indicators, notes, relationships) keep `created` =
`2026-01-01T00:00:00.000Z` and carry the case time as `modified` (STIX versioning: same id, same
`created`, later case = newer version). Note: `uuid5(V3LUM_NS, 'note|<finding|correlation>|<id>')` from
the deterministic finding ids (AR09). Relationship: `uuid5(V3LUM_NS, 'relationship|<src>|<type>|<dst>')`.
Report: `uuid5(V3LUM_NS, 'report|<case_id>')`. MISP event/attribute uuids are per case.

Tests: `tests/test_stix_v2.py`, `tests/test_misp.py`, `tests/test_export_push.py`,

## Review notes (wave 4 review)

* Push keys: `--push` uses the keys `misp` / `opencti` named by the plan. The A12 read-only
  adapters use the same key names and recommend read-only service accounts, so a push needs that
  account to be allowed to add events (MISP) or upload imports (OpenCTI); with a read-only key the
  platform refuses and the push reports 'could not verify'.
* `stix2`, `stix2-patterns` and `PyMISP` are not installed in the project venv: the oracle tests
  (`test_stix2_oracle_validates_the_bundles`, `test_stix2_patterns_oracle_accepts_every_pattern`,
  `test_pymisp_oracle_loads_the_event`) are skipped there and run where those dev packages exist.
