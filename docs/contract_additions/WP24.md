# Contract additions - WP24 (wave 4)

Correlation packs typosquat and brand abuse (P028: CR04, CR05, CR06, CR35), breach and infostealer
validation (P146: CR09-CR12) and web hygiene (P084: CR17-CR24). Nothing of the frozen guide changes:
the rules use the section 16 `@rule` API, read only the graph and emit `Correlation` objects. This
file lists what **module authors** must emit for the rules to see their facts (vocabulary in
`v3lum/data/vocab/pack_*.json`), the shared lure list, and the importable helpers of the packs.

Who needs it: **breach batches** (P133 hibp_account, P135 leakcheck_public, P137 xposedornot, P134
hudson_rock: `first_seen_breach`, `breach_records`, `breach_hit_count`), **domain batches** (P012
typosquat, P003 rdap, P001 ct_logs, P005 NRD feeds, P014/P015 reverse IP and passive DNS:
`cohosted_count`), **LIGHT/ACTIVE web modules** (G03 light, G13 active: P063 security_headers, P068
js_endpoints, P275 tls_inspect, P277 tls_protocol_scan, P279 sensitive_files, P282 cloud_buckets, P283
cors_probe, P316 jwt_analysis), **WP22** (rule fixtures, `breach_and_infostealer` removal), **WP19/
WP20/WP21** (tags `context_only`, `privacy`, `inconclusive`; the LGPD notice) and **WP26** (watch).

## Details

### Typosquat facts (P028)

The pack reads facts other modules already record; it never contacts a candidate. A domain is a
candidate when it imitates a **profile-protected** name (org brands and variants, supplier brands,
the registrable labels of own and supplier domains; no profile = no rule fires):

* relation `lookalike` (protected domain/keyword -> candidate, P012 forward scan), relation
  `lookalike_of` (candidate -> protected domain/keyword, reverse match), attribute `lookalike_matches`
  `{protected, technique}`, or the brand keyword in the candidate's owner labels after
  `fold_text` (IDNA->Unicode, accents, homoglyphs: 'аcmе' (Cyrillic), 'acrne' and 'acmé' all read
  'acme');
* registration: `registered` (rdap), `created` / `domain_age_days` (RDAP; the registrable domain's node
  for subdomains), tag `newly_registered` (NRD feeds), the P012 `typosquat_lookalikes` rows;
* registrant: `registrant_kind` (`redacted` or `privacy_proxy` -> CR04 POSSIBLE), `cnpj_roots`,
  `registrant_doc` and the `registrant` relation to a `cnpj` entity (14 characters only: a CPF is never
  read); `mx` (null MX `.` ignored) / `mx_host`, `nameservers` / `nameserver`, `a_records` /
  `aaaa_records` / `resolves_to`;
* certificates: `first_cert_seen` (earliest not_before, CT) and `ct_summary.first_cert_seen` only -
  never a renewal or a live handshake's certificate;
* parking: tag/noise kind `parked` or `is_parked`, parking name servers (`noise.is_parked`), parking
  addresses; sinkholes alike;
* TI (CR06): findings tagged malicious/phishing/malware/c2/botnet with their registry `source`
  (families from `Source.upstream_family` + `embeds`; without a source, the module's declared
  sources), `malicious` attributes, `blocklist_families`; P171 decay windows (IP 30 d, domain 90 d),
  `historical` and SUP-* suppressed findings never count; `is_cdn`, `is_hosting`, `shared_ip`,
  `cloud_role` (`cdn_edge`, `shared_hosting`, `shared_service`, `shared_proxy`), `hostnames`,
  `hosted_domain` edges and **`cohosted_count`** decide shared hosting.

Own assets are never flagged (`suppression_reason`): profile domains, supplier domains, a registrant
CNPJ root in `cnpj_roots` (from the `cnpj_roots` attribute, `registrant_doc` or a `registrant` edge to a `cnpj`), NS/MX under an own or supplier domain, `bcb_verified_domain` /
`verified_fi`, P012 rows with ownership `own_asset`/`defensive_probable` - read from the module's
**`typosquat_own_registrations`** `[{domain, ownership, evidence}]` (own and defensive registrations are
listed there, never in `typosquat_lookalikes`, and never pivoted; their verdict wins over any lookalike
row, so the same name reaching the graph through an NRD feed, CT or a reverse match stays suppressed)
and from lookalike rows. Parked/sinkholed candidates
are capped at MEDIUM with the label. Wording: 'lookalike / phishing-capable indicator'; 'malicious'
only with the CR06 consensus; no automated takedown.

### `v3lum/data/brand_lures_pt.json`

`{"schema": "v3lum.brand_lures/1", "description", "licence", "source", "reviewer", "date", "notes",
"words": [...], "pt": [...], "en": [...]}`; `words` = `pt` + `en` (lower-case ASCII, accents folded;
tests check it). Words of 5+ characters match inside a label, shorter ones only as a whole
hyphen/underscore token, after `fold_text`; the brand occurrence is removed first. The P376 guard
(`v3lum.core.policy.lure_words`) reads the same file: every list value counts, the metadata keys above
are ignored, so do not add other string keys.

### Breach facts (P146)

Breach modules emit **sanitized metadata only** (P145 schemas):

* **`breach_records`** - list of `{name, date, data_classes, password_form, verified, fabricated,
  spam_list, stealer_log, sensitive, compilation, domain, source}`: `date` as reported
  (`YYYY-MM-DD`, `YYYY-MM` or `YYYY`), `data_classes` the class NAMES (`'Passwords'`, LeakCheck field
  names), `password_form` (`'plaintext'` | `'hashed: <algorithm>'`), the HIBP flags as booleans,
  `compilation` for combo/compilation listings (LeakCheck `compilation`), `domain` of the breached
  service, `source` the registry source id (`'hibp.account'`, `'leakcheck.public'`...). The rules also
  read the same keys (and the HIBP spellings `Name`, `BreachDate`, `DataClasses`, `IsVerified`,
  `IsFabricated`, `IsSpamList`, `IsStealerLog`, `IsSensitive`, `Domain`; LeakCheck `unverified`) from
  the `data` of findings tagged `breach`, plus the core `breaches` name lists. Catalogue facts
  (`breach_metadata`, `service_breaches`) anywhere in the graph enrich name-only listings.
* **`first_seen_breach`** - the earliest breach date the module saw; CR10/CR12 read the earliest value
  of every source. On the case timeline as account-age evidence, never scored.
* **`breach_hit_count`** - LeakCheck `found` (or another aggregator's total); >= 100 marks a
  generic/shared address.
* Stealer logs keep the P134 shape: `stealer_logs` `[{date_compromised, stealer_family,
  total_corporate_services, total_user_services}]` (one record = one infected computer; >= 5 = shared),
  `infostealer`, `stealer_exposure` `{employees, ...}` on verified own domains.
* Generic identities: `generic_address` / `role_account` flags are honoured besides
  `entities.generic_address_kind`.

Rule semantics: suppression first and downgrade only (`Correlation.suppressed_by` records
`CR11 generic_or_shared_email_suppression` / `CR12 breach_predates_domain`); verified own addresses
(txt_verified/attested domains) only, or third parties under `--breach-scope all` + `--purpose` as
analyst-typed seeds (context, <= MEDIUM, tags `context_only` + `third_party`); every correlation about
an identity carries `privacy`; same breach across sources counts once (normalised name and
independent families); fabricated and spam-list breaches never count; every string passes
`sanitize.scrub_text`; recommendations carry `LGPD_NOTICE` and 'credentials are never tested'.
The suggested verdict of CR10 is computed over the breaches that counted (fabricated listings are
named under 'Not counted' and never turn it into 'false positive'; spam-list and compilation
listings of the identity still weigh as alert/doubt); CR12 uses `domain_after_breach_against` and
`is_fabricated_against` over every listing. Rules never write tags on graph nodes: the
`own_asset` / `verified_fi` labels of suppressed own lookalikes come from the engine ownership pass
(WP08) and the P360 module; the typosquat rules only stay silent for them.

### Web hygiene facts (P084)

Rules consume only facts of LIGHT/ACTIVE modules that already ran under the policy gate and never
trigger contact. Facts are recorded on the url/domain/ip entity they describe:

| attribute | producer | shape |
|---|---|---|
| `tls_certificate` | tls_inspect (LIGHT) | `{subject, issuer, not_before, not_after, self_signed, hostname_match, key_type ('rsa'\|'ec'...), key_bits, signature_hash, chain_verified, sha256}` (the core `cert_not_after` / `cert_issuer` are NOT read: CT and scan-database dates are not a live handshake) |
| `tls_protocols` | tls_protocol_scan (ACTIVE) | `{'SSLv3'\|'TLSv1'\|'TLSv1.1'\|'TLSv1.2'\|'TLSv1.3': 'accepted'\|'refused'\|'could_not_test'}` |
| `tls_weak_ciphers` | tls_protocol_scan (ACTIVE) | list of accepted weak suite names |
| `hsts` | security_headers (LIGHT data) | `{present, max_age, include_subdomains, preload}` (core `security_headers_missing` also read) |
| `login_form` | page fetch (LIGHT) | bool |
| `cookie_flags` | security_headers (LIGHT data) | `[{name, secure, httponly, samesite, session_like}]` - names and flags, never values |
| `cors_results` | **cors_probe (ACTIVE) only** | `[{endpoint, origin_kind, acao_reflected, acac, user_data, acao}]`; CR20 needs module `cors_probe`, `--mode active`, an authorization and a scope match |
| `cors_acao` | LIGHT fetch | observed ACAO: context only, never CR20 |
| `sensitive_files` | sensitive_files (ACTIVE) | `[{path, status, size, signature, sha256}]`; an entry without `signature` is ignored (never the status alone) |
| `cloud_buckets` | cloud_buckets (ACTIVE) / passive references | `[{bucket, provider, state, attribution, evidence}]`; `attribution` `permutation` (or missing) = unattributed |

CR21 reads findings tagged `credential_exposure` with the `secret_scanner` data shape (`rule`,
`kind`, `masked`, `locations [{path, line}]`, optional `entropy`) on url/domain entities or with
http(s) locations; generic/`weak_signal` matches never count. `masked` is either the secret_scanner /
archive_mining form `{rule, kind, display, sha256, length}` or the core `sanitize.mask_secret` form
`{type, preview, sha256}`; the preview (`preview` or `display`) is printed only when it is really masked
(at most 8 characters, a mask mark, at most 8 characters, or a bracketed '[redacted]'), else '****'.
Passwords (`kind` 'password') keep no digest by design and are reported by type and location only;
any other match without `sha256` is skipped. CR22 reads
`jwt_header` (`alg`, `kid`, `typ`, `jku`, `x5u`, `jwk`) and `jwt_claims` (`iss`, `aud`, `exp`, `iat`,
`nbf`). TLS interception: `rctx.meta['tls_interception']` (truthy; a string or `{issuer}`) or the core
`intercepted_by` attribute make CR17-CR19 INFO 'inconclusive'.

Scoping (`asset_scoping`): hostile hosts (tags malicious/phishing/c2/malware/botnet on the node, its
host or registrable domain) -> every rule INFO `context_only`; verified own assets (txt_verified/attested
org-profile entries; CIDR/ASN entries and an engine `own_asset` tag the profile does not contradict),
in-scope targets (`options.scope`) and explicit web assessments (an analyst-typed seed scanned with
`--mode light|active`; a seed listed in `options.unconfirmed_seeds` is not analyst-typed) keep the severity (`Scoping.kind` 'own_asset' | 'in_scope' | 'assessment');
unverified profile entries ('own_unverified', still labelled `own_asset`) and other third parties ->
CR17-CR20/CR22 INFO context, CR21/CR23/CR24 at most MEDIUM. Everything outside the org profile is tagged `third_party` with the
recommendation 'notify the owner through a manual, approved disclosure process' (explicit
assessments of a third-party seed included); only in-scope targets of an authorized engagement get the
fix text before it.
