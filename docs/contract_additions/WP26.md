# Contract additions - WP26 (wave 5)

Watch mode (P030, A14): `v3lum watch` runs in the foreground only and has no daemon. It also offers
`--once` (for cron/systemd timers), `--max-runtime`, `--max-alerts` and `--tlp`. The command has
these subcommands: `watch rules | mute | unmute | alerts | vote | status`.

The watch-source invocation was announced in the guide's "Arriving later" table
(`v3lum.core.watch.Watcher`). It lands here.

WP26 does not rename or change any frozen name. The reserved tags `watch_source` and `watch_only` and
the attribute `watch_hits` keep their documented meaning. Policy rule POL-01 (`watch_only` modules run
only when `PolicyContext.path == 'watch'`) is unchanged; this package is the first caller that uses
that path.

**Who needs this:**

* **Authors of watch-source modules** (tag `watch_source`). Examples are CT deltas for org domains
  (crt.sh / Cert Spotter), NRD feeds, and P357's Telegram channel watch. Read
  "The watch-source invocation" below. Your module runs as a normal PASSIVE module run, once per
  polling cycle, on each rule entity it accepts. It reports candidate names in `watch_hits`. The
  watcher alone does matching, first_seen diffing, mutes, alerts and retention. A source keeps no
  alert state of its own, except for its own cursors in `ctx.state`.
* **WP25** (doctor v2) shows CertStream reachability and polling-source status from
  `v3lum.core.watch.health` (see open issues).
* **WP29** adds the `watch` extra to pyproject (websocket-client) and the BACKLOG line for direct
  RFC 6962 / static-ct-api polling.
* **WP19/WP20/WP21**: the day's watch case (`watch-YYYYMMDD`, `kind: 'watch'`) is a normal stored
  case. It has one correlation per alert and one `domain` entity node per alerted registrable domain.
  It has no graph edges, findings or modules.

## The watch-source invocation (for module authors)

1. **Selection.** `Watcher.watch_sources` returns every registered module tagged `watch_source`
   (restricted by `v3lum watch --sources`). A LIGHT/ACTIVE watch source is never run: the source
   status is `skipped` with reason_code `opsec`. Watch sources are treated as explicitly selected
   (`-M`) by the analyst who started `v3lum watch`, so `default_enabled=False` does not keep them out.
   Every other gate still applies: licence, TLP, tier, keys, quota, datasets, offline and circuit.
   A watch source over a ransomware victim feed (`VICTIM_FEED_KEYS`) is selected only when it declares
   the ransomware.live PRO key in `requires_keys` (else skipped, reason_code `policy`, P030 cond 9).
   Modules tagged `watch_only` are selected only here (POL-01). Tag them `watch_source` too, or
   watch never invokes them.
2. **Entities.** The polling entities are the org profile's own registrable domains (`domain`) and
   its brand keywords (`keyword`, original spelling). No other entity type is used: no persons,
   addresses or suppliers. **A `keyword` entity is handed only to modules with disclosure `none` or
   `internal`.** Third-party sources never receive a brand keyword or a permutation (A14: keywords
   never leave the machine). Their skipped runs are counted in `WatchReport.keywords_kept_local`.
   Accept `domain` if your source queries a third party.
3. **The run.** For every (source, accepted entity), the watcher calls
   `policy.decide(cls, entity, policy.make_context(runtime, options, explicit=<sources>, path='watch'),
   run=RunInfo(entity, is_seed=True, depth=0, tlp=<watch TLP>, case_id='watch-YYYYMMDD'))`. When the
   decision allows it, the watcher calls `Engine.run_module(cls, entity, run=run, decision=decision)`.
   This gives the normal status mapping, sanitizer and redaction. `ScanOptions` are mode PASSIVE,
   depth 0, `save_evidence=False`, the watch TLP and the purpose
   `'v3lum watch: org-profile brand and domain monitoring (P030)'`. `runtime.in_scan` is True during
   the cycle, so large datasets are not downloaded (AR10). The cycle runs once per `watch_interval`.
   Throttle yourself with `ctx.state` if your provider needs a longer interval.
4. **Output.** Report candidates in the attribute `watch_hits`: a list of
   `{name, registrable_domain, serial, cert_sha256, issuer, not_before, source}`. Optionally add
   `rule_id`, which is used when it names a watch rule (`v3lum watch rules`) that applies to the hit's
   IOC type (a host name needs a domain-type rule; a post URL may also name a `cnpj_root`/`card_bin`
   rule). At most 1000 hits per run are read. `name` is a host name with a real (alphabetic or IDN)
   TLD, an http(s) URL or (domain-wide own-address rule only) an e-mail address at a verified own
   domain. **Anything else is dropped and never stored** (counted in `WatchReport.rejected`):
   third-party e-mail addresses, phone numbers, CPF/CNPJ-like digits, bare IP addresses, free text and
   other URL schemes. User info (credentials) of a URL is removed before anything is recorded, and
   the host's own registrable domain wins over a reported `registrable_domain`. Report certificate or
   listing metadata only, never page bodies or leaked content. A status other than ok/empty is
   recorded as 'could not verify' for the cycle, never as 'nothing new': per source, a run that could
   not verify on one entity wins over ok/empty on another (reason '... (N of M entity runs could not
   verify)'), and a run in which no polling source answered ends with the note 'no polling source
   answered in this run: could not verify'.
5. **Conditional sources (P030 cond 9).** A ransomware-victim watch source must declare the
   ransomware.live PRO key in `requires_keys`, so POL-12 makes it NEEDS_KEY without that key. It may
   report victim metadata only: leaked files are never downloaded or opened (rule 3). Telegram
   public-channel watch exists only as P357 delivers it (`telegram_channel_watch`, tags
   `watch_only` + `watch_source`).
6. **What the watcher does with hits.** Hits are matched locally with the rules (IDNA->Unicode, accent
   folding, homoglyph folding, permutations). A hit that matches no rule is attributed to the rule of
   the entity it came from (reason `reported by <module>:<source>`). Such a hit is keyed by its
   `registrable_domain` (or by its URL when the name is a URL, so post URLs are not collapsed). Own
   and supplier domains never alert. Next comes the dedupe on (key, serial) through an LRU, then the
   mutes (a domain mute also covers URLs on that domain and addresses at it), then first_seen. An alert fires only for a key never seen for that rule (`watch_first_seen`).
   A new serial of a known key is recorded as state, not as an alert. Each alert produces: one
   terminal line (defanged), a JSONL record (0600), an `alerts` row, and a correlation in the day's
   watch case. Alerted registrable domains go to capped passive enrichment: a normal PASSIVE scan
   through the policy gate at depth 0, with `watch_source`/`watch_only` modules excluded, at most
   `watch_enrich_per_hour` per rolling hour across runs. The rest are listed for the analyst. URLs and
   addresses are never enriched. Watch never makes automatic LIGHT/ACTIVE contact.

## Rules (`rules_from_profile`)

| kind | id | from | applies to |
|---|---|---|---|
| `domain` | `domain:<registrable>` | `domains[]` (label as a term, typosquat permutations of the domain, cross-TLD label permutations for labels of 5+ characters) | domain, url |
| `brand` | `brand:<slug>` | `brands[]` keyword + variants (folded; label permutations for 5+ characters) | domain, url |
| `supplier` | `supplier:<slug>` | `suppliers[]` brands, domains (labels and permutations) | domain, url |
| `own_addresses` | `own_addresses:<registrable>` | txt_verified/attested `domains[]` only (domain-wide; infostealer exposure) | email |
| `cnpj_root` | `cnpj_root:<root>` | `cnpj_roots[]` | cnpj |
| `card_bin` | `card_bin:<bin>` | `card_bins[]` | card_bin |

Executives never produce a rule. A brand or supplier term is dropped, with a note in `problems`, when
it is any of: an opted-in executive's name, an e-mail address, a phone number, an @handle, or shorter
than 3 characters. Terms shorter than 4 characters match only as a whole token. The executive-name
check also compares compact forms ('joanaexemplo', 'joana-exemplo'; full names of 8+ letters): an own
or supplier domain whose label is an executive's name stays protected (never alerted) and polled, but
yields no keyword and no permutation.

## CertStream (optional extra `v3lum[watch]`)

`certstream_endpoint` uses setting `certstream_url` first: a self-hosted certstream-server-go, which
has the same message format. Its disclosure is `internal` (allowed up to TLP:RED) when the host is in
the organisation's network: a private/loopback address, an internal-only name, or an own domain or
network. Any other configured host is third_party with tier `unknown`. With no URL configured, the
public `wss://certstream.calidog.io/` is used: provider `certstream`, tier community, terms open,
allowed up to TLP:AMBER. The watch TLP must not exceed the endpoint's ceiling; otherwise the consumer
is unavailable. Only `ws://`/`wss://` URLs are accepted, and `ws://` (no TLS) only for internal hosts.

Without the extra, the consumer is reported `unavailable` and polling still runs. This is never an
error. With `--once`, the consumer is not started. The consumer sends nothing. Its bounds are
`MESSAGE_MAX_BYTES`, `NAMES_PER_CERT`, `QUEUE_MAX_ITEMS`, `QUEUE_MAX_BYTES`, `LRU_SIZE`, exponential
backoff with jitter from `BACKOFF_BASE` to `BACKOFF_CAP` (reset after `HEALTHY_AFTER` s up), and at
most `MAX_RECONNECTS_PER_WINDOW` connections per `RECONNECT_WINDOW`. A handshake refused with HTTP
403/429/5xx backs off at least `REFUSED_BACKOFF_ATTEMPT` steps (counted in `StreamStats.refused`).
Errors, state and `health` never show the endpoint's user info or query. Direct RFC 6962 /
static-ct-api log polling is not implemented (BACKLOG).

## Retention and TLP

Alerts, JSONL files, first_seen rows and the watch cases follow `retention_days` (A10).
`Watcher.prune` runs at the start of every run and keeps rows linked to held cases. Expired watch
cases are purged through `Store.purge_case`, which leaves a tombstone. Alerts carry the watch TLP
(`--tlp`, default setting `tlp` = AMBER). The watch case's TLP is the highest TLP of its alerts. A
`--tlp` below the configured default is announced on the terminal and recorded (A2) in the audit of
the watch case and of each enrichment case. The 200-terminal-lines-per-hour budget is kept in
`~/.v3lum/watch/state.json`, so it holds across `--once` runs started by a timer in the same hour.

## Tests

`tests/test_watch.py` replays `tests/fixtures/watch/certstream_messages.jsonl` through an injectable
transport with a fake clock. It covers:

* prefilter, bounded queue (items, bytes, message size), LRU dedupe, backoff with jitter, reconnect
  rate cap and healthy reset;
* first_seen across runs, the 200/hour summary line, mutes, max_alerts;
* the enrichment cap (30/hour across `--once` runs), and that the default enrichment is PASSIVE only
  (LIGHT/ACTIVE never run, LIGHT watch sources skipped);
* rules never built from a natural person, watch sources and `watch_only` selection, keywords never
  in outbound requests, prune with legal hold;
* endpoint/TLP gating, the websocket transport (TLS verification, nothing sent), health, votes ->
  precision, the watch case rendering;
* the CLI acceptance: `v3lum watch --once` runs one cycle and exits 0, and reports
  "certstream: unavailable" without the extra;
* review additions: hits that are no host name / URL / own address (third-party e-mails, phones,
  CPF-like digits, IPs) dropped and never stored; URL credentials stripped and domain mutes on URLs;
  executive names in domain labels; a per-entity failure never reported ok; the hourly line budget
  across `--once` runs; refused handshakes (429) backing off long without leaking the endpoint's
  secret; `health` display URL; ransomware victim feeds only with the PRO key; the lowered-TLP audit
  row and CLI notice.
