## What LIGHT/ACTIVE module authors can rely on (enforced by the suite at every merge)

* **Scope and seeds (a).** ACTIVE runs need `--authorized REF` and a valid scope file bound to it
  (window open, limits within the A7 ceilings, the target listed); pivots never inherit scope: an
  out-of-scope, excluded, CDN-fronted (without `shared_infra_hosts`), private or metadata target -
  as a pivot, a resolved address, a redirect hop or a URL the module builds itself - gets zero
  requests. LIGHT runs only on analyst-typed, confirmed seeds; its first hop is the seed (or a
  subdomain); redirect hops are re-checked (SSRF guard, hostile-host guard) on every hop.
* **Hosts (b).** PASSIVE modules reach only their declared hosts (redirects included): anything
  else ends SKIPPED `policy` with the host named and a `policy_violation` row in the case audit
  (WP15 `AuditHook`); disclosure `none` modules get no network at all (`ctx.http`, public DoH,
  `ctx.net`, `ctx.net.run_tool`).
* **Egress (c).** A configured `proxy_light`/`proxy_active` that is down or unusable refuses the
  request (SKIPPED `policy`); nothing - not even a DoH lookup of the target - leaves on the default
  route; profile sessions ignore environment proxies, `NO_PROXY` and `~/.netrc`; target names are
  resolved through the profile, never by a local `getaddrinfo`; HTTP and raw sockets (`ctx.net`)
  of LIGHT/ACTIVE modules go through the profile proxy; third-party API calls stay on the default
  route. A URL carrying a probable per-recipient token is never fetched as a seed or a redirect hop
  without `--confirm-url`. Target contact never carries the V3LUM or contact User-Agent, a `From`
  header or the contact mailbox (LIGHT uses `ua_light`; ACTIVE the scope's ROE UA/header when set).
* **Kill switch (d).** Ctrl+C, the scan deadline and the end of the scope window stop a request or
  probe loop after at most the request in flight, and release a run blocked on a stalled target or
  an open probe socket within 2 s. Modules: make every target contact through `ctx.http` / `ctx.net`
  (each call checks the kill switch), let `Cancelled`/`DeadlineExceeded` propagate, never block in
  your own sleeps, threads or sockets.
* **Forbidden actions.** Credential headers (`Authorization`, `Cookie`, `X-Api-Key`,
  `Proxy-Authorization`...) toward a target are refused; URL userinfo (`https://admin:admin@host/`)
  never reaches the target as credentials. Do not build login checks: they fail the run.
* **Methods and ceilings (f).** LIGHT sends GET/HEAD, ACTIVE GET/HEAD/OPTIONS; anything else needs
  an approved `v3lum/data/policy/method_allowlist/<module>.json` (`approved_by` + `decision_ref`;
  PUT/PATCH/DELETE/TRACE/CONNECT... never). ACTIVE <= 10 req/s and LIGHT <= 1 req/s per target host
  whatever `max_rate`/`min_interval` say (registration refuses a higher `max_rate`); <= 2 concurrent
  connections per host; LIGHT <= 25 requests per target host per scan (shared by all LIGHT modules
  of the scan, charged atomically across worker threads); the ACTIVE case budget; <= 1000 TCP
  ports per host; the global connection-attempt rate (scope `max_pps`); wordlists <= 5000 entries.
  A passed ceiling ends the run partial (`stop_reason` `request_cap`). Note for port-scan modules: 1000
  probes at 10/s take 100 s - declare `timeout` accordingly (the analyst raises the scan deadline),
  otherwise the run deadline stops the scan early.
* **Tools (j).** `ctx.net.run_tool` never launches against an out-of-scope, CDN, private or pivot
  target, or when an argument names a host outside `targets=`; the ToolSpec forced flags, the
  rate clamp and the egress proxy (`proxy_flag`) come first and cannot be overridden; a tool without
  a `proxy_flag` never runs while the module's contact profile has a proxy (fail closed); the tool
  process gets no proxy variables or `NETRC` from the environment; every launch is an EXEC record of
  the run's request ledger; the kill switch and the run deadline kill the process group within 2 s.

## Known gaps (strict xfails until fixed - never rely on them; reviewers refuse modules that do)

| gap | owner | test (xfail, strict) |
|---|---|---|
| an unregistered ad-hoc `ctx.data.fetch(name, url)` downloads from any host on the default route, also from a disclosure-`none` module and outside an ACTIVE scope (with the V3LUM UA) | WP04 (`datasets.py`) + WP08 (`context.py`) | `test_policy_hosts.py::test_a_disclosure_none_module_cannot_download_ad_hoc_data`, `test_scope.py::test_an_active_module_cannot_reach_out_of_scope_through_ad_hoc_data` |
| the P327 lint does not flag `ctx.http.client`, `ctx.http._client`, `ctx.runtime.http` (and the other network members of `ctx.runtime`), `ScopedHttp(...)` or private `ctx.net` members in module files (each reaches the shared client without host, scope or egress checks) | WP09 (`lint.py`) | `test_policy_hosts.py::test_the_lint_refuses_reaching_around_ctx_http[*]` |
| the per-recipient-token guard (GUARD-02) runs for the seed and for redirect hops only: a token URL a LIGHT/ACTIVE module builds itself (a crawled link) is sent | WP11 (`http.py`, `_Contact.hop`) | `test_egress.py::test_a_module_never_fetches_a_recipient_token_url_it_found_itself[*]` |
| requests queued for a per-host connection slot are sent after the kill switch fired (no cancel re-check after the slot is obtained) | WP11 (`http.py`, `HttpClient._send`; same race in `net.py` `Connector.connect`) | `test_cancel.py::test_requests_queued_for_a_connection_slot_never_leave_after_the_kill_switch` |
| headers other than `User-Agent`/`From`/contact-mailbox values may still name V3LUM or the organisation's own domains toward a target | WP11 (`http.py`, `HttpClient._headers`) | `test_egress.py::test_target_contact_never_names_the_tool_or_the_organisation_in_any_header[*]` |
| a stop by an A7 ceiling (LIGHT 25/host, ACTIVE case budget, port ceiling) is reported as "request cap reached (<max_requests> per entity)", hiding which ceiling stopped the run | WP08 (`engine.py`) | `test_methods.py::test_a_ceiling_stop_names_the_ceiling` |

Until they are fixed: register every dataset (`register_dataset`) and fetch it by name; reach the
network only through `ctx.http`, `ctx.dns` and `ctx.net`; never fetch a URL a target page links to
when it carries a long opaque token or an e-mail address (it may be a per-recipient lure); never set
identifying headers; read `stop_reason`, not the reason text, to tell a ceiling stop.

When the lint fix lands it stays narrow: non-network reads such as `ctx.runtime.meta` remain allowed, and an out-of-band dataset-refresh
helper that builds its own `ScopedHttp` (refused inside a scan, explicit `allowed_hosts`) keeps
passing only with a reviewed `# v3lum-lint: allow LINT-01 -- <why>` pragma on that line.
