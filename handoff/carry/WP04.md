- (wave 3 WP28 implementer) WP04 (v3lum/core/datasets.py) + WP08 (v3lum/core/context.py). Bug (A7, P327 cond 5): an unregistered ad-hoc ctx.data.fetch(name, url) bypasses the module's host, disclosure, scope and egress binding. DataStore._dataset_http() builds its own ScopedHttp with allowed_hosts = {url host}, disclosure='third_party' and no scope or egress profile. So a disclosure-'none' module, or an ACTIVE module outside its scope, can send the investigated value to any host on the default route. Exact fix, keeping the documented v1 fetch(name, url) call (contract freeze): (1) datasets.py: change `DataStore.scoped(self)` to `scoped(self, *, http=None)`, then `DataView.__init__(self, store, http=None)` stores self._http. DataView.fetch/fetch_text/fetch_json/fetch_lines pass `http=self._http` to the store only when `url is not None and name not in DATASETS`. Add a keyword `http=None` to DataStore.fetch (and the fetch_text/json/lines wrappers) and forward it to `_download(..., http=http)`. In _download use `http = http if http is not None else self._dataset_http(reg, url)`. Registered datasets keep the reviewed datasets scope. (2) context.py line ~536: `self.data = runtime.data.scoped(http=self.http)`. The module's ScopedHttp then refuses ad-hoc URLs exactly like ctx.http: PolicyError (SKIPPED 'policy') for undeclared hosts and for disclosure 'none', the scope binding for ACTIVE, and the egress profile. Then drop the strict xfail on tests/safety/test_policy_hosts.py::test_a_disclosure_none_module_cannot_download_ad_hoc_data and tests/safety/test_scope.py::test_an_active_module_cannot_reach_out_of_scope_through_ad_hoc_data (WP28 part B drops them if WP04/WP08 have not).
