### Fixture conventions (same as the other prep batches)

- Envelope fixtures: `{"_envelope": 1, "_source"|"_synthetic": ..., "status", "headers",
  "body"}`; `load()` in the tests returns `(status, headers, body)` and `body_bytes()` turns the
  body into the bytes a FakeHttp response would carry. Other `.json` fixtures are plain bodies
  with a `_source`/`_synthetic` key; parsers ignore unknown keys.
- `.txt` fixtures are raw bodies; the synthetic ones start with a `#` comment line saying so.
- `.jpg`/`.png` are synthetic images generated by `make_ela_fixtures.py`.

### Marker convention

Helpers return `None` (usable answer) or `'<kind>: <reason>'`; `marker_kind()` extracts the kind,
`marker_status()` maps it to the V3LUM Status and canonical reason_code (A3):

| kind | Status | reason_code |
|---|---|---|
| absent | EMPTY with the module's own wording (never 'unknown BIN' / 'does not exist') | - |
| error | ERROR | error |
| rate_limited | RATE_LIMITED | rate_limited |
| quota | QUOTA | quota |
| needs_key | NEEDS_KEY | needs_key |
| blocked: challenge ... | BLOCKED | challenge (circuit for the run, A9) |
| blocked: (plain 403 policy page) | BLOCKED | core default for 403 (P321) |
| skipped: config / privacy / policy / not_applicable / not_default | SKIPPED | that code |

## geocoding (P262) - Nominatim (OSMF) + Photon (komoot)

**Sources and exact requests** (hosts for the registry: `nominatim.openstreetmap.org`,
`photon.komoot.io`; Overpass and geocode.xyz are dropped by FC2: no host, no parser, no fixture)

- Nominatim forward, structured attempts in this order (FC3), built by
  `build_nominatim_search_attempts(parse_br_address(text))`, stop at the first place found,
  stop the chain on any marker other than `absent`:
  1. street: `GET /search?countrycodes=br&format=jsonv2&addressdetails=1&limit=1&street=<number> <street>&city=<city>&state=<UF>&postalcode=<CEP>`
  2. postcode: `GET /search?countrycodes=br&format=jsonv2&addressdetails=1&limit=1&postalcode=<CEP>`
  3. city: `GET /search?countrycodes=br&format=jsonv2&addressdetails=1&limit=1&city=<city>&state=<UF>`
- Nominatim reverse: `GET /reverse?lat=<lat 6dp>&lon=<lon 6dp>&format=jsonv2&zoom=18&addressdetails=1`
  (`build_nominatim_reverse_params`; invalid and 0,0 coordinates raise and are never sent).
- Photon fallback: `GET https://photon.komoot.io/api/?q=<photon_query_from_address()>&limit=5&lang=en`
  and `GET https://photon.komoot.io/reverse?lat=&lon=&limit=1&lang=en`. Photon geometry is
  `[lon, lat]`: `parse_photon` swaps it; it also de-duplicates features of one OSM object (the
  same node comes once per tag, e.g. office + shop). Photon search is global: filter with
  `keep_country(places, "BR")` for Brazilian seeds.
- Auth: none, no key env var. Nominatim needs the `contact_email` role mailbox in the UA on OSM
  hosts only: `nominatim_user_agent(base_ua, contact_email)` -> `'<UA> (contact: <mailbox>)'`;
  without it `nominatim_config_marker()` gives SKIPPED `config` for Nominatim and Photon runs.

**Observed live behaviour (datacenter egress, generic UA without contact e-mail)**

| request | status | latency | notes |
|---|---|---|---|
| Nominatim /search street, postcode, city | 629 x3 | 0.06-0.26 s | Varnish synthetic page `629 Unknown Error`, `Retry-After: 0`, `server: Varnish` (CDN edge) |
| Nominatim /reverse Marco Zero | 200 | 0.57 s | `server: gunicorn/asgi`, `x-cache: MISS`; full jsonv2 with address |
| Nominatim /reverse 0,0 | 629 | 0.12 s | same edge refusal |
| Photon /api (3 queries) | 200 | 0.52-0.67 s | `cache-control: max-age=3600`, no rate-limit headers; random token -> `{"features": []}` |
| Photon /reverse Marco Zero | 200 | 0.52 s | one feature |
| Photon /reverse lat=999 | 400 | 0.53 s | `{"lat":[{"message":"Invalid value for 'lat' parameter.", ...}]}` |

The origin's own block pages (from the OSMF ops repository, nginx `error_page`): 403/418 ->
`Access blocked` page; 429/503 -> `Bandwidth limit exceeded` page. Research (2026-11-25) saw
`403 'Access denied'` for one custom UA and 200 for `V3LUM/0.1 (https://...)`.

**Recommended metadata**: Nominatim provider bucket 1 req/s per installation (FC1; a P334
provider bucket shared by every module, not per module), Photon min_interval 1 s (fair use, no
bulk); cache_ttl 30 days for both, negative answers included (FC1); no published daily quota -
set a soft daily_quota (e.g. 500/day Nominatim) so a batch can never become bulk geocoding;
max_requests 4 per entity (3 Nominatim attempts + 1 Photon); expected_latency 0.6 s (p50 seen
0.5-0.7 s); timeout 10 s.

**Pivots and attributes**: forward -> pivot `coordinates` `lat,lon` (6 dp) with `expand=False`
(FC5 never auto-expanded) and pivot `cep` (expand=False) from the place postcode; reverse ->
pivot `cep` only. Attributes from `geocode_record`: `label` 'approximate place (OSM)',
`precision` (street / postcode / city, plus `region` for state-level hits), `disclaimer` 'an
address is not proof of residence', `attribution` '(c) OpenStreetMap contributors (ODbL 1.0)',
`provider`, `display_name`, `osm_url`, `address{road, house_number, suburb, city, state,
state_code, postcode, country, country_code}`, `direction`.

**Final conditions -> code**

1. UA + contact on OSM hosts: `nominatim_user_agent` / `nominatim_config_marker` (SKIPPED
   `config`); 1 req/s bucket, 30-day cache: registry HTTP profile + quota block (core);
   403 -> BLOCKED: `nominatim_marker` (also catches the 'Access blocked' title on any status and
   'Access denied' on non-200).
2. Photon only fallback: `build_photon_*`, `parse_photon`, `photon_marker`. Fall back when
   Nominatim is SKIPPED config, BLOCKED, RATE_LIMITED or ERROR; also when every structured
   attempt is `absent` (one Photon query). Tiers: Nominatim (OSMF) trusted, Photon (komoot)
   community.
3. Inputs coordinates + cep; keyword only as `address:`/`endereco:` TYPE:value
   (`address_from_keyword`); no text_blob. `normalize_coordinates` (decimal, DMS with N/S/E/W/L/O,
   pairs, dicts), `normalize_cep`, fallback chain above.
4. `reverse_geocode_gate(origin, analyst_confirmed)`: only `seed` runs by default; EXIF /
   device / pivot / text origins need the per-entity confirmation (SKIPPED `privacy` otherwise).
   `forward_geocode_gate`: typed address/CEP seeds run; company records (CNPJ/CEP) only on
   explicit request (SKIPPED `not_default` otherwise).
5. PERSONAL_TYPES gate (personal_data_review, reason_code `privacy`) is core policy; the module
   only keeps pivots `expand=False`.
6. `geocode_record` (label, precision, disclaimer, attribution) and `place_export_allowed`
   (reverse results and typed-address results stay out of STIX/MISP unless the analyst opts in).
   Map links: P260, not this module (`osm_url` is evidence).
7. Fixtures for FakeHttp: Nominatim search/reverse 200, empty, not found, 403, 509, 629;
   Photon search/CEP/reverse 200, empty, 400. Registry entries: the two hosts above.

## image_ela (P264) - Error Level Analysis (offline, Pillow)

- No network, no host, disclosure `none`, terms `open`, tier `n/a`, allowed at TLP:RED,
  default_enabled=False. Pillow is an optional extra: without it UNAVAILABLE reason `package`.
- **Sandbox child** (`code/ela_child_reference.py`, port into the core/sandbox.py child,
  `python3 -I`, rlimits, no writes): read <= 100 MB; `sniff_image_format` -> anything but JPEG
  returns `{"skipped": "not_jpeg", "format_sniffed": fmt}`; `ela_input_check` refuses > 40 MP
  before decoding (`Image.MAX_IMAGE_PIXELS` also set); re-save at q90 in memory; per-pixel
  error = max over R,G,B of `ImageChops.difference`; emit `histogram` (256 bins), `tile_means`
  (8x8), `width`, `height`, `grid`, `quality_resave`, `jpeg_quality_estimate` (from the DQT via
  `jpeg_info` + `jpeg_estimate_quality`) and `ela_png_b64` (contrast-stretched, <= 1024 px wide).
- **Parent**: `normalize_ela_child_output(obj)` validates the child JSON (never trusts it) and
  returns `attributes` (ela_mean, ela_max, ela_std, ela_p99, ela_frac_ge_16, ela_region_ratio =
  hottest tile / median tile, ela_hot_regions (3 boxes as image fractions), image size,
  jpeg_quality_estimate, ela_resave_quality, ela_heuristic=True), `png_data_uri` (data: URI only
  when the PNG is <= 700 KB, so the JSON stays under the 1 MB output cap), `severity` 'info',
  `score_delta` 0, `wording` 'Error level analysis: heuristic, not proof of tampering',
  `terminal_line` 'ELA map in the HTML report (heuristic, not proof)', or `skip` / `errors`.
- **Final conditions -> code**: FC1 metadata; FC2 child + caps (`ela_input_check`, input cap,
  PNG cap); FC3 `ela_applicability` ('ELA not meaningful for lossless images' for PNG/GIF/BMP/
  TIFF/lossless WebP, SKIPPED `not_applicable`); FC4 q90 + difference + numeric metrics + data:
  PNG; FC5 no tamper key, severity info, score 0, terminal line constant; FC6 synthetic
  original/edited JPEG + PNG (`make_ela_fixtures.py`; `test_reference_child_synthetic_images_generated_in_test`
  shows generating them inside the test as FC6 asks).
- **Measured on the fixtures** (q90 'camera' image saved twice vs a pasted block saved once):
  original mean 0.78 / max 11 / region_ratio 3.09; edited mean 0.93 / max 35 / region_ratio
  8.19 with the hottest tile inside the pasted box. Source quality estimated exactly (90).
- Pivots: none. Attributes only. The ELA PNG goes to the case directory and the HTML report as
  a data: image; never print a number described as 'tamper' anywhere.
- Warning: ELA is weakest when the source quality is far below 90 or the image was
  recompressed by a messaging app; show `jpeg_quality_estimate` next to the map.

## document_identity_signals (P273) - name windows + nearest CPF (Ceos port, offline)

- No network, disclosure `none`, terms `open`, tier `n/a`, TLP:RED allowed, default_enabled=False.
- Input text comes from P269/P363 through the P172 engine (no own PDF parsing); the person
  seed is typed by the analyst; a typed `cpf` is only searched inside the case documents.
- `identity_signals(text, person_name, cpf=None, city=None, uf=None)` returns `name_found`,
  `occurrences`, `windows[]` (start, end, CPF-masked excerpt <= 200 chars, nearest masked CPF,
  kind full/masked, side, distance, ambiguous, city_near, uf_near), `nearest_cpf_masked`,
  `typed_cpf {masked, found_in_document, next_to_name}`, `signals`, `confidence`
  (strong/medium/weak/none), `criterion`, `alert`, `layout`, `privacy: True`,
  `cross_case_index: False`, `export: False`.
- **Nearest-CPF rule** (FC3): `document_layout()` decides per document. `lines` (>= 3 lines with
  exactly one CPF plus >= 2 words, >= 60 % of CPF lines: CSV/';'/'|' tables, PDF table text): a
  CPF on another line never attaches, even when the subject's own line has none. `prose`
  (gazette paragraphs, contracts, forms with 'CPF:' on its own line): records end at ';', '|',
  bullets and blank lines; then a 'CPF' label after the name, then no line break, then distance,
  then 'after' decide. Neighbour CPFs therefore never attach (tests cover DOU-style paragraph,
  CSV table with a missing CPF, a far CPF, masked lists and a form).
- City near the name = strong (+2); UF only = weak (+1) (FC3). Typed CPF next to the name +4;
  a different full CPF next to the name -> `alert` (possible homonym), confidence weak.
- **FC4**: output carries masked CPFs only (`***.XXX.XXX-**`, AR24); full digits exist only in
  memory for the exact comparison with the typed CPF; masked CPFs are never compared with the
  typed CPF's digits (no fragment join, P236 floor): signal `masked_cpf_next_to_name` and the
  analyst reads the pair. No CPF entity, no pivot.
- **FC5**: never write name-CPF pairs to the P375 sightings index (not even HMAC) or STIX/MISP;
  privacy tag; A10 retention. The result flags `cross_case_index`/`export` are False for the
  renderer/exporter to honour.
- **FC6**: synthetic fixtures (placeholder names, CPFs 000.000.00N-DV with valid check digits):
  gazette paragraph, gazette table, no CPF nearby, masked list, contract form. Every test
  asserts no full CPF in `json.dumps(result)`; the implementer still needs the masked-output
  assertion in every renderer (terminal, HTML, MD, JSON).
- `cpf_valid` mirrors P232 for tests only - use the core validator in the module.

## user_agent_analysis (P317) - own UA table + teler bad-crawlers

- **Dataset** (AR10 dataset manager, runtime download, never bundled):
  `https://raw.githubusercontent.com/kitabisa/teler-resources/master/db/bad-crawlers.txt`;
  licence CC BY 4.0 (LICENSE file confirmed: 'Attribution 4.0 International'), upstream
  Crawler-Detect (MIT). Attribution text: `parsers.TELER_ATTRIBUTION` (THIRD_PARTY_NOTICES and
  reports, FC1). Suggested `register_dataset(name='teler_bad_crawlers', expect='lines',
  min_bytes=10000, max_bytes=1_000_000, ttl=7 days, terms_class='open',
  validate=validate_bad_crawlers(parse_bad_crawlers(...)))`.
- Live: 200 in 0.36 s, 22,272 bytes, sha256 `666c95c4...b9b7873` (2026-11-26), etag present,
  `cache-control: max-age=300`; 1,741 patterns, 0 Python `re` compile errors, 11 lines with
  significant leading/trailing spaces (keep lines verbatim), a missing path gives 404 with the
  text body `404: Not Found` (`teler_dataset_marker`).
- **ReDoS (FC3)**: UA truncated to 1 KB (`truncate_ua`, UTF-8 safe) before matching. Static
  screen `redos_static_flags` rejects nested quantifiers, quantified alternations and
  backreferences without running them (Python `re` cannot be interrupted). The generic
  Crawler-Detect pattern `[a-z0-9\-_]*(bot|crawl|...)` is quadratic (~85-135 ms on 1 KB inputs);
  `normalise_crawler_pattern` drops the redundant leading `[...]*` (same matches with
  `re.search`), bringing the combined 1,741-pattern alternation to ~18-21 ms worst case and
  ~0.8 ms per typical UA. Own-table regexes are bounded by construction and each stays far
  under the 25 ms per-UA test budget.
- **False positives of the list**: no common browser UA matches; WhatsApp link previews and
  `Microsoft Office/... Outlook` do match (Crawler-Detect means 'non-human agent', not 'bad').
  `classify_user_agent` therefore maps a bare list hit to `automation`/tag `bot`, never
  scanner or malicious; link-preview agents are in the own good-bot table.
- **Output** (`classify_user_agent`): `category` browser / bot / automation / scanner /
  benign_scanner / empty / unknown, `tags`, `browser(+version)`, `os(+version)`, `device`,
  `tool`, `bad_crawler_match`, `exploit_probe` (`${jndi:` -> log4shell_jndi), `severity` info or
  low, `risk_ceiling` 'LOW', `never_malicious` True (FC4). Pivots: none.
- FC2: `is_phpids_filter_set` refuses the PHPIDS-derived `common-web-attacks.json` (LGPL-3.0)
  as UA patterns; that file is never bundled and is P340's business.
- FC5 fixtures: trimmed teler list (19 real lines), 404, PHPIDS sample (2 filters), synthetic
  UAs (browsers, bots, scanners, research scanners, Log4Shell probe with a documentation IP, empty,
  a 2 KB ReDoS candidate). `test_full_teler_list_if_present` also checks the full raw list.
- Metadata: no HTTP at scan time (dataset only); expected_latency ~0 s; default_enabled True;
  terms open (teler CC BY 4.0, own table).

## card_bin (P318) - binlist.net

- **Request**: `GET https://lookup.binlist.net/<BIN6>` with header `Accept-Version: 3`, built by
  `binlist_request(bin)` (6 digits by default; 8 only with `digits=8` - 8-digit BINs are a paid
  feature per the home page; raises for anything that is not a 6-8 digit BIN). Auth none.
- **Live**: docs BIN 45717360 -> 200 in 0.70 s (`server: cloudflare`, no rate-limit headers),
  body without `prepaid`, bank url/phone/city; BIN `100000` -> **200 with every field empty**
  `{"number":null,"country":{},"bank":{}}` (0.41 s) -> `absent`; BIN `000000` -> 400 with an empty
  body (0.97 s) -> `error`. Documented: 404 when no card matches, 429 after 5/hour (burst 5).
- **Recommended**: P334 provider bucket 5 requests per hour per IP (hour window), quota status
  in coverage; cache_ttl 30 days (absent answers too); max_requests 1 per entity;
  expected_latency 0.7 s; 429 -> RATE_LIMITED (never 'unknown BIN').
- **PCI (FC1)**: `find_pans` (13-19 digits, single space/dash separators, Luhn, known scheme
  prefix; CNPJ/phones/Luhn-invalid numbers ignored) returns only `bin6`, `bin8`, `last4`,
  `display` (BIN6 + last 4), `scheme_guess`; `mask_pans_in_text` rewrites text; `normalize_card_bin`
  keeps at most 8 digits; `pan_leak_offenders(blob, pans)` is the grep helper for the test over
  cache, evidence, logs and case DB (contiguous, 4-4-4-4 spaced and dashed forms).
- **Output (FC5)**: `parse_binlist` -> scheme, type, brand, prepaid, country (alpha2, name,
  numeric, currency), bank (name, url, phone, city), number length/luhn; centroid and emoji
  dropped. INFO severity. `own_bin_match(bin, org_card_bins)` -> 'own' / 'possible_own' for the
  own_asset tag. Pivots: none.
- **FC2 terms - likely blocker**: binlist.net publishes no terms of service or licence page; the
  home page only says 'Free BIN/IIN Lookup Web Service', the 5/hour limit, and a paid tier ('from
  EUR 0.003 per request + a subscription fee', contact form). Under FC2 the registry must record
  that evidence and, absent business-compatible terms, set class `unknown` -> the module stays
  off (default set and corporate profile) until legal records a decision or a paid plan.
- FC4: `binlist/data ranges.csv` (class unknown) and FreeBINChecker are not part of this build:
  no fixture, no code. A seed miss is never 'unknown BIN'.
- FC6 fixtures: ok, empty-in-200, 400 (live); 404, 429, Cloudflare challenge (synthetic, as
  documented / generic shape); PAN text with public test card numbers.

## imei_check (P319) - imeidb.xyz TAC -> model

- **Request**: `GET https://imeidb.xyz/api/imei/<TAC>000000<Luhn>?format=json` with header
  `X-Api-Key: <token>` (documented alternative to `?token=`; the token never goes in URLs, logs
  or cache keys, AR01). Built by `imeidb_request(imei_tac_probe(imei), token)`, which refuses any
  15-digit value whose serial is not `000000`. Key env var `V3LUM_IMEIDB_TOKEN`.
- **Live**: keyless call with the docs example TAC probe `353893100000000` -> HTTP 401 in
  1.44 s, `{"success":false,"message":"Your request was made with invalid credentials.","code":401}`
  -> `needs_key` (FC2). Documented error table: 401 credentials, 402 out of money (-> quota), 429
  rate limit (per-minute, plan-dependent), 460 invalid IMEI (Luhn) -> error.
- **Output** (`parse_imeidb`): tac, name, brand, model, models, manufacturer, device_type, os,
  os_family, sim_slots, nettech, aliases. Probe-specific fields (query, serial, controlNumber,
  valid, blacklist) and the device image URL are dropped - they describe the synthetic probe.
  Pivots: none. The IMEI itself is masked in reports as TAC + `*******` (`mask_imei`).
- **Recommended**: opt-in only; cache_ttl 30 days keyed by TAC (never by IMEI); max_requests 1;
  expected_latency ~1.5 s; daily_quota per the team's paid balance; health_check should use a
  TAC probe (the documented `/api/balance?token=` puts the token in the URL - only use it if the
  header also works there).
- **Final conditions**: FC1 Luhn/masking stay in core validators (`imei_parse` mirrors them for
  tests); FC2 header token + 401 -> NEEDS_KEY; FC3 only the TAC leaves (`imei_tac_probe`,
  enforced in `imeidb_request`); FC4 A8 unknown tier until recorded community - the module
  receives nothing; FC5 merge gate.
- **Cannot be met yet**: FC5 needs a real success capture with the team's token; the success
  fixture here is the API documentation example re-keyed to the probe (marked synthetic).
  Whether imeidb answers the model from a zero-serial probe (FC3) is therefore unverified: if it
  does not, the online part is dropped. Terms (KNK / 'theknkcorp'): clause (vi) forbids 'any
  robot, spider or other automatic device ... to access ... the Service' and the Service may not
  be 'commercially exploit[ed]' without written permission - legal must confirm that API use
  under the team's plan is allowed before `key-terms` can count as business-compatible.
