# Implementation - binding council rules (apply to every batch)

These policy decisions of V3LUM Council #1 bind every module. Where a proposal's final conditions are
silent, these rules apply; where they conflict, the stricter rule wins.

## A1 (option c (with the corporate default of a))

V3LUM ships licence_profile=corporate as the default and the only profile usable without a recorded legal basis. Every source carries per-source terms evidence in the single provider registry. Under corporate only 'open' sources, and 'key-terms' sources whose plan is recorded as business-compatible, run; 'noncommercial' and 'license' sources run only through a legal-maintained licence_allow entry (or a recorded licence); 'unknown' sources stay disabled until reviewed. The research profile exists only with a recorded legal basis and stamps a licence banner. Coverage lost to the profile is always visible (one terminal line, a report appendix, doctor --licences) and backed by manual pivot links, never by automatic LIGHT/ACTIVE substitutes.

- Module.terms takes exactly one of: 'open' | 'key-terms' | 'noncommercial' | 'license' | 'unknown'. The base-class default changes from 'open' to 'unknown', and @register refuses any module (plugins and P331 specs included) whose class body does not declare terms explicitly.
- Per-source terms live in the provider registry v3lum/data/providers.json (AR11) at providers.<provider_id>.sources.<source_id>.terms = {class, evidence_url, quote, checked_at (ISO date), reviewer, free_plan_business_use: true|false|null}. Member conditions that say data/source_terms.json mean this registry. CI fails when a module, or any feed of an aggregator module, has no entry.
- Module.terms must equal the most restrictive class among the module's registry sources, in the order open < key-terms < license < noncommercial < unknown (CI-checked). In chair files, 'terms' is that class. For aggregators, final_conditions must list the class of each feed and say which feeds are noncommercial/license.
- Setting licence_profile = 'corporate' (default) | 'research'. Under corporate: 'open' runs; 'key-terms' runs only when the provider's free_plan_business_use is true or setting key_plans.<key_name> == 'business' (recorded by `v3lum keys set <name> --plan business` or the wizard); 'noncommercial' and 'license' run only with an active licence_allow entry; 'unknown' never runs.
- Research profile: selectable (config or per run with --licence-profile research) only when licence_allow.json holds a research_basis {legal_ref, approver, date, scope} recording a provider grant or written permission. Otherwise the CLI refuses with 'licence_profile=research needs a recorded legal basis (docs/LEGAL.md)'. Research covers noncommercial/license sources within that scope only; unknown-terms sources stay disabled in every profile.
- Research cases record the profile in case metadata. Every report and export of such a case carries a licence banner listing only the noncommercial/license sources actually used in that run, and research cases are never pushed to MISP/OpenCTI (P303).
- licence_allow is a legal-maintained file (setting licence_allow_path, default ~/.v3lum/licence_allow.json, 0600; may point to a team-shared read-only path). Each entry is {source_id, basis: licence|provider_grant|terms_clause, scope (e.g. 'own-network defence only, no resale'), legal_ref, approver, decided_at, review_by (at most 12 months after decided_at), evidence_url, quote}.
- A licence_allow entry past its review_by date is inactive (fail closed) and doctor warns 30 days ahead. Active entries are shown in `v3lum info <module>` and in the report coverage section.
- Enforcement happens only in core/policy.py (P327) and covers scan, run, shell, extract --scan, batch, watch and doctor health checks. A licence-blocked source gets Status.SKIPPED with reason_code 'licence' and a readable reason ('skipped: noncommercial terms (licence profile corporate)').
- A licence-blocked passive source is never replaced automatically by a LIGHT/ACTIVE alternative (e.g. no port scan instead of InternetDB). Where the provider's web UI allows manual use, the engine emits its manual pivot link (P311) with 'automation skipped: licence'.
- Aggregators filter per source: decide() hands the module ctx.allowed_sources; the module queries and uses only those feeds and reports the others in coverage with reason_code 'licence'. A module whose sources are all blocked is skipped before it runs.
- Visibility: the terminal prints one aggregated line ('N sources skipped: licence profile corporate - v3lum doctor --licences'). The HTML/MD coverage appendix 'Coverage lost under licence profile' lists each source per entity type. `v3lum doctor --licences` (offline, from metadata) prints per-entity-type coverage before/after, the unknown-terms review queue ranked by coverage impact, and the licences to budget.
- `v3lum doctor --licences --refresh` re-fetches every evidence_url last checked more than 30 days ago (meant to run monthly; doctor reminds when a check is overdue). It stores the page hash and date and flags changed pages 'terms changed - review', and never enables or disables a source by itself.
- Initial classes (binding; a chair may only make one stricter): abuse.ch MalwareBazaar, URLhaus and ThreatFox = 'license' (terms 2026-10-21 s.4.1) until a Spamhaus/abuse.ch subscription or written decision is recorded; abuse.ch YARAify, Feodo Tracker and SSLBL = 'open' (CC0, s.3.4); Shodan InternetDB, Shodan CVEDB, VirusTotal public API and Censys free = 'noncommercial'.
- More initial classes: SANS ISC = 'noncommercial' (allow-list candidate under its 'protect your own network' clause, no resale); Google Safe Browsing v4/v5 = 'noncommercial' (Google Web Risk = 'license'); ransomware.live keyless v2 = 'noncommercial' (PRO key = 'key-terms'); XposedOrNot keyless = 'noncommercial' (xonAPI+ = 'key-terms', business plan).
- More initial classes: Team Cymru MHR, Robtex, Malpedia, blocklist.de, CINS, ET, GreenSnow, DataPlane and Phishing Army = 'noncommercial'; OpenSanctions = 'noncommercial' (business licence = 'license'); Hudson Rock free tools, LeakCheck public, Filescan, MalwareIntel, SecurityContext, VirusShare lists, ViriBack and binlist/data = 'unknown'.
- Day-1 legal review queue (doctor --licences prints it ranked by coverage impact): abuse.ch MalwareBazaar/URLhaus/ThreatFox (or a Spamhaus subscription), Shodan InternetDB (or a Shodan licence), SANS ISC, Team Cymru MHR, the FireHOL/blocklist.de/CINS family, ransomware.live PRO terms, and the OpenSanctions business licence. No unknown-terms source may be default-enabled at release.
- Reference module fix in phase 0: shodan_internetdb declares terms='noncommercial' (it currently inherits 'open'), its tests are updated, and App.doctor stops calling internetdb.shodan.io under the corporate profile.
- Terms classes (definitions for every chair file and registry entry): 'open' = free use, internal business use included (public domain, CC0, CC BY, open government data, and permissive or copyleft licences whose obligations V3LUM meets by runtime download and attribution, A6); 'key-terms' = use is through a key whose plan's terms decide business use (key_plans, BR4); 'license' = business use needs a separate paid subscription, contract or written permission (examples in BR14-BR16); 'noncommercial' = the terms exclude commercial or business use; 'unknown' = terms not published or not yet reviewed.
- Offline modules with no registry source (disclosure 'none' and no dataset, e.g. validators and extraction) declare terms='open'. A dataset is a registry source like any other: a module that uses datasets takes the most restrictive class among its sources (BR3).

## A2 (option a)

Scans default to TLP:AMBER (setting tlp, on every execution path). The FIRST TLP 2.0 labels are supported, AMBER+STRICT included. TLP is attached to each seed and inherited by pivots and extracted entities. The single policy gate enforces it: AMBER excludes unknown-tier and query-reusing providers; AMBER+STRICT allows trusted providers only and no external push; RED allows offline and internal platforms only. Providers that publish lookups never receive values at any TLP (rule 7). Renderers generate the marking on every report page, section, file name and export. At AMBER and above, manual pivot links become non-clickable text with a disclosure warning.

- TLP values (FIRST TLP 2.0): 'clear' | 'green' | 'amber' | 'amber+strict' | 'red'. Setting tlp defaults to 'amber'. --tlp exists on scan, run, extract --scan, batch input (-i) and watch. The shell has `set tlp <level>` and its prompt shows mode and TLP (e.g. v3lum[passive|AMBER]).
- TLP is stored per seed. Pivots and entities extracted from text/files inherit their parent's TLP, and case TLP = the highest of its seeds. Choosing a TLP lower than the configured default is recorded in the case audit (OS user, time, from, to). LIGHT/ACTIVE cases are at least AMBER: a lower --tlp is raised to amber with a notice.
- Gate in core/policy.py (Status.SKIPPED, reason_code 'tlp'). CLEAR/GREEN: every disclosure class, with unknown-tier providers only under the per-run --allow-unknown flag (A8). AMBER: excludes unknown-tier providers and providers flagged reuses_queries (their terms allow redistributing, selling or reusing submitted values or content, 'improve the service' and model training included).
- AMBER+STRICT: trusted-tier providers only, and no REST push to any platform outside the organisation. RED: only modules with disclosure 'none' or 'internal'. Target contact counts as internal only for verified own assets (txt_verified/attested, not third_party_hosted). At RED, LIGHT/ACTIVE runs only on such assets, through a non-corporate egress profile or with a recorded --egress-override, and every other target is refused.
- Providers flagged publishes_queries (public recent-lookups pages, public scan feeds) never receive an investigated value at any TLP (team rule 7; Status.SKIPPED reason_code 'policy'). Log retention alone is not an exclusion criterion.
- Under RED, ctx.http and ctx.dns of 'none'/'internal' modules raise PolicyError for any public host, public DoH included. DNS then works only through a configured internal resolver (disclosure 'internal'); otherwise the answer is 'could not verify'.
- Markings are generated by the renderers from the case TLP, never typed by hand: terminal report header; HTML header, footer, top of every section and print CSS (label plus TLP 2.0 colour); Markdown first line; JSON top-level 'tlp' field; report file names carry the label (e.g. <case_id>.TLP-AMBER.html).
- Exports: STIX 2.1 marking-definition with object_marking_refs on every object (TLP 2.0 definitions, AMBER+STRICT supported); MISP tlp:* tag, with distribution 0 (your organisation only) for AMBER, AMBER+STRICT and RED (P303).
- Manual pivot links: at AMBER and above they render as non-clickable text with 'opening sends <value> to <host>'. At RED, third-party links are hidden from reports and shown only by `v3lum links` with the warning. Links are never auto-opened, and `links --open` at AMBER+ needs an interactive confirmation naming the host (non-TTY refuses).
- Cross-case data never travels down: a case shows sightings only from cases with TLP <= its own. Higher AMBER/AMBER+STRICT cases appear as 'seen in N restricted cases' with no ids, dates or verdicts. RED cases and LIGHT/ACTIVE engagement cases never surface in a lower-TLP case. CLEAR/GREEN exports and shareable reports omit cross-case references.
- TLP is not a privacy classification: the LGPD controls of A4, A8 and A10 apply at every TLP, CLEAR included.
- TLP-skipped modules are summarised in one terminal line with the reason and listed in the HTML/MD coverage appendix. core/policy.py ships table-driven tests over TLP x disclosure x tier x publishes/reuses flags x opsec x own-asset/scope.

## A3 (option a)

The default set is computed by core/policy.py from metadata: a module runs in a plain `v3lum scan x` only if its Module.default_enabled is True and it passes every gate (licence, TLP, tier, privacy, keys, opsec, egress, quota). Module.default_enabled can only lower the computed set. It must be False for LIGHT/ACTIVE, unknown-tier or unknown-terms sources, unbounded or slow sources, bulk downloads and person-profiling sweeps. Official Brazilian open data, offline data, case-DB/internal sightings, DoH DNS and manual links are explicitly default-on. A measured time budget, named presets, demotion rules and one canonical list of skip reasons make the default set observable.

- Effective default set = modules with Module.default_enabled=True that pass every gate of core/policy.decide at run time (licence, TLP, tier, privacy, keys, opsec, egress, quota, demotion). The set is computed from metadata, and Module.default_enabled can only lower it: an author can opt a module out, never force it in.
- default_enabled (Module attribute and chair-file field) MUST be False when any of these holds: opsec LIGHT or ACTIVE; terms 'unknown'; provider tier 'unknown'; declared max_requests > 10 per entity (except curated packs with their own cap and deadline, A5); expected_latency (p50) > 10 s; a known high false-positive rate; needs a dataset > 50 MB that `v3lum data update` cannot pre-fetch; category person_name (source modules that search or enrich people by name; offline correlation packs over facts already collected, such as P258, follow their own purpose-gated conditions).
- default_enabled MUST also be False for: username sweeps beyond the A5 default subset; fresh assessments by fetches_target providers (modes that use cached results with no publication may be True); sensitive site categories (NSFW, dating, religion, health, politics).
- default_enabled MAY be True for 'noncommercial'/'license' sources that meet every other criterion. Under the shipped corporate profile the gate skips them with reason_code 'licence' (that is how 'coverage lost under licence profile' is reported) until a licence_allow entry or recorded licence clears them. legal_dpo's requirement that a default source be allowed by the licence profile is thus enforced on the effective default set, and Module.default_enabled is only the candidate flag. Their final_conditions must say 'off under the corporate profile until licence-cleared'.
- Key-required sources MAY be default_enabled=True: they run by default once the key is configured, and report NEEDS_KEY otherwise.
- New contract fields: Module.max_requests (int, HTTP requests per entity per run). ScopedHttp enforces it: further requests raise RequestCapReached, the run keeps its data with partial=True and stop reason 'request_cap'. Module.expected_latency (float seconds, declared p50). doctor and the feedback loop measure the real p50 and precision.
- Demotion: a default module whose measured p50 > 10 s over >= 20 runs, whose findings are marked wrong in > 30% after >= 10 votes, that fails its health check on 3 consecutive `doctor --sources` runs, or that is BLOCKED on 5 consecutive runs leaves the default set (state in ~/.v3lum/health.json) with a doctor notice. Explicit -M still runs it, and it returns once it passes again.
- Privacy defaults: per-person breach/infostealer modules use run_on='own_assets' (A4); username packs use run_on='seeds' (A5); person_name modules are never default. A provider receiving PERSONAL_TYPES (A8) enters the default set only when the registry records personal_data_review {basis, reviewer, date}; until then it runs only when explicitly selected in a case with a recorded purpose (reason_code 'privacy').
- Default-on by decision (still subject to every gate): the BR CNPJ/QSA official open-data chain (BrasilAPI with Minha Receita fallback, QSA; CPF never looked up); CGU sanctions bulk lists matched locally once fetched by `v3lum data update`; TCU certidoes; BCB authorised institutions and DominiosVerificados; registro.br RDAP for .br names. Geo-blocked gov.br endpoints are on only when egress_country='BR' (A9).
- Also default-on: offline/local modules (warninglists, validators, extraction); case-DB sightings (P375); internal TIP lookups when configured (A12); DoH-based DNS modules; manual pivot links (no network).
- Time budget (acceptance tests AR21): default scans of a domain, IPv4, URL, SHA-256, e-mail and CNPJ show the first-screen summary within 20 s and complete at p90 within 60 s with recorded latencies on a cold cache. Setting scan_deadline (default 90 s; 0 = unlimited; --timeout overrides) ends a scan with partial results, a header banner, and pending sources marked SKIPPED reason_code 'deadline'.
- Presets: --preset quick (the default set) | deep (every ready module that passes the gates; --all-modules becomes an alias). -M/-x/-c keep working, and no preset or -M bypasses a gate.
- Reporting: the terminal prints one line 'N opt-in sources not run (use --preset deep)'. `v3lum modules` and `v3lum info` show, per module, whether it is in the effective default set and the reason_code when it is not.
- Minimum answer set: docs list the default sources for ipv4, domain, url, sha256, email and cve. A test asserts that at least 2 reputation-capable sources per type are default-ready under corporate (keyless, or with the recommended free keys of A15), and doctor warns when fewer are ready.
- Canonical reason codes, used by policy, engine, coverage, docs and every chair file. SKIPPED: not_default, demoted, licence, tlp, tier, privacy, own_asset, opsec, authorization, scope, egress_country, deadline, policy, config, not_applicable. NEEDS_KEY: needs_key. UNAVAILABLE: package, dataset, offline. QUOTA: quota. RATE_LIMITED: rate_limited.
- More canonical reason codes. BLOCKED: hostile_host, circuit, challenge, geo_block, login_wall. ERROR: timeout, sanitizer, error. ModuleResult.reason_code carries the code, and the human text stays in the reason/error field. Partial runs keep status ok/empty with partial=True and stop_reason in {request_cap, deadline, quota, rate_limited, cancelled}.

## A4 (option a+b+c (the third-party opt-in limited to analyst-typed seeds))

Breach and infostealer data is scrubbed at ingestion at one engine choke point, and the HTTP cache is covered too. Values are pseudonymised with a keyed HMAC in evidence file names and in the case-DB/sightings search indexes. By default, per-person breach and stealer checks run only for addresses on verified org-profile domains. They run for other addresses only when the analyst typed them as seeds and passed --breach-scope all with a recorded purpose, never for pivots or for addresses found in text. Generic, role and test addresses are flagged and never scored. Credentials are never tested.

- Breach, infostealer and people-data providers are flagged sensitive=true in the provider registry. Module.sensitive is derived (category breach_leak, or any source of a sensitive provider) and requires a per-source sanitizer schema registered in core/sanitize.py; otherwise @register fails.
- The P145 sanitizer is a mandatory engine stage right after Module.run returns. It runs before the graph, evidence, case DB, events/live feed, reports, STIX/MISP and --debug output, and modules cannot opt out. It fails closed: on an exception the raw payload is dropped and the run ends Status.ERROR with reason_code 'sanitizer'.
- HTTP cache: raw bodies of sensitive providers never reach http_cache.db. HttpClient applies the source's sanitizer schema to the body before caching or returning it, and falls back to no-store when no schema exists. Their TTL is at most min(7 days, cache_max_age_days, retention_days).
- Kept: breach names, breach dates, data classes, counts, stealer family, log/compromise dates, corporate/user service counts, and the password FORM (plaintext, or hashed: <algorithm>).
- Dropped, never masked: passwords, password hashes, salts, masked passwords/hints, top_passwords, top_logins, logins, cookies, session tokens, autofill, computer names, infected-host IPs, malware paths, leaked file contents and combo lines (email:password, user:pass@host).
- Generic, role and test addresses are flagged, capped at POSSIBLE and never scored as exposure. The bundled list is v3lum/data/generic_addresses.json: role local parts such as test, info, contato, contact, sac, admin, noreply/no-reply, suporte, support, vendas, financeiro, rh, webmaster, postmaster, abuse; IANA example and test domains; plus LeakCheck found >= 100 or Hudson Rock >= 5 computers.
- Evidence filenames are <module>__<type>__<hmac12>__<sha10>.json for every entity type. hmac12 = the first 12 hex of HMAC-SHA256(installation secret, '<type>:<normalized value>'). The installation secret is ~/.v3lum/secret.key (32 random bytes, 0600, created on first run). No raw value ever appears in a path.
- For PERSONAL_TYPES (A8), the case-DB search columns and the sightings index store the same keyed HMAC, never the value. Exact-value search hashes the query. Plain values stay only inside the 0600 case JSON and the report.
- Breach scope: per-person breach/infostealer modules declare run_on='own_assets' and by default run only for addresses on verified org_profile domains (txt_verified or attested, A11 BR4). With `--breach-scope all` plus `--purpose "<text>"` (recorded in the case and audit) they also run on analyst-typed seed addresses. Addresses found as pivots, in WHOIS, in pasted text or in pages outside org domains are never checked.
- Without the flag, a non-org address produces one line 'breach check skipped: not an org domain' (Status.SKIPPED, reason_code 'privacy'). Third-party addresses that are checked produce context only (first_seen_breach, data classes), severity at most MEDIUM, with no exposure score.
- Breach/stealer sources with 'unknown' or 'noncommercial' terms stay disabled under corporate until reviewed or allow-listed (A1); Hudson Rock free tools and LeakCheck public are 'unknown' today. Own-domain bulk endpoints (HIBP domain search, XON domain breaches, stealer domain searches) use run_on='own_assets_only' (A11).
- Leaked credentials are never tested, validated or used, in any mode or engagement (no login attempts, spraying or validation).
- Tests run trimmed Hudson Rock, LeakCheck, XposedOrNot and HIBP fixtures end to end. A grep over http_cache.db, evidence, case DB, every report and export format, events and --debug output finds no masked password/login, computer name, victim IP or malware path.

## A5 (option a (amended for the archived WhatsMyName dataset))

One username checker engine. WhatsMyName (CC BY-SA, runtime-only, pinned, attributed) is the default engine, with a small reliability-ranked default subset run only on analyst-typed handles. The Maigret DB is the opt-in extended pack. WhatsMyName was archived on 2026-11-09; Maigret entries with explicit two-sided markers may back-fill default slots left by failing WMN sites only after legal_dpo approves it in writing, and then only through a V3LUM selection list, never through a merged dataset. Every result is tri-state, polite and labelled as a weak signal, and the politeness limits are hard.

- One checker engine (P113 username_check) serves every pack. Site definitions come from WhatsMyName and the Maigret DB. WhatsMyName (CC BY-SA 4.0, archived 2026-11-09) is downloaded at runtime into ~/.v3lum/datasets, pinned by SHA-256, attributed, and never bundled or merged. The Maigret DB (MIT) is pinned; updates are verified with db_meta SHA-256 and never applied mid-run.
- V3LUM corrections, exclusions and per-site tiers live in a separate V3LUM-authored overlay (v3lum/data/username_overlay.json) that never copies WMN text. Sherlock data is used only for username-syntax regexes and its exclusions list.
- Default pack: module username_check (P113), run_on='seeds', default_enabled=True. It holds at most `username_default_sites` sites (default 100, hard max 150), selected by measured precision: the official claimed account must be FOUND and a random 20-char control ABSENT, from the team's egress. Every selected site has explicit presence AND absence markers.
- The default pack takes WhatsMyName entries plus the Ceos calibrated sites (P113). Maigret entries with two-sided markers may fill the slots of failing WMN sites only after legal_dpo records approval in docs/LEGAL.md (legal floor: until then Maigret stays the opt-in extended pack). Any selection ships as a V3LUM selection list (site ids plus dataset hash), never as merged data.
- Extended pack: module username_check_extended (same engine), default_enabled=False, run only by -M or --preset deep. It covers the Maigret curated profile (no protection, activation or engine entries) plus the remaining WMN sites, with a cap of 600 requests per username.
- Rule 2 lint (P327) over the datasets: entries whose probe is a sign-up, register, availability, check_username, validate, password-reset or login endpoint are excluded (about 26 in WMN, plus Maigret and Sherlock ones). Only public profile URLs are fetched: no logged-in scraping, cookies, or WAF/challenge bypass.
- Limits: exactly one request per handle per site, with no retries (a connection error or timeout = UNKNOWN); global concurrency <= 8; one request at a time per host; min_interval >= 1 s per host; per-site timeout 10 s; redirects not followed (the redirect response is evaluated against the markers); after a 403, 429 or challenge on a host its remaining sites are stopped; cap 150 requests per username in the default pack; pack deadline 120 s (target p50 <= 30 s). A FOUND site may get one control request with a random handle (P113, legal_dpo's '+1 control re-check'), counted in the cap; it is not a retry.
- Tri-state per site: FOUND only on the presence marker with no absence marker; ABSENT only on the absence marker; blocked, challenge, login redirect, timeout or 429 = UNKNOWN (rule 5). Each result keeps site, state, matched marker, URL and checked_at as evidence.
- Presentation: the terminal lists FOUND rows only, with counts per state. Every hit is labelled 'same handle does not prove identity' with confidence POSSIBLE; PROBABLE needs a P258 linkage signal (non-default avatar match, extracted ids, bio link to a known entity). Handles of <= 4 chars or dictionary words are flagged high-collision. Found profiles become pivots with expand=False.
- Privacy: packs run only on analyst-typed seeds, never on pivots or on usernames found in pasted text. A single token detected as a username with confidence < 0.75 runs a pack only after a TTY confirmation or with an explicit 'username:' prefix. Never infer sensitive traits from hits.
- Sensitive and closed sites: nsfw_sites=false and sensitive_sites=false (dating, religion, health, politics) are the defaults. Sites whose profiles are visible only after login are excluded, and Tor/I2P sites are excluded unless opted in.
- Each site is a provider that receives a username (A8). Only sites recorded in the overlay as trusted or community are ever queried, with a rationale such as 'major platform' or 'Tranco top-50k on <date>'. Unknown-tier sites never receive a username at any TLP; at AMBER+STRICT only trusted sites are queried.
- Health: `doctor --sources` re-measures a rotating sample of <= 25 sites per run, at most once a day. Sites failing their claimed/unclaimed self-test are auto-disabled until they pass again, with a doctor notice.

## A6 (option a)

V3LUM never copies or vendors GPL/AGPL/LGPL code: behaviour is reimplemented from documentation and specs. LGPL libraries may be used only as unmodified optional extras, and GPL/AGPL tools only as separately installed external processes. GPL, CC BY-SA and non-commercial data are downloaded at runtime only. Only permissive data is bundled, and every notice is generated from one registry and checked in CI. V3LUM's own licence is proprietary-internal (company-owned, internal use), written to stay Apache-2.0-compatible.

- No GPL, AGPL or LGPL code is copied, pasted or vendored into V3LUM. Behaviour from such projects (e.g. InQuest iocextract, AGPL scanners) is reimplemented from documentation and specs, and those projects serve as study material only.
- LGPL libraries may be used only as unmodified optional pip dependencies inside an extra, never in core and never vendored. ioc-finder (LGPLv3+) is not adopted (P172).
- GPL/AGPL tools (nmap, nuclei, masscan...) run only as separately installed external processes found on PATH and version-checked by doctor. They are never imported, bundled, auto-downloaded or auto-updated.
- Data licences: GPL, CC BY-SA and non-commercial datasets (e.g. webappanalyzer technologies GPL-3.0, WhatsMyName CC BY-SA 4.0, PHPIDS LGPL-3.0, Malpedia/OpenSanctions NC) are downloaded at runtime into ~/.v3lum/datasets and never bundled. Only MIT, BSD, Apache-2.0, CC0, CC BY 4.0, IANA public data and the unmodified PSL (MPL-2.0) may be bundled.
- One registry (P330: bundled files, register_dataset licence/terms/attribution fields, adapted code) generates THIRD_PARTY_NOTICES.md and data/NOTICE, each entry with name, source URL, version/commit or etag, SHA-256, licence, attribution text and bundled-or-runtime. CI fails on a bundled file without an entry, or on a copyleft/NC dataset that is bundled.
- Code adapted from MIT/BSD/Apache projects (SpiderFoot, Maigret, Sherlock, ioc-extractor, ioc-fanger, lemmeknow, Machinae, mihari...) carries a header with source URL, commit and licence, plus a THIRD_PARTY_NOTICES.md entry.
- Dependency licence check in CI: runtime dependencies must be permissive, or LGPL used unmodified as optional extras. Everything beyond rich + requests is an optional extra with wheels.
- Datasets that drive LIGHT/ACTIVE behaviour (wordlists, nuclei templates, takeover fingerprints) are pinned by commit/SHA-256 in a lock file (data/active.lock) and refreshed only by `v3lum data update` with a diff summary, never mid-engagement.
- Runtime datasets larger than 5 MB are fetched by `v3lum data update` (with a first-run hint), never in the middle of a scan. Reports surface the attributions of the sources and datasets actually used (P336).
- V3LUM's own licence is proprietary-internal (all rights reserved, company-owned, internal use only), written to stay Apache-2.0-compatible. Apache-2.0 is decided only if an external release is approved.

## A7 (option a)

LIGHT stays opt-in (--mode light) and runs only on analyst-typed seeds, after the passive results for that entity. ACTIVE needs a real authorization reference and a scope file on every execution path. The core checks scope at connection time, after DNS resolution and on every redirect hop. Pivots never inherit scope. Hard rate and size ceilings, a list of forbidden actions enforced in code, safe pinned nuclei templates, a kill switch, an audit record with a hash-chained request ledger, and an engagement banner on every report page complete the envelope. No LIGHT or ACTIVE module merges before the safety suite passes.

- ACTIVE needs --mode active, --authorized REF and --scope FILE on every path (scan, run, shell, watch, batch; TTY or not; -y included). - Scope is checked by the core at connection time, after DNS resolution through the egress profile and again on every redirect hop. The target must match by domain/URL prefix or CIDR, and the resolved IP must not be private, loopback, link-local, CGNAT, ULA or cloud metadata unless the scope lists it.
- CDN/shared-hosting/SaaS IPs (noise and warninglist ranges) are excluded from every ACTIVE probe unless the scope lists them explicitly. For an in-scope domain resolving to such an IP, HTTP probes to that host name need it listed under shared_infra_hosts, and network probes (ports, TLS sweeps) need the IP/CIDR itself.
- Pivots never inherit scope. ACTIVE modules run only on entities matching the scope, and LIGHT modules only on analyst-typed seeds. LIGHT never runs on pivots. light_for_own_assets=true (default false) only lets LIGHT run without --mode light on typed seeds that are verified own assets. Every other entity gets passive modules only (Status.SKIPPED, reason_code 'scope').
- Hard ceilings, enforced in HttpClient and the socket connector (modules and host profiles cannot raise them). Every ACTIVE probe type: <= 10 requests/probes per second and <= 2 concurrent connections per target host. Port scans: <= 1000 TCP ports (top-1000 by default or an explicit list), no UDP sweeps, <= 100 packets/s in total unless the scope raises the total (maximum 1000).
- More hard ceilings: wordlists <= 5000 entries from any source, --wordlist included; ACTIVE budget 10000 requests/probes per case unless the scope sets max_requests (<= 50000); LIGHT <= 1 req/s and <= 25 requests per target host per scan.
- Forbidden in code and in the P327 lint, in every mode and engagement: exploitation or payload-based confirmation; credential brute force, spraying, default-login checks or any login attempt; use of leaked or found credentials and keys; JWT/hash cracking; DoS, stress or load tests; uploads, writes or deletes.
- Also forbidden: state-changing methods toward targets (ACTIVE uses GET/HEAD/OPTIONS unless core policy allow-lists a module for a documented read-only reason; LIGHT uses GET/HEAD); claiming dangling resources or takeovers; downloading object contents from exposed buckets beyond the listing/metadata needed to prove exposure; OAST/interactsh callbacks.
- nuclei is an optional external binary: found on PATH, version-checked by doctor, never auto-installed or updated. It runs with -duc -ni, rate limit <= 10, and a pinned template set (data/active.lock).

- Audit (P324): every LIGHT/ACTIVE run (scan, run, shell) writes a case with an audit record (OS user, REF, scope SHA-256, window, mode, egress profile, targets, modules, time) and a per-case JSONL request ledger (UTC time, module, method, host, resolved IP, port, redacted path, status, bytes, egress profile, opsec). The ledger is hash-chained and written even with --no-evidence.
- Every page and section of a LIGHT/ACTIVE case report carries a banner: mode, authorization reference, scope SHA-256, window, egress profile/IP, targets touched and request counts. Out-of-scope refusals list each target and the reason.
- Sequencing: passive results for an entity (TI and archive lookups included) are absorbed before any LIGHT/ACTIVE module runs on it (P376). URLs that probably carry a per-recipient token (an org_profile e-mail in plain, URL-encoded or base64 form, or opaque tokens of >= 16 chars in path/query) are never fetched automatically and need a per-URL confirmation.
- `v3lum run` uses the configured mode (passive by default) and honours an explicit --mode. It refuses with a hint ('needs --mode light: contacts the target') instead of escalating with max(mode, opsec). In the shell, `set authorized <ref>` binds to a scope file (`set scope <file>`) and expires after 8 h.
