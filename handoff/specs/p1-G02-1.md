## P031 `ripestat` - RIPEstat Data API (network-info, prefix-overview, whois, abuse contact, geoloc, AS pivots, searchcomplete, reverse DNS)

- council: **approved**, priority P1, default_enabled=True, provider_tier=trusted, terms=open, opsec=passive, shares_input=True
- category: ip_network; group: G02; inputs: ipv4, ipv6, cidr, asn, company_name; produces: asn, cidr, domain, email

### Final conditions (binding spec - implement every item)

1. Keyless RIPEstat Data API (stat.ripe.net/data/<call>/data.json), sourceapp=v3lum on every call, attribution to RIPE NCC per its terms. cache_ttl 24 h.
2. IPs: network-info, prefix-overview, rir-geo, whois, abuse-contact-finder and reverse-dns-ip. ASNs: as-overview, announced-prefixes and asn-neighbours. Company names: searchcomplete (ASN/prefix candidates, low confidence, expand=False). PTR chains: dns-chain.
3. Check the JSON envelope inside HTTP 200 (status, status_code, messages of type error) and map it to ERROR or RATE_LIMITED through P321 markers, never EMPTY.
4. announced-prefixes for big ASNs (~680 KB) is streamed and capped: at most 100 cidr pivots, while the attribute keeps the total counts.
5. Drop RIPE person objects at ingestion; keep role, organisation and abuse-c contacts (LGPD minimisation).
6. Expose the abuse-contact lookup as a shared helper reused by takedown_packet (P345). rir-geo is shown as geolocation context only (MaxMind-derived).
7. Tests with the recorded fixtures (network-info, prefix-overview, whois, abuse-contact), an error envelope and a capped announced-prefixes answer.

Chair rationale: Approved 6-0 at median P1. legal_dpo's floor: person objects dropped at ingestion, sourceapp and RIPE NCC attribution. The architect's floor: error checks inside the 200 envelope, capped announced-prefixes, low-confidence searchcomplete, the shared abuse-contact helper. RIPE NCC is a regional internet registry: tier trusted; free for corporate use: terms open.

Synthesizer conditions (background; the final conditions win on conflict): Keyless; always send sourceapp=v3lum; use network-info/prefix-overview/rir-geo for IPs, as-overview/announced-prefixes/asn-neighbours for ASNs (announced-prefixes for big ASNs is ~680 KB: cap/stream), abuse-contact-finder for abuse_contact, searchcomplete for org name -> ASN/prefix candidates (low confidence), reverse-dns-ip/dns-chain for PTR. Cache 24 h. Free for corporate use.
Notes: Authoritative routing/registration context for every IP/ASN; fully free for corporate use.

## P034 `cloud_ranges` - Cloud/CDN provider ranges (AWS, GCP, Azure, Cloudflare, Fastly, Oracle...) + cloudcheck signatures

### Final conditions (binding spec - implement every item)

1. One shared core IP-range index (sorted integer intervals + bisect, IPv4 and IPv6), used by cloud_ranges, ip_context_lists, nicbr_asn, ip_offline_db, ip_blocklists and tor_relays. No per-module radix trees. The noise layer reads it through a core noise-provider hook with no network on the noise path (AR06).
2. Each provider file is a registered dataset with its own TTL (daily; Azure Service Tags weekly) and parser test: AWS ip-ranges.json, Google cloud.json, Cloudflare ips-v4/v6, Fastly public-ip-list, Oracle OCI public_ip_ranges.json, GitHub meta. Azure Service Tags only from a stable URL or via cloudcheck data, never by scraping the download page.
3. cloudcheck signatures (AGPL-3.0 repository): runtime-downloaded data only into ~/.v3lum/datasets, never bundled, committed or code-copied, with a THIRD_PARTY_NOTICES entry (A6). The official provider files alone must pass the same tests (a test runs without cloudcheck).
4. Downloads are validated (content type, minimum size and entry count, parse success) before replacing the cached copy; a failed download keeps the last good copy with its date. Dataset age is shown; a missing dataset gives UNAVAILABLE, never 'not cloud'.
5. Accept IP/CIDR only (domains are covered through their resolves_to pivots), so the module keeps disclosure 'none' (shares_input=False). Labels: is_cloud, is_cdn, is_hosting plus provider/region/service.
6. Shared edges (CDN/WAF/anycast fronts: Cloudflare, Akamai, Fastly, CloudFront, Azure Front Door, Google front ends) are noise: no pivots and no IP-reputation expansion to co-tenants. IaaS compute (EC2, GCE, Azure VMs, OCI, DigitalOcean...) is NOT noise: reputation still applies, with a verdict lifetime <= 14 days because addresses are reassigned.
7. CDN/shared-hosting labels make IP-reputation and co-hosting pivots expand=False but never suppress findings about the domain or URL itself.
8. Scope guard (A7): ACTIVE network probes against IPs labelled CDN or shared hosting are refused unless the scope file lists that IP or range. Own domains on these ranges are tagged third_party_hosted (P378). If the dataset is missing or older than 7 days, ACTIVE network modules refuse to run (fail closed) and doctor warns.
9. The provider/service label (e.g. 'Cloudflare CDN edge', 'AWS us-east-1 EC2') appears next to the IP in the terminal entity map and HTML, and the pivot note says 'not pivoted: shared CDN/cloud IP'. Unit tests for an edge IP and an IaaS IP.

Chair rationale: Approved 6-0 at median P1. The architect's floor: one shared core range index, a dataset per provider file, IP/CIDR input only, a local noise hook. legal_dpo's floor (A6): cloudcheck data runtime-only and attributed, official files preferred. cti_lead separated CDN edges from IaaS compute so real C2 on rented VPSs is not hidden. redteam_lead made it a fail-closed safety dataset for the ACTIVE scope guard. osint_investigator: labels never hide domain/URL findings. analyst_ux: visible labels and dataset age. Tier community is the lowest dataset provider (cloudcheck); the cloud providers are trusted. Terms open (public provider data; AGPL data met by runtime download, A1 BR19).

Synthesizer conditions (background; the final conditions win on conflict): Download official range files (ip-ranges.amazonaws.com, gstatic cloud.json, Cloudflare ips-v4/v6, Fastly public-ip-list, Oracle OCI...) and blacklanternsecurity/cloudcheck signatures (fetch at runtime; cloudcheck code is AGPL -> data only, no code copy) into a local radix tree; label is_cloud/is_cdn/is_hosting + provider/region/service; CDN IPs become noise (no IP-reputation expansion).
Notes: Suppresses false positives (CDN co-tenancy) and powers CR08 dangling_cloud_ip.
