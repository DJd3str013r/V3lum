## P064 `url_unwrap` - URL rewrite unwrapping & decoding (SafeLinks, Proofpoint, Google redirects, Unfurl-style)

- council: **approved**, priority P1, default_enabled=True, provider_tier=n/a, terms=open, opsec=passive, shares_input=False
- category: url_web; group: G03; inputs: url, text_blob; produces: url, domain
- auth: none; key env vars: -; hosts: dfir.blog

### Final conditions (binding spec - implement every item)

1. Strictly offline (disclosure 'none', shares_input=False): unwrap Microsoft SafeLinks (url=), Proofpoint v2/v3 (u= and __...__ forms), Google /url?q=, Mimecast and LinkedIn/Facebook redirectors, nested wrappers included (bounded at 5 levels), and decode Unfurl-style parameters (timestamps, base64, snowflake ids) without following any redirect.
2. No automated call to dfir.blog or any Unfurl service (manual link only). Unfurl code is ported only after re-checking its Apache-2.0 LICENSE, with attribution.
3. It is the single unwrapping helper, also used by email_header_analyzer (P085) and the P172 text extraction.
4. Keep wrapped -> unwrapped as a relation. Wrapper hosts (safelinks.protection.outlook.com, urldefense.com, *.proofpoint.com, Mimecast, Google /url) are noise: never IOCs, never reputation-checked.
5. Recipient identifiers embedded in wrapper parameters (SafeLinks data=/sdata= recipient e-mail and tenant id, Proofpoint recipient fields, base64-encoded e-mails) are redacted before evidence and report.
6. wa.me/<digits> and api.whatsapp.com/send?phone= decode to phone entities (E.164, BR default region); t.me/<name> to telegram_handle (P333). They are PERSONAL_TYPES from text: expand=False pivots for analyst selection (AR07), never followed.
7. Unwrapped URLs inherit the case TLP and are passive-only pivots; URLs carrying recipient tokens are flagged 'recipient token' and never fetched automatically (A7).
8. Tests with the recorded SafeLinks fixture, a SafeLinks-in-Proofpoint nesting, recipient redaction and a wa.me decode.

Chair rationale: Approved 6-0 at median P1. legal_dpo's floor: strictly offline and recipient identifiers redacted. cti_lead: nested wrappers and wrapper hosts as noise. osint_investigator: WhatsApp/Telegram hand-offs decoded, kept as non-expanding personal pivots per AR07. The architect: the single bounded unwrapping helper. Offline module: tier n/a, terms open (own code).

Synthesizer conditions (background; the final conditions win on conflict): Offline: unwrap Microsoft SafeLinks (url=), Proofpoint v2/v3 (u=/__...__), Google /url?q=, Mimecast, LinkedIn/Facebook redirectors; decode Unfurl-style parameters (timestamps, base64) without following any redirect.
Notes: Recovers the real IOC from rewritten URLs in pasted e-mails.

## P066 `urlscan_search` - urlscan.io search (search only, never submit)

- council: **approved**, priority P1, default_enabled=True, provider_tier=trusted, terms=noncommercial, opsec=passive, shares_input=True
- category: url_web; group: G03; inputs: domain, ipv4, url, asn; produces: url, domain, ipv4
- auth: none; key env vars: V3LUM_URLSCAN_KEY; hosts: urlscan.io
- sources shared with other proposals: {"C0143": ["P347"]}

### Final conditions (binding spec - implement every item)

1. Search API only. No scan-submission code path exists in V3LUM (public, unlisted or private) unless a later proposal is separately approved: a test asserts no POST to /api/v1/scan/ is ever issued (rule 7). Only the submission endpoint publishes, so the search source is not flagged publishes_queries.
2. Terms: the urlscan.io ToS (verified 2026-11-26) provide the free service 'only for your own personal use' and bar commercial endeavours not approved by urlscan, so free/keyless use is noncommercial. Off under the corporate profile until licence-cleared: a company key under urlscan's commercial terms or urlscan's written approval recorded in licence_allow (A1 day-1 queue).
3. API-Key header (key 'urlscan' in config.KNOWN_KEYS). Honour X-Rate-Limit-* headers; 429 = RATE_LIMITED. size <= 100 and at most 2 search_after pages. Result details (/api/v1/result/{uuid}) only with a key (403 fixture otherwise).
4. Two labelled queries per domain: page.domain:{d} (the site itself) and domain:{d} AND NOT page.domain:{d} (third-party pages that loaded its resources; for org_profile domains these are brand-abuse candidates). hash: searches for favicon/JS hashes give expand=False pivots and skip common library/CDN files (noise list).
5. E-mails, recipient identifiers and token-like values in result URLs are redacted by the core URL-redaction helper before attributes, res.raw and evidence (fixture test).
6. Every hit shows its scan date; results older than 30 days are historical, not current state. urlscan verdicts count as one vote in consensus.
7. Screenshots and DOM of existing public scans come only from urlscan.io, never from the target, and may be stored as evidence and embedded as data URIs in reports (P336).
8. Report links urlscan.io/domain/{domain} and urlscan.io/ip/{ip} are the manual links. Tests with the recorded search, no-key and result-403 fixtures.

Chair rationale: Approved 6-0 at median P1 (legal_dpo voted P2). cti_lead and legal_dpo both verified the personal-use clause; legal_dpo's floor makes free use noncommercial, so it stays a default candidate that is off under corporate until a commercial plan or written approval is recorded (stricter than the A15 BR8 key list, which assumed checked terms). The architect's floor and legal_dpo: no submission code path at all, header key, capped pagination, redaction before storage. osint_investigator: the brand-abuse query and hash pivots. redteam_lead and cti_lead: dated, historical hits and urlscan-only screenshots. urlscan is an established company: tier trusted.

Synthesizer conditions (background; the final conditions win on conflict): Search API only (q=domain:/page.domain:/ip:/hash:, size<=100, search_after pagination); keyless works with low limits, optional V3LUM_URLSCAN_KEY; result detail /api/v1/result/{uuid} needs a key (403 fixture). NEVER submit scans from V3LUM (public scans publish the client's URL); private scans only via explicit gated action. Redact e-mails embedded in result URLs.
Notes: Historical scans of phishing/attacker pages and the org's own pages, with screenshots and IOCs.

## P071 `url_domain_blocklists` - Downloadable phishing/malicious domain & URL lists matched locally (OpenPhish, CERT.PL, Phishing.Database, HaGeZi TIF, Phishing Army, StevenBlack, Botvrij, PhishTank dump, CyberCrime-Tracker, ScamSniffer, MetaMask, spmedia, Procon-SP)

- council: **approved**, priority P1, default_enabled=True, provider_tier=community, terms=noncommercial, opsec=passive, shares_input=False
- category: url_web; group: G03; inputs: domain, url; produces: 
- auth: none; key env vars: V3LUM_PHISHTANK_KEY, V3LUM_PHISHTANK_APP_KEY; hosts: openphish.com, raw.githubusercontent.com, hole.cert.pl, phishing.army, botvrij.eu, data.phishtank.com, cybercrime-tracker.net, sistemas.procon.sp.gov.br

### Final conditions (binding spec - implement every item)

1. One on-disk index (SQLite: host / registrable domain / normalised URL -> feed bitmask, fetched_at) built at `v3lum data update` or background refresh time; lookups never load the ~2-3M entries into Python sets. Per-feed TTL (1-12 h), conditional GET, provenance per hit, per-feed terms label and enable flag. Large feeds use their txt variants and are > 5 MB: never fetched mid-scan (A6).
2. Per-feed terms: CERT.PL Hole (any use incl. commercial; trusted), Phishing.Database (MIT), StevenBlack (MIT), MetaMask eth-phishing-detect (permissive), spmedia (MIT), Botvrij, CyberCrime-Tracker and Procon-SP run with attribution. HaGeZi TIF and ScamSniffer are GPL-3.0 data: runtime download only, never bundled or used as fixtures (A6). Test fixtures are synthetic or from permissive lists.
3. OpenPhish community feed: 'non-commercial use only', and its terms forbid use for an organisation's security operations, detection or enrichment without written consent (verified 2026-11-26): off under every profile unless legal records OpenPhish's written consent or a paid feed in licence_allow.
4. Phishing Army (CC BY-NC, with OpenPhish upstream): off under the corporate profile until licence-cleared.
5. PhishTank dump (commercial use allowed per its FAQ) only with the team's own app key if downloads are reachable; disabled until then. Procon-SP 'Evite estes sites' (BR fake stores) is optional with retry; when its backend errors, the source emits its manual pivot link.
6. Verdict scope: URL-list entries match the exact normalised URL, and the host only when it is not a shared platform. A URL listing never propagates to the registrable domain of shared hosting, file sharing, PSL private suffixes (data/shared_platforms.json, P010) or Tranco top-10k domains. Domain lists match the FQDN and its parents, except shared platforms.
7. Category and fidelity per list: phishing (CERT.PL, Phishing.Database, OpenPhish) = MEDIUM for one list, HIGH with >= 2 independent families (P171) or CERT.PL; c2 (CyberCrime-Tracker) = HIGH; crypto_scam (ScamSniffer, MetaMask, spmedia) = MEDIUM; ads/tracking/aggregate (StevenBlack, HaGeZi TIF) = LOW tag only, never 'phishing'.
8. Hits carry the list name and listing date; listings older than 30 days are historical. CERT.PL InsertDate/DeleteDate (JSON) give listing and removal history. Missing or stale lists give UNAVAILABLE ('not checked'), never 'not listed'.
9. Feed specifics: MetaMask fuzzylist Levenshtein matching against crypto brands (re-implemented); ScamSniffer domains.json only (address.json and combined.json are frozen since Feb 2024 and never used for address reputation; the public list has a 7-day delay); CyberCrime-Tracker entries have no scheme: host/IP pivots and path patterns (/panel/, /gate.php) as family hints.
10. Matching is local (disclosure 'none', allowed at TLP:RED). Tests with the recorded feed slices: a sharepoint.com/docs.google.com phishing URL flags only the URL, a stale list reads 'not checked', an OpenPhish entry is skipped under corporate.

Chair rationale: Approved 6-0 at median P1. legal_dpo's floor, confirmed by cti_lead and osint_investigator: OpenPhish's community terms exclude corporate security use (written consent needed), Phishing Army is non-commercial, GPL feeds are runtime-only. The architect's floor: one on-disk index with per-feed TTL, provenance and enable flags. cti_lead, osint_investigator and analyst_ux: URL-level scope on shared platforms, per-list fidelity, listing dates and honest 'not checked'. Terms is noncommercial for OpenPhish and Phishing Army only. Tier community is the lowest list maintainer; CERT.PL and Procon-SP are trusted.

Synthesizer conditions (background; the final conditions win on conflict): Dataset manager with per-feed TTL (1-12 h) and provenance; large lists (CERT.PL 22.6 MB JSON, HaGeZi TIF 17.6 MB): prefer the txt variants and store as sets. OpenPhish community feed moved to raw GitHub (confirm 'commercial use' attribute before corporate use); Phishing Army believed CC BY-NC -> disabled until licence confirmed; ScamSniffer data is GPL-3 -> download at runtime only (domains.json; address.json frozen since Feb 2024); MetaMask eth-phishing-detect has a fuzzy look-alike list (use for crypto brands); PhishTank dumps effectively unavailable (app keys closed, signed URL 404) -> keep disabled unless reachable; Procon-SP 'evite estes sites' backend errored -> optional. Match on registrable domain and full URL; a hit tags phishing/malicious with the list name.
Notes: Offline URL/domain verdicts for phishing triage without disclosing the URL.

- council: **approved**, priority P1, default_enabled=True, provider_tier=n/a, terms=open, opsec=passive, shares_input=False
- category: utility; group: G03; inputs: text_blob, file, url, jwt; produces:

### Final conditions (binding spec - implement every item)

1. Shared engine (architect floor): a library used by js_endpoints, public_api_exposure, archive_mining, email_header_analyzer and P172, plus a module for text_blob, file and jwt inputs only. It never fetches URLs itself.
2. Bundle gitleaks.toml (MIT, attribution; 222 rules, RE2-only patterns converted so 221 compile in Python re). Pipeline: keyword prefilter -> regex -> Shannon entropy -> allowlist. Every compiled pattern passes a ReDoS harness in CI (adversarial strings, per-pattern time budget). Input cap 5 MB per scan, lines truncated at 10k chars; google-re2 used when installed.
3. Allowlist of documented example/test credentials and placeholders (AKIAIOSFODNN7EXAMPLE, sk_test_ keys, the jwt.io sample token, 'xxxx', 'changeme'...), plus one positive and one negative synthetic test vector per rule.
4. Masking: tokens/keys of >= 20 chars are stored as type + first 4/last 4 + SHA-256 (P145); shorter secrets as type + SHA-256 only; password-type values (config passwords, SMTP credentials) never show any character (rule 3). The location (file/URL, line) is kept.
5. Redaction applies to findings, attributes and res.raw before the HTTP cache, evidence, case DB, reports, events and --debug output; an end-to-end test asserts a fake token appears nowhere on disk or in events.
6. Found secrets never leave the machine: never validated against providers (trufflehog-style verification is forbidden; trufflehog is AGPL, ideas only), never pivoted, never sent as search values (GitHub, grep.app, IntelX, Postman). They are SECRET_TYPES; only the local SHA-256 is used for dedupe and sightings.
7. Severity from context without any validity test: the organisation's own credentials HIGH/CRITICAL with a notify recommendation; third-party credentials MEDIUM with an owner-notification recommendation; provider-specific rules MEDIUM/HIGH; generic/entropy-only matches an info count. The same secret in several places is one finding with N locations.
8. Phishing-kit exfiltration rules enabled (Telegram bot token, Discord webhook, SMTP credentials). The optional P141 helper may add 'appears N times in public breach corpora' to credential-type findings.

Chair rationale: Approved 6-0 at median P1 (analyst_ux voted P2). The architect's floor: a shared library plus a text/file module, ReDoS harness, input caps, redaction including res.raw with a test. legal_dpo: redaction covers evidence, cache and logs. cti_lead's stricter masking (nothing shown for passwords, limited characters for short values) is adopted because a first/last-4 hint of a password would be a masked password (team rule 3). redteam_lead: secrets never leave the machine. osint_investigator: kit exfiltration rules. analyst_ux: provider-specific vs generic severity and one finding per secret. Offline: tier n/a; bundled MIT rules: terms open.
