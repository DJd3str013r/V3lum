## P085 `email_header_analyzer` - E-mail header / .eml / .msg analyzer

- council: **approved**, priority P1, default_enabled=True, provider_tier=n/a, terms=open, opsec=passive, shares_input=False
- category: email; group: G04; inputs: file, text_blob; produces: ipv4, domain, email, url
- auth: none; key env vars: -; hosts: -

### Final conditions (binding spec - implement every item)

1. Static, offline parsing (disclosure 'none', allowed at TLP:RED): stdlib email parser on bytes with caps of 25 MB per file, 2,000 headers and 64 KB per header. Malformed input gives ERROR with the reason, never a crash (MHA's fallback Received regex as an idea).
2. A reported e-mail is attacker-controlled: never fetch remote images, tracking pixels, CSS, fonts or links, never resolve UNC/file paths, never open, render, execute, upload or write attachments to disk.
3. Received chain: reversed to chronological order, each split on its LAST ';' for the date, hop delays via total_seconds() (day-aware, negatives flagged), 'IPv6:' tags blanked before scanning addresses. Tokenization ported from mail-parser (Apache-2.0, NOTICE; the trailing '::' branch of REGXIP6 last).
4. Trust boundary: only Received headers added by the organisation's own MTAs/gateways (hostnames and authserv-id configured in org_profile/settings) are trusted; the first external hop they record is the originating IP. Lower hops are attacker-controllable and labelled unverified; private/internal hops are skipped.
5. Authentication-Results are trusted only from the configured authserv-id; others read 'claimed by <host>', never verified. SPF/DKIM/DMARC results are parsed, with Received-SPF as fallback.
6. Findings: From vs Return-Path/Reply-To mismatch, display-name brand spoofing (an org_profile brand in the display name with an unrelated domain), X-Mailer and similar sender-tool hints.
7. Bodies are decoded (quoted-printable/base64); URLs are unwrapped through the url_unwrap helper (P064, no second implementation), defanged and never followed. URLs carrying the recipient's address (plain, URL-encoded or base64) are flagged 'recipient token'. Extracted IPs, domains and URLs are passive-only pivots.
8. Attachments: name, size, declared type and locally computed SHA-256/MD5 only, as hash pivots with expand=False; never sent to sandboxes or services that publish.
9. .msg files via the optional olefile package (requires_packages, size cap), reading __substg1.0_007D001F (UTF-16LE transport headers). extract-msg, EmailAnalyzer and MHA (GPL) are ideas only.
10. Privacy: recipient and reporter addresses are redacted in shared reports (HTML/MD) and STIX/MISP exports and kept only in the local case; recipients are never pivoted; bodies and attachments are not stored beyond the case evidence, under case retention (A10).
11. The report opens with a verdict block: From vs Return-Path/Reply-To, SPF/DKIM/DMARC and who asserted them, originating IP, sending infrastructure (ASN/provider), total delay, unwrapped URLs. Input via the email_headers type (P333, phase 1). Fixtures: a trimmed real .eml with a Received chain, a SafeLinks URL and a malformed header.

Chair rationale: Approved 6-0 at median P1. cti_lead's trust boundary keeps forged lower hops from blaming innocent IPs. redteam_lead: static parsing only, so planted beacons never fire. legal_dpo's floor: recipients redacted in shared outputs, bodies under case retention, GPL tools ideas only. The architect's floor: byte caps, no attachment handling, olefile as an optional extra, the single unwrapping helper, authserv-id trust. osint_investigator: Reply-To and display-name tricks. analyst_ux: the verdict block. Offline: tier n/a, terms open.

Synthesizer conditions (background; the final conditions win on conflict): Stdlib email parser: reverse Received list (chronological), split each on its LAST ';' for the date, hop delays via total_seconds(), blank 'IPv6:' tags before scanning addresses, trust only Authentication-Results from the team's own authserv-id, parse SPF/DKIM/DMARC results, extract URLs and unwrap SafeLinks/Proofpoint offline (never follow). Port Received tokenization from mail-parser (Apache-2.0); .msg via olefile stream __substg1.0_007D001F (extract-msg is GPL: reference only); EmailAnalyzer/MHA (GPL) ideas only. Needs an email_headers input type or file detection (G15).
Notes: Phishing triage of reported e-mails: sending infrastructure, spoofing, embedded IOCs.
