- council: **approved**, priority P1, default_enabled=True, provider_tier=community, terms=open, opsec=passive, shares_input=True
- category: username_social; group: G05; inputs: username; produces: url, username
- auth: none; key env vars: -; hosts: raw.githubusercontent.com, gitlab.com, hub.docker.com, dev.to, hacker-news.firebaseio.com, keybase.io, huggingface.co, codeberg.org, en.gravatar.com, about.me, dribbble.com, linktr.ee, kaggle.com

### Final conditions (binding spec - implement every item)

1. One checker engine, two modules (A5): username_check, the default pack (run_on='seeds', default_enabled True, <= setting username_default_sites sites, default 100, hard max 150), and username_check_extended (default_enabled False, only -M or --preset deep, <= 600 requests per username: the Maigret curated profile without protection, activation or engine entries, plus the other WMN sites).
2. Default pack: WhatsMyName entries plus the Ceos calibrated sites, each with explicit presence AND absence markers, selected by measured precision from the team's egress (official claimed account FOUND, random 20-char control ABSENT), BR-tagged and CTI-relevant platforms first. Maigret back-fill of default slots only after legal_dpo's written approval in docs/LEGAL.md.
3. Data: WhatsMyName (CC BY-SA 4.0, archived 2026-11-09) downloaded at runtime, pinned by SHA-256, attributed in THIRD_PARTY_NOTICES and the report footer, never bundled or merged; Maigret DB (MIT) pinned, updates verified with db_meta SHA-256 and applied only by `v3lum data update`. Packs ship as V3LUM selection lists (site ids + dataset SHA-256), never merged data.
4. Corrections, exclusions and per-site tiers live in v3lum/data/username_overlay.json (A5): V3LUM-authored, never copying or adapting WMN text (corrections are V3LUM's own measured markers); a fix legal deems a WMN adaptation is CC BY-SA 4.0, attributed and never bundled (A6).
5. Sherlock data is used only for its regexCheck username-syntax patterns (nested-quantifier patterns dropped) and its exclusions list. Platforms whose dedicated module checks presence itself (P099, the P100 adapters, P102-P105, P109, P111, P112, P120) are excluded from both packs; the P116 enricher platforms stay in, because P116 runs only on username_check FOUND.
6. Rule 2 lint (P327) at pack build and in CI over both packs: entries whose probe URL or body hits sign-up, register, availability, check_username, validate, password-reset, login, exists, attempt or is_taken endpoints are dropped and logged (fixtures: X username_available, Discord username-attempt-unauthed, Fiverr validate_username, Roblox usernames/validate, Steemit and Pikabu signup).
7. Only unauthenticated GETs of public profile pages or documented profile APIs (legal floor). Excluded: e-mail lookups, any POST body, cookies, activation tokens, TLS impersonation, FlareSolverr/webgate, login-only profiles, the HudsonRock stealer API (rule 3), Tor/I2P; nsfw_sites=false and sensitive_sites=false (dating, religion, health, politics) by default. A test asserts no oracle remains.
8. Tiers (A8): each site is a provider that receives a username; only sites recorded in the overlay as trusted or community (rationale such as 'major platform' or 'Tranco top-50k on <date>') are queried. Unknown-tier sites, criminal forums included (P195's offline data answers that question), never receive a username at any TLP; at AMBER+STRICT only trusted sites.
9. Limits: exactly one request per handle per site, no retries (connection error or timeout = UNKNOWN); one control request with a random handle on FOUND sites, counted in the cap; global concurrency <= 8 in a bounded P339 lane; one in-flight request and min_interval >= 1 s per host; per-site timeout 10 s; redirects not followed but evaluated against the markers.
10. After a 403, 429 or challenge on a host its remaining sites stop. Caps: 150 requests per username in the default pack; pack deadline 120 s, extended pack 600 s (Module.timeout >= deadline, ctx.cancelled() checks), target p50 <= 30 s. UA per P326: neutral 'V3LUM/<version>' or the overlay's common browser UA where a public page needs one, never rotated or used to pass a bot wall.
11. Tri-state per site: FOUND only on the presence marker with no absence marker; ABSENT only on the absence marker; blocked, challenge, login redirect, 403/429/5xx and timeouts = UNKNOWN (rule 5). Evidence per site: site, state, matched marker, URL, status, checked_at and body SHA-256 (no bodies).
12. Output: one counts line (found / could not verify / absent / not checked: budget) and FOUND rows only (site, URL, display name); UNKNOWN reasons are aggregated in the coverage appendix (e.g. '22 blocked/WAF, 3 timeouts'). Found profiles become has_account URL pivots with expand=False.
13. Confidence: every hit reads 'same handle does not prove identity', POSSIBLE; PROBABLE needs a P258 linkage signal (non-default avatar match, extracted ids, bio link to a known entity). Handles < 5 chars, dictionary words or in a bundled common-username/first-name list are flagged high-collision and never raise severity above info (test: 'maria', 'admin').
14. Privacy: personal_data_review covers every site of the default selection list (one review naming each site, A3 BR8/A8 BR8); packs run only on analyst-typed seeds, never on pivots or pasted-text usernames; a single token read as a username below 0.75 needs a TTY confirmation or a 'username:' prefix; no sensitive traits are inferred from hits.
15. Health: `doctor --sources` re-tests <= 25 sites a day in rotation; sites failing their claimed/unclaimed self-test or marked wrong >= 3 times are disabled with a doctor notice until they pass. Test: the default pack on recorded fixtures finishes within 30 s simulated and prints the counts line.
16. Per-site terms (A1 BR2/BR3): each site carries a terms class with evidence in the overlay or provider registry; the default selection list holds only sites recorded 'open', so the module class stays 'open'; other sites run only through per-source filtering (A1 BR11) and appear in coverage. YouTube pages (P110 legal floor), x.com/twitter.com pages (P119) and login-walled LinkedIn are never queried.

Chair rationale: Approved 6-0 at median P1. The drafted 2,700-site Maigret-primary default at concurrency 24 is replaced by the binding A5 decision, which every member's conditions converge on: a WMN-based default of <= 100 sites (hard max 150) with two-sided markers, Maigret as the opt-in extended pack, the rule-2 oracle lint (redteam_lead's live oracle fixtures), one request per handle per site plus the FOUND control, concurrency <= 8 (architect), tier-gated sites (A8) and POSSIBLE wording (cti_lead, osint_investigator, analyst_ux). Members' 'one retry' and concurrency 10 are superseded by A5's stricter limits, and redteam_lead's read-only GraphQL POST exception is not adopted because legal_dpo's floor allows only unauthenticated GETs; redteam_lead's criminal-forum exclusion follows from the unknown-tier rule and cti_lead's rarity rule is kept.

Synthesizer conditions (background; the final conditions win on conflict): Normalised site schema; Maigret data.json (MIT, curated 2,700-entry default profile: enabled, no engine/protection/activation, non-NSFW) as primary with db_meta manifest + SHA-256 verified updates (never during a run); WMN wmn-data.json (CC BY-SA 4.0, archived 2026-11-09) downloaded at runtime and pinned by blob hash, attribution in report footer, fixes in a separate overlay; Sherlock only for its 95 regexCheck patterns and exclusions list. Tri-state FOUND/ABSENT/UNKNOWN (absent only on positive evidence); block/WAF fingerprints -> UNKNOWN(blocked) never solved; follow_redirects=false; control username re-check of FOUND sites (3 strikes -> local disable); self-test command. Drop registration/availability/reset oracle entries at pack-build time (regex sign[-_]?up|register|validat|availab|check[_-]?username|... with archive.org/MediaWiki exceptions) and log them; NSFW/dating off by default (tags + keyword regex); BR-tagged sites first; global semaphore 24, per-host 2, 12-15 s timeout, 120 s budget (10 min --deep).
Notes: One engine replaces ~60 caipora username tools; calibrated zero false positives in sample.
