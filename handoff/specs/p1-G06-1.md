## P126 `phone_parse` - Phone parsing offline (libphonenumber) + BR DDD -> UF table

- council: **approved**, priority P1, default_enabled=True, provider_tier=n/a, terms=open, opsec=passive, shares_input=False
- category: phone; group: G06; inputs: phone, text_blob; produces: 
- auth: none; key env vars: -; hosts: dadosabertos.anatel.gov.br, www.gov.br

### Final conditions (binding spec - implement every item)

1. Offline module phone/phone_parse (disclosure none, no network). python 'phonenumbers' (Apache-2.0) is an optional extra (requires_packages, pure-Python wheel); the core E.164 normalisation is reused (no second implementation); default_region comes from the existing setting (BR).
2. Output: validity, line type, E.164/national formats, geodescription (DDD -> city/state) and time zones. The carrier is labelled 'original carrier (portability not reflected)'.
3. Bundled data/br_ddd.json (DDD -> UF and main city) is generated by a maintainer script from Anatel's published numbering plan, with source and date, and registered in the P330 notices registry. The full city list per DDD comes from the brasilapi_ddd dataset (P127) when present.
4. PhoneNumberMatcher(text, 'BR') runs only inside text/file extraction (P172) with a match cap; extracted phones are PERSONAL_TYPES pivots with expand=False (AR07).
5. CPF region, DDD and CEP UF mismatches are weak consistency signals (people move): info only, never fraud verdicts.
6. The Anatel numbering open-data enrichment (number block -> original operator; 0800/0300/0303/4004/4003 holders) is deferred until its dataset URL is verified from the team network (the research egress got CONNECT 502); it will then be a registered dataset fetched by `v3lum data update`.
7. The current operator after portability is available only manually through ABR Telecom's 'consulta numero portado' page (reCAPTCHA): a manual pivot link (P128), never automated. Tests: BR mobile, landline and 0800 vectors, invalid numbers and the extraction cap.

Chair rationale: Approved 6-0 at median P1. All members want offline parsing with the 'original carrier' wording (portability); legal_dpo adds that region mismatches are weak signals. The architect's floor makes phonenumbers an optional extra, reuses the core E.164 code, bundles a generated DDD table and defers the Anatel part until its URL is verified. Offline: tier 'n/a', terms 'open'.

Synthesizer conditions (background; the final conditions win on conflict): python 'phonenumbers' (Apache-2.0): parse with default_region BR, validity, line type, geodescription (DDD -> city/state), time zones; PhoneNumberMatcher(text, 'BR') for extraction; carrier from libphonenumber is only the ORIGINAL assignee (portability) -> label 'original carrier'; bundled DDD -> UF table for offline cross-checks (CPF region vs DDD vs CEP). Gap fill: optional Anatel numbering open data (block -> original operator, non-geographic 0800/0300/4004 holders) once the dataset URL is verified from the team network (CONNECT 502 from research egress); portability means the block holder is only the original operator.
Notes: Validates and contextualises every phone with zero network calls.

### Final conditions (binding spec - implement every item)

1. Data-only pivot pack v3lum/data/pivot_links/phone.json for the P311 engine: spamcalls.net (https://spamcalls.net/en/num/{e164}, labelled 'user reports, unverified') and, after URL verification, ABR Telecom's 'consulta numero portado' page (current operator after portability; CAPTCHA, manual only). V3LUM never fetches any of these links.
2. Messaging links wa.me/{digits} and t.me/+{e164} are off by default (setting phone_messaging_links=false). When enabled they carry 'manual: opens the app with YOUR account; nothing is sent unless you type; use a team research device' and are never used as presence checks (P131 stays rejected).
3. Core links gets an {e164}/{digits} placeholder and encoder (today's placeholders cannot express digits without '+'), with tests; every template passes the P311 lint (https, declared host, value only in the path/query, no CPF).
4. TLP: at AMBER and above the links render as non-clickable text with 'opening sends <number> to <host>' (A2). privacy=true (P311): the links apply only to analyst-typed phone seeds, never to auto-discovered numbers, and stay hidden unless the analyst opts in for the case.
5. Link hosts carry registry tiers: spamcalls.net community, wa.me and t.me trusted, ABR Telecom trusted; the P311 lint rejects unknown-tier hosts for phone templates (A8). As a pivot-link pack it ships in phase 1 with the P311 engine (A16 BR1/BR4).

Chair rationale: Approved 6-0 at median P3; priority raised to P1 because A16 BR1 and BR4 (binding) ship every approved pivot-link pack in phase 1 even if related modules slip, and osint_investigator rated it P1 as the only step past parsing for phones. legal_dpo's floor makes the messaging links opt-in (they invite the presence checks rejected in P131) and non-clickable at AMBER+; analyst_ux's opsec label and the architect's placeholder work are included. A data pack with no network: tier 'n/a', terms 'open'.

Synthesizer conditions (background; the final conditions win on conflict): Verified template https://spamcalls.net/en/num/{e164}; manual link only (V3LUM never fetches it); add generated messaging links (wa.me/{digits}, t.me/+{digits}) as manual-only links without any automated presence check. Gap fill: manual messaging pivots wa.me/<E164> and t.me/+<E164> (generic pages for any number; never fetched, never presence checks).
Notes: Caller-reputation pivots for analysts.
