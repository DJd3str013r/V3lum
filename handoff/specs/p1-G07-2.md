## P173 `circl_hashlookup` - CIRCL hashlookup (known-good / NSRL + hash expansion)

- council: **approved**, priority P1, default_enabled=True, provider_tier=trusted, terms=open, opsec=passive, shares_input=True
- category: malware_hash; group: G07; inputs: md5, sha1, sha256, sha512; produces: md5, sha1, sha256
- auth: none; key env vars: -; hosts: hashlookup.circl.lu

### Final conditions (binding spec - implement every item)

1. Module malware_hash/circl_hashlookup: GET https://hashlookup.circl.lu/lookup/{md5|sha1|sha256}/{h} and the bulk endpoints (/bulk/md5, /bulk/sha1) for pasted lists. 404 = 'not in hashlookup' (EMPTY, no finding, coverage only; absent_statuses {404}), never clean. Registry provider circl (national CERT): tier trusted, terms open.
2. A hit is not automatically known-good: a record carrying KnownMalicious (EICAR -> malshare.com) gives a malware finding (medium); known_good is set only when the record has no KnownMalicious field and comes from NSRL/OS/vendor sets.
3. Wording 'known file: <product/OS> (<source set>)', never 'clean'. known_good dampens AV-consensus votes but never suppresses specific listings (KnownMalicious, MalwareBazaar, ThreatFox), LOLDrivers/LOLBAS/LOLRMM context (P268), YARA hits or internal sightings (P348); a conflict is shown as 'conflict: known file vs listed'.
4. parent/children records give other hash forms (hash expansion) as pivots. Internal file hashes disclose possession: disclosure third_party, so the TLP:RED gate applies. Fixtures: NSRL hit, EICAR KnownMalicious, 404; a test with a LOLDrivers hash present in NSRL keeps the BYOVD finding.

Chair rationale: Approved 6-0 at median P1. The KnownMalicious gap fill is unanimous; cti_lead and analyst_ux add that 'known file' never hides BYOVD/LOLBin context or specific listings, and legal_dpo notes the TLP:RED gate because hashes disclose possession.

Synthesizer conditions (background; the final conditions win on conflict): lookup/{md5|sha1|sha256}/{h} (404 = unknown, not malicious); bulk endpoints for pasted lists; known-good hits set known_good and suppress malware scoring; parent/children give other hash forms (hash expansion). Free for corporate use. Gap fill: a hashlookup hit is NOT automatically known-good: records can carry 'KnownMalicious' (EICAR -> 'malshare.com'); set known_good only when the record has no KnownMalicious field and comes from NSRL/OS/vendor sets; KnownMalicious -> malware finding (medium).
Notes: First stop in the hash chain: removes known-good files from triage.

## P175 `yaraify` - YARAify lookup_hash (abuse.ch)

- council: **approved**, priority P1, default_enabled=True, provider_tier=trusted, terms=open, opsec=passive, shares_input=True
- category: malware_hash; group: G07; inputs: md5, sha1, sha256, sha512; produces: malware_family

- sources shared with other proposals: {"C0413": ["P351"]}

### Final conditions (binding spec - implement every item)

1. Module malware_hash/yaraify: POST https://yaraify-api.abuse.ch/api/v1/ with {'query':'lookup_hash','search_term':<hash>} only; file scan and upload endpoints are never built (unit test). Terms 'open': YARAify is CC0 for commercial and non-commercial use (abuse.ch terms s.3.4, A1 BR14), so it runs under corporate even while MalwareBazaar is licence-gated.
2. The shared abuse.ch Auth-Key ('abusech') is sent on every call (terms s.2.1: authenticated users only; a keyless answer is not a permission). Without the key the module returns NEEDS_KEY with the manual YARAify link. The key is redacted everywhere (AR01).
3. query_status no_results = EMPTY 'unknown to YARAify' (not clean); illegal_* -> SKIPPED reason_code 'not_applicable'.
4. At most 5 matched rule names with authors, mapped to a family when the rule is family-specific (alias index P295); generic/heuristic rules (SUSP_, PUA, Generic, Heuristic, packer/UPX/installer rules) are low-confidence context and never above low alone.
5. Metadata imphash/ssdeep/tlsh/telfhash/gimphash/dhash_icon become structural attributes for P351. YARAify belongs to the abuse.ch upstream family (P171). Fixtures: EICAR hit, no_results, 401.

Chair rationale: Approved 6-0. The median is P2 (cti_lead and legal_dpo voted P1); the chair raises it to P1 because, as cti_lead argued, it is the corporate-safe hash source while MalwareBazaar is licence-gated and VirusTotal public is non-commercial, and the A3 minimum answer set needs default-ready sha256 reputation sources under corporate from the first phase; effort S. cti_lead's and osint_investigator's reading of terms s.2.1 (send the Auth-Key; keyless answers are not relied upon) is stricter than the draft and adopted; analyst_ux's generic-rule cap is kept.

Synthesizer conditions (background; the final conditions win on conflict): POST {'query':'lookup_hash'} worked without key (observed); query_status no_results = unknown; matching YARA rule names -> family hints; CC0 data. Gap fill: lookup_hash answered keyless on 2026-11-25 (abuse.ch terms: YARAify, Feodo and SSLBL free without limitation): run keyless, send the Auth-Key when configured; metadata also gives imphash/ssdeep/tlsh/telfhash/gimphash/dhash_icon for structural pivots.
Notes: Free YARA-rule matches for known samples.

## P267 `file_hashing` - Local file hashing (MD5/SHA-1/SHA-256/SHA-512, ssdeep via ppdeep, TLSH) + hash type identification

- council: **approved**, priority P1, default_enabled=True, provider_tier=n/a, terms=open, opsec=passive, shares_input=False
- category: file_analysis; group: G07; inputs: file, md5, sha1, sha256, sha512, ssdeep; produces: md5, sha1, sha256, ssdeep
- auth: none; key env vars: -; hosts: -
- sources shared with other proposals: {"C0627": ["P351"]}

### Final conditions (binding spec - implement every item)

1. Offline module file_analysis/file_hashing (disclosure none): regular files only (os.stat S_ISREG; FIFOs, devices and sockets are refused so /dev/zero cannot hang a run), streamed in 1 MB chunks with ctx.cancelled() checks; MD5, SHA-1, SHA-256 and SHA-512 always.
2. ssdeep via ppdeep (pure Python, Apache-2.0, optional extra) only for files <= 50 MB. TLSH computation is omitted in this build because py-tlsh ships no wheels; TLSH values returned by providers are kept as attributes.
3. Hash-type identification is a shared detector helper with ambiguity flagged (sha256 vs certificate fingerprint): non-TTY runs try both readings, a TTY may let the analyst choose. Identification only: no cracking and no plaintext lookup (hashes.com, CrackStation, ntlm.pw excluded); password-hash formats are only labelled.
4. Emitted hash entities feed the hash chain (P173 first). Tests: a regular file, FIFO refusal, large-file streaming and the ambiguity handling.

Chair rationale: Approved 6-0 at median P1. The architect's floor (regular files only, no wheel-less compiled dependency) and analyst_ux's non-TTY 'try both' rule are added to the unanimous identification-only scope. Offline: tier 'n/a', terms 'open'.

Synthesizer conditions (background; the final conditions win on conflict): Hash files locally (stream, any size) and emit hash entities for the hash chain; ppdeep (pure-Python ssdeep, Apache-2.0) and py-tlsh optional extras; hash type identification by length/charset with ambiguity (sha256 vs cert fingerprint) resolved by asking or trying both.
Notes: Entry point for file inputs into hash reputation modules.

- council: **approved**, priority P1, default_enabled=True, provider_tier=n/a, terms=open, opsec=passive, shares_input=True

### Final conditions (binding spec - implement every item)

1. Read-only adapters cti_framework/misp_sightings and opencti_sightings (P1) and thehive_sightings (P2, A12): plain requests clients (no PyMISP/pycti dependency), each enabled only when URL and key are configured via `v3lum keys` (least-privilege read-only service accounts). MISP restSearch lands first; OpenCTI and TheHive land when synthetic fixtures for their documented versions exist.
2. disclosure 'internal' (allowed at TLP:RED) only for instances operated by the company or a contracted processor; community, sector-ISAC or shared instances and sharing groups are third_party providers with tier and terms. The SSRF guard lets these adapters reach only their configured internal hosts.
3. TLS verification is always on with the ca_bundle setting; no verify=False exists anywhere. Read-only in code: a per-platform method+path allow-list (MISP restSearch and sightings reads, OpenCTI queries without mutations, TheHive search) with a test that refuses add/edit/mutation calls; a startup check warns when a configured key has write permissions.
4. Values travel only in JSON bodies or GraphQL variables, never interpolated into query strings. <= 50 results per value; per-run request cap (<= 2 req/s per platform); TIP lookups time out after 5 s; a failure means could not verify (rule 5).
5. MISP: to_ids=false attributes are context only (no malicious tag); decay scores, false-positive sightings and warninglist hits returned by restSearch are honoured. OpenCTI: x_opencti_score, revoked and valid_until (expired -> historical, low).
6. Every hit carries event/case id, org, TLP/marking and date as references. Source markings are respected and never downgraded: Finding.tlp is stored per finding, the higher of platform and case TLP applies, and renderers omit findings above the report TLP.
7. Galaxy/actor tags become attributed_to pivots with expand=False, names kept unchanged for STIX/MISP round-trips. No write-back, sightings or sharing from V3LUM: export happens only through the explicit P303 command.
8. Covert red-team exercises: a case flag --covert (alias --no-internal), recorded in the case, skips internal lookups, because TIP and SIEM query logs would show the SOC the red team's own infrastructure.
9. Report: internal sightings first ('known internally: MISP event #N, TheHive case #M'); query order case DB (P375) -> MISP/OpenCTI -> TheHive. Synthetic fixtures per platform version.

Chair rationale: Approved 6-0 at median P1, consistent with A12. legal_dpo's floor limits 'internal' to company-operated or contracted instances; the architect's floor requires plain clients, injection-safe queries, the ca_bundle setting and per-finding TLP; redteam_lead adds code-enforced read-only allow-lists and the covert-exercise skip; cti_lead's to_ids/decay semantics and analyst_ux's 5 s fail-soft timeout are kept. The architect's 'drop runs FIRST' is honoured (results merge regardless of order; the report lists them first). Internal platform: tier 'n/a'.

Synthesizer conditions (background; the final conditions win on conflict): Each adapter enabled only when its URL + key are configured (read-only service accounts); runs FIRST in the pipeline; plain HTTP clients (PyMISP 3.x needs Python >= 3.11, pycti must match the platform version); results carry the source event/case TLP and are never written into lower-TLP reports; galaxy/actor tags become attributed_to pivots with expand=False; new disclosure class 'internal' (value leaves the workstation but stays inside the organisation) allowed for TLP:RED by policy_as_code, distinct from shares_input=False (offline) and third-party; per-run request cap to protect the servers.
Notes: Answers 'have we seen this before, in which event/case?' and is the only enrichment allowed for TLP:RED besides offline modules.
