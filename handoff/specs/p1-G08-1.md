## P182 `cisa_kev` - CISA Known Exploited Vulnerabilities

- council: **approved**, priority P1, default_enabled=True, provider_tier=n/a, terms=open, opsec=passive, shares_input=False
- category: vulnerability_cve; group: G08; inputs: cve, keyword; produces: 
- auth: none; key env vars: -; hosts: cisa.gov

### Final conditions (binding spec - implement every item)

1. Offline module vulnerability_cve/cisa_kev: known_exploited_vulnerabilities.json from www.cisa.gov registered with register_dataset (TTL 6 h; US public domain) and indexed locally by cveID; zero per-CVE requests (disclosure none, TLP:RED-safe).
2. It sets kev=true, dateAdded, dueDate, vendor/product and knownRansomwareCampaignUse on the CVE entity; knownRansomwareCampaignUse='Known' is shown as its own flag.
3. Asset severity is decided only by CR15 (P291): a KEV CVE inferred from a version string or CPE (InternetDB/Shodan banners) caps at HIGH, labelled 'version-inferred, backports not considered'; CRITICAL needs verified evidence on an own or in-scope asset.
4. 'Not in KEV' never reads 'not exploited'. Dataset age is shown in coverage and doctor flags a copy older than 48 h. kev stays CISA-only: VulnCheck, CIRCL, MSRC and EUVD exploitation evidence goes to the exploited attribute.

Chair rationale: Approved 6-0 at median P1. redteam_lead's condition binds severity to the verified/inferred split of P291 (backported banners are the classic false CRITICAL); analyst_ux adds the 'not in KEV' wording. Offline dataset: tier 'n/a', terms 'open'.

Synthesizer conditions (background; the final conditions win on conflict): Download known_exploited_vulnerabilities.json every 6 h (register_dataset), local set lookup -> kev=true, dateAdded, knownRansomwareCampaignUse, dueDate; critical tag when found on an org asset (CR15).
Notes: Top prioritisation signal for exposed CVEs.

## P183 `cve_record` - CVE record (MITRE cveawg + NVD 2.0 + CWE)

- council: **approved**, priority P1, default_enabled=True, provider_tier=trusted, terms=open, opsec=passive, shares_input=True
- category: vulnerability_cve; group: G08; inputs: cve, keyword; produces: keyword
- auth: none; key env vars: V3LUM_NVD_KEY; hosts: cveawg.mitre.org, services.nvd.nist.gov, nvd.nist.gov, cwe-api.mitre.org

### Final conditions (binding spec - implement every item)

1. Module vulnerability_cve/cve_record. Precedence: offline mirror (P352) when present -> cveawg.mitre.org/api/cve/{id} (CNA and CISA ADP containers: CVSS, SSVC, KEV ADP) -> NVD 2.0 services.nvd.nist.gov/rest/json/cves/2.0?cveId= only when CPE configurations are needed (seed CVEs or has_vuln on an org asset) or key 'nvd' is set. NVD web pages are an SPA: links only.
2. NVD keyless 5 req/30 s (50 with key 'nvd', V3LUM_NVD_KEY alias, from a team account) as a P334 token bucket that defers instead of sleeping in a worker; per-case NVD budget of 10 keyless calls. CWE names come from a registered CWE dataset, never a per-CVE CWE REST call.
3. CVE fan-out rule shared by P181, P183, P184's API fallback, P185, P186, P188-P191 and the P354 VEX adapter: online per-CVE calls run for seed CVEs and for at most setting cve_fanout_budget (default 20) pivot CVEs per case, KEV/EPSS-ranked first; the rest are answered offline (P182, P184, P352) or listed as deferred.
4. One shared CVE 5 parser (with P181 and P352). REJECTED/RESERVED records -> info, never scored. Cache 24 h.
5. One consolidated CVE card per CVE (P335 grouping): CVSS with source/version, EPSS + percentile with date, KEV (dateAdded, ransomware use, due date), exploitation evidence by source, exploit availability (curated count + links), vendor fix (KB/advisory/fixed versions) and affected products; the other CVE modules add fields with provenance instead of separate findings.
6. One plain-words priority line (e.g. 'KEV + EPSS 0.97: patch now'). A bare CVE lookup shows that patch-priority label instead of a case risk level unless the CVE is linked to an own asset (CR15). Test: 5 CVE modules on one CVE fixture give one card and no CRITICAL case level.
7. Notices: 'This product uses data from the NVD API but is not endorsed or certified by the NVD.' wherever NVD data appears (v3lum info, report footer); MITRE's CVE/CWE copyright designation and licence in THIRD_PARTY_NOTICES. Registry providers mitre and nist_nvd: tier trusted, terms open.

Chair rationale: Approved 6-0 at median P1. legal_dpo's notices, the architect's precedence, token bucket and fan-out budget (NVD's keyless rate would stall workers when InternetDB yields 30 CVEs per IP) and analyst_ux's consolidated CVE card with a patch-priority line are combined; the fan-out rule is defined here once for every per-CVE module in this chunk.

Synthesizer conditions (background; the final conditions win on conflict): cveawg.mitre.org/api/cve/{id} first (CNA + CISA ADP containers: CVSS, SSVC, KEV ADP), NVD 2.0 ?cveId= for CPE configurations (5 req/30 s keyless, 50 with V3LUM_NVD_KEY; NVD web pages are now an SPA - links only), CWE REST for weakness names; normalise cvss/cvss_vector/cwe/affected products; cache 24 h.
Notes: Authoritative CVE data for every CVE pivot.

### Final conditions (binding spec - implement every item)

1. Offline module vulnerability_cve/epss (disclosure none, TLP:RED-safe, default_enabled True): the daily bulk CSV (gz) registered with the dataset manager (safe decompression, size cap) and indexed locally; zero per-CVE calls, so 500-CVE scanner exports cost nothing.
2.
