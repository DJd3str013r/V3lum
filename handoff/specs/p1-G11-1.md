## P169 `warninglists` - MISP warninglists compact bundle (false-positive suppression + context tags)

- council: **approved**, priority P1, default_enabled=True, provider_tier=trusted, terms=open, opsec=passive, shares_input=False
- category: threat_intel_ioc; group: G11; inputs: ipv4, ipv6, cidr, domain, url, md5, sha1, sha256; produces: 
- auth: none; key env vars: -; hosts: github.com, raw.githubusercontent.com
- upgrades existing module: core/noise.py

### Final conditions (binding spec - implement every item)

1. Bundle: a compact build made by a reproducible dev script pinned to a MISP warninglists commit, CI size budget <= 3 MB gzip, only string, hostname and cidr list types (regex lists excluded: Python re has no timeout; substring lists only if bounded). Refresh through the dataset manager (`v3lum data update warninglists`, weekly TTL); doctor shows the age.
2. Matching is offline (disclosure 'none') and lazy (loaded on first use, not at start-up): CIDR lists go into the one shared IP interval index used for noise, blocklists and cloud ranges; hostnames into sets keyed by PSL registrable domain plus subdomain match; no string suffix matching. It merges into core/noise.py (AR06).
3. Three outcomes. SUPPRESS (infrastructure values only: bare IP, CIDR, domain, hash): reserved/RFC ranges, public resolvers, empty-file hashes; recorded, not pivoted, shown as 'likely benign because <list> (<version date>)'. TAG: cloud, CDN, scanner, Tor, VPN, sinkhole, dynamic DNS, URL shortener, disposable mail, user-content hosting.
4. TOP-SITE (Tranco, Umbrella, Radar lists) only tags 'popular site' and down-weights registrable-domain reputation; it never suppresses URL-level, subdomain or hash verdicts (cti_lead, analyst_ux).
5. User-content and dynamic-DNS parents (docs/sites/drive/forms.google.com, storage.googleapis.com, *.blob.core.windows.net, SharePoint, github.io, blogspot, firebaseapp, pages.dev, workers.dev, ngrok, duckdns...) are never suppressed, even in a top list. A URL with a path or query on any listed domain is tagged hosted_on_legit_platform and still investigated (AR06).
6. Never silent and never destructive: a hit never deletes findings or entities; SUPPRESS lowers the confidence of verdicts on that entity, TAG lists add context only and never lower a direct malicious finding, and a match never overrides a malicious TI finding on the same entity (it is displayed next to it). The analyst can override per entity.
7. Sinkholes: a match sets is_sinkhole; a domain resolving to a sinkhole is tagged sinkholed (formerly malicious), never counted as live C2, with 'hits = infected clients, not attacker infrastructure'. EICAR and test-file hashes are tagged test_file and shown. Sinkhole and parking-NS lists ship with the bundle and vocab gains sinkhole, parked, benign_scanner (AR06).
8. Display: the terminal shows one collapsed line 'N indicators suppressed as known-benign (lists...)'; HTML/JSON list each match with list name and version. Cloud/CDN/scanner tags feed the P378 third_party_hosted tag and the A7 CDN exclusion.
9. Licence (A6): MISP warninglists are CC0 and may be bundled; the X4BNet-derived VPN/datacenter lists keep their MIT notice in THIRD_PARTY_NOTICES. Heavy top-1M and known-good-hash lists are optional `v3lum data update` downloads, never bundled or fetched mid-scan.
10. Tests: fixtures for 8.8.8.8, 1.1.1.1, google.com, a CDN IP, a sinkhole IP and the EICAR hash, plus regressions: a phishing-feed URL on docs.google.com stays flagged and a sites.google.com phishing URL extracted from a pasted e-mail is investigated and scored (today core/noise.py marks it as noise).

Chair rationale: Approved 6-0 at median P1: the main false-positive control for every IOC verdict (CR27 needs it). The architect's floor sets the build: pinned compact bundle under 3 MB, no regex lists, lazy load, one shared IP interval index, merge into core/noise.py. cti_lead, osint_investigator and analyst_ux insisted that abused big platforms must never be silenced, so SUPPRESS applies to infrastructure values only and top-site lists only tag. The confidence conflict (architect: hits lower confidence; analyst_ux: tags never lower a malicious finding) is resolved per outcome. legal_dpo confirmed CC0/MIT bundling under A6. The dataset provider (MISP project) is trusted, terms open.

Synthesizer conditions (background; the final conditions win on conflict): Bundle a compact build (95 lists, 340k entries, 2.26 MB gzip, ~1 s load; CC0, X4BNet lists keep MIT notice); two outputs: SUPPRESS (RFC ranges, public DNS, top sites, empty-file hashes, EICAR) and TAG (cloud, CDN, scanner, Tor, VPN, sinkhole, dynamic DNS, URL shortener, disposable mail); never drop silently: show 'likely benign because <list>'; heavy top-1M/known-good-hash lists optional downloads.
Notes: Main false-positive control for every IOC verdict (CR27 needs it).

## P292 `attack_index` - MITRE ATT&CK compact index (STIX bundle at runtime + TAXII update check)

### Final conditions (binding spec - implement every item)

1. A compact offline index (Enterprise + Mobile + ICS ATT&CK; CAPEC 2.1 optional; ~0.27 MB gzip) with ATT&CK version, build date and the MITRE notice (data/NOTICE and the report footer). Matching is offline (disclosure 'none'); the index loads in < 100 ms.
2. Shipping (A6): the prebuilt index ships inside the release only after legal records that the MITRE ATT&CK/CAPEC Terms of Use (royalty-free, commercial use allowed with the notice reproduced) are permissive for bundling; until then `v3lum data update attack` builds it on first run (first-run hint).
3. Rebuild: the ~55 MB STIX bundles (raw.githubusercontent.com attack-stix-data, index.json for versions) are streamed through the dataset manager and parsed object by object (no json.load of the whole bundle); a slow test on a synthetic 50 MB bundle asserts bounded memory. Never during a scan. TAXII 2.1 (attack-taxii.mitre.org) only detects a newer version.
4. Revoked and deprecated objects are dropped and a revoked-by map kept (T1656 -> T1684.001); an analyst-typed revoked id renders 'revoked -> replaced by T1684.001', never a silent rewrite. Tactic names and order are read from the data (v18+ renames, e.g. Stealth and Defense Impairment); none are hard-coded.
5. Detection normalises T1059/001 and t1059.001 to T1059.001; text_blob inputs are handled by the P172 extractor. Detections come from x-mitre-detection-strategy objects.
6. Exports: STIX uses the official ATT&CK STIX ids (attack-pattern--..., intrusion-set--...), MISP uses galaxy tags (misp-galaxy:mitre-attack-pattern="Name - T1059.001"); no regenerated ids. The ATT&CK version is recorded per case and in report footers.
7. Cards show name, tactics from the data, at most 10 related groups/software and the attack.mitre.org link. Group/software 'uses' edges are context, never attribution evidence; CWE -> CAPEC -> ATT&CK links carry low confidence.
8. Provider: MITRE (trusted tier); downloads only, no value sent. Fixtures: a trimmed real bundle slice (Enterprise, Mobile, ICS objects incl. a revoked technique) plus the TAXII captures.

### Final conditions (binding spec - implement every item)

1. Sources (legal floor): bundle only the MISP galaxy clusters (dual CC0/BSD-2; keep their notices, MITRE-derived clusters keep the ATT&CK notice) and the Microsoft threat actor naming map (CC BY 4.0, attributed). ETDA/ThaiCERT Threat Group Cards have no licence: fetched at runtime (getmisp.cgi export, weekly), attributed, never bundled or redistributed.
2. ETDA publishes no licence or terms, so under A1 its source class is 'unknown' until legal records it in the provider registry (legal_dpo's 'runtime fetch, attribution, no redistribution' is the proposed basis). Until then ETDA is not fetched, the index runs on the galaxy and MSTIC sources, and Module.terms stays 'open'.
3. APTmap (CC BY 4.0, GitHub Pages URL; raw path 404) is an optional dataset outside the default update set; CyCat is excluded until a useful fixture exists. Malpedia family ids come from the bundled galaxy 'malpedia' cluster, so joins never depend on the non-commercial Malpedia API. Source versions are recorded.
4. No transitive mega-clusters: every alias edge keeps source, kind (synonym vs overlaps/similar/associated), date and confidence. An exact synonym resolves to its cluster; overlapping clusters are listed as overlaps_with, never merged. Clusters merge only through the same MITRE G/S id, an explicit MSTIC mapping or a source's explicit synonym assertion, never on normalised-name equality alone.
5. Over-merge guards (architect): a stop-list of generic aliases (unknown, apt, group, team, short tokens); no merge that would put two different MITRE G ids or two Malpedia actor ids in one cluster; no merge through an alias present in clusters of several sources without a shared id; a cluster-size alarm and a build-time collision report that fails CI unless reviewed.
6. Ambiguity: umbrella names (Lazarus, Winnti/APT41, TA505, FIN7/Carbanak...) are flagged and return candidates with a disambiguation note; a lookup hitting more than one primary actor returns the alternatives ('X: APT41 (MISP) / Winnti (ETDA)'). Actor and malware namespaces stay separate, so an ambiguous input returns both cards.
7. Normalisation: lowercase and strip spaces, dashes and underscores ('APT 28' -> 'apt28'). Cards show the canonical name, up to 10 aliases with the source asserting each ('X = Y according to <source>'), worded 'vendor assessment, not identity'. ETDA card links use ?u={uuid}.
8. Offline lookup (disclosure 'none'); refresh weekly through the dataset manager. Dataset providers: MISP project/CIRCL, Microsoft, MITRE and ETDA/ThaiCERT, all trusted tier. Used by P203, P219, P254, P372 and the console to tell malware names from usernames (AR18).
9. Regression tests: APT28 vs APT29, Lazarus vs Kimsuky, Conti vs Black Basta stay separate; Brazilian banking families (Grandoreiro, Mekotio, Casbaneiro, Guildma/Astaroth, Mispadu) resolve through galaxy/Malpedia ids; fixtures include known conflicting aliases.
