## P269 `document_metadata` - PDF/Office metadata (authors, software, internal paths, macros, remote templates)

- council: **approved**, priority P1, default_enabled=True, provider_tier=n/a, terms=open, opsec=passive, shares_input=False
- category: file_analysis; group: G12; inputs: file, url; produces: username, person_name, url, domain
- auth: none; key env vars: -; hosts: -

### Final conditions (binding spec - implement every item)

1. FILE input only: this passive module never fetches URLs. An analyst-typed URL is downloaded only by the shared LIGHT file fetcher (--mode light, after the passive lane, P376 hostile-host guard fail closed, core address guard, 20 MB cap, P334 LIGHT budget, P324 ledger, archived copy preferred), which hands the module a file.
2. Ownership: core/sandbox.py (used by P259, P261, P264, P271, P272, P287, P363, P364, P367, P368) and the shared LIGHT file fetcher (used by P259, P261, P287, P364) are core pieces built with this P1 item; no module writes its own (no chunk-D AR action owns them).
3. The fetcher is LIGHT target contact (A7): analyst-typed seed URLs only (never pivots, BR5), GET only, ua_light UA, <= 1 req/s and <= 25 requests per host per scan, manual redirects re-checked by the guards. URLs that probably carry a per-recipient token (an org_profile e-mail in plain, URL-encoded or base64 form, or an opaque token >= 16 chars) need a per-URL confirmation (BR15).
4. Merge gate for the fetcher: it is LIGHT, so it is not merged or enabled before the AR20 safety suite passes (A16 BR6); until then URL inputs of the file modules get the manual pivot link and the passive modules keep working on FILE inputs.
5. Parsing runs in the shared file-analysis sandbox core/sandbox.py: a python -I child process with a wall timeout, POSIX rlimits (memory <= 1 GiB, CPU, no file writes), input cap 100 MB and JSON output cap 1 MB; doctor reports the reduced isolation on Windows. Downloaded data is never executed. The wall timeout matters: pypdf has had infinite-loop CVEs on crafted PDFs.
6. Formats: PDF info and XMP via pypdf (BSD-3; dates D:YYYYMMDDHHmmSSOHH'mm' parsed to ISO); OOXML/ODF docProps through the core safe archive helper (member count, total size and ratio caps) and the safe XML helper (DOCTYPE and entity declarations rejected); OLE metadata and VBA presence via olefile (BSD); .msg through olefile streams (__substg1.0_*), not the GPL extract-msg.
7. oletools is only an optional extra for olevba keywords (it pulls extra dependencies); macros are never executed, documents never rendered, and encrypted files never decrypted with guessed passwords.
8. External relationships (TargetMode=External, attachedTemplate, remote OLE/frame links, UNC and WebDAV paths, external hyperlinks) become hostile url/domain pivots tagged remote_template, for passive modules only; they are never fetched or resolved over HTTP, SMB or WebDAV (fetching is the beacon that tells the sender the document was opened).
9. Severity table (tested): remote template / external relationship = HIGH (T1221); auto-exec macro (AutoOpen, Document_Open, Workbook_Open), XLM 4.0 macro sheets and DDE fields = HIGH, worded 'suspicious' unless a hash/family source confirms; macro present = MEDIUM; PDF /Launch or /JavaScript with /OpenAction = HIGH, /EmbeddedFile = MEDIUM; PDF URIs = url pivots.
10. Personal data (legal floor): author, lastModifiedBy and company are INFO attributes; author names become person_name pivots (relation document_author) and C:\Users\<name> paths username pivots (relation local_account), both expand=False with the privacy tag and never auto-checked by username, e-mail or person modules (A5).
11. Internal paths, usernames and author names are redacted in external sharing exports (STIX/MISP) unless the analyst passes --include-personal (recorded). One summary line per document.
12. Tests on synthetic fixtures built in tests: the research PDF/DOCX prototypes, a docx with a remote template, an XXE docx, a zip-bomb docx, a macro-bearing OLE file and a PDF with OpenAction.

Chair rationale: Approved 6-0 at median P1: phishing attachments are a daily input. The architect's floor sets the sandbox, FILE-only input, safe archive/XML helpers and the olefile baseline with oletools optional. redteam_lead, cti_lead and osint_investigator insisted that remote templates and UNC links are recorded and never touched. legal_dpo's floor keeps author names and usernames from triggering sweeps and out of exports. analyst_ux's severity table is adopted with cti_lead's 'suspicious, not malicious' wording. Audit: this item also owns core/sandbox.py and the shared LIGHT file fetcher, which carries the A7 LIGHT limits, the token-URL rule and the AR20 gate.

Synthesizer conditions (background; the final conditions win on conflict): pypdf (BSD-3) info + XMP; OOXML/ODF docProps via stdlib zipfile + defusedxml, external relationships (attachedTemplate/remote template injection -> url pivots), oletools/olefile (BSD) for VBA macro presence/auto-exec keywords and OLE metadata; zip-bomb limits (member count, ratio); never execute macros or render documents.
Notes: Internal usernames/software versions and maldoc indicators from documents.

## P270 `file_type_sniff` - File type detection (own magic table; filetype/Magika/libmagic optional; hachoir ideas)

- council: **approved**, priority P1, default_enabled=True, provider_tier=n/a, terms=open, opsec=passive, shares_input=False
- category: file_analysis; group: G12; inputs: file, text_blob; produces: 
- auth: none; key env vars: -; hosts: -

### Final conditions (binding spec - implement every item)

1. Offline module: disclosure 'none' (no network at all; ScopedHttp refuses any request), terms 'open', provider tier 'n/a'; allowed at TLP:RED. Exposed as a library function that every file module calls, so routing logic is not duplicated.
2. An own magic table (bundled data with offsets, tested per type) is the default and needs no dependency. It covers at least PE, ELF, Mach-O, ZIP, OOXML, OLE, PDF, RAR, 7z, ISO, LNK, MSI, OneNote, APK/JAR and script types (HTA, JS, VBS, PS1, batch by heuristics), so every approved file parser is reachable.
3. It reads at most the first 64 KB plus the zip central directory (through the safe archive helper) to tell OOXML, APK and JAR apart.
4. Licences (A6): filetype.py (MIT) may be an optional extra; Magika (onnxruntime) and python-magic (system libmagic) are not used in this build; hachoir (GPL-2.0) is never imported or bundled.
5. Findings, tested: executable content behind a document or image extension, or a double extension such as invoice.pdf.exe = HIGH; other extension/content mismatches = MEDIUM; polyglots (e.g. PDF+ZIP) = MEDIUM at POSSIBLE confidence. Shown as 'claimed .pdf, actually PE32 executable'.
6. Fixtures: tiny synthetic files per type generated in tests, plus a double-extension PE and a PDF+ZIP polyglot.

Chair rationale: Approved 6-0 at median P1 (redteam_lead voted P2). The architect's floor: a dependency-free bundled magic table, a 64 KB read limit, no Magika/libmagic in this build and a shared routing function. legal_dpo and every member keep hachoir (GPL) out, per A6. cti_lead's coverage list makes every approved parser reachable; analyst_ux's severity and wording are adopted.

Synthesizer conditions (background; the final conditions win on conflict): Own magic-byte table first (no dependency); optional extras filetype.py (MIT), Magika (Apache-2.0, ML), python-magic (libmagic); hachoir is GPL-2.0 -> ideas only; flag extension/content mismatches (double extensions, polyglots).
Notes: Routes files to the right analyzer and flags disguised payloads.

2. 8. Fixtures: a minimal benign APK built in tests (v1 and v2 signed) plus malformed-zip variants (duplicate entries, bad central directory, bomb ratio).

## P365 `archive_listing` - Archive and disk-image listing (ZIP/TAR/RAR/7z/ISO) with bomb and depth limits

- council: **approved**, priority P1, default_enabled=True, provider_tier=n/a, terms=open, opsec=passive, shares_input=False
- category: file_analysis; group: G12; inputs: file; produces: file
- auth: none; key env vars: -; hosts: -

### Final conditions (binding spec - implement every item)

1. Offline module: disclosure 'none' (no network at all; ScopedHttp refuses any request), terms 'open', provider tier 'n/a'; allowed at TLP:RED. Built on the single core safe archive helper shared with the dataset manager, P269 and P364: zipfile/tarfile (filter='data') listing by default; members are never executed.
2. Limits: total uncompressed <= 500 MB, ratio <= 100, members <= 10,000, nesting depth <= 3. Names with absolute paths, '..', drive letters, symlinks, hardlinks or devices are flagged and never extracted.
3. Extraction only with an explicit flag, into a fresh 0700 temp dir that is deleted after the run.
4. Encrypted members are listed and decrypted only with an analyst-supplied password; the conventional sample passwords ('infected', 'malware') only as an explicit option; never guessed or brute-forced.
5. Licences (A6): rarfile (ISC; header listing only, no unrar extraction), py7zr (LGPL-2.1+) and pycdlib (LGPL-2.1) only as unmodified optional extras imported dynamically. VHD/VHDX are reported, never mounted.
6. Rule 3 (legal floor): archives recognised as stealer-log or leak bundles (members such as Passwords.txt, Cookies, Autofill, wallet files) are listed only as names, sizes and counts, never extracted, parsed or printed beyond member names.
7. Findings: containers that defeat Mark-of-the-Web (ISO/IMG/VHD holding LNK/EXE/JS/HTA) are suspicious; executables, scripts and double extensions inside are flagged; small members are hashed in memory and emitted as hash pivots (at most 50 per archive) routed to P270 and hash lookups under the case TLP (no external lookups at RED).
8. Fixtures: synthetic zip/tar/ISO files plus path-traversal, symlink, bomb, encrypted and stealer-bundle-like samples generated in tests.

Chair rationale: Approved 6-0 at median P1 (osint_investigator and redteam_lead voted P2). The architect's floor: one hardened archive helper with tested limits, listing by default, no guessed passwords, LGPL extras only dynamically. legal_dpo's rule 3 floor keeps stealer bundles metadata-only. cti_lead's Mark-of-the-Web finding and TLP-bound member lookups are adopted.

Synthesizer conditions (background; the final conditions win on conflict): Listing by default (names, sizes, encryption, double extensions, nested containers up to depth 3); extraction only with an explicit flag into a temp dir with size/ratio/count limits and path-traversal guards; rarfile/py7zr/pycdlib optional extras (LGPL libraries imported dynamically, not vendored); VHD/VHDX reported, not mounted; small members hashed and passed to file_type_sniff and hash lookups.
Notes: ISO/ZIP/RAR wrappers carry the LNK/MSI/JS payloads analysts receive.
