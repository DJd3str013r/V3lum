## P004 `hostio` - host.io domain relations (keyed)

- council: **approved**, priority P2, default_enabled=True, provider_tier=trusted, terms=key-terms, opsec=passive, shares_input=True
- category: domain_dns; group: G01; inputs: domain, analytics_id; produces: domain, ipv4, analytics_id
- auth: free_key; key env vars: V3LUM_HOSTIO_TOKEN; hosts: host.io

### Final conditions (binding spec - implement every item)

1. Requires key 'hostio', registered once in config.KNOWN_KEYS (env V3LUM_KEY_HOSTIO; V3LUM_HOSTIO_TOKEN/V3LUM_HOSTIO_KEY only as aliases). Without it: NEEDS_KEY. The token goes in a header if the API supports it; otherwise as a query parameter registered with the central redactor (AR01).
2. Key-terms: the key belongs to a company/team account, never an analyst's personal free account, on a plan whose terms permit internal business use. The plan (key_plans.hostio) and terms URL are recorded in the registry before it runs under the corporate profile (A1).
3. Endpoints: /api/web/{domain}, /api/related/{domain} and /api/domains/{field}/{value} for googleanalytics, adsense, redirects, backlinks and ipinfo. run_on='seeds'; pivots only on explicit -M. Monthly budget via the P334 quota block (<= 80% of the plan); at most 5 requests per entity (max_requests 5). cache_ttl 7 days.
4. Reverse analytics/AdSense results follow the P061 rules: an id seen on > 50 domains is a shared agency/platform id (no same_analytics link); an id shared with an org_profile own site on a non-own site is a clone indicator, not a same-owner link; same_analytics confidence is at most PROBABLE (<= 0.7).
5. Redirect relations are recorded with their dates. Backlinks become links_to pivots with expand=False. Results are ownership candidates for the analyst, never scope.
6. Errors in 200 bodies are mapped through P321 markers: invalid key -> NEEDS_KEY, quota -> QUOTA, throttling -> RATE_LIMITED, never EMPTY.
7. Merge only with a trimmed real success fixture captured with the team key, plus an error fixture (architect floor). The web view https://host.io/{domain} is the manual_link.

Chair rationale: Approved 6-0 at median P2 (architect and analyst_ux voted P3). legal_dpo's floor is the key-terms rule (company account, recorded plan). The architect's floor: one key name with aliases, header token or redaction, the core monthly budget, seeds-only through run_on (AR07 now provides it), and a real fixture before merge. cti_lead and osint_investigator: the P061 shared-id rule and the confidence cap. Key-required sources may be default-enabled (A3 BR5). host.io is a commercial API with published terms and paid plans: tier trusted.

Synthesizer conditions (background; the final conditions win on conflict): Requires V3LUM_HOSTIO_KEY; use /api/web, /api/related, /api/domains/{field}/{value} (backlinks, redirects, ipinfo, googleanalytics/adsense reverse) with monthly budget; reverse analytics hits are strong same-owner pivots (relation same_analytics).
Notes: Reverse analytics/adsense and redirect relations: strong ownership links.

## P005 `nrd_feeds` - Newly registered / released domain feeds (WhoisDS, smet.cz, registro.br release list, DomainsDB)

- council: **approved**, priority P2, default_enabled=True, provider_tier=community, terms=open, opsec=passive, shares_input=False

### Final conditions (binding spec - implement every item)

1. Module nrd_feeds matches locally (disclosure 'none', shares_input=False) against registered datasets: the WhoisDS daily free NRD zip (terms open: 'may be reused, including for commercial purposes', verified 2026-11-26) and the registro.br release list lista-processo-liberacao.txt (open; NIC.br, trusted). Lists are never redistributed.
2. smet.cz today.txt has unclear licence terms (unknown): it ships as a separate dataset source nrd_smet, default_enabled=False and disabled in every profile until legal records its terms. ICANN CZDS is deferred to BACKLOG.md (needs streaming download-to-disk and per-TLD caps; later only with the company's own account, legal-accepted per-TLD terms, no redistribution, superseded zones deleted).
3. DomainsDB keyword search discloses the brand: a separate module domainsdb_search, key-terms, default_enabled=False, keywords only from org_profile brands.
4. domainsdb_search's provider is unknown tier until reviewed, and A8 BR4 lets unknown-tier providers receive only IOC_TYPES values (a brand keyword is not one): it runs only after a recorded promotion to community tier, and its source is then flagged reuses_queries (fail closed) so it stays excluded at AMBER and above.
5. Lists are fetched by `v3lum data update` or a background refresh into ~/.v3lum/datasets, never blocking a scan for more than 10 s. A missing or > 48 h old list gives UNAVAILABLE reason_code 'dataset' ('NRD lists not downloaded/stale'), never EMPTY. A challenge page or empty file never replaces the last good copy (P321, AR10).
6. Zip via the core safe_extract helper: in memory, at most 3 members, <= 50 MB uncompressed, ratio cap 100x, member names never used as paths. The registro.br file is decoded as ISO-8859-1 and '#' lines are comments.
7. Keep a rolling 30-day local window of daily lists, first_seen = list date, so a scan answers 'registered/released in the last 30 days'. first_seen diffing is persisted in the case DB so watch (P030) alerts only on new matches.
8. Brand matching uses only org_profile brands and domains (P378) and the shared P012 permutation helper (one implementation), including pt-BR combo-squats with lure words and accent homoglyphs. No brand or keyword leaves the machine.
9. Tag newly_registered (and typosquat when matched) only after DoH confirms an A or MX answer, capped at 100 confirmations per run. registro.br release-list hits are tagged in_release (re-registration risk), not newly_registered. An NRD hit alone is LOW; severity rises only with a brand match plus MX or a fresh certificate (P028).
10. Wording on a miss: 'not in the last N days of WhoisDS lists (gTLD coverage only)', never 'not newly registered'. For .br: 'no NRD feed for .br: CT + permutations + DoH only'.
11. Tests with trimmed fixtures (WhoisDS zip, registro.br release list): local match, DoH-confirmed tagging, stale-list UNAVAILABLE, oversized/zip-bomb rejection, challenge page not replacing the last good copy.

Chair rationale: Approved 6-0 at median P2 (osint_investigator voted P1). legal_dpo's floor sets per-feed terms: WhoisDS and the registro.br list are open, smet.cz is unknown (so it is split out and stays off until reviewed, which keeps the default module's terms open, A3 BR2), DomainsDB discloses the keyword and is opt-in, CZDS needs an institutional account. The architect's floor defers CZDS for lack of streaming support and requires the safe-archive helper and one permutation implementation. cti_lead: the 30-day window and the severity ladder. osint_investigator: pt-BR combo-squats, dataset validation, the in_release tag. analyst_ux: no scan waits on downloads, honest miss wording. Tier community for the WhoisDS list operator; no value is sent. Auditor: while DomainsDB is unknown tier it cannot receive brand keywords (A8 BR4), so it runs only after a recorded promotion and keeps the AMBER+ exclusio...

Synthesizer conditions (background; the final conditions win on conflict): Download daily lists (WhoisDS zip at a base64-date URL, smet.cz today.txt, registro.br lista-processo-liberacao.txt) into the dataset cache and match brand keywords/permutations locally (no brand leaves the premises). DomainsDB keyword search needs V3LUM_DOMAINSDB_KEY and discloses the keyword: optional. Emit newly_registered + typosquat tags only after DoH confirms the domain resolves or has MX. Gap fill: ICANN CZDS gTLD zone diffs with the team's own account (credentials stored like API keys; per-TLD approval; one download per TLD per 24 h; diff locally, keep brand/permutation matches, confirm via DoH/RDAP). .br has no new-registration feed: document 'CT + permutation + DoH only' for .br.
Notes: Early detection of brand lookalikes; pairs with typosquat and CertStream watch mode.
