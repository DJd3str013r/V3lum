## P010 `tranco_rank` - Tranco popularity rank

- council: **approved**, priority P2, default_enabled=True, provider_tier=trusted, terms=open, opsec=passive, shares_input=True
- category: domain_dns; group: G01; inputs: domain; produces: 
- auth: none; key env vars: -; hosts: tranco-list.eu

### Final conditions (binding spec - implement every item)

1. Local list only (architect floor): the Tranco daily top-1M zip is a dataset fetched by `v3lum data update` (> 5 MB, never mid-scan, A6), extracted with the core safe_extract helper and indexed on disk at refresh time (SQLite table or sorted file + bisect). Lookups never load 1M entries into a Python dict.
2. No API fallback: a missing list gives UNAVAILABLE reason_code 'dataset'. The module keeps disclosure 'none' (shares_input=False) and runs under TLP:RED. List id and date are recorded in provenance.
3. Rank is a score dampener only, never known_good or an allow-list, and only for the exact registrable domain. It never lowers URL-level or consensus (P171) verdicts.
4. Ship data/shared_platforms.json (sharepoint.com, onedrive.live.com, 1drv.ms, sites.google.com, docs.google.com, drive.google.com, forms.gle, storage.googleapis.com, s3.amazonaws.com, blob.core.windows.net, dropbox.com, notion.site, forms.office.com, free hosting, dynamic DNS, URL shorteners...). Hosts on it show their rank but are never dampened.
5. PSL private suffixes (github.io, pages.dev, web.app, workers.dev, netlify.app, vercel.app, firebaseapp.com...) are ranked per registrable domain under the suffix, never by the platform's rank.
6. Display as context: 'Tranco #1,234 - popular' or 'not in top 1M' with the list date. 'Not in top 1M' is info only, never a finding by itself; 'young and unpopular' contributes at most LOW.
7. The Le Pochat et al. (NDSS 2019) citation goes into THIRD_PARTY_NOTICES.md and the report footer when Tranco data is used.
8. Tests with a trimmed CSV slice: exact-domain lookup, a phishing URL on a top-1k shared platform (sites.google.com) keeps its full score, a PSL private-suffix host is ranked per registrable domain.

Chair rationale: Approved 6-0 at median P2 (cti_lead and analyst_ux voted P1). The architect's floor removes the API fallback (cti_lead allowed it at CLEAR/GREEN) so the module never discloses, and requires an on-disk index. cti_lead and analyst_ux supplied the shared-platform list and the rule that rank never dampens URL-level or consensus verdicts. legal_dpo: the citation. Tranco is an academic project: tier trusted, terms open.

Synthesizer conditions (background; the final conditions win on conflict): Prefer the downloadable daily top-1M list matched locally (no disclosure); API /api/ranks/domain/{d} only when the list is not cached. Use as a 'young & unpopular' phishing heuristic and as a known_good dampener (never a whitelist).
Notes: Cheap false-positive control and phishing triage signal.

## P011 `m365_tenant` - Microsoft 365 / Entra tenant discovery (domain-level)

- council: **approved**, priority P2, default_enabled=True, provider_tier=trusted, terms=open, opsec=passive, shares_input=True
- category: domain_dns; group: G01; inputs: domain, email; produces: domain, company_name
- auth: none; key env vars: -; hosts: azmap.dev, login.microsoftonline.com, odc.officeapps.live.com

### Final conditions (binding spec - implement every item)

1. Module m365_tenant uses Microsoft first-party domain-level endpoints only: login.microsoftonline.com/{domain}/.well-known/openid-configuration (tenant GUID, tenant_region_scope), GetUserRealm with one hard-coded, documented non-existent local-part constant, and the ODC federationprovider endpoint (tenant id).
2. E-mail inputs are reduced to their domain before any request. Unit tests assert that no request URL ever contains the input's local part and that the only local part sent is the constant.
3. Rule 2: GetCredentialType, Autodiscover user checks and OneDrive/Teams/login oracles must not exist in code; a test asserts such URLs cannot be built.
4. One openid-configuration call per registrable seed domain; GetUserRealm/ODC only when a tenant exists. NameSpaceType 'Unknown' means no Entra ID tenant (EMPTY). An unexpected ODC schema gives ERROR 'schema changed', never EMPTY.
5. Federation AuthURL/IdP hostnames (ADFS, Okta, Ping) become identity_provider attributes and pivots that get passive modules only. This module never contacts them.
6. azmap.dev (no published terms, unknown operator) is a separate adapter module m365_tenant_azmap: default_enabled=False, terms 'unknown' and tier unknown, so it stays disabled until legal records its terms and a promotion; even then it is excluded at AMBER and above, one call per domain, cache 24 h.
7. Related tenant domains (azmap): the full list as an attribute with a count. A related domain pivots only after DNS confirmation (MX *.mail.protection.outlook.com or TXT MS=), at most 50 confirmations within 100 DoH queries and 10 pivots per tenant, relation same_m365_tenant (added to core/vocab.py), confidence at most PROBABLE.
8. The same tenant id across domains feeds the company correlation as PROBABLE same organisation. A tenant shared by a suspicious domain and others is an attacker-infrastructure cluster candidate (PROBABLE), never proof of ownership. Wording: 'N domains share Microsoft 365 tenant <name>'.
9. Tenant-related domains are candidate own assets for `org seed` (analyst confirms) and never join an ACTIVE scope automatically. bbot (AGPL) code is not copied; the technique is re-implemented. Tests use the six recorded fixtures.

Chair rationale: Approved 6-0 at median P2 (redteam_lead voted P1). legal_dpo's floor: domain-level endpoints only, a fixed constant local part, no user-level oracles in code (rule 2), azmap.dev a separate adapter with unknown terms (so the chair keeps it out of the default module, A3 BR2). The architect's floor makes enumeration structurally impossible through URL assertions and caps the DNS confirmation. redteam_lead: IdP hosts are never contacted and tenant domains never join a scope. analyst_ux: one call per seed and the 10-pivot cap. cti_lead and osint_investigator: PROBABLE clustering. Microsoft public identity endpoints: tier trusted, terms open.

Synthesizer conditions (background; the final conditions win on conflict): Domain-level endpoints only: login.microsoftonline.com/{domain}/.well-known/openid-configuration (tenant GUID, region), GetUserRealm with a FIXED fake local-part (never a real user), ODC federationprovider (tenant id), azmap.dev for related tenant domains (unknown third-party operator: OPSEC note, cache 24 h, one call per domain). Never enumerate users (no Autodiscover/OneDrive/login oracles). Confirm azmap related domains with DNS (MX *.mail.protection.outlook.com, TXT MS=) before pivoting; relation same_m365_tenant needs to be added to vocab.py.
Notes: One corporate domain -> every domain verified in the same tenant (subsidiaries, brands): strong same-owner signal.

5. analyticslookup results go through the P061 shared-id rule.

7. An exhausted quota gives ONE report line per scan ('HackerTarget free quota used for this egress IP: add a key'), not one per entity.
