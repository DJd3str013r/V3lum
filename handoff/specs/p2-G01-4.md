## P342 `saas_verification_tokens` - SaaS footprint from DNS TXT verification tokens (vendor prefix map)

- council: **approved**, priority P2, default_enabled=True, provider_tier=trusted, terms=open, opsec=passive, shares_input=True
- category: domain_dns; group: G01; inputs: domain; produces: 
- auth: none; key env vars: -; hosts: cloudflare-dns.com, dns.google

### Final conditions (binding spec - implement every item)

1. Reuse the TXT answer already fetched by email_security_posture/dns_records (DoH cache hit); at most one TXT query through ctx.dns when absent. DoH errors mean could not verify, never 'no SaaS'.
2. Map record prefixes to vendors with a bundled own-work table data/txt_verification_prefixes.json (atlassian-domain-verification, google-site-verification, MS=, docusign=, stripe-verification, zoom-domain-verification, notion-domain-verification, knowbe4-site-verification, adobe-idp-site-verification, openai-/anthropic-domain-verification, DirectFedAuthUrl...).

4. Tokens prove a past verification, not current use: worded 'verification record present'. Token values are never pivoted and not republished in bulk: reports show vendor names, raw values stay in evidence only.
5. Tests with the recorded gaps__saas_tenants fixture.

Chair rationale: Approved 6-0 at median P2 with no member conditions beyond the synthesizer's. legal_dpo: public DNS answers, no personal data, values not republished in bulk. The architect: cached DoH answer, bundled map, saas_vendors in vocab.py. Data travels through the core DoH resolvers: tier trusted, terms open.

Synthesizer conditions (background; the final conditions win on conflict): Reuse the TXT answer already fetched by email_security_posture/dns_records (DoH, passive); map record prefixes to vendors with a bundled table (data/txt_verification_prefixes.json: atlassian-domain-verification, google-site-verification, MS=, docusign=, stripe-verification, zoom-domain-verification, notion-domain-verification, miro-verification, knowbe4-site-verification, jamf-site-verification, adobe-idp-site-verification, openai-/anthropic-domain-verification, 1password-site-verification, DirectFedAuthUrl ...); output saas_vendors attribute (info) and hints for phishing-simulation/ASM; unknown prefixes listed raw; token values never pivoted.

## P343 `whois_fallback` - WHOIS fallback for TLDs without RDAP (who-dat RDAP/WHOIS-over-HTTPS + port-43 via IANA root db)

- council: **approved**, priority P2, default_enabled=True, provider_tier=trusted, terms=open, opsec=passive, shares_input=True
- category: domain_dns; group: G01; inputs: domain; produces: domain
- auth: none; key env vars: -; hosts: who-dat.as93.net, www.iana.org

### Final conditions (binding spec - implement every item)

1. applies() is decided only from the shared IANA RDAP bootstrap helper of P003 (a TLD without an RDAP service, e.g. .ru via the bootstrap), never from another module's runtime result (the engine has no module ordering). The second .br path runs only on explicit analyst selection.
2. Order: a self-hosted who-dat instance (MIT) when the setting whodat_url is configured, then direct port-43 WHOIS to the registry server taken from the IANA root-zone page (cached 7 days). The public who-dat.as93.net instance is a separate module whois_fallback_public: unknown tier, default_enabled=False, excluded at AMBER and above.
3. Port 43 goes through a small core whois43 helper on the core socket connector: 10 s timeout, 64 KB cap, at most one referral hop; UNAVAILABLE when a proxy is configured or 43/tcp is blocked. Registry WHOIS terms are respected (per-query only, no bulk or marketing use).
4. Keep registrar, dates, nameservers, status, DNSSEC and meta.source/server. Personal contact fields are dropped at ingestion, before evidence (registro.br exposes tech-contact names/e-mails); unit test with the .br sample.
5. WHOIS/who-dat output never creates CNPJ pivots: the .br -> CNPJ pivot stays RDAP-only (publicIds, P003).
6. Tests with the recorded gaps__whois_fallback fixture and a referral case.

Chair rationale: Approved 6-0 at median P2 (architect voted P3). The architect's floor: applicability from the bootstrap helper, not module ordering; a bounded whois43 helper; the public who-dat instance as a separate input-sharing adapter off at AMBER and above (osint_investigator rates it unknown tier, so it is opt-in, A3 BR2). legal_dpo: personal fields dropped, registry terms, no CNPJ pivots. Default module tier trusted (IANA and registries), terms open.

Synthesizer conditions (background; the final conditions win on conflict): Runs only when RDAP (P003) has no service for the TLD (rdap.org/IANA bootstrap 404, e.g. .ru via bootstrap) or answers 403/429/timeout (rdap.registro.br was intermittent: 403 to the datacenter egress per the gap, 200 to a non-browser UA on 2026-11-25 23:5x UTC). Order: self-hosted who-dat instance (MIT) if configured, public who-dat.as93.net otherwise (discloses the domain to a third party: off for TLP:AMBER+), direct port-43 WHOIS only when the network allows 43/tcp (server from the IANA root-zone page). Keep registrar, dates, nameservers, status, DNSSEC and meta.source/server; drop personal contact fields at ingestion (registro.br exposes tech-contact names/e-mails). The .br -> CNPJ pivot stays RDAP-only (publicIds); who-dat output never creates CNPJ pivots.
Notes: Gives registrar/creation dates for .ru/.cn/.su-style ccTLD domains and a second path for .br registration data.
