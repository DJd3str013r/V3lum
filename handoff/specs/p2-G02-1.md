## P033 `asn_context` - ASN context (PeeringDB, CIRCL BGP Ranking, Shadowserver public API)

- council: **approved**, priority P2, default_enabled=True, provider_tier=trusted, terms=open, opsec=passive, shares_input=True
- category: ip_network; group: G02; inputs: asn, ipv4, company_name; produces: company_name
- auth: none; key env vars: V3LUM_PEERINGDB_KEY, V3LUM_SHADOWSERVER_KEY; hosts: peeringdb.com, bgpranking-ng.circl.lu, api.shadowserver.org, transform.shadowserver.org

### Final conditions (binding spec - implement every item)

1. Per-source status for PeeringDB, CIRCL BGP Ranking and Shadowserver, so one throttled API does not hide the others. Registry (A1 BR3, A8 BR12): PeeringDB (free under its AUP), CIRCL BGP Ranking (free CIRCL service) and the Shadowserver public API (free public-benefit service) are 'open', tier trusted, each with evidence recorded.
2. PeeringDB: GET peeringdb.com/api/net?asn={n}&depth=2 (org name as ASN operator, network type NSP/Content/Enterprise/Hosting, IXPs, policy). Responses capped; anonymous throttling handled by min_interval and an optional key 'peeringdb' in config.KNOWN_KEYS (Authorization header).
3. PeeringDB AUP: poc/contact objects are dropped at ingestion and never stored or reused (no harvesting or marketing); only role information needed for context is kept.
4. CIRCL BGP Ranking per ASN (position/total as a percentile) and ipasn_history are context only, shown as 'rank X (higher = more malicious activity observed)' with an explanation. They never raise an IP or domain above INFO and never count as a consensus vote (P171): large clouds and hosters always rank high.
5. Shadowserver keyless net/asn API (origin and prefix lookups), terms recorded in the registry; a key, if used, goes in a header. Failures = could not verify.
6. Registering the company's own ASNs/netblocks with Shadowserver for free reports is an institutional DPO/IT decision documented in docs/LEGAL.md, not something the tool does; ingesting those reports is out of scope for this module.
7. Tests with the recorded PeeringDB, BGP Ranking and Shadowserver fixtures.

Chair rationale: Approved 6-0 at median P2. cti_lead and analyst_ux: ASN reputation is context only, never a vote or a finding above info. legal_dpo's floor: the PeeringDB AUP on contact data, and Shadowserver registration as an institutional decision. The architect's floor: per-source status, capped depth=2 answers, keys in headers. All three operators are established non-profits or CERTs: tier trusted, terms open.

Synthesizer conditions (background; the final conditions win on conflict): PeeringDB net?asn=&depth=2 (org, IXPs, policy); CIRCL BGP Ranking per ASN (maliciousness rank) and ipasn_history; Shadowserver keyless net/asn API. Recommend the team registers its own ASNs/netblocks for free Shadowserver reports (ingest later via log/report input).
Notes: Who operates an ASN and how 'dirty' it is.

## P035 `ip_context_lists` - IP context lists (X4BNet VPN/datacenter, FireHOL proxies, mthcht awesome-lists)

- council: **approved**, priority P2, default_enabled=True, provider_tier=community, terms=noncommercial, opsec=passive, shares_input=False

- auth: none; key env vars: -; hosts: raw.githubusercontent.com, iplists.firehol.org, mask-api.icloud.com

### Final conditions (binding spec - implement every item)

1. Local matching only (disclosure 'none', allowed at TLP:RED) through the shared core IP-range index (P034). Each list is a registered dataset with TTL and provenance, refreshed daily; the 12 MB Apple iCloud Private Relay CSV refreshes weekly via `v3lum data update` (> 5 MB, never mid-scan) and is parsed once per refresh, never per run.
2. A missing or stale list gives UNAVAILABLE ('not checked'), never 'not a VPN/proxy/datacenter IP' (rule 5); a failed or invalid download never replaces the last good copy.
3. Per-list terms recorded before enabling: X4BNet VPN/datacenter lists (repository licence, MIT notice), mthcht awesome-lists (MIT, attribution), Apple Private Relay ranges (published by Apple for geolocation/allow-listing: open). Notices go to data/NOTICE and THIRD_PARTY_NOTICES.md (runtime data, A6).
4. FireHOL proxy ipsets inherit each upstream list's terms and are consumed per upstream (the ipset header names it). Noncommercial upstreams stay off under the corporate profile until licence-cleared; upstreams with unrecorded terms are not wired.
5. Tags are context only, never malicious verdicts: vpn, datacenter, proxy, rmm_tool, dynamic_dns, suspicious_user_agent and privacy_relay (new attribute in core/vocab.py).
6. privacy_relay is never scored as an anonymiser and suppresses VPN/proxy scoring for those ranges (ordinary Safari users).
7. Domain lists (RMM tools, dynamic DNS) match on the PSL registrable domain or suffix; user-agent lists match exactly. FireHOL proxy sets are large and churn (residential proxies): never sole evidence, and an IP is never actively tested as an open proxy.
8. Tests with trimmed fixtures (X4BNet list, mthcht CSV head, a Private Relay slice, a FireHOL ipset header): context tag only, privacy_relay suppression, a licence-blocked upstream reported in coverage.

Chair rationale: Approved 6-0 at median P2 (cti_lead and analyst_ux voted P1). legal_dpo's floor: each list's licence recorded, FireHOL upstreams keep their own terms with noncommercial ones off under corporate, Private Relay users never profiled as anonymisers. The architect's floor: the shared IP index, datasets with provenance, the large CSV parsed once per refresh. Terms is noncommercial for the FireHOL NC upstreams only. Tier community: the list maintainers are public community projects; Apple is trusted; no value leaves the machine.

Synthesizer conditions (background; the final conditions win on conflict): Downloaded lists matched locally as TAG context (vpn, datacenter, proxy, RMM tool domains, dynamic DNS, suspicious user agents), never as malicious verdicts; X4BNet lists keep their MIT notice; refresh daily. Gap fill: Apple iCloud Private Relay egress ranges (12 MB CSV, weekly) -> privacy_relay context attribute, never malicious; suppresses VPN/proxy scoring for those ranges.
Notes: Context labels for anonymizers and RMM/dynamic-DNS infrastructure.
