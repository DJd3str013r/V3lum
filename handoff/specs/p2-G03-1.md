## P061 `analytics_ids` - Analytics / tag-manager / AdSense ID extraction and reverse lookup

- council: **approved**, priority P2, default_enabled=True, provider_tier=trusted, terms=open, opsec=passive, shares_input=False
- category: url_web; group: G03; inputs: url, domain, analytics_id, text_blob; produces: analytics_id, domain
- auth: mixed; key env vars: V3LUM_SPYONWEB_TOKEN; hosts: builtwith.com, api.hackertarget.com, host.io, search.dnslytics.com, www.googletagmanager.com, api.spyonweb.com

### Final conditions (binding spec - implement every item)

1. Split (architect floor). analytics_ids extracts ids locally from bodies already in hand (web_fingerprint, archived snapshots, urlscan DOM, text/file inputs): disclosure 'none', runs under TLP:RED, makes no request to the target. gtm_expand fetches https://www.googletagmanager.com/gtm.js?id=GTM-... from Google: disclosure third_party.
2. Regexes, bounded, case-sensitive and tested against a 1 MB adversarial body within a time budget: UA-\d{4,10}-\d{1,4}, G-[A-Z0-9]{6,12} (the bellingcat digits-only regex is fixed), GTM-[A-Z0-9]{4,9}, pub-\d{16} and ca-pub-; in GTM expansion also quoted AW- and DC- ids.
3. GTM expansion: at most 5 containers per run, 1 MB cap, cache 7 days. Unknown containers return HTTP 200 with a generic ~242 KB runtime and no macros: 'not found' is decided from content, never from status.
4. Reverse lookups happen by pivoting analytics_id entities to the modules that accept that type (host.io P004, HackerTarget P014, urlscan P066), each under its own licence and key decisions; no reverse client is re-implemented here. SpyOnWeb is left out until a real fixture exists.
5. Shared-id rule: an id whose reverse lookup returns > 50 domains, or a known agency/CMS/site-builder template id, is labelled 'shared ID': info, no pivots, no same-owner correlation, confidence <= 0.3. Reverse-lookup pivots are capped at 10 per id.
6. Clone rule: a non-own site carrying an id used by an org_profile own site gives 'possible clone of <brand> (copied tracking ID)' as a phishing indicator, never a same-owner link.
7. same_analytics pivots are expand=False, confidence at most PROBABLE (<= 0.7), never sufficient alone for CONFIRMED ownership (P013). Ids from archived snapshots carry the snapshot date; a same_analytics link needs overlapping dates.
8. Each same_analytics link shows the id and where it was seen (live page, archive date, GTM container). Tests with the recorded GTM container fixture, a high fan-out id and the clone case.

Chair rationale: Approved 6-0 at median P2 (osint_investigator voted P1). The architect's floor splits the offline extractor from the Google fetch (legal_dpo asked the same so TLP:RED keeps local extraction) and moves reverse lookups to the modules that own those clients. cti_lead supplied the clone rule; cti_lead, osint_investigator and analyst_ux the > 50-domain shared-id rule. redteam_lead's 10-domain threshold is not adopted, but his expand=False pivots and analyst_ux's 10-pivot cap bound the agency fan-out he feared. Google is trusted; terms open (public JavaScript).

Synthesizer conditions (background; the final conditions win on conflict): Extract from fetched pages and archived snapshots: UA-\d{4,10}-\d{1,4}, G-[A-Z0-9]{6,12} (bellingcat regex only matches digits: fix), GTM-[A-Z0-9]{4,9}, pub-\d{16}/ca-pub-; reverse lookups through hostio/hackertarget/BuiltWith pivots and urlscan search; relation same_analytics (strong ownership signal, but shared agency/CMS IDs -> confidence 0.7). Gap fill: expand GTM-XXXX ids by fetching https://www.googletagmanager.com/gtm.js?id=... (passive towards the target, cache 7 d) and extracting quoted G-/UA-/AW-/DC- ids case-sensitively; unknown containers return HTTP 200 with a generic ~242 KB runtime and no macros -> 'not found' from content, never from status; SpyOnWeb only with a token.
Notes: One of the strongest ownership pivots between sites. GTM expansion verified on a public gov.br container (3 measurement ids).

## P345 `takedown_packet` - Takedown / abuse packet for hostile URLs and hosts (RDAP abuse, RIPEstat abuse-c, Abusix, IANA registrar ids, report forms)

- council: **approved**, priority P2, default_enabled=True, provider_tier=trusted, terms=open, opsec=passive, shares_input=True
- category: url_web; group: G03; inputs: url, domain, ipv4, ipv6; produces: email
- auth: none; key env vars: -; hosts: www.iana.org, safebrowsing.google.com, report.netcraft.com, www.cert.br, stat.ripe.net, dns.google
- sources shared with other proposals: {"C0075": ["P031"], "C0096": ["P041"]}

### Final conditions (binding spec - implement every item)

1. Implemented as a report exporter (-f takedown, and `v3lum takedown <case>`) over the case graph (architect floor): registrar and abuse contacts already produced by rdap (P003), ripestat (P031) and abusix_contacts (P041), plus the IANA registrar-ID registry as a weekly dataset. No network at report time and no new HTTP clients.
2. Generated automatically only when the case has a phishing/malicious finding >= HIGH backed by consensus (>= 2 independent families, P171) or analyst confirmation; never from a single-source hit. Otherwise only on request.
3. Contacts are ranked by authority with the reason, source and retrieval date: registrar abuse (RDAP via the IANA registrar id) > hosting abuse-c (RIR) > Abusix > CDN abuse portal (with origin hints when a CDN is in front). Compromised legitimate sites add the owner contact from security.txt (P065) when available.
4. .br domains and BR-hosted IPs add CERT.br guidance (notify the source network, cert@cert.br in Cc). Manual report links: Google Safe Browsing report_phish, Netcraft, and the platforms abused in BR scams (WhatsApp, Instagram/Meta, Telegram, Google Forms/Sites) when the case holds such entities.
5. V3LUM never sends e-mails or submits forms. Submitting a report shares the URL with the provider: the analyst decides per case and records the disclosure decision in the case audit.
6. Minimisation: the packet includes only what the takedown needs (hostile URL/host, timestamps, evidence SHA-256 hashes, screenshots of the hostile page); victims' e-mails, tokens and other personal data and internal case details are redacted. The packet carries the case TLP marking.
7. Each evidence item lists its SHA-256 with UTC and America/Sao_Paulo timestamps; a ready-to-copy message template in pt-BR and English cites the hashes.
8. Unit tests on a synthetic case graph (registrar + RIR + Abusix contacts, a .br case, a single-source hit that must not generate a packet).
