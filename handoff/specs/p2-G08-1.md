- council: **approved**, priority P2, default_enabled=True, provider_tier=trusted, terms=open, opsec=passive, shares_input=True

### Final conditions (binding spec - implement every item)

1. Module vulnerability_cve/circl_vulnlookup: vulnerability.circl.lu /api/vulnerability/{id} (CVE, GHSA, PySec and CSAF ids), plus the sightings and EPSS endpoints; optional key 'circl_vuln' (V3LUM_CIRCL_VULN_KEY alias); 404 -> EMPTY; x-ratelimit 20 per 60 s honoured through P334. Registry provider circl: tier trusted, terms open (CC BY 4.0 where applicable, attribution).
2. One shared CVE JSON 5 parser and attribute normaliser (cvss, cvss_vector, cwe, affected, kev, epss) for circl_vulnlookup, cve_record (P183) and cve_offline_mirror (P352): CIRCL returns the CVE 5 schema for CVE ids, so there is no second parser.
3. Sightings (seen/exploited/confirmed) go to the vocab attribute exploited (dict source -> first date) with source 'circl', never to kev (kev stays CISA KEV). Advisories are deduplicated with P183/P352 by CVE/GHSA alias.
4. Per-CVE calls follow the CVE fan-out rule of P183 (seed CVEs plus cve_fanout_budget pivot CVEs per case). Results fill the consolidated CVE card (P183) with provenance instead of separate findings.

Chair rationale: Approved 6-0 at median P2 (legal_dpo and the architect voted P1). cti_lead keeps CIRCL sightings separate from CISA KEV; the architect requires one CVE parser and the fan-out budget; analyst_ux routes the output into the CVE card.

Synthesizer conditions (background; the final conditions win on conflict): api/vulnerability/{id} (multi-source: CVE, GHSA, PySec, CSAF...), sightings (seen/exploited/confirmed) and EPSS endpoints; free for corporate use; page link as pivot.
Notes: Aggregated advisories and community exploitation sightings.

## P185 `osv_ghsa` - OSV.dev + GitHub Advisory Database

- council: **approved**, priority P2, default_enabled=True, provider_tier=trusted, terms=key-terms, opsec=passive, shares_input=True
- category: vulnerability_cve; group: G08; inputs: cve, keyword; produces: keyword
- auth: mixed; key env vars: V3LUM_GITHUB_TOKEN; hosts: api.osv.dev, api.github.com

### Final conditions (binding spec - implement every item)

1. Module vulnerability_cve/osv_ghsa: api.osv.dev/v1/vulns/{id} for CVE/GHSA ids (fixtures exist; 404 -> EMPTY); GHSA advisories via REST advisories?cve_id= through the shared GitHub client and budget of P111, with its no-scope machine-account token rule; the GHSA path is re-tested from the team network with fixtures before merge. Per-CVE calls follow the CVE fan-out rule (P183).
2. Sources: OSV (CC BY 4.0, per-source licences, attribution) 'open'; GHSA through the GitHub REST API 'key-terms' (as P111). Per-source filtering (ctx.allowed_sources) lets OSV run when the GitHub source is not cleared.
3. package@version querybatch is built only once a purl/package entity type exists (a later P333 wave); until then it is not built. Package queries would disclose the internal software inventory and follow the TLP gate like any shared input.
4. OSV distro records (Debian/Ubuntu/Alpine, e.g. DEBIAN-CVE-*) are read for CVE ids to show per-release fixed versions on the CVE card; the banner-revision backport check is done offline by P355.
5. Affected ranges are stored compactly (ecosystem, package, introduced/fixed) instead of whole records in evidence. Registry providers osv (Google) and github: tier trusted.

Chair rationale: Approved 6-0 at median P2. cti_lead's distro ecosystems and the architect's compact storage and package-entity precondition are adopted; redteam_lead's backport check needs a package entity this build does not have, so it is delivered offline by P355 for Debian banners. legal_dpo's attribution and machine-account token rule apply. Terms follow the most restrictive source (GitHub REST, 'key-terms').

Synthesizer conditions (background; the final conditions win on conflict): OSV vulns/{id} and querybatch for package@version; GHSA REST advisories?cve_id= (token raises limits; sandbox proxy returned 403: re-test); package/ecosystem impact for developer-facing findings.
Notes: Open-source package impact for CVEs and secrets found in repos.

## P187 `endoflife` - endoflife.date product lifecycle

- council: **approved**, priority P2, default_enabled=True, provider_tier=n/a, terms=open, opsec=passive, shares_input=True
- category: vulnerability_cve; group: G08; inputs: keyword; produces: 
- auth: none; key env vars: -; hosts: endoflife.date

### Final conditions (binding spec - implement every item)

1. Implemented as a registered dataset plus a correlation rule, not a per-keyword module (the engine never auto-expands keywords): dataset endoflife (weekly) downloads endoflife.date/api/v1/products/{slug} for the slugs of a curated mapping table data/eol_products.json (technology name -> slug). No per-scan request, so the investigated stack is never disclosed.
2. The mapping is pinned (no fuzzy guessing): unmapped technologies are skipped. Version parsing (major/minor/cycle) is unit-tested per product.
3. The rule fires an EOL/unsupported finding only when an explicit version string was detected (banner, meta generator, header) and maps to a release cycle, with the version's source shown; inferred or major-only versions give info with confidence <= 0.4, labelled 'version-inferred'.
4. Distro packages with backports are not reported as upstream EOL; EOL findings cap at medium unless the version is authoritative.
5. One grouped finding per asset lists all EOL components: medium/low on own or in-scope assets (org_profile), info on third-party or attacker infrastructure (CDN/SaaS edges are context). Attribution: endoflife.date (MIT data). Registry provider endoflife: tier community (dataset source).

Chair rationale: Approved 6-0 at median P2. The architect's floor reshapes it into a dataset plus a correlation rule because the drafted web_fingerprint -> keyword -> module flow does not exist in the engine; cti_lead, osint_investigator, redteam_lead and analyst_ux require explicit versions, honest version-inferred labels and own-asset scoping. Offline at scan time: tier 'n/a', terms 'open'.

Synthesizer conditions (background; the final conditions win on conflict): api/v1/products/{product} for detected technologies (web_fingerprint) -> EOL/unsupported version findings (outdated software), cache 7 d.
Notes: Flags unsupported software versions on org assets.
