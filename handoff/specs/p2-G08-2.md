## P190 `exploit_index` - Exploit/PoC indexes (PoC-in-GitHub, Exploit-DB CSV, Metasploit metadata, nuclei cves.json, trickest/cve)

- council: **approved**, priority P2, default_enabled=True, provider_tier=trusted, terms=open, opsec=passive, shares_input=False
- category: vulnerability_cve; group: G08; inputs: cve; produces: url
- auth: none; key env vars: -; hosts: raw.githubusercontent.com, gitlab.com

### Final conditions (binding spec - implement every item)

1. Split by disclosure. Offline module exploit_index (disclosure none): Exploit-DB files_exploits.csv (from gitlab.com/exploit-database raw; GPL-2.0 repository, downloaded at runtime only, never vendored), Metasploit modules_metadata_base.json (~11 MB, BSD-3) and nuclei-templates cves.json (NDJSON, MIT), indexed at weekly refresh by the dataset manager.
2. Separate adapter poc_index (disclosure third_party: the CVE id leaves the machine): PoC-in-GitHub per-CVE JSON (raw.githubusercontent.com/nomi-sec/PoC-in-GitHub/master/{year}/{CVE}.json; 404 = none) and trickest/cve markdown ('#### Reference' / '#### Github' sections), under the CVE fan-out rule (P183). Both are link indexes only (no data licence) and never redistributed.
3. Maturity in vocab attribute exploit_maturity: a Metasploit module or Exploit-DB entry -> 'weaponised' (exploit_available); a nuclei CVE template -> 'detection template'; PoC-in-GitHub/trickest -> 'poc_claimed (N repos)' with confidence <= 0.4. exploit_available is set only from curated sources (Exploit-DB, Metasploit, nuclei, KEV).
4. Exploit or PoC availability raises priority only: it never turns a version-inferred match into a verified vulnerability or sets CRITICAL by itself (P291).
5. PoC repository URLs are untrusted references: defanged, top 5 by stars/recency, labelled 'unverified code, may be malicious: never run outside an isolated lab', expand=False. V3LUM never clones, downloads, renders READMEs of or runs PoCs; Metasploit and nuclei entries are references only (the nuclei runner stays the gated ACTIVE P369).
6. Datasets come from pinned source URLs, are refreshed out of band and show their age; attributions (Exploit-DB GPL-2.0 runtime data, Metasploit BSD-3, nuclei MIT) are generated from the registry. Registry providers github and gitlab (raw hosts): tier trusted, terms open.

Chair rationale: Approved 6-0 at median P2 (cti_lead and redteam_lead voted P1). The architect's floor splits the per-CVE GitHub fetches into a third_party adapter (the draft wrongly marked everything offline, breaking TLP:RED); legal_dpo's runtime-only GPL data and link-only PoC indexes, cti_lead's maturity levels, redteam_lead's 'never CRITICAL by itself' and analyst_ux's capped, labelled PoC links are consolidated. GPL data fetched at runtime with attribution is 'open' under the A1 definitions.

Synthesizer conditions (background; the final conditions win on conflict): Datasets downloaded at runtime (never vendored): Exploit-DB files_exploits.csv comes from a GPL-2.0 repo, Metasploit modules_metadata_base.json (11.4 MB, BSD), nuclei-templates cves.json (NDJSON, MIT), PoC-in-GitHub per-CVE JSON (404 = none), trickest/cve markdown; emit exploit_available + PoC URLs (expand=False); PoC repos can be malicious -> never clone/execute.
Notes: Exploit availability raises CVE priority (CR15/CR16).

## P352 `cve_offline_mirror` - Offline CVE mirror (CVEProject cvelistV5 baseline + hourly deltas incl. CISA ADP Vulnrichment)

- council: **approved**, priority P2, default_enabled=True, provider_tier=n/a, terms=open, opsec=passive, shares_input=False
- category: vulnerability_cve; group: G08; inputs: cve; produces: cve
- auth: none; key env vars: -; hosts: raw.githubusercontent.com, github.com

### Final conditions (binding spec - implement every item)

1. Explicit `v3lum data sync cves` only, never inside a scan: the CVEProject cvelistV5 daily baseline release zip is streamed to disk by the dataset manager and read member by member (zip-of-zip handled; caps on member count, 5 MB per member and total uncompressed; no extraction, member names never used as paths); declared hosts include the release-asset redirect host.
2. Records are indexed into SQLite (id, state, dates, CNA/ADP metrics, KEV/SSVC fields, compressed JSON), resumably; hourly deltas come from deltaLog.json with githubLink restricted to raw.githubusercontent.com/CVEProject/ and are applied only when dateUpdated is newer. Never a git clone.
3. cve_record (P183) reads the mirror first and falls back to cveawg/NVD only for misses, with the shared CVE 5 parser. The mirror exposes CISA ADP SSVC (exploitation, automatable, technical impact), the KEV flag and ADP CVSS.
4. Attribution per the CVE terms (MITRE copyright designation in the notices; CISA ADP content public domain). doctor shows disk usage and mirror age; the baseline size is verified from the team network.

Chair rationale: Approved 6-0 at median P2. The architect's floor (explicit sync, streamed archive reading with caps, restricted delta links, SQLite index) and legal_dpo's attribution are the conditions; the other members' notes (NVD rate limits, TLP:RED offline lookups) are the reason it ships. Offline: tier 'n/a', terms 'open'.

Synthesizer conditions (background; the final conditions win on conflict): Optional `v3lum data sync cves`: daily baseline release zip + hourly deltaLog-driven updates into SQLite (never a full git clone); cve_record (P183) reads the mirror first and falls back to cveawg/NVD only for misses; expose CISA-ADP SSVC (exploitation, automatable, technical impact), KEV flag and ADP CVSS; attribution per CVE terms.
Notes: Removes the dependency on slow/rate-limited online CVE APIs and adds CISA ADP enrichment.

## P353 `msrc_patch_tuesday` - Microsoft Patch Tuesday data (MSRC CVRF v3: KBs, products, Exploited / Publicly Disclosed flags)

- council: **approved**, priority P2, default_enabled=True, provider_tier=n/a, terms=open, opsec=passive, shares_input=False
- category: vulnerability_cve; group: G08; inputs: cve, keyword; produces: cve
- auth: none; key env vars: -; hosts: api.msrc.microsoft.com

### Final conditions (binding spec - implement every item)

1. Offline module vulnerability_cve/msrc_patch_tuesday on the dataset manager: api.msrc.microsoft.com/cvrf/v3.0/updates lists the month documents; each document (~20 MB; max_bytes 64 MB per document) is streamed to disk, parsed one at a time and indexed into SQLite (CVE -> KBs, products, exploited/publicly disclosed, severity, fixed build, supersedence).
2. Refresh out of band by `v3lum data update` (never mid-scan) when CurrentReleaseDate changes in /updates (GET with If-Modified-Since; never HEAD, which returns 405); default window the last 24 months, older months on demand.
3. Threats Type 1 'Exploited:Yes' goes to the exploited attribute with source 'msrc' and raises severity like KEV, but kev stays CISA-only; Type 3 gives severity; Remediations Type 2 (KB, URL, FixedBuild, supersedence) become remediation attributes on the CVE card; product names come from the ProductTree.
4. Disclosure none at scan time. Tests use a trimmed fixture cut from the gap-fill sample.

Chair rationale: Approved 6-0 at median P2 (cti_lead voted P1). The architect's floor indexes the 20 MB month documents instead of holding them in memory; cti_lead keeps Microsoft's exploited flag separate from CISA KEV. Offline: tier 'n/a', terms 'open'.

Synthesizer conditions (background; the final conditions win on conflict): Download each month document once (20+ MB JSON; refresh when CurrentReleaseDate changes in /updates), index offline by CVE and KB: exploit status from Threats Type 1 ('Exploited:Yes' -> exploit_available/kev-like finding even before CISA KEV), severity Type 3, remediations Type 2 (KB, FixedBuild, supercedence), product names via ProductTree; never HEAD (405).
Notes: Corporate patch prioritisation is mostly Microsoft: KB mapping and Microsoft's own exploited flag.
