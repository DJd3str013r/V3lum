## P198 `deepdarkcti_index` - deepdarkCTI source index (onion leak sites / Telegram channels -> actors)

- council: **approved**, priority P2, default_enabled=True, provider_tier=n/a, terms=open, opsec=passive, shares_input=False
- category: darkweb_ransomware; group: G09; inputs: onion, threat_actor, username, keyword; produces: threat_actor
- auth: none; key env vars: -; hosts: raw.githubusercontent.com
- sources shared with other proposals: {"C0460": ["P357"]}

### Final conditions (binding spec - implement every item)

1. Offline module darkweb_ransomware/deepdarkcti_index (disclosure none): the deepdarkCTI markdown lists downloaded weekly at runtime only through the dataset manager (GPL-3.0 data: never vendored, attribution in THIRD_PARTY_NOTICES, A6).
2. A tolerant markdown-table parser ('|Name|Status|...'), shared with P357's channel list, skips malformed rows; a parse below an expected row count marks the dataset unhealthy (doctor) instead of returning empty.
3. Only onion hosts (core onion v3 validator, P217) and t.me handles are indexed (onion host / Telegram handle -> actor/group and category); each entry keeps its Status column and the repository commit date.
4. A match reads 'listed in deepdarkCTI as <category> of <group> (status ONLINE/OFFLINE, list date <commit date>)': info/medium context, not attribution; OFFLINE or stale entries are labelled historical.
5. Listed onion, Telegram and forum addresses are hostile-tagged, rendered defanged and never fetched by any module.

Chair rationale: Approved 6-0 at median P2. GPL-3.0 data used at runtime with attribution (legal_dpo, A6) is 'open' under the A1 definitions; cti_lead's status/date rule, the architect's parser-health check and redteam_lead's never-fetch rule are consolidated. Offline: tier 'n/a'.

Synthesizer conditions (background; the final conditions win on conflict): GPL-3 data -> fetch at runtime only (never vendored); parse markdown tables into onion/telegram -> actor/category index; matching only, never visit listed sites.
Notes: Maps onion/Telegram identifiers to known groups.

## P199 `onion_lookup` - Onion metadata (AIL onion-lookup + Ahmia onion index and banned list)

- council: **approved**, priority P2, default_enabled=True, provider_tier=trusted, terms=open, opsec=passive, shares_input=True
- category: darkweb_ransomware; group: G09; inputs: onion; produces: threat_actor
- auth: none; key env vars: -; hosts: onion.ail-project.org, ahmia.fi

### Final conditions (binding spec - implement every item)

1. Module darkweb_ransomware/onion_lookup: AIL onion-lookup (CIRCL) GET https://onion.ail-project.org/api/lookup/{onion} only for onions already in the case (never bulk), after the v3 checksum is validated locally (P217); disclosure third_party (CIRCL sees the address). No Tor connections in this module.
2. The Ahmia banned/CSAM MD5 list (md5 of the onion host, one per line) is a registered dataset (refreshed at most daily) exposed as a core safety filter is_banned_onion(); every module applies it before any onion is displayed, stored, enriched or fetched. It is used as Ahmia offers it (filtering) and registered as an 'open' source for that use, with Ahmia's offer quoted as evidence (A1 BR2).
3. A banned-list hit shows only 'onion on Ahmia's abuse (banned) list: details withheld'; nothing else is stored or displayed and the onion is never enriched further.
4. The core HTTP and DNS layers refuse .onion hosts outside a configured Tor profile (test), so onion names never reach the corporate resolver or DoH providers.
5. The Ahmia onion index list is not downloaded in this build: Ahmia's ToS (25 Sep 2026) forbid replicating the service without permission; it may be added as a 'license' dataset only with Ahmia's written permission recorded. Ahmia search stays manual-only (rotating form token).
6. AIL titles are shown as plain text, first/last seen dated, tags as attributes. Registry provider circl (AIL): tier trusted, terms open. Fixtures: found and not found.

Chair rationale: Approved 6-0 at median P2. The CSAM filter is mandatory for every onion-displaying module (all members; the architect moves it into core). legal_dpo's floor limits the Ahmia onion list to recorded permission, so it stays out of this build; redteam_lead's .onion refusal in the HTTP/DNS layers and analyst_ux's 'details withheld' display rule are kept.

Synthesizer conditions (background; the final conditions win on conflict): Passive only (no Tor): onion.ail-project.org/api/lookup/{onion} (titles, first/last seen, tags); Ahmia onion index list and banned/CSAM MD5 list downloaded as datasets (banned list is a mandatory safety filter for any Tor feature); Ahmia search is manual-only (needs a rotating form token, ToS forbid scraping).
Notes: Context for onion addresses found in IOCs and ransom notes.

## P206 `goplus_security` - GoPlus address/token security + Honeypot.is

- council: **approved**, priority P2, default_enabled=True, provider_tier=community, terms=key-terms, opsec=passive, shares_input=True

### Final conditions (binding spec - implement every item)

1. Module crypto/goplus_security: GoPlus api.gopluslabs.io address_security/{addr}?chain_id= and token_security (keyed by lowercase contract) for EVM/TRON addresses; phishing_site only for URLs/domains with crypto context in the case (wallet, token or drainer tags), never for every URL; Honeypot.is only for token contracts (404 'No pairs found' = not applicable, no row).

3. Responses {'code':1,'message':'ok','result':{...}}: code != 1 -> ERROR via P321; string flags '0'/'1' are cast to bool. Each flag maps to a named finding with its data_source; specific flags (phishing_activities, stealing_attack, cybercrime, money_laundering, blackmail_activities) -> tags; doubt-type flags (e.g. blacklist_doubt) are low.
4. GoPlus 'sanctioned' is not authoritative: the sanctions tag comes only from P205. One vote in consensus.

Terms (legal floor): GoPlus and Honeypot.is terms could not be verified (docs JS-only, 2026-11-26): class 'key-terms'; under corporate only after legal records the terms (free_plan_business_use) or a company key plan; optional key 'goplus' (app key/secret) from a company account. Honeypot.is is queried only if its registry review records tier community or higher.
6. Registry: GoPlus Security tier community; Honeypot.is per its review. Fixtures: address_security, token_security, phishing_site and the Honeypot.is 404.

Chair rationale: Approved 6-0 at median P2. legal_dpo's floor applies the key-terms rule (terms unverified) and strips victims' data from URLs; redteam_lead limits phishing_site to crypto contexts so ordinary CSIRT URLs are not sent to a Web3 vendor; cti_lead keeps GoPlus 'sanctioned' non-authoritative; analyst_ux's named flags and the architect's string/code semantics are kept.

Synthesizer conditions (background; the final conditions win on conflict): GoPlus address_security/{addr}?chain_id= (keyless; flags are strings '0'/'1' -> cast; {'code':1} = ok), token_security keyed by lowercase contract, phishing_site for URLs; Honeypot.is for token contracts (404 for non-token addresses = not applicable).
Notes: Malicious-address and scam-token flags for EVM/TRON.
