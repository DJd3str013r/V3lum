## P211 `btc_explorers` - Bitcoin/Litecoin explorers with failover (Esplora, mempool.space/litecoinspace, Blockchain.com, BlockCypher, Blockchair, Bitaps, SoChain)

- council: **approved**, priority P2, default_enabled=True, provider_tier=community, terms=key-terms, opsec=passive, shares_input=True
- category: crypto; group: G09; inputs: btc_address, other_crypto_address; produces: btc_address
- auth: mixed; key env vars: V3LUM_BLOCKCYPHER_TOKEN, V3LUM_BLOCKCHAIR_KEY, V3LUM_SOCHAIN_KEY; hosts: blockstream.info, mempool.space, litecoinspace.org, blockchain.info, api.blockcypher.com, dogechain.info, api.blockchair.com, blockchair.com, api.bitaps.com, sochain.com

### Final conditions (binding spec - implement every item)

1. Module crypto/btc_explorers: one Esplora parser for Blockstream, mempool.space and litecoinspace.org (balance = funded_txo_sum - spent_txo_sum, in sats); a configured self-hosted esplora_url is always tried first. With one disclosure class per module (A8 BR7), the self-hosted path is also a class btc_esplora_internal (disclosure 'internal', no public failover) for TLP:AMBER+ and RED cases.
2. Fallbacks in this build: Blockchain.com rawaddr/multiaddr (%7C separators) and BlockCypher (LTC/DOGE/DASH; optional token 'blockcypher', sent only after AR01 redaction). Bitaps and SoChain are dropped (value 2). Blockchair only with a commercial key 'blockchair' (keyless use is personal/non-commercial, and our egress got HTTP 430 on the second call).
3. Failover is sequential and only on error, never a fan-out of the same address to every provider: the first successful provider wins; total explorer time <= 15 s per address; the answering provider, failover order and per-provider status are recorded. Without a self-hosted URL the report lists which public explorers received the address.
4. Per-host P334 buckets; 429/430 -> RATE_LIMITED and that host is short-circuited for the run, never empty. Addresses are validated with the core validators (P217) to choose chain and provider; transaction pagination <= 2 pages.
5. Summary: balance, tx count, first/last activity and data freshness; the top 10 counterparties by value become transacted_with pivots with expand=False (only P213 decides expansion), labelled 'counterparty (role unknown)'; uninvolved counterparties' balances and histories are not kept beyond the case.
6. Per-adapter terms recorded: Esplora, mempool, litecoinspace and Blockchain.com 'open'; BlockCypher and Blockchair 'key-terms'. Registry tiers: Blockstream, Blockchain.com, BlockCypher and Blockchair trusted; mempool.space and litecoinspace community.

Chair rationale: Approved 6-0 at median P2 (the architect voted P1). The architect's floor trims seven providers to one Esplora parser plus two fallbacks; cti_lead, redteam_lead and analyst_ux require sequential failover so only one operator sees each address and a self-hosted Esplora first; legal_dpo requires Blockchair's commercial key and minimises counterparties; osint_investigator leaves expansion to P213.

Synthesizer conditions (background; the final conditions win on conflict): Esplora schema shared by Blockstream/mempool.space/litecoinspace (one parser; balance = funded_txo_sum - spent_txo_sum in sats); fallback Blockchain.com rawaddr/multiaddr (%7C separators), BlockCypher (DOGE/DASH; optional token), Bitaps, SoChain; Blockchair only with key (keyless use limited/non-commercial and our egress got HTTP 430 temporary blacklist on the 2nd call). Per-host token buckets with 429/430 backoff; counterparties = depth-1 pivots ranked by value, capped (top-N); providers see queried addresses -> configurable self-hosted Esplora URL for sensitive cases.
Notes: Balances, history and counterparties for BTC/LTC/DOGE/DASH addresses.

### Final conditions (binding spec - implement every item)

1. Only inside `v3lum watch` (A14), never in scan: foreground, with --once, --max-runtime (default 8 h) and --max-alerts bounds. It polls https://t.me/s/{channel} public previews with the shared t.me parser of P112; no account, session, joining or bot token (rule 1).
2. Channel list = team-curated data/telegram_watch.json (public channel handles only, with a justification, owner and review date per channel, reviewed by the CTI lead and legal before use) plus deepdarkCTI Telegram entries marked ONLINE/VALID (GPL-3.0, runtime download, parser shared with P198); <= 50 channels per cycle; channels unreachable for 30 days are auto-paused.
3. Politeness: >= 10 s between requests, <= 3 pages (?before=) per channel per cycle and backoff on 429; the last-seen post id is persisted so only new posts are read; the generic 'Contact @name' page = could not read.
4. Rules only over org_profile brands, domains, CNPJ roots, the organisation's own card BINs and the supplier list, plus IOC types; never natural persons. Matching is local after IDNA->Unicode and accent folding; BIN prefixes match only inside a Luhn-valid PAN-like string or next to a 'BIN' keyword.
5. P145 scrubbing before alerts or cache: card numbers reduced to BIN6 + last 4, CPFs masked, credentials, combos and leaked records dropped, secrets redacted (type + hash); alerts keep post id, date, URL and a short excerpt only.
6. Text only: media, files, og:image and link previews are never fetched and links in posts are never visited; extracted URLs and wallets become hostile-tagged, passive-only pivots; hits only enqueue capped passive enrichment (<= 30 per hour, A14).
7. Alerts: a deduplicated digest (one line per new match with channel, date, matched rule and channel-list provenance, deepdarkCTI vs team list), first_seen by post id, mutes per channel and per rule; alerts follow retention_days and the case TLP (default AMBER).
8. Companion feed: Dark Web Informer RSS (headline + link only, safe XML helper); DarkFeed is login-gated and not used. Offline tests replay recorded pages with a fake clock (fixtures: channel page, generic page, a post with a PAN and a CPF).

Chair rationale: Approved 5-0-1 at median P2. osint_investigator deferred pending legal review and minimisation; legal_dpo approved with exactly those safeguards (org-only rules, curated reviewed list, P145 scrubbing, retention), which are adopted together with A14. The architect's bounds and shared parsers, redteam_lead's text-only rule and analyst_ux's BIN matching and digest complete the spec. GPL lists used at runtime are 'open' under the A1 definitions; tier is Telegram's (the only provider that receives requests).
