## P238 `rfb_cnpj_bulk` - RFB CNPJ open-data bulk import (offline reverse lookups)

- council: **approved**, priority P2, default_enabled=False, provider_tier=trusted, terms=open, opsec=passive, shares_input=False
- category: brazil_public_data; group: G10; inputs: cnpj, company_name, person_name, email, phone; produces: cnpj
- auth: none; key env vars: -; hosts: arquivos.receitafederal.gov.br

### Final conditions (binding spec - implement every item)

1. A separate command, `v3lum data import-rfb`, that a scan never triggers. It shows download size and required disk first, refuses when free space < 3x the download, and is resumable with progress. One RFB importer is shared with P361 (table selection, e.g. --names light vs full QSA), not two.
2. Legal floor: only the WebDAV share token RFB itself publishes on its official open-data page (configured with that source URL recorded); never a token taken from third-party code if it differs; stop if RFB requires a login. A rotated or invalid token gives UNAVAILABLE with a doctor hint, never 'no companies'.
3. Robust ETL (architect): PROPFIND parsed with the safe XML helper; streaming, resumable Range downloads to unique temp files with size/etag checks; zip members streamed, latin-1 ';' CSV parsed row by row, batched inserts, indexes built after load; peak memory < 500 MB, checked on a 1M-row synthetic file in a slow test. Import logic re-implemented from minha-receita (MIT) with attribution.
4. Minimisation at import (rule 4, legal floor): CPF digits embedded in MEI/EI razao social are stripped; natural-person partner rows keep only RFB's masked CPF, never completed or brute-forced and never used as a join key (no CPF-fragment joins); faixa etaria is not stored for display.
5. Storage: SQLite under ~/.v3lum/datasets (dir 0700, file 0600) with schema version and source month, never exported; superseded monthly dumps are deleted after a successful import (storage limitation).
6. Lookups: CNPJ root -> branches on request; person-centric reverse lookups (partner name, e-mail, phone, address -> CNPJs) only as explicit analyst queries on analyst-typed seeds inside a case with a recorded purpose, logged in the audit trail, capped at the top 50 plus a total count per query and with a per-case limit (no bulk enumeration).
7. Results are company-centric hypotheses: CNPJ pivots with expand=False; partner-name matches across companies are POSSIBLE (name only); no free-text person search command, no person dossiers and no export of person-centric lists.
8. Shared contacts: an e-mail, phone or address shared by >= 20 CNPJs is tagged shared_contact ('possible accountant/virtual office') and excluded from same-owner rules (P258). Every finding cites 'RFB snapshot YYYY-MM'.
9. Opt-in (default_enabled=False); offline once imported (disclosure 'none'). When the index is absent the module is UNAVAILABLE reason_code 'dataset' ('run v3lum data import-rfb'). Tests import a tiny synthetic zip in the real layout end to end on a temp home.

Chair rationale: Approved 6-0 at median P2 (analyst_ux voted P3): the only lawful route to partner -> companies and shared-contact clustering (laranjas, shell rings). legal_dpo's floor makes it proportionate: the RFB-published token only, purpose-bound and audited person-centric lookups with caps, minimisation at import, no dossiers, deletion of superseded dumps; it also forbids CPF-fragment joins, so cti_lead's and osint_investigator's use of the visible CPF digits as a homonym key is not adopted and name-only matches stay POSSIBLE. The architect's floor: a separate, resumable, memory-bounded importer shared with P361. analyst_ux's honest 'unavailable' status and the shared-contact threshold (cti_lead, osint_investigator) are kept.

Synthesizer conditions (background; the final conditions win on conflict): Optional 'v3lum data import-rfb' (multi-GB monthly dump) via the Nextcloud WebDAV share (PROPFIND https://arquivos.receitafederal.gov.br/public.php/webdav/, basic-auth user = share token from config; tokens taken from minha-receita may rotate; old /dados/cnpj/ path 404) into a local SQLite with access control: partner name -> companies, e-mail/phone/address -> CNPJs, CNPJ root -> branches; LGPD minimisation, never publish person dossiers; port minha-receita (MIT) import logic.
Notes: Only legal path to reverse lookups (partner -> companies) that no free API offers.

### Final conditions (binding spec - implement every item)

1. Licence (legal floor): terms='noncommercial'. DataJud Termo de Uso v1.2 (27/11/2023) offers the API 'exclusivamente para fins legais, nao comerciais e autorizados' (3.3) and forbids commercial exploitation (3.8).
2. Off under the corporate profile until licence-cleared by a licence_allow entry (CNJ's written confirmation, or a recorded legal opinion that internal incident/litigation-risk analysis is not commercial use), reported as coverage lost with reason_code 'licence'.
3. Offline part (always available): the CNJ unified-number parser NNNNNNN-DD.AAAA.J.TR.OOOO in core validators, valid iff int(N+AAAA+J+TR+OOOO+DD) % 97 == 1, with the routing table to the 91 tribunal aliases (J=8 TR in UF order, J=4 trf1-6, J=5 trt1-24 / TR 00 tst, J=6 tre-xx) and test vectors such as 0700055-10.2018.8.01.0022 -> api_publica_tjac.
4. A cnj_process entity type (P333) replaces the keyword/text_blob inputs; at most 5 process numbers per text input. Numbers found while pivoting (gazettes, DJEN) are pivots with expand=False, so the slow API never runs automatically on them.
5. API key: config value, defaulting to the 'APIKey atual' CNJ publishes on datajud-wiki.cnj.jus.br/api-publica/acesso (a public key, not a borrowed one). On 401 one refresh per run fetches that official page and extracts the key with a strict pattern; never taken from third-party code, never logged, stored only in config, redacted (AR01).
6. Queries only by a validated process number routed by J.TR; no party, name, CNPJ or CPF search (terms 3.11, 4.2). Output metadata only: court, class, subjects, filing date, last movements, link. Sealed or absent processes read 'not found in public DataJud', never 'no case'.
7. Latency 25-30 s (expected_latency declared): default_enabled=False (A3); a per-run deadline of 60 s with ctx.cancelled() checks in a threaded run, never delaying the report. 429 es_rejected_execution_exception -> RATE_LIMITED ('could not verify: DataJud overloaded'), retried once with backoff. Rate <= 120 req/min (terms 3.13).
8. DataJud-derived data is never shared with third parties or included in STIX/MISP exports (terms 4.6), and the module is never used to screen employees or job candidates.
9. Merge gate (A16): offline tests with FakeHttp (unmatched requests fail, network guard active) over trimmed real fixtures without personal data (the 5 DataJud captures including the 429 overload body), a provider-registry entry for every host, the registry contract test and the P327 lint.

Chair rationale: Approved 6-0 at median P2 (cti_lead and redteam_lead voted P3). legal_dpo's floor relabels it noncommercial per the CNJ terms (3.3, 3.8), so it is off under the corporate profile until legal records an allow entry, and it adds the rate, export and screening limits. The 25-30 s latency makes it opt-in under A3, which matches cti_lead. osint_investigator's and analyst_ux's metadata-only output and wording are kept; the public CNJ key is not a borrowed key (redteam_lead).

## P242 `dou_search` - Diario Oficial da Uniao search (Imprensa Nacional)

- council: **approved**, priority P2, default_enabled=True, provider_tier=trusted, terms=open, opsec=passive, shares_input=True
- category: brazil_public_data; group: G10; inputs: cnpj, company_name, person_name, keyword; produces: 
- auth: none; key env vars: -; hosts: in.gov.br

### Final conditions (binding spec - implement every item)

1. Legal floor (A9 BR8): www.in.gov.br/robots.txt disallows all robots ('Disallow: /', checked 2026-11-26), so the public search page is never scraped. Automation uses only the official DOU open-data dumps (XML published by Imprensa Nacional), downloaded by `v3lum data update dou` through the dataset manager and matched locally (disclosure 'none'), never during a scan.
2. INLABS (daily XML behind a login) is not built in this build: it needs a team account created by an authorised employee (A15) and a P327 lint decision on authenticated downloads (BACKLOG). The manual pivot link is the public search URL (in.gov.br/consulta/-/buscar/dou?q=), emitted as Module.manual_link.
3. Without the dataset the module is UNAVAILABLE reason_code 'dataset' ('run v3lum data update dou'), aggregated into one coverage line, with the manual link; results always say 'DOU dump as of <date>' because recent acts may be missing. The local index covers a configurable window (default the last 24 months) and older months are pruned.
4. Source: the official dump URL is recorded in the provider registry with evidence after a check from the team network, and a trimmed real dump excerpt is captured before merge; if no lawful dump is reachable, only the manual link ships.
5. Parsing: XML through the core safe XML helper with size caps; a dump whose structure does not match the expected schema is ERROR 'format changed', never 'no mentions' (fixture with a broken dump).
6. Matching: the formatted CNPJ (and its digits) and the exact razao social of CNPJ seeds and analyst-typed company names by default; person names only for a typed person seed in a due-diligence case with a recorded purpose, never QSA names automatically; keyword only on explicit request.
7. Output: hit count plus the 5 most recent excerpts (date, section, organ/act type, link), with excerpts containing penalty terms (penalidade, inidoneidade, rescisao, multa, sancao, suspensao) ranked first. Routine mentions are INFO and never raise the risk score.
8. Case data keeps per hit only title, date, section, organ, URL and an excerpt of at most 300 chars; no full act text. Person names in excerpts are never pivoted; CNJ process numbers in excerpts become P241 pivots with expand=False.
9. Tests: a trimmed real dump excerpt (one act with a CNPJ, one with a penalty term, one routine), a no-match case and the broken-format case; registry entry and P327 lint (A16).

Chair rationale: Approved 6-0 at median P2 (cti_lead voted P3). legal_dpo's floor is decisive: the portal's robots.txt forbids all robots and A9 binds V3LUM to respect it, so the scrape of the search page planned by the synthesizer, the architect and osint_investigator is replaced by the official open-data dumps matched locally. INLABS, the other official channel legal_dpo allows, is backlogged because it needs a team login and a lint decision. The architect's loud-failure rule, cti_lead's and analyst_ux's query and output limits, and osint_investigator's excerpt size and CNJ routing are applied to the dump parser.

Synthesizer conditions (background; the final conditions win on conflict): Low-volume GET of the public search page (in.gov.br/consulta/-/buscar/dou?q=&s=) parsing the embedded JSON blob (not the HTML); min_interval >= 3 s; snippets only (appointments/penalties of individuals: minimise); the INLABS XML API needs a login -> not used.
Notes: Federal contracts, sanctions and CNPJ mentions.
