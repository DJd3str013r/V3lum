## P243 `querido_diario` - Querido Diario municipal gazettes search

- council: **approved**, priority P2, default_enabled=True, provider_tier=community, terms=open, opsec=passive, shares_input=True
- category: brazil_public_data; group: G10; inputs: cnpj, company_name, person_name, keyword; produces: keyword
- auth: none; key env vars: -; hosts: api.queridodiario.org.br, api.queridodiario.ok.org.br

### Final conditions (binding spec - implement every item)

1. Host api.queridodiario.org.br only; the old api.queridodiario.ok.org.br fails TLS and is removed (never a fallback; the Ceos port must be fixed). <= 1 req/s, cache 24 h, ~3 s per query. Open Knowledge Brasil open data with attribution in reports.
2. Queries: the formatted CNPJ in quotes and the exact razao social/nome fantasia, by default only for CNPJ seeds and analyst-typed company names; default date window 2 years; keyword only on explicit request. Person names only for a typed person seed in a due-diligence case with a recorded purpose, never QSA names automatically (legal_dpo).
3. Bounded output: at most 10 excerpts per query; the analyst sees the count plus the 5 most recent excerpts with penalty terms (penalidade, inidoneidade, rescisao, multa, sancao, suspensao) ranked first (a large CNPJ hits 2,000+ gazettes). Routine mentions are INFO and never raise the score.
4. Minimisation: each hit keeps municipality, date, gazette URL (as a link) and an excerpt of at most 300 chars as finding data; no bulk storage of gazette texts and no PERSON entities extracted from excerpts.
5. Derived pivots: CNJ process numbers found by the shared parser become cnj_process pivots with expand=False (P241, under its licence gate); other CNPJs in excerpts become cnpj pivots with expand=False (hypotheses, not confirmed links).
6. Empty results read 'not found in covered gazettes (Querido Diario indexes only part of Brazil's municipalities)', never 'no mentions'. Rule 5: 401/403/429, timeouts, 5xx and error-in-200 bodies mean could not verify (P321/P328 statuses: BLOCKED, RATE_LIMITED, QUOTA, ERROR), never EMPTY or 'not found'; such responses are never cached.
7. Merge gate (A16): offline tests with FakeHttp (unmatched requests fail, network guard active) over trimmed real fixtures without personal data (the 4 Querido Diario captures plus an empty result and a 5xx), a provider-registry entry for every host, the registry contract test and the P327 lint.

Chair rationale: Approved 6-0 at median P2 (cti_lead voted P3). Every member asked for the new host only; the architect's bounded excerpts and non-expanding derived pivots, analyst_ux's count-plus-5 presentation shared with dou_search, cti_lead's coverage caveat and osint_investigator's excerpt limits are combined. legal_dpo's floor keeps person searches purpose-bound and storage to excerpts. Open Knowledge Brasil is recorded as community tier.

Synthesizer conditions (background; the final conditions win on conflict): Use the NEW host api.queridodiario.org.br (old api.queridodiario.ok.org.br fails TLS; Céos still uses it - fix when porting); search the FORMATTED CNPJ in quotes and exact company names; excerpts only, minimise personal data in appointments/penalties; extract CNJ numbers from excerpts for datajud.
Notes: Municipal contracts, sanctions and mentions of companies.

- sources shared with other proposals: {"C0744": ["P360"], "C0745": ["P360"], "C0515": ["P220"], "C0523": ["P224"]}

### Final conditions (binding spec - implement every item)

1. Two steps (architect): step 1 ships the offline sector registries (CVM cadastros ';' ISO-8859-1, BCB Sedes*/DominiosVerificados through the loader shared with P360/P244) plus GLEIF and Wikidata through the clients shared with P220 and P224; step 2 adds the local RFB name index once the shared P238 importer exists.
2. Index: built only by `v3lum data import-rfb --names` (Empresas + Estabelecimentos only, ~6.8 GB compressed, streaming, resumable, disk-space check, shared downloader with P238), never during a scan.
3. SQLite FTS5 is detected at runtime (PRAGMA compile_options) with a normalised-token table as fallback; names are normalised by core/namematch.py (accents; LTDA, S.A., S/A, EIRELI, ME, EPP, SLU); active head offices rank first.
4. Rule 4 / legal floor: MEI names are stripped of 11-digit CPF sequences before indexing (tested); the index serves company-name search only, never person search (even for MEI/EI names), and a person_name input never queries it (test).
5. Output: ranked 'possible CNPJ' hypotheses with match evidence (similarity, normalised name, UF/city, situacao, head office, source, index snapshot date) as pivots with expand=False; non-interactive scans list at most 5 with the exact follow-up command.
6. The P236 chain starts automatically only on an exact unique match of the normalised razao social of an active head office; nome fantasia matches never auto-chain; every other case needs analyst confirmation (TTY selection or the printed command). The resolver never runs on a legal name that came from a CNPJ record.
7. Online fallbacks only when the local index is absent or returns nothing (tiers: RFB, CVM, BCB, GLEIF and Wikimedia all trusted): GLEIF fuzzycompletions/fulltext (CC0) and Wikidata P6204 items (identifying UA on Wikimedia hosts only), labelled 'large companies only'. Without the index the module says 'local name index not installed (v3lum data import-rfb --names, ~7 GB)'.
8. CNPJs derived from DOU/Querido Diario excerpts stay hypotheses. Hypotheses and domains derived from them never become LIGHT/ACTIVE seeds, org_profile entries or scope entries without analyst confirmation (redteam_lead).
9. Performance and tests: a query returns in < 500 ms (benchmark on a synthetic 200k-row index); fixtures: the 11 GLEIF/Wikidata/CVM/BCB captures plus a synthetic RFB slice with an MEI name carrying CPF digits.

Chair rationale: Approved 6-0 at median P2 (legal_dpo voted P1). It lets Brazilian chains start from 'Empresa X Ltda'. legal_dpo's floor (company search only, CPF digits stripped, confirmation before P236) and the architect's two-step delivery with shared clients and importer are adopted. On auto-chaining the strictest consistent rule wins: exact unique razao social of an active head office (cti_lead, analyst_ux), never nome fantasia. osint_investigator's person_name test and redteam_lead's no-scope-leak rule complete it.

Synthesizer conditions (background; the final conditions win on conflict): Local first: optional monthly `v3lum data import-rfb --names` builds the light FTS5 index from Empresas + Estabelecimentos only (~6.8 GB compressed download; MEI names stripped of embedded CPF digits; legal suffixes/accents normalised; QSA import stays P238); sector registries matched offline (CVM cadastros ';' ISO-8859-1, BCB Sedes*/DominiosVerificados daily); online fallbacks GLEIF fuzzycompletions/fulltext (registeredAs = formatted CNPJ, CC0) and Wikidata items with P6204 (only ~2,900 items; identifying UA, 429 otherwise); Querido Diario/DOU excerpts may add CNPJs as hypotheses (P242/P243). Output ranked 'possible CNPJ' hypotheses with match evidence; the CNPJ chain (P236 cnpj_lookup) starts only after analyst confirmation or an exact unique match.
Notes: Lets Brazilian due-diligence chains start from 'Empresa X Ltda' instead of requiring a CNPJ.
