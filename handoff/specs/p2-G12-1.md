## P259 `image_metadata` - Image metadata (EXIF/XMP/IPTC/GPS, camera serials)

- council: **approved**, priority P2, default_enabled=True, provider_tier=n/a, terms=open, opsec=passive, shares_input=False
- category: geo_image_meta; group: G12; inputs: file, url; produces: coordinates, keyword
- auth: none; key env vars: -; hosts: -

### Final conditions (binding spec - implement every item)

1. FILE input only: this passive module never fetches URLs. An analyst-typed URL is downloaded only by the shared LIGHT file fetcher (--mode light, after the passive lane, P376 hostile-host guard fail closed, core address guard, 20 MB cap, P334 LIGHT budget, P324 ledger, archived copy preferred), which hands the module a file.
2. Parsing runs in the shared file-analysis sandbox core/sandbox.py: a python -I child process with a wall timeout, POSIX rlimits (memory <= 1 GiB, CPU, no file writes), input cap 100 MB and JSON output cap 1 MB; doctor reports the reduced isolation on Windows. Downloaded data is never executed.
3. Pillow (optional extra) with Image.MAX_IMAGE_PIXELS set; DecompressionBombError becomes an ERROR result with a clear reason; ExifRead (BSD-3) is the optional fallback for HEIC/RAW; ExifTool (GPL) only as an external binary on PATH (A6).
4. Extracted: EXIF/XMP/IPTC dates, camera make/model/serial and software as attributes; editing software (Photoshop, GIMP...) as an INFO tag; an EXIF thumbnail whose aspect ratio differs from the main image flagged 'possible crop/edit'.
5. GPS becomes a coordinates pivot (relation photo_taken_at) with the privacy tag, never auto-expanded: no automatic reverse geocoding, map, Wi-Fi or other lookup; map links are privacy=true manual links shown only after the analyst confirms for that image (legal_dpo).
6. Legal floor: no face detection or recognition of any kind (no biometrics). GPS, camera serials and owner fields are stripped from STIX/MISP exports unless the analyst opts in for the case, and GPS is shown only inside the case report.
7. Plain-language summary first ('taken 2026-03-01 14:22 with <make/model>, GPS present'), stating that missing EXIF is normal (WhatsApp, Telegram, social platforms and screenshots strip it) and that EXIF can be edited; missing EXIF is never a finding.
8. Tests use synthetic images generated in the tests (the research JPEG prototype with GPS) plus a decompression-bomb image and a truncated file. Offline: disclosure 'none', default-on (A3).

Chair rationale: Approved 6-0 at median P2 (osint_investigator, legal_dpo and the architect voted P1). The architect's floor removes the url input from this passive module and sandboxes the parser. redteam_lead, cti_lead and osint_investigator's LIGHT-only download through the egress guard becomes one shared fetcher. legal_dpo's floor forbids face processing, automatic geocoding and GPS in exports. analyst_ux's and osint_investigator's wording on missing or editable EXIF and the thumbnail check are kept.

Synthesizer conditions (background; the final conditions win on conflict): Offline with Pillow (MIT-CMU) and ExifRead (BSD-3) as fallback; parse untrusted files in a subprocess with timeout/memory cap, Pillow MAX_IMAGE_PIXELS, no external renderers; GPS -> coordinates entity (never auto-expanded), camera make/model/serial and software as attributes; privacy tag when GPS present.
Notes: Locates and attributes photos/screenshots in fraud and phishing cases.

## P261 `qr_decode` - QR/barcode decoding from images (quishing, PIX QR)

- council: **approved**, priority P2, default_enabled=True, provider_tier=n/a, terms=open, opsec=passive, shares_input=False

2. Decoder: zxing-cpp as an optional extra v3lum[qr] (Apache-2.0, small binary wheels for Linux, macOS and Windows, CPython >= 3.11; it also reads the ITF barcodes printed on boletos). 3. Parsing runs in the shared file-analysis sandbox core/sandbox.py: a python -I child process with a wall timeout, POSIX rlimits (memory <= 1 GiB, CPU, no file writes), input cap 100 MB and JSON output cap 1 MB; doctor reports the reduced isolation on Windows. Downloaded data is never executed. Pillow's pixel cap applies; each payload is capped at 4 KB.

Routing: URLs become url entities with provenance qr and go only to passive URL reputation, never fetched or opened (a tokenised QR URL would confirm the scan to the phisher); PIX payloads and boleto ITF codes go to the P233 parser functions called directly; other text goes to the shared P172 IOC extractor.
5. Display: payload type and defanged value ('QR -> URL hxxps://...'). No code decoded reads 'no QR/barcode found', never 'clean'.
6. Fixtures: small QR and ITF PNGs generated once with a dev-only encoder and committed (benign URL, PIX BR Code with a valid CRC, boleto line), plus a multi-code image and an oversized image.

Chair rationale: Approved 6-0 at median P2 (osint_investigator and legal_dpo voted P1): quishing and tampered PIX QR codes are common in Brazil. The architect's floor picks zxing-cpp, which also covers the boleto barcodes osint_investigator wanted, instead of OpenCV or pyzbar, inside the shared sandbox. Every member agreed decoded URLs are never fetched (redteam_lead: fetching confirms the scan). cti_lead's and analyst_ux's routing and wording are kept.

Synthesizer conditions (background; the final conditions win on conflict): Offline decoding (OpenCV QRCodeDetector Apache-2.0 or pyzbar optional extra); decoded URLs go to url_unwrap/blocklists (never fetched automatically), PIX payloads to boleto_pix.
Notes: Detects malicious QR codes in e-mails/flyers and tampered PIX QRs.

## P271 `pe_triage` - PE header/imports/imphash triage (pefile)

- council: **approved**, priority P2, default_enabled=True, provider_tier=n/a, terms=open, opsec=passive, shares_input=False
- category: file_analysis; group: G12; inputs: file; produces: md5, sha256

3. pefile (pure Python, MIT) with fast_load, parsing only the IMPORT, EXPORT, RESOURCE and DEBUG directories, with caps on section and import counts.
4. Outputs: compile timestamp (zero, future or pre-2000 values such as the Delphi 1992 stamp flagged 'unreliable/forged'), imphash, Rich header hash, sections with entropy, imports, packer hints, Authenticode presence with signer subject/issuer/serial recorded as 'signed, not verified' (no claim of validity), and the PDB path.
5. Pivots: imphash and the signer become pivots with expand=False for hash-lookup modules once the P333 types exist (until then attributes, never free-text keywords); md5/sha256 of the file are hash pivots; the Rich hash stays an attribute.

7. Packer hints and high entropy are context, not verdicts; they are downgraded when a known-good source in the case marks the hash (CIRCL hashlookup without KnownMalicious, P169 known-good lists), because a hashlookup hit alone is not proof of good.
8. Fixtures: small benign PE files built for the tests (no malware in the repository; EICAR string only) plus a truncated and a malformed PE.

Chair rationale: Approved 6-0 at median P2 (cti_lead and legal_dpo voted P1). The architect's floor: pefile in the shared sandbox with fast_load and caps, no claim of signature validity, benign fixtures only. cti_lead's outputs (Rich hash, signer, unreliable timestamps, known-good check) and osint_investigator's rule that PDB usernames stay attributes are adopted.

Synthesizer conditions (background; the final conditions win on conflict): pefile (MIT) in a sandboxed subprocess: compile timestamp, imphash, sections + entropy, imports, signatures present, PDB paths (often leak usernames) -> attributes; imphash as keyword pivot.
Notes: Quick static triage of executables shared by victims.
