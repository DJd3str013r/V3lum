## P314 `id_timestamp_decoders` - Snowflake/ID -> timestamp decoders (X, Discord, TikTok, LinkedIn, Instagram)

- council: **approved**, priority P2, default_enabled=True, provider_tier=n/a, terms=open, opsec=passive, shares_input=False
- category: utility; group: G12; inputs: url, text_blob, keyword; produces: 
- auth: none; key env vars: -; hosts: -

### Final conditions (binding spec - implement every item)

1. Offline module: disclosure 'none' (no network at all; ScopedHttp refuses any request), terms 'open', provider tier 'n/a'; allowed at TLP:RED.
2. Decode only ids taken from recognised platform URLs (x.com/twitter.com .../status/ID, discord.com/channels/... and webhook URLs, tiktok.com/@.../video/ID, linkedin.com/...activity-ID) or an explicit prefix (snowflake:ID); arbitrary long numbers in text blobs or keywords are never interpreted.
3. Epochs: X 1288834974657 (ids below ~2.9e13, pre-November 2010, are sequential and not decoded), Discord 1420070400000, TikTok video ids (top 32 bits = Unix seconds), LinkedIn activity ids (first 41 bits = ms). Instagram and Mastodon variants are excluded until validated with vectors. tiktok-timestamp (MIT, Bellingcat) is attributed if adapted.
4. Sanity window: a decoded time must fall between the platform's launch and now + 1 day, otherwise it is discarded.
5. Output: a 'created' attribute in UTC ISO with the epoch used, rendered 'created ~2024-05-02 13:11 UTC (decoded from the ID)'.
6. Test vectors: X 1536682540265873408 -> 2022-06-14T12:10:42.437Z; Discord 613425648685547541 -> 2019-08-20T17:34:31.544Z; TikTok 6718335390845095173 -> 2019-07-27T13:32:33Z; plus out-of-window and bare-number negatives.

Chair rationale: Approved 6-0 at median P2 (cti_lead voted P3). Offline and disclosure-free (legal_dpo). The architect's and analyst_ux's rule that only platform URLs or an explicit prefix are decoded, with a sanity window, prevents confident dates from arbitrary numbers.

Synthesizer conditions (background; the final conditions win on conflict): Offline decoders for 64-bit snowflakes (Twitter/X epoch 1288834974657, Discord 1420070400000), TikTok video ids, LinkedIn post ids; output creation timestamps as attributes.
Notes: Dates accounts/posts/guilds without any API.

## P315 `mac_oui` - MAC OUI vendor lookup (IEEE registries offline + maclookup/macvendors fallback)

- council: **approved**, priority P2, default_enabled=True, provider_tier=trusted, terms=open, opsec=passive, shares_input=False
- category: utility; group: G12; inputs: mac_address; produces: 
- auth: none; key env vars: V3LUM_MACLOOKUP_KEY; hosts: standards-oui.ieee.org, api.maclookup.app, api.macvendors.com

### Final conditions (binding spec - implement every item)

1. Offline module (disclosure 'none', runs at TLP:RED): IEEE MA-L, MA-M, MA-S (and CID) CSVs from standards-oui.ieee.org through the dataset manager (monthly; sent with the V3LUM UA because IEEE may block generic library UAs), parsed into a compact prefix index with longest-prefix match (MA-S 36 bits > MA-M 28 > MA-L 24).
2. Locally administered (0x02 bit of the first octet), multicast and randomised MACs are flagged 'random/private MAC: vendor lookup not meaningful' and are never looked up or sent anywhere.
3. The online fallbacks (api.maclookup.app with a team-account key, api.macvendors.com keyless at 1 req/s and 1,000/day) live in a separate opt-in module (architect), used only for prefixes missing from the IEEE index; 404 = unknown OUI, 429 = RATE_LIMITED. Both providers need a recorded community tier before that module runs (A8).
4. Privacy (legal floor): the fallback sends only the registry prefix (6, 7 or 9 hex digits for MA-L/MA-M/MA-S), never the full MAC, which is a device identifier; a unit test asserts it on the request URL.
5. Fixtures: trimmed real IEEE CSV heads plus the maclookup.app and macvendors captures; tests for longest-prefix match and the locally-administered bit.

Chair rationale: Approved 6-0 at median P2 (cti_lead voted P3). legal_dpo, osint_investigator, redteam_lead and analyst_ux all require prefix-only fallback lookups; the architect's floor makes the IEEE path offline and TLP:RED-safe and moves the redundant online mirrors to an opt-in module.

Synthesizer conditions (background; the final conditions win on conflict): IEEE oui.csv/mam/oui36 downloaded monthly and matched locally; online maclookup.app / api.macvendors.com (1 req/s) only when the prefix is unknown; flag locally administered/randomised MACs.
Notes: Device vendor context for MACs in logs/pcaps.

## P316 `jwt_analysis` - JWT decode & weak-configuration analysis

- council: **approved**, priority P2, default_enabled=True, provider_tier=n/a, terms=open, opsec=passive, shares_input=False
- category: utility; group: G12; inputs: jwt, text_blob; produces: url, domain
- auth: none; key env vars: -; hosts: -

### Final conditions (binding spec - implement every item)

1. Offline module: disclosure 'none' (no network at all; ScopedHttp refuses any request), terms 'open', provider tier 'n/a'; allowed at TLP:RED. JWTs are SECRET_TYPES (A8): never sent to jwt.io or any online decoder, never replayed, forged or verified against the issuer.
2. Redaction (core rule, architect): JWT entity values are persisted only redacted (signature stripped, replaced by its length and hash; sensitive claim values masked) in the case DB, reports and evidence file names; the full token exists only in memory. JWTs are SECRET_TYPES (A8): never exported, so STIX/MISP carry only the finding and the token's SHA-256.
3. Structural checks for any token: alg=none (CRITICAL), missing exp, excessive lifetime, kid/jku/x5u pointing to external URLs, PII claims present (e.g. name, email). jku/x5u/kid URLs become url pivots with expand=False and are never fetched. Findings map to T1606/T1528 and CR22.
4. Known-default-secret check, not cracking (A7 BR8): only for HS256/384/512 tokens whose issuer or audience is an org_profile or in-scope asset, against a bundled list of <= 100 publicly documented default secrets (e.g. 'your-256-bit-secret'); no generated candidates or wordlists; skipped for third-party tokens and never applied to RS/ES tokens.
5. A matched secret is never printed, stored or exported: the finding reads 'signed with a publicly known default secret (list entry n)'.
6. Detection in text blobs uses ^eyJ[\w-]+\.eyJ[\w-]+\.[\w-]*$ through the P172 extractor. Tests use the research jwt_demo and jwt_none vectors plus a third-party token that must skip the secret check.

Chair rationale: Approved 6-0 at median P2 (cti_lead voted P3). redteam_lead, author of the A7 forbidden-action list, and legal_dpo's floor limit the default-secret check to own or in-scope tokens and never reveal a secret; the chair takes redteam_lead's 100-entry list over the architect's 10,000 so the check stays a misconfiguration test rather than JWT cracking (A7 BR8). The architect's core redaction rule keeps the full token out of every persisted output.

Synthesizer conditions (background; the final conditions win on conflict): Offline decode (no verification against third parties): alg=none, HS* secret in a small offline weak-secret list, missing exp, long lifetime, kid/jku/x5u pointing to external URLs; redact signature and sensitive claims in output (CR22).
Notes: Flags weak tokens found in public assets or pasted by analysts.

## P363 `image_ocr` - Offline OCR of screenshots and scans (Tesseract por+eng; PDF text layer first)

- council: **approved**, priority P2, default_enabled=True, provider_tier=community, terms=open, opsec=passive, shares_input=False
- category: geo_image_meta; group: G12; inputs: file; produces: text_blob
- auth: none; key env vars: -; hosts: raw.githubusercontent.com

### Final conditions (binding spec - implement every item)

1. Offline (disclosure 'none', TLP:RED-safe). The tesseract binary is optional, found via a config path or PATH and never auto-installed; pytesseract (Apache-2.0) is the wrapper; rapidocr-onnxruntime is not used. A missing binary gives UNAVAILABLE reason_code 'package' with the exact install command.
2. Models: por and eng tessdata_fast (Apache-2.0, tesseract-ocr project on GitHub) through the dataset manager with SHA-256 pinning.
3. Parsing runs in the shared file-analysis sandbox core/sandbox.py: a python -I child process with a wall timeout, POSIX rlimits (memory <= 1 GiB, CPU, no file writes), input cap 100 MB and JSON output cap 1 MB; doctor reports the reduced isolation on Windows. Downloaded data is never executed. Images pass Pillow's pixel cap first (Leptonica parses hostile images).
4. pypdf text layer first; OCR only for image-only pages and at most 10 pages per document.
5. Because text is never auto-expanded, the module itself calls the shared P172 extractor, the P232 BR rules, the P233 boleto/PIX parsers and the P261 QR helpers, and emits their results as pivots (relation extracted_from), not a text_blob.
6. OCR-derived entities carry provenance ocr, confidence <= 0.6 and expand=False until the analyst confirms (0/O, l/1, rn/m misreads). They never trigger typosquat/lookalike findings, and OCR-derived boleto/PIX check-digit failures never trigger tampering findings, without a non-OCR confirmation.
7. The report shows the OCR snippet around each extracted IOC; the full OCR text is kept only in case evidence (it may hold personal data) and CPFs found are masked and never pivoted.
8. Fixtures: synthetic rendered-text images generated in tests (URL, PIX payload, boleto line, CPF to mask, a misread-prone domain).

Chair rationale: Approved 6-0 at median P2 (osint_investigator, legal_dpo and the architect voted P1): most Brazilian scam evidence arrives as screenshots. The architect's floor: optional external binary, pinned models, sandboxed OCR, and the module running the shared extractors itself. cti_lead's and analyst_ux's OCR-misread guards keep misreads from becoming lookalike or tampering findings, consistent with P233; legal_dpo confirmed offline Apache-2.0 components.

Synthesizer conditions (background; the final conditions win on conflict): Optional extra (tesseract binary + pytesseract; rapidocr-onnxruntime as pure-pip alternative on Python < 3.13): pypdf text layer first, OCR only for image-only pages/images; models por + eng (tessdata_fast); text goes to ioc_extraction_engine, br_validators (CPF validated offline, never expanded), boleto_pix and QR/barcode results; OCR text kept inside the case only (may contain personal data); offline (shares_input False, TLP:RED OK).
Notes: Most scam evidence in Brazil arrives as screenshots.

## P366 `script_decoder` - Script de-obfuscation (PowerShell -enc, JS/VBS/HTA string decoding) for IOC extraction
