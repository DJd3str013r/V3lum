## P367 `windows_artifact_triage` - Windows artefact triage: LNK shortcuts, MSI installers and OneNote files

- council: **approved**, priority P2, default_enabled=True, provider_tier=n/a, terms=open, opsec=passive, shares_input=False
- category: file_analysis; group: G12; inputs: file; produces: url, domain, ipv4, keyword
- auth: none; key env vars: -; hosts: -

### Final conditions (binding spec - implement every item)

1. Offline module: disclosure 'none' (no network at all; ScopedHttp refuses any request), terms 'open', provider tier 'n/a'; allowed at TLP:RED. FILE input only.
2. Parsing runs in the shared file-analysis sandbox core/sandbox.py: a python -I child process with a wall timeout, POSIX rlimits (memory <= 1 GiB, CPU, no file writes), input cap 100 MB and JSON output cap 1 MB; doctor reports the reduced isolation on Windows. Downloaded data is never executed.
3. LNK through LnkParse3 (MIT) as an optional extra (it pulls PyYAML, allowed only inside that extra): target, arguments, working dir, icon location, timestamps, machine id, droid MAC and volume serial. Arguments go to the P366 decoder functions.
4. OneNote: embedded files found by an own scan for the FileDataStoreObject GUID header (pyOneNote 0.0.2 is not used). MSI: olefile streams and, when the optional pre-release pymsi (MIT) is installed, the CustomAction, Binary and Property tables; otherwise the status says 'MSI tables not parsed', never empty.
5. Embedded scripts (HTA, JS, VBS, PowerShell in CustomActions or OneNote) go to P366; embedded files are hashed in memory and emitted as hash pivots, never written to disk or made executable. A parser failure is ERROR, never EMPTY.
6. UNC and WebDAV targets in shortcuts become hostile pivots that are never touched (no SMB or WebDAV access), as in P269.
7. LNK machine id, droid MAC and volume serial are clustering attributes only (expand=False, never sent to any lookup) and are indexed in the P375 case-DB sightings so Grandoreiro/Mekotio-style campaigns link across cases.
8. Fixtures: synthetic LNK, OneNote and MSI samples built in tests (including a malformed one of each).

Chair rationale: Approved 6-0 at median P2 (legal_dpo voted P1). The architect's floor avoids the pre-release parsers (own OneNote scan, pymsi optional with an honest 'not parsed' status) inside the sandbox. cti_lead's cross-case clustering of LNK machine ids, redteam_lead's untouched UNC/WebDAV targets and legal_dpo's attributes-only rule for machine identifiers are adopted.

Synthesizer conditions (background; the final conditions win on conflict): LnkParse3 for LNK (target, arguments, machine id, droid MAC, timestamps), olefile/oletools for MSI tables (CustomAction, Binary, Property) with pymsi as optional parser, pyOneNote for embedded OneNote files (pre-release libraries wrapped in try/except); embedded scripts to script_decoder, embedded files hashed (never written executable); machine id / MAC as clustering attributes only.
Notes: LNK/MSI/OneNote are the usual first stages of Grandoreiro/Mekotio/Casbaneiro-style chains.
