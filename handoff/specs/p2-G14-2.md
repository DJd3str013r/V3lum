## P203 `pivots_darkweb` - Pivot links: ransomware group pages + clearnet onion search

- council: **approved**, priority P2, default_enabled=True, provider_tier=n/a, terms=open, opsec=passive, shares_input=False
- category: darkweb_ransomware; group: G14; inputs: threat_actor, keyword, company_name; produces: 
- auth: none; key env vars: -; hosts: ransomlook.io, ransomware.live, onionsearchengine.com

### Final conditions (binding spec - implement every item)

1. Ship data/pivot_links/darkweb.json in the frozen P311 pack schema (label, template, entity_types, category, host, verified, checked_at, privacy, publishes=false, touches_target, login_required, antibot), plus the optional per-link max_tlp field that the phase-0 schema must include. The pack is offline data (disclosure 'none'): V3LUM never requests these URLs or any API behind them.
2. Rendering follows A2/P311: at TLP:AMBER and above every link is non-clickable text with 'opening sends <value> to <host>'; at RED third-party links are hidden from reports and listed only by `v3lum links` with the warning; links are never auto-opened and `links --open` at AMBER+ needs an interactive confirmation naming the host.
3. CI renders every template with a sample value per declared entity type and with hostile values (quotes, spaces, unicode, newlines): each result must be an https URL on the declared host, built only from whitelisted placeholders through the declared encoder (never str.format, never {raw} in URL position).
4. Every link host has a provider-registry entry with tier and rationale (A8); unknown-tier hosts get the 'unknown operator' badge and their templates take IOC_TYPES values only (A8 BR4): never PERSONAL_TYPES, CNPJ, company names, keywords, malware or actor names, or other free text (P311 lint).
5. Initial host tiers for the registry reviewer to confirm: community - ransomlook.io, ransomware.live; unknown - onionsearchengine.com.
6. Order: P311 groups links by analyst question with verified links first; inside a group the pack's file order is the curated analyst-value order (ransomware group pages first, then onion search); the terminal shows at most 8 links per seed, the rest go to HTML and `v3lum links`.
7. Verified links carry checked_at; `v3lum doctor --links` (offline) lists unverified links and links not re-checked for more than 180 days. The pack ships in phase 1 with the other pivot packs (A16), whatever the state of the related automated modules.
8. Group pages: ransomlook.io/group/{slug} and ransomware.live/group/{slug}, with the per-site slug resolved through the P295 alias index (trackers name groups differently, e.g. lockbit3 vs lockbit); when no slug is known the site's search URL is used instead of a guessed path (architect, cti_lead).
9. Rule 3: claim pages, leak-file, download and victim-file URLs are never linked or generated; the P311 lint rejects such paths.
10. OnionSearchEngine is unknown tier: its template exists only for IOC values (domain, onion), never for company names, brands or keywords (A8: unknown operators receive IOC_TYPES only), with max_tlp=green so it is hidden from reports at TLP:AMBER+ (cti_lead, redteam_lead).
11. Onion-search and .onion links carry the warning 'illicit content, possibly child sexual abuse material (possession is a crime, ECA art. 241-B): open only in the team's isolated browsing environment'; .onion addresses render as non-clickable text and nothing is ever auto-fetched (legal_dpo, redteam_lead).

Chair rationale: Approved 6-0 at median P2 (osint_investigator voted P1). The architect's slug mapping through P295 prevents 404 links. legal_dpo's floor adds the isolation warning (ECA art. 241-B) and rule 3 (no claim or leak-file URLs). Because OnionSearchEngine is an unknown-tier operator, the A8 floor limits it to IOC values, which is stricter than osint_investigator's 'org brands or typed seeds' and keeps company names away from it; cti_lead and redteam_lead's hiding at AMBER+ is adopted.

Synthesizer conditions (background; the final conditions win on conflict): ransomlook.io/group/{g}, ransomware.live/group/{g}, onionsearchengine.com/search.php?search=; never link claim/leak-file URLs; onion search results open in the analyst's browser only (warning banner).
Notes: Group profiles and onion mentions for analysts.
