## P007 `subdomains_keyed` - Keyed subdomain sources (Chaos, DNSDumpster, FullHunt, BeVigil, BufferOver, jsmon)

- council: **approved**, priority P3, default_enabled=True, provider_tier=community, terms=key-terms, opsec=passive, shares_input=True
- category: domain_dns; group: G01; inputs: domain; produces: domain, url
- auth: free_key; key env vars: V3LUM_CHAOS_KEY, V3LUM_DNSDUMPSTER_KEY, V3LUM_FULLHUNT_KEY, V3LUM_BEVIGIL_KEY, V3LUM_BUFFEROVER_KEY, V3LUM_JSMON_KEY; hosts: dns.projectdiscovery.io, api.dnsdumpster.com, fullhunt.io, osint.bevigil.com, tls.bufferover.run, subdomains.jsmon.sh

### Final conditions (binding spec - implement every item)

1. One adapter per provider, each with its own key, terms label, min_interval, P334 budget and per-source status. Module subdomains_keyed: Chaos (ProjectDiscovery, trusted), DNSDumpster, FullHunt and BeVigil (community). Module subdomains_keyed_minor (default_enabled=False): BufferOver and jsmon, unknown tier (excluded at AMBER and above, --allow-unknown at CLEAR/GREEN).
2. Each adapter runs only when its own key is configured (optional_keys) and reports NEEDS_KEY, never EMPTY, without it. Keys are registered in config.KNOWN_KEYS (V3LUM_KEY_<NAME>; V3LUM_CHAOS_KEY, V3LUM_DNSDUMPSTER_KEY, V3LUM_FULLHUNT_KEY, V3LUM_BEVIGIL_KEY, V3LUM_BUFFEROVER_KEY, V3LUM_JSMON_KEY as aliases) and sent in headers only (DNSDumpster: X-API-Key on api.dnsdumpster.com).
3. Key-terms per adapter: a company/team account, never an analyst's personal free account, on a plan whose terms permit internal business use; legal records plan and terms URL in the registry before the adapter runs under the corporate profile (A1).
4. Parsing: Chaos labels come back without the apex (append '.{domain}'); BufferOver returns comma-separated records (split the IP from the hostname); DNSDumpster keeps ~1 request per 2 s (min_interval 2 s). Every name goes through the shared hostname sink of P001 (validation, provenance per name, dedupe).
5. Per-source cap of 5000 names and a per-provider budget so one huge domain cannot drain a quota. Runs once per registrable domain, on seeds and own assets first.
6. 401/403 bodies map to NEEDS_KEY ('invalid key'), credit/quota exhaustion to QUOTA, throttling to RATE_LIMITED; never EMPTY.
7. Each adapter merges only with a trimmed real success fixture captured with the team key (only 401 fixtures exist for DNSDumpster and FullHunt, which serve the NEEDS_KEY tests).

Chair rationale: Approved 6-0 at median P3 (redteam_lead voted P2). legal_dpo's floor: key-terms per adapter, and jsmon/BufferOver are unknown tier, never default and excluded at AMBER and above; the chair puts them in a separate opt-in module so the default module keeps a community tier (A3 BR2, A8 BR12). The architect's floor: one adapter per provider with its own key, status and budget, header auth, the shared hostname sink, real success fixtures before merge. Key-required sources may be default-enabled (A3 BR5).

Synthesizer conditions (background; the final conditions win on conflict): Each adapter runs only when its own key is configured (optional_keys; V3LUM_CHAOS_KEY, V3LUM_DNSDUMPSTER_KEY (new api.dnsdumpster.com, X-API-Key), V3LUM_FULLHUNT_KEY, V3LUM_BEVIGIL_KEY, V3LUM_BUFFEROVER_KEY, V3LUM_JSMON_KEY). Same validation/provenance pipeline as subdomains_passive; per-source MaxResults cap so one huge domain cannot drain a quota.
Notes: Optional extra coverage for teams that register free keys.
