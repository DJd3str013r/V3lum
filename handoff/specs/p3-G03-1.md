## P069 `public_api_exposure` - Public API exposure (Postman public workspaces, APIs.guru directory)

- council: **approved**, priority P3, default_enabled=False, provider_tier=community, terms=unknown, opsec=passive, shares_input=True
- category: url_web; group: G03; inputs: domain, company_name, keyword; produces: url, domain
- auth: none; key env vars: V3LUM_POSTMAN_KEY; hosts: postman.com, api.getpostman.com, api.apis.guru

### Final conditions (binding spec - implement every item)

1. This build (architect floor): Postman public workspace/collection search metadata only (workspace/collection name, publisher, URL, request hosts matching the target domain) plus the APIs.guru list.json (CC0) as a daily dataset matched locally. No collection/environment downloads: deep mode is deferred to BACKLOG.md.
2. Postman's search is an undocumented website API: terms 'unknown', so the Postman source stays disabled in every profile until legal records its terms (A1); meanwhile the Postman public search page is a manual pivot link. APIs.guru matching runs normally.
3. Queries are limited to org_profile domains and brands: no searches about third-party organisations. Hits not tied to the target by publisher or request host are discarded.
4. Report existence and location only (workspace/collection URL, publisher, matched domain, secret type when visible in metadata), never request bodies; secrets are masked by P312 and never used or replayed.
5. Undocumented endpoint: 403 or a challenge = BLOCKED with no bypass; an unexpected shape = ERROR 'schema changed', never EMPTY; queries capped per scan; pagination (body.from += 25) bounded to 2 pages.
6. default_enabled=False. bbot code (AGPL) is not copied; the technique is re-implemented.
7. Tests with the recorded postman_public_search.json and apisguru_metrics.json fixtures and a schema-change case.

Chair rationale: Approved 6-0 at median P3 (cti_lead and redteam_lead voted P2). legal_dpo's floor: the undocumented endpoint has unknown terms (so it stays disabled until reviewed, A1) and raw collections must never be stored; the architect's floor defers deep mode altogether. cti_lead's own-asset-only scope is adopted (stricter than osint_investigator's 'or the case company'). redteam_lead: no replay and the publisher/host filter. Tier community for APIs.guru (Postman is trusted); terms unknown for the Postman part; opt-in.

Synthesizer conditions (background; the final conditions win on conflict): Postman public search (undocumented website API, may change): query org domain + brand, keep hits whose publisher or request URLs contain the target domain; deep mode (download collections/environments) only with authorization, secrets masked via secret_scanner and never used; APIs.guru list.json downloaded daily and matched locally. bbot code is AGPL: reimplement.
Notes: Leaked API collections with live secrets are a common corporate exposure.

### Final conditions (binding spec - implement every item)

## P075 `phishtank_checkurl` - PhishTank checkurl (single-URL verdict)

- council: **approved**, priority P3, default_enabled=False, provider_tier=trusted, terms=open, opsec=passive, shares_input=True
- category: url_web; group: G03; inputs: url; produces: 
- auth: none; key env vars: V3LUM_PHISHTANK_APPKEY; hosts: checkurl.phishtank.com

### Final conditions (binding spec - implement every item)

1. POST checkurl.phishtank.com/checkurl/ with format=json and the full URL base64-encoded then form-encoded. The User-Agent is PhishTank's documented format 'phishtank/<the team's own registered username or app name>' from a setting, never another user's username or app key (rule 1); the optional app key 'phishtank_app' goes in config.KNOWN_KEYS.
2. default_enabled=False until a live check from the team network shows it answers reliably (< 10% blocked), recorded by doctor.
3. 403 or a Cloudflare challenge gives BLOCKED (one coverage line), never bypassed. After 5 consecutive blocked runs the source is demoted to link-only (A3/A9) and doctor says so.
4. A finding only when verified=true AND valid=true; in_database alone is not a verdict (example.com shows in_database=true). Hits older than 30 days are historical; PhishTank counts as one vote in consensus.
5. Only suspected-phishing URLs under triage (analyst-typed seeds or URLs tagged phishing/suspicious), never org_profile or confidential client URLs. Per-IP limits from X-Request-Limit headers go into the P334 budget.
6. Tests with the recorded checkurl JSON and 403 HTML fixtures, including the in_database quirk.

Chair rationale: Approved 6-0 at median P3. legal_dpo and redteam_lead confirm the 'phishtank/<app>' UA is the provider's documented requirement, not a bypass, and the FAQ allows commercial use. The architect's and analyst_ux's condition keeps it opt-in until reachability from the team network is proven. analyst_ux and osint_investigator: verified/valid only, demotion after repeated blocks. PhishTank (Cisco Talos): tier trusted, terms open.

Synthesizer conditions (background; the final conditions win on conflict): POST checkurl with format=json and a UA of the form 'phishtank/<appname>' (other sweeps saw 403/Cloudflare with other UAs) -> on 403/challenge return blocked (could not verify), never bypass.
Notes: Community-verified phishing verdict for a URL.
