## P139 `intelx_metadata` - Intelligence X selector metadata (phonebook/search metadata only)

- council: **approved**, priority P3, default_enabled=False, provider_tier=trusted, terms=key-terms, opsec=passive, shares_input=True
- category: breach_leak; group: G04; inputs: email, domain, url; produces: email, url, domain
- auth: free_key; key env vars: V3LUM_INTELX_KEY; hosts: free.intelx.io

### Final conditions (binding spec - implement every item)

1. Selector/phonebook metadata only. Endpoint allow-list: phonebook and intelligent search plus result polling; a test asserts that file/preview/view/read/download endpoints can never be built (leaked content is forbidden, rule 3).
2. x-key header (key 'intelx' registered). Key-terms: a company/team account; legal records the free-account plan and terms before it runs under corporate. Daily credits via the P334 block.
3. Async search with bounded polling (<= 5 polls, <= 30 s in total) and a terminate call.
4. Store only system id, bucket name, date and selector type. Sensitive bucket names are masked. IntelX is a sensitive provider (P145 schema before the HTTP cache).
5. Phonebook e-mail harvesting is own-asset-only (run_on='own_assets_only', A11 BR4: txt_verified or attested org_profile domains): harvesting third parties' e-mails from a leak index is people-search over leaks (rule 4). For non-own selectors only bucket names and dates are kept, and e-mail selectors follow the A4 scope (own assets; third parties only as seeds with --breach-scope all and --purpose).
6. The manual link https://intelx.io/?did={systemid} is offered for analysts (privacy rules of P311 apply). Merge only with a trimmed real success fixture. default_enabled=False.

Chair rationale: Approved 6-0 at median P3. legal_dpo's floor: metadata only, never content, phonebook harvesting only for own domains (rule 4), masked bucket names, key-terms. A11 BR4 binds the own-asset verification. The architect's floor: endpoint allow-list with a test, bounded polling, real fixture. cti_lead and osint_investigator: third-party selectors keep bucket names and dates only. Intelligence X is an established company: tier trusted.

Synthesizer conditions (background; the final conditions win on conflict): Free key (V3LUM_INTELX_KEY, small daily credits); ONLY selector/phonebook metadata (system id, bucket name, date, selector type); never call file preview/view/read or download endpoints (leaked content = forbidden); phonebook e-mail harvesting only for the org's own domains; manual link https://intelx.io/?did={systemid} for analysts.
Notes: Shows where corporate selectors appear in leaks/pastes without touching content.

## P141 `pwned_passwords_internal` - HIBP Pwned Passwords k-anonymity check (internal use by secret scanner)

- council: **approved**, priority P3, default_enabled=False, provider_tier=trusted, terms=open, opsec=passive, shares_input=True
- category: breach_leak; group: G04; inputs: text_blob; produces: 
- auth: none; key env vars: -; hosts: api.pwnedpasswords.com

### Final conditions (binding spec - implement every item)

1. Not a registered module (architect floor): a core helper v3lum/core/pwned.py callable only by secret_scanner (P312) for credential-type findings, so no analyst input, CLI argument or text_blob path can reach it (unit test). It is off unless setting secret_scanner_pwned_check is true.
2. The SHA-1 is computed in memory (uppercase hex); only the 5-char prefix is sent to api.pwnedpasswords.com/range/{prefix} with the Add-Padding: true header; the 35-char suffix is compared in memory.
3. The plaintext and the full hash exist only in memory during the call and are never logged, cached, placed in res.raw or evidence, or shown (test asserts). Only the public range response may be cached.
4. The result is stored on the already-masked finding as 'appears N times in public breach corpora'. A k-anonymity range lookup never validates a credential against its service.
5. Attribution to HIBP (CC BY 4.0). Tests with the recorded range fixtures (5BAA6).

Chair rationale: Approved 6-0 at median P3. The architect's floor makes it an internal helper so the rule-3 guarantees are testable and no password can be typed into it. legal_dpo's floor: in-memory only, prefix only, count only, no input path. cti_lead, osint_investigator and redteam_lead found the k-anonymity design safe and marginal. HIBP Pwned Passwords: tier trusted, terms open (CC BY 4.0).

Synthesizer conditions (background; the final conditions win on conflict): Never accept a password as analyst input or CLI argument; only called internally when secret_scanner finds a credential in a public asset: hash locally (uppercase SHA-1), send the 5-char prefix, match the suffix, store only 'pwned N times' and drop the plaintext/full hash immediately (rule 3).
Notes: Tells whether an exposed credential is also in public breach corpora without disclosing it.
