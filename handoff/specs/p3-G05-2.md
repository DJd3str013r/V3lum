## P115 `git_metadata_identity` - Git metadata identity extraction (gitcolombo technique)

- council: **approved**, priority P3, default_enabled=False, provider_tier=trusted, terms=key-terms, opsec=passive, shares_input=False
- category: username_social; group: G05; inputs: url, username; produces: email, person_name, username
- auth: none; key env vars: V3LUM_GITHUB_TOKEN; hosts: api.github.com

### Final conditions (binding spec - implement every item)

1. Module username_social/git_metadata_identity, disclosure third_party (it sends account/repo names to api.github.com). This build reads commit metadata through the shared GitHub REST client and budget of P111 only: repos sorted by pushed, <= 10 repos, one commits page (per_page=100) each, <= 11 requests per account. No git binary and no clone.
2. Runs only on accounts, orgs or repos already in the case as subjects (malicious repos, phishing kits, leaked code, own org), with the purpose recorded (AR16); never on arbitrary developers. default_enabled False.
3. Extraction (gitcolombo logic, MIT, attribution header): author/committer names and e-mails, Co-authored-by and Signed-off-by trailers parsed from messages, noreply ids decoded by the shared P111 helper; noreply, system (^(noreply|no-reply|donotreply|do-not-reply)@) and bot addresses dropped.
4. Identities tied to the investigated account (author/committer of its own commits, its noreply id) are PROBABLE, since git author fields are self-declared and forgeable. Other contributors, co-authors and sign-offs are counted, not listed, unless they match a case entity; contributors to forks/upstream projects are never pivots.
5. Personal identifiers output (e-mails, names, handles) are pivots with expand=False unless CONFIRMED or analyst-selected, are never auto-sent to breach/stealer modules (A4) and are kept no longer than retention_days (GitHub AUP s.8 purpose limit).
6. A clone path, if added later, must be one hardened core helper reviewed by the architect: --bare --filter=blob:none --no-tags, no checkout, no submodules, https only on declared forge hosts, core.hooksPath=/dev/null, GIT_TERMINAL_PROMPT=0, GIT_LFS_SKIP_SMUDGE=1, protocol.file.allow=never, system/global config ignored, size/time caps, temp dir removed.
7. Terms follow the GitHub REST source of P111 ('key-terms'). Fixtures (repo list, a commits page with trailers and noreply addresses) are captured from the team network before merge; tests use FakeHttp.

Chair rationale: Approved 6-0 at median P3. The architect's floor keeps this build API-only (no external git binary or untrusted clones) with a tight per-account cap, stricter than cti_lead's 30 x 200; redteam_lead's and osint_investigator's clone hardening becomes the requirement for any later clone helper. legal_dpo's floor sets disclosure third_party (the draft's shares_input=False was wrong), case-subject-only use with a recorded purpose and no auto-expansion; osint_investigator's 'count, do not list' contributors rule is kept.

Synthesizer conditions (background; the final conditions win on conflict): For public repositories of an investigated account/org: read commit metadata through the GitHub API (repos?per_page=100, commits) or a shallow --filter=blob:none clone (never execute repo code); collect author/committer names+e-mails, Co-authored-by/Signed-off-by trailers, noreply-id decoding; link identities (MIT gitcolombo, attribution); cap repos/commits per run.
Notes: Links pseudonymous developers to real names/e-mails through commit history.

2. Duolingo is not built: an undocumented internal API whose ?email= variant is an account-enumeration oracle (rule 2) and the vector of a mass scrape. A lint test asserts that no spec in the pack accepts e-mail or phone inputs or builds an 'email=' URL.
3. Gate without inter-module calls: specs accept URL entities (the has_account pivots emitted by username_check FOUND) and match their host in applies(), so an enricher runs only for a platform username_check reported FOUND on an analyst-typed or PROBABLE+ handle. default_enabled False (legal_dpo, A3).

Per-spec terms (P377): documented public APIs (Chess.com PubAPI, Lichess, Mojang, Steam Community XML, Medium RSS, Pinterest widget, Stack Exchange API, Twitch Helix with the team's app) are 'open' once recorded; Snapchat __NEXT_DATA__ and the Disqus profile page are 'unknown' and stay disabled in every profile until legal records them (A1).
5. Found/absent rules: Steam XML is always HTTP 200 (FOUND iff <steamID64>, '<error>' = ABSENT); Chess.com 404 = ABSENT, serial requests only; Lichess 404 = ABSENT, one request at a time, 429 = RATE_LIMITED and no Lichess call for 60 s (no in-run wait beyond P326's 15 s); Medium RSS 404 = ABSENT; Mojang 404 = ABSENT (~600 req/10 min).
6. Snapchat __NEXT_DATA__ is guarded by a schema check: a layout change = ERROR 'layout changed', never empty; bot/challenge pages = BLOCKED via P321. SnapIntel (AGPL) is used for ideas only.
7. Optional keys (Steam, Stack Exchange, Disqus, Twitch): a missing key = NEEDS_KEY, never absent. Twitch uses only the team's own app (client id + secret for the app token), never a user token.
8. Output: one row per site with identity-raising fields only (created date, display name, linked accounts/URLs); linked accounts become pivots with expand=False; bios and content only when relevant to the case; Stack Exchange content attributed (CC BY-SA).
9. Registry tiers: Valve (Steam), Chess.com, Medium, Snap, Disqus, Microsoft (Mojang), Pinterest, Stack Exchange and Twitch trusted; Lichess community. personal_data_review before any spec enters the default set (A3 BR8).

Chair rationale: Approved 6-0 at median P3. Duolingo is left out of the build, as osint_investigator and analyst_ux asked: its e-mail variant is a rule-2 oracle one parameter away, the architect had no fixture for it, and dropping it meets cti_lead's, redteam_lead's and legal_dpo's 'impossible by construction' requirement more strictly than a unit test. legal_dpo's floor sets per-spec terms (scrapes 'unknown') and default off; the architect's FOUND gate through has_account pivots replaces the inter-module dependency the engine cannot express. Mojang stays (fixtures exist, documented API) despite analyst_ux's low-value note.

Synthesizer conditions (background; the final conditions win on conflict): Declarative JSON/XML/HTML specs (G15 declarative collector) with explicit found/absent rules: Steam XML (200 + <error> = absent), Chess.com/Lichess pub APIs, Duolingo USERNAME variant only (?email= is account enumeration: forbidden), Medium RSS, Pinterest widget pins, Snapchat __NEXT_DATA__ (SnapIntel AGPL: ideas only), Stack Exchange users?inname (quota), Disqus profile page, Mojang profile, Twitch Helix only with app token. Run only when username_check reports FOUND (saves requests).
Notes: Created dates, bios and linked accounts that raise identity confidence.
