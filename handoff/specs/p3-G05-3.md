## P119 `x_twitter_public` - X/Twitter public data without login (syndication tweet JSON, oEmbed, deleted-tweet recovery via Wayback)

- council: **approved**, priority P3, default_enabled=False, provider_tier=trusted, terms=unknown, opsec=passive, shares_input=True
- category: username_social; group: G05; inputs: url, username; produces: username, url
- auth: none; key env vars: -; hosts: cdn.syndication.twimg.com, publish.twitter.com, web.archive.org

### Final conditions (binding spec - implement every item)

1. Module username_social/x_twitter_public needs the tweet/status URL detector pattern (P333). Default path: publish.twitter.com/oembed?url= for twitter.com/x.com status URLs, a published interface.
2. The cdn.syndication.twimg.com tweet-result adapter is not built: X's ToS allow access only through published interfaces and forbid working around technical limitations without written consent (legal floor; analyst_ux). It may be revisited only with X's written consent recorded by legal.
3. oEmbed 404 = 'no longer available (deleted, protected or suspended)', never 'deleted' or 'never existed'; 429/5xx = could not verify. twitter.com and x.com pages are never requested directly.
4. Deleted-post recovery is opt-in per run and goes through the shared Wayback CDX client of web_archives (P059) under the Internet Archive research-purpose decision recorded for P059: collapse=urlkey, limit <= 500, archive hosts only. No crawler or search-engine UA spoofing anywhere (twayback's DuckDuckBot trick excluded); a test asserts no bot UA is sent.
5. Status ids are decoded offline to timestamps by the shared P314 decoder and labelled 'derived from id'; user.id_str and author handles become username pivots with expand=False. Recovered posts are labelled 'archived copy' and used only for case subjects.
6. Terms 'unknown' until legal records the X oEmbed terms and confirms the P059 Internet Archive decision for this use: disabled in every profile until then (A1); default_enabled False. Registry: x (X Corp, oEmbed) tier trusted; Internet Archive with the tier recorded for P059.

Chair rationale: Approved 6-0 at median P3. cti_lead, osint_investigator, redteam_lead and the architect would keep the undocumented syndication endpoint as an opt-in or second step; legal_dpo's floor removes it (X's ToS: published interfaces only, no working around technical limits), as analyst_ux also asked. Everyone forbids the twayback crawler-UA trick and the 'deleted' wording on a 404. legal_dpo's 'terms registry entries before corporate use' and 'not default-enabled' make the class 'unknown' until recorded; the architect's shared CDX client avoids a second implementation.

Synthesizer conditions (background; the final conditions win on conflict): cdn.syndication.twimg.com/tweet-result?id=&token= (token derived from id as the embed widget does) and publish.twitter.com/oembed for tweet URLs; no login, no API v1.1 (dead); twayback technique (Apache-2.0) = Wayback CDX for twitter.com/{u}/status/* to recover deleted tweets (archive hosts only); tweet/status URL needs a detector pattern (G15).
Notes: Tweet author ids and deleted content for actor investigations.

## P120 `wikimedia` - Wikimedia global account + contributions by user/IP

- council: **approved**, priority P3, default_enabled=True, provider_tier=trusted, terms=open, opsec=passive, shares_input=True
- category: username_social; group: G05; inputs: username, ipv4, ipv6; produces: url
- auth: none; key env vars: -; hosts: meta.wikimedia.org

### Final conditions (binding spec - implement every item)

1. Module username_social/wikimedia: meta.wikimedia.org/w/api.php?action=query&meta=globaluserinfo (home wiki, edit count, registration) and list=usercontribs (uclimit <= 50) on pt.wikipedia.org and en.wikipedia.org; uciprange for CIDR inputs. Hosts: meta.wikimedia.org, pt.wikipedia.org, en.wikipedia.org. Registry provider wikimedia: tier trusted, terms open.
2. Wikimedia's UA policy (rule 6): the UA is built at run time as 'V3LUM/<version> (<contact_email>)' from the role-mailbox setting of P326, sent only to Wikimedia hosts and never an analyst's personal address. With contact_email empty the module is SKIPPED reason_code 'config' ('needs contact setting').
3. IP contributions only for analyst-typed IP seeds and org_profile CIDRs, never for pivot IPs. Results say that IP edits are historical where IP editing is closed or masked (pt.wikipedia since 2020, temporary accounts) and that IP attribution is low confidence (shared NAT, VPN).
4. For usernames keep counts, dates and the pages relevant to the case, never full edit histories or topic profiles, which can reveal political or religious views (LGPD art. 11). personal_data_review before default use for usernames (A3 BR8).
5. maxlag=5; error objects inside HTTP 200 detected through P321 error_markers; 1 req/s; 429 = could not verify, never absent. Trimmed fixtures are captured before merge (the sweep only saw the 429).

Chair rationale: Approved 5-0-1 at median P3. analyst_ux deferred for low SOC value and 429s on shared egress; the 1 req/s limit, could-not-verify handling and seed-only IP lookups (cti_lead, osint_investigator, redteam_lead) contain that cost. The UA follows the architect's run-time contact setting and legal_dpo's role-mailbox rule, consistent with P326's veto_lift (identifying UAs only for providers that require them). legal_dpo's minimisation of edit histories is kept.

Synthesizer conditions (background; the final conditions win on conflict): Wikimedia returns 429 to generic UAs: send 'V3LUM/<ver> (<team URL>; <contact>) python-requests/<ver>'; meta=globaluserinfo (home wiki, edit count, registration) and list=usercontribs by user or by IP (anonymous edits from an IOC IP or corporate range) on pt/en wikis; error seen in sweep was the UA/429 problem.
Notes: Edits from corporate IPs or actors' accounts.

## P121 `x_archive_import` - X/Twitter archive import + automation indicators (Céos port)

- council: **approved**, priority P3, default_enabled=False, provider_tier=n/a, terms=open, opsec=passive, shares_input=False
- category: username_social; group: G05; inputs: file, username; produces: username, url
- auth: none; key env vars: -; hosts: -

### Final conditions (binding spec - implement every item)

1. Offline module username_social/x_archive_import (disclosure none, no network; a unit test asserts no HTTP call) for X/Twitter archives the analyst already holds. It runs only when selected (-M or run); default_enabled False.
2. Only archives lawfully obtained (provided by the account holder or produced under legal process) are imported, with provenance (source, date, legal basis) recorded in the case before import.
3. Archives are untrusted: read through the core safe-archive helper in memory, never extracted, member names never used as paths, <= 2,000 members, <= 200 MB uncompressed, ratio cap 100x; only data/*.js parsed; the bundled HTML/JS viewer is never opened or rendered; media files are not decoded.
4. The 'window.YTD.<name>.part0 = ' prefix is stripped and the rest parsed with json.loads, never evaluated. The parser is written from X's documented archive format; twitter-archive-parser (GPL-3.0) is not used as a template (A6).
5. Automation indicators use the Ceos thresholds (interval CV < 0.5 with >= 20 gaps; > 80% reposts with n >= 20; >= 23 distinct active hours with n >= 50; handle ending in >= 6 digits; default avatar; > 72 posts/day; < 90 days old with > 1,000 posts); likelihood high at >= 3 signals, medium at 2, as an attribute.
6. Findings from indicators are info/low with confidence <= 0.4 and show the underlying metrics; they are never the sole basis of a decision about a person (LGPD art. 20). A synthetic archive fixture is used in tests, including zip-slip and zip-bomb cases.

Chair rationale: Approved 4-0-2 at median P3. osint_investigator and analyst_ux deferred for low demand; as a P3 item it is built only when cheap (A16). redteam_lead's and the architect's untrusted-archive handling (in-memory reading, caps, no JS evaluation), legal_dpo's provenance and GPL clean-room rules and cti_lead's low-confidence indicators are consolidated. Offline with no registry source: tier 'n/a', terms 'open' (A1 BR20).

Synthesizer conditions (background; the final conditions win on conflict): Offline import of an archive/export the analyst already holds (no scraping); behaviour/automation indicators (posting cadence, client apps) as low-confidence signals.
Notes: Reuses Céos analysis for bot/automation cases.

## P251 `name_permutations` - Name -> username/e-mail permutations (accent and particle aware)

- council: **approved**, priority P3, default_enabled=False, provider_tier=n/a, terms=open, opsec=passive, shares_input=False
- category: person_name; group: G05; inputs: person_name, company_name, domain; produces: username, email
- auth: none; key env vars: -; hosts: -

### Final conditions (binding spec - implement every item)

1. One shared offline core helper (core/permute.py, disclosure none), reused by the e-mail pattern modules: NFKD accent stripping; particles {de, da, do, das, dos, e, di, du, del, van, von} dropped; suffixes {junior, jr, filho, neto, sobrinho} handled; last surname primary; Ceos priority patterns (f+l, f.l, f_l, f[0]+l...) plus maigret Permute 'strict' (MIT) in deterministic order.
2. <= 15 candidates per person. Corporate e-mail candidates only for domains in the case or org_profile, ranked by the domain's format inferred from observed addresses (commit e-mails, public pages) and shown with the number of samples behind it.
3. Candidates are hypotheses: a collapsible 'candidates (unverified guesses)' list, never findings and never scored; all are pivots with expand=False labelled 'generated'. The top 3 are offered first and reach username_check only after the analyst selects them; results for generated handles start at POSSIBLE.
4. Generated e-mails are never sent automatically to breach, stealer, reputation or validation services (a breach hit on a guessed address is an existence oracle by proxy, rule 2) and are never validated by SMTP (VRFY/EXPN/RCPT), login, sign-up or reset flows.
5. Category person_name: the module (name_permutations) is default_enabled False and runs only when the analyst selects it on an analyst-typed person_name seed (A3 BR2); the core helper itself stays available to the e-mail pattern modules. Unit tests: accents, particles, suffixes (fixture 'Jose Carlos de Oliveira Junior' with and without accents), the cap and the order.

Chair rationale: Approved 6-0 at median P3. legal_dpo's floor makes every generated candidate a non-expanding hypothesis that only the analyst can send on; the architect's proposal to auto-expand the top 3 is therefore reduced to 'offered first'. osint_investigator's and redteam_lead's oracle-by-proxy and SMTP bans (rule 2), the architect's shared helper and cap, and analyst_ux's 'unverified guesses' presentation are kept. The draft's default_enabled True is lowered to False because A3 BR2 (legal floor) keeps person_name modules out of the default set. Offline: tier 'n/a', terms 'open'.

Synthesizer conditions (background; the final conditions win on conflict): Offline: NFKD strip accents, drop particles {de, da, do, das, dos, e, di, du, del, van, von}, suffixes {junior, jr, filho, neto, sobrinho}; Céos priority patterns (f+l, f.l, f_l, f[0]+l...) + maigret Permute 'strict'; corporate e-mail candidates ranked by the domain's known pattern; budget 15 handles/person (wide DB only for top 3); person names are never auto-expanded by the engine (analyst confirms).
Notes: Bridges a person name to usernames/e-mails without enumeration oracles.
