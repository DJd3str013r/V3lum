## P127 `brasilapi_ddd` - BrasilAPI DDD (cities per area code)

- council: **approved**, priority P3, default_enabled=True, provider_tier=n/a, terms=open, opsec=passive, shares_input=False

- auth: none; key env vars: -; hosts: brasilapi.com.br

### Final conditions (binding spec - implement every item)

1. Folded into phone_parse (P126) as offline data: no per-scan network call. A registered dataset brasilapi_ddd (register_dataset, 30-day TTL) is prefetched by `v3lum data update` with one GET of brasilapi.com.br/api/ddd/v1/{ddd} per valid DDD (67 calls, <= 1 req/s); requests carry only the 2-digit DDD, never a phone number.
2. Scan-time answers are offline lookups (disclosure none). When the dataset is missing, the bundled DDD -> UF table answers and coverage says 'city list unavailable (run v3lum data update brasilapi_ddd)'.
3. Report: UF + main city + 'N cities in DDD', with the full city list behind a toggle in HTML and in JSON only. Attribution: BrasilAPI (MIT code) over Anatel data, in THIRD_PARTY_NOTICES. Registry provider brasilapi: tier community, terms open.

Chair rationale: Approved 6-0 at median P3 (legal_dpo voted P2). cti_lead, the architect and analyst_ux asked to fold this static data into phone_parse instead of calling an API per number; that is adopted as a prefetched dataset that sends only DDDs. Offline at scan time: tier 'n/a' (the dataset provider BrasilAPI is community tier), terms 'open'.

Synthesizer conditions (background; the final conditions win on conflict): brasilapi.com.br/api/ddd/v1/{ddd} cached forever (static data); sends only the DDD, not the number.
Notes: City list per DDD for BR numbers.
