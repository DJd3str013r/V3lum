## P354 `csaf_advisories` - CSAF 2.0 vendor advisories (Cisco, Siemens, Red Hat; generic provider-metadata client)

- council: **approved**, priority P3, default_enabled=True, provider_tier=trusted, terms=open, opsec=passive, shares_input=False
- category: vulnerability_cve; group: G08; inputs: cve, keyword; produces: cve
- auth: none; key env vars: -; hosts: www.cisco.com, cert-portal.siemens.com, security.access.redhat.com

### Final conditions (binding spec - implement every item)

1. Generic CSAF 2.0 client on the dataset manager: provider-metadata.json -> distributions (changes.csv or ROLIE feeds) -> daily incremental sync by `v3lum data update` into a local index (CVE -> vendor advisory id, products, fixed versions, CVSS, exploitation notes, VEX status). Vendors in config with licence and attribution (start: Cisco, Siemens ProductCERT, Red Hat; perimeter vendors next).
2. Every document URL must stay on the provider's declared hosts (https only; URLs taken from data elsewhere are refused); <= 2,000 documents per provider per sync and 5 MB per document; .sha256/.sha512 checked when published.
3. Red Hat VEX is fetched only per CVE for in-scope CVEs: that part sends the CVE id and is a separate adapter with disclosure third_party under the CVE fan-out rule (P183). VEX not_affected lowers a version-based CVE match for that product (context, never a deletion).
4. Each advisory is stored with vendor id, canonical URL and licence/terms (Red Hat CC BY 4.0 to confirm; Cisco treats copies without the distribution URL as uncontrolled; Siemens under its website terms); reports show excerpts plus links, never full copies. Output feeds the CVE card's vendor-fix line.

Chair rationale: Approved 6-0 at median P3. The architect's floor pins document URLs to declared hosts, caps the sync and splits the per-CVE VEX fetch out as a third_party adapter; legal_dpo's floor keeps provenance and links instead of redistributing documents; cti_lead's VEX use and redteam_lead's perimeter-vendor order are included. Tier refers to the Red Hat VEX adapter (the index itself is offline).

Synthesizer conditions (background; the final conditions win on conflict): Generic CSAF 2.0 client: provider-metadata.json -> distributions (directory index/changes.csv or ROLIE feeds) -> incremental sync of advisories (daily) into a local index (CVE -> vendor advisory id, products, fixed versions, CVSS, exploitation notes, VEX status); vendor list in config (start: Cisco, Siemens ProductCERT, Red Hat); Red Hat VEX only for CVEs/products in scope (size); keep vendor attribution/licences (Red Hat CC BY 4.0 to confirm).
Notes: Network/OT/Linux vendor fixes and exploited notes for patch teams; independent of NVD enrichment backlog.

## P355 `debian_security_tracker` - Debian security tracker (distro fix status per CVE/package)

- council: **approved**, priority P3, default_enabled=False, provider_tier=n/a, terms=open, opsec=passive, shares_input=False
- category: vulnerability_cve; group: G08; inputs: cve, keyword; produces: 
- auth: none; key env vars: -; hosts: security-tracker.debian.org

### Final conditions (binding spec - implement every item)

1. Opt-in dataset security-tracker.debian.org/tracker/data/json (~93 MB, refreshed at most daily by `v3lum data update`), parsed with a streaming parser (ijson optional extra) into SQLite (package -> CVE -> release status/fixed version); never json.load'ed whole; no per-query network calls; default_enabled False.
2. Results are shown only when the asset is known to run a Debian-based system (fingerprint/banner or analyst input).
3. Backport check: when a banner exposes a Debian package revision (e.g. 'OpenSSH_8.4p1 Debian-5+deb11u3'), map it to the source package and release and compare it with the tracker's fixed_version using the dpkg version algorithm (own implementation of Debian Policy 5.6.12, test vectors with epochs).
4. Fixed -> the version-inferred CVE is suppressed through a named P322 suppression rule with reason 'fixed in distro package'; unfixed -> confidence raised. Without a visible distro revision nothing changes. A trimmed fixture is used in tests.

Chair rationale: Approved 5-1 at median P3. cti_lead rejected it as redundant with OSV's Debian records; redteam_lead's backport check (the main false-positive class in external assessments) is the part OSV cannot do without a package entity, so it is included. The architect's streaming parser and SQLite index and the opt-in default are kept. Offline: tier 'n/a', terms 'open'.

Synthesizer conditions (background; the final conditions win on conflict): Opt-in dataset (92.8 MB JSON, download at most daily); index package -> CVE -> release status/fixed version; shown only when the asset is known to run Debian-based systems (fingerprint/banner or analyst input); no per-query network calls.
Notes: Linux server patch status for pentest/ASM findings.
