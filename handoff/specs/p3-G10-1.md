## P221 `icij_offshore` - ICIJ Offshore Leaks (reconcile API + bulk CSV)

- council: **approved**, priority P3, default_enabled=False, provider_tier=trusted, terms=open, opsec=passive, shares_input=True
- category: company_org; group: G10; inputs: company_name, person_name; produces: 
- auth: none; key env vars: -; hosts: offshoreleaks.icij.org, offshoreleaks-data.icij.org

### Final conditions (binding spec - implement every item)

1. Legal floor (rule 4, chair's reading): ICIJ Offshore Leaks is a leak-derived database, so person-name search in it is people-search over leaked data. The module searches entities only: company_name values (analyst-typed company names, razao social and nome fantasia resolved from a CNPJ, PJ partners); 'person_name' is removed from accepts.
2. Officers and intermediaries appear only as nodes linked to a matched entity; natural persons' addresses are never displayed, and linked persons are never pivoted or expanded.
3. Local first: the bulk CSV (ODbL database + CC BY-SA contents, several hundred MB) is imported into SQLite only by `v3lum data update icij` through the dataset manager, never bundled (A6) and never downloaded during a scan. Matching is local (no disclosure) with the shared core/namematch.py matcher (score >= 0.90, at most 5 candidates).
4. Without the local index the reconcile API (offshoreleaks.icij.org, one POST per entity, <= 5 candidates) is used only at TLP:CLEAR/GREEN or when the analyst selects the module explicitly; otherwise the result is UNAVAILABLE reason_code 'dataset' ('run v3lum data update icij'), never 'no match'.
5. Opt-in (default_enabled=False): runs on -M icij_offshore or --preset deep, only on seeds and CNPJ-resolved names, never on pivoted partner names (cti_lead).
6. Findings are POSSIBLE matches at INFO/LOW only, never tagged malicious, never risk-scored above LOW, expand=False, showing node id, leak (Panama/Paradise/Pandora...), jurisdiction, intermediary, dates and a manual node link, worded 'appears in ICIJ Offshore Leaks - not evidence of wrongdoing' plus ICIJ's own disclaimer.
7. No leaked document text is stored. The web search page (202 + JS challenge) is never fetched (rule 1). ODbL/CC BY-SA attribution goes into the report footer and THIRD_PARTY_NOTICES.
8. Rule 5: 401/403/429, timeouts, 5xx and error-in-200 bodies mean could not verify (P321/P328 statuses: BLOCKED, RATE_LIMITED, QUOTA, ERROR), never EMPTY or 'not found'; such responses are never cached.
9. Merge gate (A16): offline tests with FakeHttp (unmatched requests fail, network guard active) over trimmed real fixtures without personal data (the captured reconcile response plus a no-candidate response and a trimmed bulk-CSV sample), a provider-registry entry for every host, the registry contract test and the P327 lint.

Chair rationale: Approved 6-0 at median P3. legal_dpo's floor limits it to entity search and asked the chair to confirm rule 4's scope: the chair confirms that a person-name search over a leak-derived database is people-search over leaked data (rule 4), so person names are removed, which is stricter than the person-by-flag designs of osint_investigator, cti_lead and analyst_ux. Local-first matching (cti_lead, osint_investigator, legal_dpo, analyst_ux) is combined with the architect's dataset-manager rule for the large share-alike bulk and his reconcile fallback, which runs only at CLEAR/GREEN or on explicit request. cti_lead's opt-in default and analyst_ux's wording keep juniors from reading presence as guilt. ODbL/CC BY-SA are met by runtime download and attribution, so terms are open (A1).

Synthesizer conditions (background; the final conditions win on conflict): Reconciliation API (or local bulk CSV, ODbL + CC BY-SA attribution); results are 'possible match' (homonyms); persons only on explicit due diligence.
Notes: Offshore structure links for companies and partners.
