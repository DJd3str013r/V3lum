- council: **approved**, priority P3, default_enabled=False, provider_tier=trusted, terms=open, opsec=passive, shares_input=False
- category: company_org; group: G10; inputs: company_name, domain; produces: email

### Final conditions (binding spec - implement every item)

1. Dataset: iana.org enterprise-numbers.txt downloaded monthly through the dataset manager and parsed offline (disclosure 'none' for matching). Records are 4-line blocks (number / organisation / contact / e-mail with '&' for '@').
2. Legal floor: only the PEN number, the organisation name and the contact e-mail DOMAIN are kept; contact person names and full e-mail addresses are dropped at parse time and never reach the index, evidence or reports. The module produces domain (not email) pivots with expand=False, never for webmail domains.
3. Forward lookup: company_name or domain -> PEN number(s), with organisation names matched through the shared core/namematch.py matcher (possible-match wording below an exact match).
4. Reverse lookup (the more useful direction, cti_lead, osint_investigator, analyst_ux): a core helper pen_lookup(number) maps OIDs 1.3.6.1.4.1.<n> found by other parsers (certificate extensions, SNMP/syslog text) to the organisation, offline.
5. Opt-in (default_enabled=False). IANA public registry. Fixture: a trimmed excerpt of the real file with synthetic contacts; a test asserts that no contact name or full address survives parsing.

Chair rationale: Approved 4-1-1 at median P3 (analyst_ux rejected, cti_lead deferred: little value as a company module, and the registry lists individual contacts). legal_dpo's floor limits the output to organisation-level data (domain, not e-mail) and the architect drops contacts at parse time. The reverse OID -> organisation helper asked for by osint_investigator, cti_lead and analyst_ux is the main deliverable.

Synthesizer conditions (background; the final conditions win on conflict): Download enterprise-numbers.txt monthly, match org names locally; contacts are personal -> keep role data only; low value, opt-in.
Notes: SNMP/OID enterprise ids for an organisation.

### Final conditions (binding spec - implement every item)

1. Each list is a dataset with its own refresh, fetched only by `v3lum data update` (size shown), never mid-scan: MTE 'lista suja' CSV on www.gov.br (weekly, ';' ISO-8859-1), CVM registries (companhias abertas, intermediaries, sanction proceedings; daily) through one CVM loader shared with P360/P361, BrasilAPI CVM brokers list, and PGFN divida ativa (quarterly, multi-GB).
2. PGFN is opt-in: a separate `v3lum data update pgfn` import, streamed into an on-disk index keyed by CNPJ root (never loaded in memory) and not part of the default update set. The CAPTCHA-protected listadevedores.pgfn.gov.br app is never used (rule 1); CVM stop orders exist only as HTML news and are not automated.
3. Structural minimisation (architect, rule 4): natural-person rows (CPF debtors or employers) are dropped at import unless `--include-persons` is passed and recorded. With it, individuals are matched by name only for due-diligence subjects with a recorded purpose (possible match, P252 homonym score); a CPF is never a lookup key, shown masked and never pivoted.
4. Matching is local (disclosure 'none') through core/namematch.py; exact CNPJ (or root, stated) matches produce findings with list, amount band and date; only matched rows enter the case.
5. Severity table (documented and tested): MTE lista suja = HIGH (labour/ESG); CVM sanction proceeding = MEDIUM; PGFN divida ativa = LOW context with debt nature (previdenciaria, FGTS, demais), amount band and situation, because debt is common among legitimate companies.
6. CVM registries and the BrasilAPI brokers list answer 'is this broker/adviser/platform authorised?' by CNPJ or exact name and feed P360. Absence reads 'not found in CVM registries as of <date>', never fraud.
7. A missing or stale dataset reads 'not screened against <list> (<date>)' (UNAVAILABLE reason_code 'dataset'), never 'clean'. Tiers: PGFN, MTE and CVM trusted, BrasilAPI community; CVM data share-alike obligations apply only if redistributed.
8. Merge gate: trimmed real fixtures for PGFN and MTE captured before merge (only a CVM head exists today), person rows synthetic; offline tests and the P327 lint (A16).

Chair rationale: Approved 6-0 at median P3. legal_dpo's rule 4 floor and the architect's structural minimisation (person rows dropped at import unless recorded) protect individuals in these lists. The architect's dataset rules, cti_lead's shared CVM loader and opt-in PGFN, analyst_ux's severity table and osint_investigator's CVM authorisation answer are adopted. Scheduling (A16 BR1): P3 with effort M, so it is not built in this build (only effort-S P3 items are); BACKLOG.md keeps this spec as the target, and P360 owns the shared CVM loader meanwhile.

Synthesizer conditions (background; the final conditions win on conflict): Bulk datasets matched locally: PGFN quarterly divida ativa (';' ISO-8859-1), MTE 'lista suja' CSV (slave-like labour employers), CVM cadastro de companhias abertas/intermediarios/sanction proceedings, BrasilAPI CVM brokers; individual debtors/employers (CPF) only as possible matches on explicit due diligence.
Notes: Debt, labour and capital-market risk signals for suppliers/counterparties.
