## P262 `geocoding` - Geocoding / reverse geocoding (Nominatim, Photon, Overpass, geocode.xyz)

- council: **approved**, priority P3, default_enabled=True, provider_tier=community, terms=open, opsec=passive, shares_input=True
- category: geo_image_meta; group: G12; inputs: coordinates, cep, keyword, text_blob; produces: coordinates, cep
- auth: none; key env vars: -; hosts: nominatim.openstreetmap.org, photon.komoot.io, overpass-api.de, geocode.xyz

### Final conditions (binding spec - implement every item)

1. Nominatim (nominatim.openstreetmap.org) per the OSMF usage policy: identifying UA with the contact_email role mailbox only on OSM hosts (P326; SKIPPED reason_code 'config' without it), provider bucket 1 req/s per installation, no bulk geocoding, cache 30 days; 403 'Access denied' -> BLOCKED (rule 5).
2. Photon (photon.komoot.io, returns [lon, lat]) is the only fallback. Overpass and geocode.xyz are dropped (unreachable or throttled, no success fixtures). Tiers: OSMF trusted, komoot community.
3. Inputs: coordinates and cep; text_blob is removed (geocoding pasted text would disclose it) and keyword is accepted only as an explicit address-style TYPE:value. Address search falls back street -> postal code -> city.
4. Legal floor: reverse geocoding runs by default only for coordinates the analyst typed as seeds; coordinates from photos (EXIF), devices or other sources that may locate a natural person are geocoded only after a per-entity analyst confirmation. Forward geocoding of company addresses (CNPJ/CEP records, typed addresses) runs on explicit request.
5. Coordinates are PERSONAL_TYPES (A8): the module enters the effective default set only after personal_data_review is recorded for these providers; until then it runs only when selected in a case with a recorded purpose (reason_code 'privacy'). Coordinates are never auto-expanded.
6. Results are labelled 'approximate place (OSM)' with the precision level (street/postcode/city) and 'an address is not proof of residence'; reports carry '(c) OpenStreetMap contributors' (ODbL). Map links come from P260. Places derived from coordinates that may locate a person stay in the case and are left out of STIX/MISP exports unless the analyst opts in (as P259 GPS).
7. Merge gate (A16): offline tests with FakeHttp (unmatched requests fail, network guard active) over trimmed real fixtures without personal data (the Nominatim and Photon captures plus a 403 sample), a provider-registry entry for every host, the registry contract test and the P327 lint.

Chair rationale: Approved 6-0 at median P3 (osint_investigator, legal_dpo and analyst_ux voted P2). The architect's floor: identifying UA from config, a 1 req/s provider bucket, Photon as the only fallback, no text_blob input. legal_dpo's and osint_investigator's floor: coordinates that may locate a person are geocoded only on analyst confirmation. analyst_ux's default of reverse geocoding typed coordinates is kept behind the A3/A8 personal-data review.

Synthesizer conditions (background; the final conditions win on conflict): Nominatim usage policy: max 1 req/s, identifying UA (one custom UA was 403'd, another accepted) + contact, cache results, no bulk; address search with precision fallback (street -> postal code -> city); Photon (komoot) as fallback; Overpass for POIs around coordinates (instances unreachable from sandbox: optional); geocode.xyz throttles anonymous calls (optional). OSM ODbL attribution; map links via pivots_geo_image.
Notes: Turns EXIF GPS/addresses into places and CEPs.

## P264 `image_ela` - Error Level Analysis (image tamper heuristic)

- council: **approved**, priority P3, default_enabled=False, provider_tier=n/a, terms=open, opsec=passive, shares_input=False
- category: geo_image_meta; group: G12; inputs: file; produces: 
- auth: none; key env vars: -; hosts: -

### Final conditions (binding spec - implement every item)

1. Offline module: disclosure 'none' (no network at all; ScopedHttp refuses any request), terms 'open', provider tier 'n/a'; allowed at TLP:RED. Opt-in (default_enabled=False).
2. Parsing runs in the shared file-analysis sandbox core/sandbox.py: a python -I child process with a wall timeout, POSIX rlimits (memory <= 1 GiB, CPU, no file writes), input cap 100 MB and JSON output cap 1 MB; doctor reports the reduced isolation on Windows. Downloaded data is never executed.
3. JPEG inputs only: PNG and other lossless images (most PIX-receipt screenshots) are SKIPPED reason_code 'not_applicable' with 'ELA not meaningful for lossless images'.
4. Method: Pillow re-save at a fixed quality (q90) and ImageChops.difference. Output: numeric metrics (mean/max error level, region statistics) as attributes plus an optional ELA PNG in the case directory, embedded in HTML reports only as a data: image.
5. Wording: severity INFO with 'heuristic, not proof of tampering'; it never raises severity or the score on its own. The terminal shows only 'ELA map in the HTML report (heuristic, not proof)', never a bare tamper number (analyst_ux's concern).
6. Tests use synthetic fixtures generated in the tests: an original and an edited JPEG, a PNG that must be skipped.

Chair rationale: Approved 4-2 at median P3 (cti_lead and analyst_ux rejected: ELA misleads on recompressed images). The objections are met structurally: JPEG only (osint_investigator, architect), numeric informational output that never raises severity, and no tamper number in the terminal. The architect's sandbox and data:-image rules apply, and it is opt-in.

Synthesizer conditions (background; the final conditions win on conflict): Offline Pillow re-save at fixed quality and difference map; heuristic only (never 'proof of tampering'); opt-in.
Notes: Quick check of edited receipts/screenshots in fraud cases.
