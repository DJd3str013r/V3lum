## P320 `vin_decoder` - Vehicle VIN decoder (NHTSA vPIC)

- council: **approved**, priority P3, default_enabled=False, provider_tier=trusted, terms=open, opsec=passive, shares_input=True
- category: utility; group: G12; inputs: keyword; produces: 
- auth: none; key env vars: -; hosts: vpic.nhtsa.dot.gov

### Final conditions (binding spec - implement every item)

1. Needs the vin entity type (P333, may slip to P3), detected only through an explicit TYPE:value prefix or a 'VIN/chassi' label next to a 17-character value without I/O/Q; never any bare 17-character token (collisions with other ids).
2. Offline first: a bundled WMI table (NHTSA public-domain data, manufacturer and country, incl. Brazilian WMIs such as 9BW, 9BD, 93H). The position-9 check digit is evaluated only for North American WMIs; for other WMIs a failed check is a note, never 'invalid'.
3. Online step (opt-in, default_enabled=False): NHTSA vPIC decodevinvalues (vpic.nhtsa.dot.gov, batches of up to 50 VINs), US-centric and labelled as such; VINs are PERSONAL_TYPES, so it runs only when selected in a case with a recorded purpose until personal_data_review is recorded (A3/A8).
4. Forbidden: owner, plate or registration lookups for a VIN (the P327 lint rejects such hosts). VINs are masked (partly) in external exports.
5. Merge gate (A16): offline tests with FakeHttp (unmatched requests fail, network guard active) over trimmed real fixtures without personal data (the captured vPIC response plus a non-North-American VIN with a failing check digit), a provider-registry entry for every host, the registry contract test and the P327 lint.

Chair rationale: Approved 4-0-2 at median P3 (cti_lead and analyst_ux deferred: rare and US-centric). osint_investigator and the architect identified the trap that Brazilian chassis numbers need not satisfy the North American check digit; the architect's strict detection, legal_dpo's no-owner-lookup and masking rules, and the opt-in online step are adopted.

Synthesizer conditions (background; the final conditions win on conflict): Offline VIN check digit + WMI table first; NHTSA vPIC decodevinvalues for details (US-centric); needs a vin entity type (G15); vehicle-owner lookups remain forbidden.
Notes: Vehicle context in fraud cases.

## P368 `elf_triage` - ELF basic triage (pyelftools + telfhash)

- council: **approved**, priority P3, default_enabled=True, provider_tier=n/a, terms=open, opsec=passive, shares_input=False
- category: file_analysis; group: G12; inputs: file; produces: keyword
- auth: none; key env vars: -; hosts: -

### Final conditions (binding spec - implement every item)

1. Offline module: disclosure 'none' (no network at all; ScopedHttp refuses any request), terms 'open', provider tier 'n/a'; allowed at TLP:RED. FILE input only; samples are parsed, never executed. This module makes no network call.
2. Parsing runs in the shared file-analysis sandbox core/sandbox.py: a python -I child process with a wall timeout, POSIX rlimits (memory <= 1 GiB, CPU, no file writes), input cap 100 MB and JSON output cap 1 MB; doctor reports the reduced isolation on Windows. Downloaded data is never executed.
3. pyelftools (pure Python, public domain) only: architecture, interpreter, needed libraries, imported and exported symbols, section entropy and UPX markers (INFO hints).
4. The telfhash library is not used (its dependency set includes the dead nose package, capstone and two TLSH bindings); a telfhash value is taken from YARAify/MalwareBazaar results when those modules return it, and those lookups follow the abuse.ch licence decision (A1: MalwareBazaar class 'license').
5. Fixtures: a small benign ELF built in tests plus a truncated one.

Chair rationale: Approved 6-0 at median P3 (legal_dpo voted P2). The architect's floor drops the telfhash package and keeps pyelftools in the sandbox; cti_lead's and legal_dpo's licence condition on the MalwareBazaar telfhash pivot is enforced where those lookups happen. Scheduling (A16 BR1): P3 effort S, but pyelftools would be a new runtime dependency (optional extra), so it is not built in this build; BACKLOG.md keeps this spec.

Synthesizer conditions (background; the final conditions win on conflict): Optional extra: architecture, interpreter, linked libraries, imported symbols, section entropy/UPX hint, telfhash (pivot via MalwareBazaar get_telfhash with Auth-Key); parse only.
Notes: Linux/IoT botnet and miner samples from server incidents.
