## P307 `web_search_api` - Keyed/official web search APIs (SerpApi, Marginalia, DuckDuckGo Instant Answer)

- council: **approved**, priority P3, default_enabled=False, provider_tier=community, terms=unknown, opsec=passive, shares_input=True
- category: search_dorks; group: G14; inputs: keyword, domain, company_name, email, person_name; produces: url, domain
- auth: mixed; key env vars: V3LUM_SERPAPI_KEY, V3LUM_MARGINALIA_KEY, V3LUM_BRAVE_KEY, V3LUM_TAVILY_KEY, V3LUM_EXA_KEY; hosts: serpapi.com, api2.marginalia-search.com, api.duckduckgo.com, api.search.brave.com, api.tavily.com, api.exa.ai

### Final conditions (binding spec - implement every item)

1. veto_lift (1): SerpApi is removed, together with any provider that scrapes search engines with CAPTCHA solving, IP/proxy rotation or browser emulation (rule 1 by proxy); no registry entry exists for serpapi.com and a unit test asserts that no request ever reaches it.
2. veto_lift (2): engines are limited to first-party APIs with their own index and business-compatible terms: Brave Search API (preferred; X-Subscription-Token header; class key-terms, business plan recorded in key_plans) and DuckDuckGo Instant Answer (context only, not web search; class open, with attribution).
3. veto_lift (2, continued): Marginalia only with a commercial key; its free keys are CC BY-NC-SA 4.0, so the source is class 'license': off under the corporate profile until licence-cleared or a commercial key plan is recorded.
4. veto_lift (2, continued): Tavily and Exa only with a company-account key and terms recorded by legal; until then their class is 'unknown' and they run in no profile (hence this module's class 'unknown'). Never keyless x402 or any other autonomous payment: HTTP 402 or an x402 offer maps to NEEDS_KEY, and no payment code path exists (unit test).
5. Tiers: Brave and DuckDuckGo trusted; Marginalia, Tavily and Exa community. Per-provider sub-sources with separate statuses in coverage; keys in headers where supported, any key in a URL covered by the central redactor (AR01).
6. veto_lift (3): Brave results are never cached raw (ttl=0) and never stored as raw JSON: the case and evidence keep only URL + title of returned results (no snippets) unless a Brave storage-rights plan is recorded in the registry; the shell lets the analyst keep only selected results.
7. veto_lift (4): person_name and e-mail queries only for subjects the analyst entered in a case with a recorded purpose, never automatically from pivots. Queries are built only from typed entities or org_profile identifiers and never contain secrets, tokens or full URLs with query strings (victim identifiers).
8. veto_lift (5): a per-case query budget (default 10, setting web_search_case_budget) and a per-provider monthly budget (P334) with QUOTA status and a coverage line ('3/10 queries used'); the TLP gate applies (excluded at RED; providers flagged reuses_queries excluded at AMBER+).
9. Opt-in (default_enabled=False): runs only on -M web_search_api, --preset deep or when another approved module (P287, P289) calls its Brave source (P253 uses GDELT only); seed-only by default.
10. Merge gate: the captured no-key/422/402 responses now, plus a success fixture captured with each provider's key before that provider is enabled (architect).

Chair rationale: Vetoed by legal_dpo (SerpApi advertises solving CAPTCHAs, which breaks rule 1 by proxy; Marginalia free keys are non-commercial); veto_lift adopted, so the item is approved with every lift condition in final_conditions. The other five members approved it as the lawful way to automate a few dorks, and their conditions (Brave preferred, no autonomous payments, URL/title-only storage, budgets, TLP gate, seed-only) coincide with the lift. The architect's floor adds per-provider statuses, header keys, 402 -> needs_key and real success fixtures per provider. The class is 'unknown' while Tavily and Exa await legal review, so it stays opt-in. Median priority P3 (osint_investigator voted P2).

Synthesizer conditions (background; the final conditions win on conflict): Only official APIs: SerpApi with paid key (keyless returned a cached search only), Marginalia with a personal key (shared 'public' key returns 429 daily limit), DDG Instant Answer (no web results; context only); query budget per case; the query leaves the premises (TLP gate). Gap fill: Brave Search API is the preferred official engine (X-Subscription-Token; US$5/1,000 requests with US$5 free credits per month, 50 QPS; storing results needs a custom plan -> keep only selected URLs/titles as evidence); Tavily/Exa as optional alternates with keys; Exa's keyless x402 pay-per-call must never be used (no autonomous payments).
Notes: Lawful way to automate a few dorks.
