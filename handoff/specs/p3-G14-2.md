### Final conditions (binding spec - implement every item)

1. Ship data/pivot_links/search.json in the frozen P311 pack schema (label, template, entity_types, category, host, verified, checked_at, privacy, publishes=false, touches_target, login_required, antibot). The pack is offline data (disclosure 'none'): V3LUM never requests these URLs or any API behind them.
2. Rendering follows A2/P311: at TLP:AMBER and above every link is non-clickable text with 'opening sends <value> to <host>'; at RED third-party links are hidden from reports and listed only by `v3lum links` with the warning; links are never auto-opened and `links --open` at AMBER+ needs an interactive confirmation naming the host.
3. CI renders every template with a sample value per declared entity type and with hostile values (quotes, spaces, unicode, newlines): each result must be an https URL on the declared host, built only from whitelisted placeholders through the declared encoder (never str.format, never {raw} in URL position).
4. Every link host has a provider-registry entry with tier and rationale (A8); unknown-tier hosts get the 'unknown operator' badge and their templates take IOC_TYPES values only (A8 BR4): never PERSONAL_TYPES, CNPJ, company names, keywords, malware or actor names, or other free text (P311 lint).
5. Initial host tiers for the registry reviewer to confirm: community - WikiLeaks (search.wikileaks.org); Lyzem pending review (unknown until recorded).
6. Order: P311 groups links by analyst question with verified links first; inside a group the pack's file order is the curated analyst-value order (Lyzem, then WikiLeaks); the terminal shows at most 8 links per seed, the rest go to HTML and `v3lum links`.
7. Verified links carry checked_at; `v3lum doctor --links` (offline) lists unverified links and links not re-checked for more than 180 days. The pack ships in phase 1 with the other pivot packs (A16), whatever the state of the related automated modules.
8. Legal floor (rule 4): WikiLeaks search links only for company names and keywords, never person names or usernames (a person search over leaked documents is people-search over leaked data); link only, nothing ingested or stored (rule 3); banner 'leaked documents: open manually and handle per policy'.
9. Lyzem (lyzem.com/search?q=, Telegram content search for BR fraud channels): person-name and username links are privacy=true, only for analyst-entered subjects with the case opt-in. A8 gate: until the reviewer records Lyzem as community tier, only IOC values (domain, url) are templated for it.
10. All links in this pack render only for analyst-typed seeds (analyst_ux) and carry the caution marker.

Chair rationale: Approved 6-0 at median P3 (osint_investigator voted P2). legal_dpo's floor keeps WikiLeaks to organisations, consistent with the chair's rule 4 reading in P221, and allows Lyzem person links only for entered subjects; analyst_ux limits the pack to typed seeds. A8 limits Lyzem to IOC values until its operator tier is recorded. The architect's standard pack schema applies.

Synthesizer conditions (background; the final conditions win on conflict): lyzem.com/search?q= and search.wikileaks.org/?query=; manual-only; WikiLeaks content may include leaked personal data -> analyst caution banner.
