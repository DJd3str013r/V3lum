## P013 `domain_ownership` - Domain ownership verifier (company + person) via RDAP, homepage and CT (Céos port)

- council: **approved**, priority P2, default_enabled=True, provider_tier=n/a, terms=n/a, opsec=light, shares_input=True

### Final conditions (binding spec - implement every item)

1. A correlation rule in v3lum/correlations/ownership.py (architect floor), not a module with clients. It reads facts already in the graph from rdap (registrant CNPJ/org), ct_logs (certificate O=), dns_records/email_security_posture (MX/SPF tenancy), m365_tenant (tenant id) and web_fingerprint or the archived homepage snapshot (P059). No network calls.
2. CONFIRMED only from authoritative data: the RDAP registrant CNPJ root (registro.br publicIds) matches org_profile cnpj_roots or the queried company, or the domain is an org_profile own domain. Only CONFIRMED marks an asset own/known_good.
3. PROBABLE at most: an OV/EV certificate O= match, especially with a DNS tenancy signal (MX/SPF/M365 tenant). A CNPJ printed on the site never confirms ownership: at most POSSIBLE (fake stores copy real companies' CNPJs). POSSIBLE is worded 'unconfirmed link'.
4. A site CNPJ that differs from the RDAP registrant CNPJ, or a site CNPJ on a domain <= 90 days old without a registry match, raises MEDIUM 'CNPJ displayed does not match registrant' (tags fraud, clone indicator). Site CNPJs are validated offline by check digits (P232); an invalid CNPJ on a commercial site is suspicious.
5. The verdict lists its evidence bullets with evidence ids ('RDAP CNPJ = org CNPJ root', 'CT O= matches', 'MX in the same M365 tenant'). In passive mode the rule uses RDAP/CT/DNS facts only, and the report says when no homepage evidence was available.
6. Person ownership only for a person the analyst typed as a seed, inside a case with a recorded purpose, from public registrant data already returned by RDAP/CT. CPF is never unmasked. Natural-person matches are POSSIBLE/PROBABLE with evidence, tagged privacy, never auto-pivoted (expand=False), and follow the case retention (A10).
7. Homepage facts come only from web_fingerprint (LIGHT, analyst-typed seeds, P376 guard) or archived snapshots. Candidates from typosquat/NRD/CT are never fetched live. CONFIRMED/PROBABLE results feed the report and `org seed` proposals (analyst-confirmed), never an ACTIVE scope.
8. Unit tests on synthetic graphs, one per verdict level, including the copied-footer case and an RDAP-contradicted footer CNPJ.

Chair rationale: Approved 6-0 at median P2 (osint_investigator voted P1). The architect's floor turns the Céos verifier into a rule over existing facts, which also removes the module's own LIGHT homepage fetch. cti_lead and osint_investigator: only registry data confirms, a displayed CNPJ is at most POSSIBLE and a mismatch is a fraud signal (the Céos 'published CNPJ confirms' rule is not ported). legal_dpo's floor: person ownership only for analyst-supplied persons with a purpose, never auto-pivoted. redteam_lead: no live visits to candidates and no scope effect. analyst_ux: evidence bullets and wording. A correlation rule: tier and terms n/a.

Synthesizer conditions (background; the final conditions win on conflict): Port Céos dominios.Verificador to English: combine RDAP registrant (registro.br CNPJ), homepage footer/CNPJ text (light mode only), CT certificate O= and MX/SPF tenancy into CONFIRMED/PROBABLE/POSSIBLE ownership with evidence; person ownership only when the analyst provides the person and only from public registrant data.
Notes: Answers 'is this domain really the company's?' before attack-surface or typosquat conclusions.
