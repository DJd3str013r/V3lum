## P072 `web_fingerprint` - Light web fingerprint (status, title, server, technologies via Wappalyzer-format DB, passive WAF/CDN signatures)

- council: **approved**, priority P2, default_enabled=True, provider_tier=trusted, terms=open, opsec=light, shares_input=False
- category: url_web; group: G03; inputs: url, domain; produces: cve, domain
- auth: none; key env vars: -; hosts: raw.githubusercontent.com
- sources shared with other proposals: {"C0638": ["P280"]}

### Final conditions (binding spec - implement every item)

1. Two modules over one matcher library. web_fingerprint_archive (PASSIVE, default): runs the matchers over the closest archived homepage snapshot provided by web_archives (P059); no target contact. web_fingerprint (LIGHT, default_enabled=False; not merged or enabled before the AR20 safety suite passes): one homepage GET.
2. The LIGHT GET uses the core safe-fetch helper, shared with security_headers, analytics_ids, js_endpoints and favicon_fetch (cache hit): analyst-typed seeds only, after the passive lane, through the P376 guard, within the P334 LIGHT budget. Redirects are followed manually (<= 5 hops), each hop re-checked; private, loopback, link-local, CGNAT and metadata addresses are refused.
3. The LIGHT request uses the egress-profile browser-like UA (setting ua_light, P326), never the API UA. A challenge or block page gives BLOCKED and is never retried with other UAs or a headless browser (rule 1).
4. Technology data: enthec/webappanalyzer JSON (GPL-3.0 data) downloaded at runtime into ~/.v3lum/datasets, never vendored or committed, attributed in THIRD_PARTY_NOTICES.md (A6). Test fixtures use a small hand-written fingerprint file in the same format. An own MIT rule set for phishing-kit and panel signatures (titles, asset paths) stays separate from the GPL data.
5. Matchers: headers, cookies, meta, html, scriptSrc, url, dns (via ctx.dns) and certIssuer from tls_inspect/CT data (no new socket). No JS engine and no probe rules. JS-flavoured regexes are compiled by a converter that skips and logs failing patterns, scan at most the first 500 KB of HTML and pass a per-pattern time-budget test.
6. Passive WAF/CDN detection: the header/cookie-only subset of wafw00f signatures (BSD-3 NOTICE) plus CNAME/IP-range attribution (P034). wafw00f's attack-payload probes are never ported.
7. Corporate secure-web-gateway block/warning pages (Zscaler, Netskope, Fortinet, Palo Alto... configurable signatures) read 'blocked by corporate proxy' and are never fingerprinted as the target. 4xx/5xx and proxy error bodies are inconclusive.
8. Output: one compact technology list (name, version, category). Version-inferred CVEs collapse into one finding per technology ('jQuery 1.12.4: 4 CVEs, max CVSS 6.1'), POSSIBLE (<= 0.5), at most MEDIUM unless KEV (then capped HIGH, P291 label). Hostile-tagged hosts get technologies as attributes, not vulnerability findings.
9. Capture 3-5 trimmed real homepage fixtures (none exists) plus a challenge page and a corporate-proxy block page.

Chair rationale: Approved 6-0. The tally median is P2 (redteam_lead and the architect voted P1). LIGHT is never default (A3 BR2), so the chair adds the passive path osint_investigator asked for (fingerprint the archived snapshot) as the default module; the live GET is opt-in. The architect's floor: one shared safe homepage fetch, GPL data runtime-only with hand-written test data, the regex converter with time budgets, no probes, real fixtures. legal_dpo: GPL hygiene and no evasion of block pages. cti_lead: corporate proxy pages. redteam_lead: seeds only, per-hop checks, the LIGHT UA. analyst_ux and redteam_lead: collapsed, capped CVEs. Passive path tier trusted (Internet Archive); terms open.

Synthesizer conditions (background; the final conditions win on conflict): One normal GET of the homepage (light mode, browser-like UA, record redirect chain). Technologies from enthec/webappanalyzer JSON downloaded at runtime into the cache (GPL-3 data: never vendored); implement headers/cookies/meta/html/scriptSrc/url/dns/certIssuer matchers (no JS engine, no 'probe' rules). Passive WAF/CDN detection = header/cookie-only subset of wafw00f signatures (BSD-3 notice) + CNAME/IP-range attribution; attack-payload probes belong to waf_active_probe. Never derive findings from 4xx/5xx or proxy error bodies (inconclusive). CPE -> CVE matches are low confidence (CR16).
Notes: Stack/WAF/CDN context for every site; feeds outdated-version CVE matching.
