## P281 `axfr` - DNS zone transfer test (direct AXFR + HackerTarget third-party AXFR)

- council: **approved**, priority P3, default_enabled=False, provider_tier=n/a, terms=open, opsec=active, shares_input=False
- category: pentest_recon; group: G13; inputs: domain; produces: domain
- auth: none; key env vars: -; hosts: api.hackertarget.com

### Final conditions (binding spec - implement every item)

1. ACTIVE gate (A7): runs only with --mode active, a non-empty --authorized REF and a --scope FILE on every path (scan, run, shell, watch, batch; non-interactive runs refuse without both), on scope-file matches only after resolution and per redirect hop, never on pivots or on entities extracted from text/files; CDN/shared-hosting/SaaS IPs excluded unless listed. Only zones in the scope file.
2. A7 ceilings enforced by the core client and socket connector: <= 10 requests/probes per second and <= 2 concurrent connections per target host, the case ACTIVE budget, the kill switch (traffic stops within 2 s), proxy_active egress profile (A13), the hostile-host guard, and every request in the hash-chained P324 ledger; the report banner carries REF, scope SHA-256, window and egress.
3. Name servers are resolved through the core DoH resolver. An NS is contacted only if its name or resolved IP matches the scope; NS of managed DNS providers (data list matched by NS name/ASN: Cloudflare, Route 53, Azure DNS, Google Cloud DNS, NS1, UltraDNS, Akamai, registro.br...) are skipped as 'not tested: managed provider'.
4. One AXFR attempt per authoritative NS per run over TCP/53, using dnspython (optional extra) over the core raw-socket connector with the egress profile; response caps 10,000 records, 10 MB and 30 s per NS. TCP/53 refused, blocked or proxied = 'could not test'.
5. The HackerTarget third-party AXFR is not included: a third party would probe the target outside V3LUM's egress and ledger, and it spends the shared 50/day quota (cti_lead, redteam_lead).
6. Results: success = HIGH misconfiguration (T1590.002) with the record count; refused = INFO 'zone transfer refused: good'. Transferred names become subdomain pivots with axfr provenance, expand=False and capped by max_pivots (no automatic probing of every host); TXT values pass the P312 secret detector and central redactor. Zone data stays in the case only.
7. Results are tri-state (confirmed / not observed / could not test): blocked egress, a proxy, 403/429, a challenge or a timeout is 'could not test', never closed, absent or safe (rule 5). Merge only after the AR20 safety suite passes (A16).
8. Tests use a local loopback TCP DNS server returning a canned zone and a refusal, plus a managed-provider skip case.

Chair rationale: Approved 6-0 at median P3. The A7 floor (legal_dpo, redteam_lead) and the architect's raw-socket connector, response caps and loopback tests apply. The HackerTarget variant is dropped, as cti_lead and redteam_lead asked: legal_dpo confirmed that outsourcing the AXFR does not make it passive, so it would be the same probe outside the ledger with a contended shared quota. redteam_lead's managed-provider skip and analyst_ux's tri-state wording are kept.

Synthesizer conditions (background; the final conditions win on conflict): Active+authorized only; for each NS (resolved via DoH) try AXFR over TCP/53 with dnspython (optional extra; dnspython 2.9 needs Python >= 3.11) or own client; TCP/53 blocked -> 'could not test'; HackerTarget zonetransfer makes a third party attempt the AXFR (also gated, shares quota); success = HIGH misconfiguration (T1590.002).
Notes: Classic DNS misconfiguration check for owned domains.

## P282 `cloud_buckets` - Cloud storage bucket permutations (S3, GCS, Azure Blob, DO Spaces)

- council: **approved**, priority P3, default_enabled=False, provider_tier=n/a, terms=open, opsec=active, shares_input=False
- category: pentest_recon; group: G13; inputs: company_name, domain, keyword; produces: url

### Final conditions (binding spec - implement every item)

1. ACTIVE gate (A7): runs only with --mode active, a non-empty --authorized REF and a --scope FILE on every path (scan, run, shell, watch, batch; non-interactive runs refuse without both), on scope-file matches only after resolution and per redirect hop, never on pivots or on entities extracted from text/files; CDN/shared-hosting/SaaS IPs excluded unless listed.
2. Scope model (architect): bucket endpoints are never in the target's IP scope, so core policy holds a provider-endpoint allow-list for this module only (S3, GCS, DigitalOcean Spaces). Candidate names come only from org_profile brands/domains confirmed in the scope file, bucket references found passively on in-scope assets (HTML, JS, archives, CNAMEs) and a bounded permutation list.
3. Caps: <= 60 candidate names per run and <= 3 req/s per provider (stricter than the 5 req/s and 100-200 names some members proposed), plus the A7 ceilings, kill switch, proxy_active egress and P324 ledger. Azure Blob is excluded until its semantics are captured in fixtures (research got a proxy error).
4. Semantics (captured fixtures): 404 NoSuchBucket = absent; 403 AccessDenied/AllAccessDisabled = exists-private (LOW); 301 PermanentRedirect = exists in another region; ListBucketResult = public listing; anything else = could not verify. XML parsed with the safe XML helper.
5. Minimal listing (A7 BR9, legal floor): one key only (?max-keys=1); objects are never downloaded and object key names are never stored (only 'public listing' and the sampled key's extension). No PUT/POST/DELETE and no ACL checks by modification.
6. Ownership before severity: a public listing is HIGH only when the bucket is attributed (referenced by an in-scope asset, a CNAME, or listed in the scope file); an unattributed brand-named bucket is LOW 'brand-named bucket, owner unknown', never 'ours', and is not accessed beyond the one-key listing.
7. Results are tri-state (confirmed / not observed / could not test): blocked egress, a proxy, 429, a challenge, a timeout or a 403 without the provider's AccessDenied/AllAccessDisabled XML body is 'could not test', never absent or safe (rule 5); only those documented 403 bodies mean exists-private. Merge only after the AR20 safety suite passes (A16).
8. Only existing buckets are reported, with a count of names tested; absent names are never listed individually. GrayhatWarfare (P290) is the passive manual alternative.

Chair rationale: Approved 6-0 at median P3 (redteam_lead and the architect voted P2). The A7 floor gates it, and the architect's provider-endpoint allow-list closes the scope-model gap. redteam_lead's one-key listing and ownership-before-severity rule satisfy legal_dpo's metadata-only floor more strictly than storing masked key names (cti_lead, osint_investigator). The tightest caps proposed (60 names, 3 req/s) are taken. Azure waits for fixtures (architect).

Synthesizer conditions (background; the final conditions win on conflict): Active+authorized (requests go to cloud providers for the target's names); bounded permutation list; semantics verified: S3/GCS/DO 404 NoSuchBucket = absent, 403 AccessDenied = exists/private (LOW), ListBucketResult/EnumerationResults = public listing (HIGH, CR24); never download objects (personal data); passive alternative = grayhatwarfare.
Notes: Detects public buckets named after the brand.

## P284 `jarm` - JARM active TLS server fingerprint

- council: **approved**, priority P3, default_enabled=False, provider_tier=n/a, terms=open, opsec=active, shares_input=False
- category: pentest_recon; group: G13; inputs: domain, ipv4; produces:

### Final conditions (binding spec - implement every item)

1. Passive JARM first: values already present from licensed indexed-scan sources (Shodan/Censys modules) are used before any probe, and this module adds nothing when they exist.
2. ACTIVE gate (A7): runs only with --mode active, a non-empty --authorized REF and a --scope FILE on every path (scan, run, shell, watch, batch; non-interactive runs refuse without both), on scope-file matches only after resolution and per redirect hop, never on pivots or on entities extracted from text/files; CDN/shared-hosting/SaaS IPs excluded unless listed.
3. Only host:port pairs listed in the scope file are probed.
4. Legal floor (A7 BR5, Codigo Penal art. 154-A): never against hostile, C2 or other non-owned infrastructure, whatever the egress profile; ten unusual ClientHellos are also a recognisable scanner signature (redteam_lead). C2 clustering uses passive JARM values only.
5. A7 ceilings enforced by the core client and socket connector: <= 10 requests/probes per second and <= 2 concurrent connections per target host, the case ACTIVE budget, the kill switch (traffic stops within 2 s), proxy_active egress profile (A13), the hostile-host guard, and every request in the hash-chained P324 ledger; the report banner carries REF, scope SHA-256, window and egress.
6. Algorithm: the 10 JARM ClientHello probes adapted from salesforce/jarm (BSD-3 header and notice) over the core raw-socket connector (CONNECT tunnel supported, scope and egress checks). JA4+ (FoxIO License 1.1) is not used.
7. A path behind TLS interception (detected as in P275) is 'could not test'. Results are tri-state (confirmed / not observed / could not test): blocked egress, a proxy, 403/429, a challenge or a timeout is 'could not test', never closed, absent or safe (rule 5). Merge only after the AR20 safety suite passes (A16).
8. A JARM match is a clustering signal: the bundled known-C2 JARM list carries collision notes (the Cobalt Strike default equals common Java TLS stacks), a match alone is at most LOW and never raises severity, and CR30 needs a second signal.
9. Unit tests compute hashes from recorded ServerHello byte fixtures.

Chair rationale: Approved 6-0 at median P3. The legal floor as applied by the D audit (P171: no live JARM probe of out-of-scope hostile hosts, A7 BR5) and redteam_lead's and osint_investigator's tip-off concern limit the probe to scope-file host:port pairs; legal_dpo's and the architect's 'hostile infrastructure through a non-corporate egress' option is therefore not adopted. Passive values first (cti_lead, redteam_lead, architect, analyst_ux) and the weak-signal rule (CR30) are kept. Scheduling (A16 BR1): P3 with effort M, so it is not built in this build; BACKLOG.md keeps this spec.

Synthesizer conditions (background; the final conditions win on conflict): Active+authorized; 10 crafted ClientHello probes (salesforce/jarm BSD-3 algorithm); raw TCP blocked behind proxies -> could not test; a JARM match to known C2 defaults is never enough alone (CR30 needs another signal).
Notes: Clusters C2/attacker servers and detects default TLS stacks.
