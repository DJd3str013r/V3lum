## P369 `nuclei_runner` - Template-based exposure checks (nuclei + filtered nuclei-templates allow-list)

- council: **approved**, priority P2, default_enabled=False, provider_tier=n/a, terms=open, opsec=active, shares_input=True
- category: pentest_recon; group: G13; inputs: url, domain, ipv4; produces: cve, url
- auth: none; key env vars: -; hosts: github.com, raw.githubusercontent.com

### Final conditions (binding spec - implement every item)

1. ACTIVE gate (A7): runs only with --mode active, a non-empty --authorized REF and a --scope FILE on every path (scan, run, shell, watch, batch; non-interactive runs refuse without both), on scope-file matches only after resolution and per redirect hop, never on pivots or on entities extracted from text/files; CDN/shared-hosting/SaaS IPs excluded unless listed.
2. The nuclei target list is written only from scope-file entries; nuclei opens its own sockets, so the proxy, argv and template rules below replace the core per-request scope check.
3. Binary (A7 BR10): external nuclei (MIT) from a config path or PATH, version and SHA-256 checked by doctor against a pinned range; never downloaded, installed or updated by V3LUM. Without it the module is UNAVAILABLE reason_code 'package' ('install nuclei vX.Y'); no internal template engine is re-implemented.
4. Templates: a pinned nuclei-templates release (SHA-256 in data/active.lock) through the dataset manager, refreshed only by `v3lum data update` with a diff summary. Allowed only when ALL tags are in {tech, panel, exposure, misconfig, ssl, dns, detect, discovery}, none is in A7's forbidden set, protocols are http, ssl or dns only, and the id is on the list reviewed by the red team lead and legal.
5. Consequence of A7 BR11: templates tagged cve, kev or takeover are excluded in this build (takeover is covered by P276; version-inferred CVEs by P291). Templates that confirm by exploiting (file read, command execution, SSRF, auth bypass, data extraction) are excluded whatever their tags.
6. Fixed argv, no shell: -ni -duc -dut -dr -or -lna (unless the scope lists private ranges) -rl 10 -c 2 -bs 5 -timeout 10 -retries 1 -jsonl -tlog <case trace>, -p set to the proxy_active profile, and the scope file's ROE header via -H (never the organisation's identity, P326). A unit test asserts the built argv.
7. Never passed: -pd/-pdu/-cup, -ut/-turl, -sa, -ev, -lfa, -tlsi, -dast, -code, -headless, -sresp/-srd, -sf; -ept code,headless,javascript,file,websocket,whois always set; the environment is scrubbed (no PDCP_API_KEY).
8. CI test over the pinned template set: it fails on any excluded tag, on {{interactsh-url}}, on methods other than GET/HEAD, and on payloads that read files, run commands or bypass auth (A7 BR8).
9. Ledger and kill switch: the -tlog trace is folded into the hash-chained P324 ledger; on cancel, end of window or deadline the process gets SIGTERM, then SIGKILL, so target traffic stops within 2 s. Template ids and versions are recorded in the audit trail; the banner shows REF, scope SHA-256, egress IP and start/end time for SOC deconfliction.
10. Output: JSONL size-capped, every value untrusted (AR13 escaping) and matched values passed through the P145 sanitizer. Info results collapse into one count ('12 technologies detected'); medium+ results are findings with template id, version, matched URL and evidence; tech/panel/version detections read 'exposure', never 'vulnerable'.
11. Results are tri-state (confirmed / not observed / could not test; blocked egress or proxy = could not test). Tests use a stub executable that emits recorded JSONL; merge only after the AR20 safety suite passes (A16).

Chair rationale: Approved 6-0 at median P2 (osint_investigator voted P3). redteam_lead's argument list (pinned binary and templates, no interactsh, no cloud upload, no TLS impersonation, caps, tracing), the architect's fixed argv, protocol exclusions and scope-derived targets, and legal_dpo's no-exploit-confirmation floor are merged. The binding A7 BR11 tag rule excludes cve/kev/takeover templates, which is stricter than cti_lead's and redteam_lead's reviewed KEV list; widening it needs an A7 amendment (needs_human). -c is 2 so per-host concurrency stays within A7's 2 connections.

Synthesizer conditions (background; the final conditions win on conflict): ACTIVE + --authorized + scope file + audit log; external nuclei binary (MIT) pinned version, run with -rl/-c limits, -duc, no interactsh (-ni) and an allow-list of tags (exposure, misconfig, tech, panel, kev, takeover, non-intrusive cves) excluding intrusive, default-login, oast, fuzz/fuzzing, dos, bruteforce and the dast/code/headless/javascript directories; results parsed from JSONL into findings mapped to KEV/EPSS; a minimal internal matcher for simple GET word/status templates when the binary is unavailable.
Notes: Pentesters expect KEV-class edge-device checks; one engine reaches community coverage.

## P370 `dns_bruteforce` - Authorized DNS brute force and permutations (SecLists + alterx-style patterns, wildcard-aware)

- council: **approved**, priority P3, default_enabled=False, provider_tier=n/a, terms=open, opsec=active, shares_input=True
- category: pentest_recon; group: G13; inputs: domain; produces: domain, ipv4, ipv6
- auth: none; key env vars: -; hosts: raw.githubusercontent.com, github.com
- sources shared with other proposals: {"C0650": ["P285"]}

### Final conditions (binding spec - implement every item)

1. ACTIVE gate (A7): runs only with --mode active, a non-empty --authorized REF and a --scope FILE on every path (scan, run, shell, watch, batch; non-interactive runs refuse without both), on scope-file matches only after resolution and per redirect hop, never on pivots or on entities extracted from text/files; CDN/shared-hosting/SaaS IPs excluded unless listed. Only apexes listed in the scope file.
2. A7 ceilings enforced by the core client and socket connector: <= 10 requests/probes per second and <= 2 concurrent connections per target host, the case ACTIVE budget, the kill switch (traffic stops within 2 s), proxy_active egress profile (A13), the hostile-host guard, and every request in the hash-chained P324 ledger; the report banner carries REF, scope SHA-256, window and egress.
3. Candidates: SecLists subdomains-top1million-5000 by default (MIT, pinned SHA-256 in data/active.lock, through the dataset manager); custom lists <= 5,000 entries (A7); permutations (alterx/dnsgen style, MIT ideas re-implemented) generated offline only from names already found under scoped apexes, <= 2,000 per parent and <= 10,000 per run.
4. Resolution through ctx.dns over the proxy_active profile's DoH (Cloudflare or Quad9; Google only with edns_client_subnet=0.0.0.0/0), never by querying the target's authoritative NS directly from the analyst host; its own provider bucket of <= 10 queries/s (legal_dpo, A7, stricter than 20); answers bypass the shared HTTP cache (no cache or a dedicated short cache).
5. Wildcards: >= 3 random labels per parent, comparing answer sets. Existence = an A/AAAA/CNAME answer that differs from the wildcard answer; NODATA or NXDOMAIN alone prove nothing (Cloudflare 'black lies'); SERVFAIL or a timeout = unknown (rule 5).
6. Found names become subdomain pivots with expand=False and provenance 'brute-force'; they join the ACTIVE scope only if they fall under a scoped apex AND resolve to scoped IPs; names on CDN/SaaS IPs get passive modules only.
7. Runtime: module timeout set explicitly (600 s) with ctx.cancelled() checks and progress events. Output summarised: count plus the top 20 by interest (dev, staging, admin, vpn...). Tri-state results; merge only after the AR20 safety suite passes (A16).
8. Tests with DoH fixtures (FakeHttp add_dns) covering a wildcard zone, a Cloudflare NODATA zone and a SERVFAIL.

Chair rationale: Approved 6-0 at median P3 (redteam_lead, legal_dpo and the architect voted P2). The A7 floor applies; where members' numbers differed the stricter value wins (legal_dpo's 10 qps, the 10,000-per-run permutation cap). redteam_lead's resolver rule (never direct to the target NS from the analyst host, no ECS) and scope-join rule, the architect's cache isolation and wildcard logic, and analyst_ux's summary are adopted. Scheduling (A16 BR1): P3 with effort M, so it is not built in this build; BACKLOG.md keeps this spec as the unblock target.

Synthesizer conditions (background; the final conditions win on conflict): ACTIVE + --authorized + scope file + audit log (the target's authoritative servers see the queries); wordlist SecLists subdomains-top1million-5000 by default (MIT), permutations generated offline from already discovered names (cap 2,000 per parent); resolution through configurable resolvers/DoH with a rate cap (e.g. 20 qps) and wildcard detection by random labels; existence = A/AAAA/CNAME answer (Cloudflare-hosted zones answer NOERROR/NODATA for non-existent names, so NXDOMAIN tests are wrong); found names marked 'brute-force' provenance.
Notes: Finds staging/internal-looking hosts never seen in CT or passive DNS.
